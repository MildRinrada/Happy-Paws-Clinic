# ความปลอดภัย

เอกสารชุดนี้บอกว่าระบบป้องกันอะไรไว้แล้ว ป้องกันด้วยวิธีไหน และยังขาดอะไร เขียนสำหรับคนที่รับช่วงดูแลระบบ ตรวจรับงาน หรือประเมินความเสี่ยงก่อนนำขึ้นใช้งานจริง ทุกข้อมาจากการอ่านโค้ดและชุดทดสอบ และอ้างไฟล์จริง

|---|---|

| [สิทธิ์และการให้สิทธิ์](../authorization.md) | scope role 2FA กฎระดับข้อมูล กติกาเมื่อให้สิทธิ์ |

## ขอบเขตความเชื่อใจ

```text
เบราว์เซอร์  ──(คุกกี้ httpOnly hp_at, hp_rt)──>  Next.js (BFF)  ──(Bearer token)──>  API (ASP.NET Core)  ──>  PostgreSQL
                                                                                       ^
ผู้ดูแลเซิร์ฟเวอร์  ──(คำสั่ง migrate, bootstrap, reset-credentials บนเครื่อง)───────────┘
```

| ส่วน | เชื่ออะไร | ไม่เชื่ออะไร |
|---|---|---|
| เบราว์เซอร์ | ไม่ถือ token ใดเลย อ่านคุกกี้ไม่ได้ | ทุกอย่างที่ส่งมา |
| Next.js | ถือ token ของผู้ใช้ไว้ในคุกกี้ เรียก API แทนผู้ใช้ | ไม่ตัดสินสิทธิ์ ซ่อนปุ่มเพื่อความสะดวกเท่านั้น |
| API | ตรวจลายเซ็น token scope 2FA และกฎระดับข้อมูลทุกคำขอ | token ที่ลายเซ็น อัลกอริทึม issuer audience หรืออายุไม่ถูก |
| คำสั่ง operator | คนที่รันคำสั่งบนเครื่องได้ ถือฐานข้อมูลอยู่แล้ว | ไม่มี endpoint ใดทำสิ่งเดียวกันได้ |

- สิทธิ์ทุกอย่างตรวจที่ API endpoint ที่ลืมใส่ attribute ถูกปิดเป็นค่าเริ่มต้น (fallback policy)
- API ไม่รู้ IP จริงของเบราว์เซอร์ ทุกคำขอที่ผ่าน BFF มาจาก IP ของเซิร์ฟเวอร์ Next.js และ API ไม่ได้อ่าน `X-Forwarded-For` ผลคือ IP ในเซสชัน IP ใน audit log และ IP ที่ใช้นับ rate limit ของคำขอที่ยังไม่เข้าสู่ระบบ เป็นของ Next.js ทั้งหมด
- `docker-compose.yml` เปิดพอร์ต API (`5080`) และ PostgreSQL (`5432` หรือ `POSTGRES_PORT`) ออกสู่เครื่อง host บนเซิร์ฟเวอร์จริงควรให้เข้าถึงได้เฉพาะในเครือข่ายภายใน

## สิ่งที่ป้องกันไว้แล้ว

- รหัสผ่านเก็บเป็น hash ของ ASP.NET Core Identity เข้าสู่ระบบผิดทุกแบบตอบข้อความเดียวกัน และบัญชีที่ไม่มีอยู่ก็คำนวณ hash หลอกให้เวลาตอบใกล้กัน
- พนักงานลงทะเบียน TOTP ตั้งแต่ตอนรับคำเชิญ token ที่ไม่ผ่าน 2FA ใช้ scope อ่อนไหวไม่ได้
- refresh token หมุนทุกครั้ง ส่งค่าเก่าซ้ำแล้วปิดทั้งเซสชัน ฐานข้อมูลเก็บเพียง SHA-256
- เบราว์เซอร์ไม่ถือ token ทั้งหมดอยู่ในคุกกี้ httpOnly
- ให้สิทธิ์ได้ไม่เกินที่ตัวเองถือ และคลินิกต้องเหลือเจ้าของอย่างน้อยหนึ่งคนเสมอ
- ลูกค้าขอข้อมูลคนอื่นได้ 404 ไม่ใช่ 403
- error 500 ไม่ส่ง message stack หรือ SQL กลับ มีเพียง `request_id`
- คำขอสร้างเงิน นัด และคิว ต้องมี `Idempotency-Key` ส่งซ้ำได้ผลเดิม ไม่ทำซ้ำ
- การเปิดอ่านเวชระเบียนและประวัติสัตว์ถูกบันทึกใน audit log เสมอ
- ข้อความถึงลูกค้าทุกฉบับผ่านด่านความยินยอมก่อนถึงช่องทางส่ง
- webhook ส่งได้เฉพาะ `https` ไปยังที่อยู่สาธารณะ ตรวจทั้งก่อนส่งและตอนต่อ socket ไม่ตาม redirect และลงนาม HMAC-SHA256 ทุกครั้ง
- API key เก็บเป็น hash ใช้ได้ไม่เกิน scope และสาขาที่ผู้สร้างมีตอนนี้ หมดอายุเสมอ และใช้กับเส้นของคนไม่ได้
- token ของจอห้องรอเก็บเป็น hash ใช้ได้สองเส้น (กระดานที่ย่อแล้วและ stream ของสาขาเดียว) ถูกปฏิเสธทุกเส้นอื่นตั้งแต่ขั้นยืนยันตัว และไม่เคยอยู่ใน URL หรือ script ของหน้า
- secret ของ webhook และความลับของผู้ให้บริการเข้ารหัสด้วย Data Protection กุญแจอยู่นอกฐานข้อมูล

## ข้อจำกัดที่รู้อยู่

1. **challenge ของ 2FA ยังเป็นค่าเดียวกับ refresh token** ช่องที่เคยทำให้แลก challenge เป็น access token ผ่าน `POST /auth/refresh` ได้โดยไม่กรอกรหัส ปิดแล้วที่ `RefreshSessionHandler` พร้อมเทสต์ แต่การแยก challenge ออกเป็นค่าของตัวเองจะปลอดภัยกว่าในระยะยาว ดู [การเข้าสู่ระบบและเซสชัน](../authentication.md)
2. **ความลับ TOTP เก็บแบบไม่เข้ารหัส** ใน `user_accounts.two_factor_secret` และ `staff_invitations.pending_two_factor_secret` คำอธิบายใน `UserAccount.cs` ที่บอกว่าเข้ารหัสไม่ตรงกับโค้ด ใครได้สำเนาฐานข้อมูลไปจะสร้างรหัส 2FA ของทุกคนได้
3. **recovery code มีเฉพาะบัญชีที่ลงทะเบียน 2FA เอง** เจ้าของที่สร้างด้วย `bootstrap` และพนักงานที่รับคำเชิญยังไม่มี จนกว่าจะลงทะเบียนเองด้วย `POST /me/2fa/enroll` ระหว่างนั้นคนที่ทำโทรศัพท์หายต้องให้ผู้ดูแลเซิร์ฟเวอร์รัน `reset-credentials`
4. **ปิดบัญชีพนักงานแล้ว access token เดิมยังใช้ได้จนหมดอายุ** ไม่เกิน 15 นาทีกับอีก 30 วินาที API ไม่ตรวจเซสชันทุกคำขอ เรื่องเดียวกันใช้กับการเปลี่ยน role การเปลี่ยนรหัสผ่าน และการสั่งออกเครื่องอื่น
5. **ไม่มีการล็อกบัญชีเมื่อเดารหัสผิด** และไม่จำกัดจำนวนครั้งที่ลองรหัส TOTP ต่อ challenge รหัส TOTP เดียวกันใช้ซ้ำได้ภายในช่วงที่ยอมรับ
6. **rate limit ของคำขอที่ยังไม่เข้าสู่ระบบเป็นถังเดียวกันทั้งคลินิก** เพราะ API เห็นทุกคำขอจาก IP ของ Next.js เพดาน 600 ครั้งต่อนาทีจึงใช้ร่วมกันทุกคนที่กำลังเข้าสู่ระบบ policy `messaging` (60 ครั้งต่อนาทีต่อ token) ใช้กับการส่งข้อความของพนักงานและการตอบในกล่องข้อความ ส่วนรหัส OTP นับต่อเบอร์จากฐานข้อมูลแล้ว ไม่ขึ้นกับถังนี้ เพดานต่อ IP ของการจองโดยไม่ต้องสมัครก่อน (`guest-hold` 30 และ `guest-verify` 60 ครั้งต่อชั่วโมง) ก็เป็นถังเดียวของทั้งคลินิกเช่นกัน คนที่ตั้งใจยิงจนเต็มทำให้คนอื่นจองที่ `/book` ไม่ได้จนครบชั่วโมง ลูกค้าที่ล็อกอินแล้วยังจองที่ `/portal/book` ได้
7. **signing key ของ dev อยู่ใน `appsettings.Development.json`** และ `docker-compose.yml` ตั้ง `ASPNETCORE_ENVIRONMENT` เป็น `Development` เป็นค่าเริ่มต้น ถ้ารัน compose โดยไม่แก้ค่า API จะใช้กุญแจที่อยู่ใน repository เปิด OpenAPI ออก cookie ที่ไม่มี `Secure` และเขียนลิงก์คำเชิญลง log
8. **ยังไม่มี security header และ CSP** ทั้ง API และหน้าเว็บ ไม่มี `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options` หรือ `Referrer-Policy` มีเพียง HSTS และการ redirect ไป HTTPS เมื่อไม่ใช่ `Development`
9. **audit log ยังขาดบางรายการ** `auth.signed_in`, `auth.sign_in_failed`, `auth.password_changed`, `auth.session_revoked` อยู่ในรายการที่ต้องบันทึก แต่ยังไม่มีโค้ดเขียน และการยกเลิกนัดผ่าน `POST /appointments/{id}/cancel` ไม่เขียน `appointment.cancelled` ดู [Audit และความเป็นส่วนตัว](audit-and-privacy.md)
10. **log มีข้อมูลส่วนบุคคลบางส่วน** อีเมลที่พิมพ์ตอนเข้าสู่ระบบไม่สำเร็จ อีเมลผู้ถูกเชิญ และตัวส่งแจ้งเตือนที่ยังเป็น stub เขียนข้อมูลในข้อความรวมถึงคำวินิจฉัยลง log
11. **ระเบียนใน `idempotency_records` ไม่เคยถูกลบ** และเก็บ response เต็มของคำขอ ซึ่งมีข้อมูลการรักษาและการเงิน
12. **การเข้าสู่ระบบของลูกค้ายังไม่มีตัวส่งจริง** รหัส OTP และลิงก์รีเซ็ตรหัสผ่านไปอยู่ใน log เมื่อเปิด `Auth:SignIn:LogUndeliveredSecrets` ห้ามเปิดค่านี้นอกเครื่อง dev รหัส OTP เป็นตัวเลข 6 หลัก การป้องกันจึงพึ่งอายุ 5 นาที การเดาผิดได้ 5 ครั้ง และเพดาน 3 รหัสต่อเบอร์ใน 10 นาที LINE webhook ยังไม่มี
15. **ไฟล์ที่อัปโหลดเก็บบนดิสก์ของ API โดยไม่เข้ารหัส** ถ้าไม่ตั้ง `Storage:LocalRoot` ไฟล์อยู่ในโฟลเดอร์ชั่วคราวและหายได้ ไม่มีการสแกนไวรัส ระบบตรวจแค่ชนิดที่ผู้ส่งประกาศและขนาด ไฟล์ดาวน์โหลดส่ง `X-Content-Type-Options: nosniff` เพื่อกันเบราว์เซอร์เดาชนิดเอง
16. **API key ยกเลิกก่อนหมดอายุไม่ได้** contract ไม่มี endpoint นี้ ทางหยุด key ทันทีคือปิดบัญชีผู้สร้างหรือเอา scope ออกจาก role ของเขา ลิงก์ปฏิทินที่หลุดก็สร้างใหม่ไม่ได้เช่นกัน ดู [การเชื่อมต่อระบบภายนอก](integrations.md)
17. **กุญแจ Data Protection ต้องอยู่ในโฟลเดอร์ถาวร** ถ้าไม่ตั้ง `DataProtection:KeysDirectory` กุญแจใน container หายเมื่อสร้างใหม่ และ secret ของ webhook กับความลับของผู้ให้บริการจะอ่านไม่ได้
13. **ยังไม่เคยผ่านการทดสอบเจาะระบบ** ไม่มีการสแกนช่องโหว่ของไลบรารีอัตโนมัติ และไม่มี CI ในโปรเจกต์ เนื้อหาในชุดนี้มาจากการอ่านโค้ดและชุดทดสอบ ไม่ใช่ผลรับรองจากบุคคลที่สาม
14. **ยังไม่มีช่องทางแจ้งช่องโหว่** ไม่มีไฟล์ `SECURITY.md`

## ก่อนนำขึ้นใช้งานจริง

ทำทุกข้อ แล้วทดสอบซ้ำตามรายการในหัวข้อก่อนหน้า

**ต้องแก้โค้ดก่อน**

- [x] `RefreshSessionHandler` ปฏิเสธเซสชันที่ยังไม่ผ่าน 2FA ของบัญชีที่ลงทะเบียน TOTP แล้ว (แก้แล้วพร้อมเทสต์)
- [ ] พิจารณาแยก challenge ออกจาก refresh token เป็นค่าของตัวเอง
- [ ] เข้ารหัสความลับ TOTP และความลับของ LINE ก่อนเก็บ ใช้ `ISecretProtector` ที่มีแล้ว และย้ายค่าเดิม
- [x] เก็บรหัสสำรองเป็น hash และเพิ่มทางใช้ (`POST /me/2fa/enroll` และ `POST /auth/2fa/verify`)
- [ ] ใส่ตัวส่ง SMS และอีเมลจริง และปิด `Auth:SignIn:LogUndeliveredSecrets`
- [ ] ย้ายไฟล์ไปที่เก็บถาวรที่เข้ารหัส (เช่น S3) และลบไฟล์ของเอกสารที่ไม่เคยอัปโหลดเสร็จ
- [ ] เพิ่ม `UseForwardedHeaders` ที่เชื่อเฉพาะ proxy ของเราเอง และให้ Next.js ส่ง IP ของเบราว์เซอร์ต่อ ไม่อย่างนั้น rate limit และ audit log ไม่มีความหมาย
- [ ] จำกัดการเข้าสู่ระบบและการยืนยัน 2FA แยกจาก rate limit รวม และพิจารณาล็อกบัญชีแบบเพิ่มเวลา
- [ ] เพิ่ม security header และ CSP ทั้งใน API และ `next.config.ts`
- [ ] เขียน audit ที่ยังขาด และงานลบ `idempotency_records` ที่หมดอายุ

**ต้องตั้งค่า**

- [ ] `ASPNETCORE_ENVIRONMENT=Production`
- [ ] `Auth__Jwt__SigningKey` สุ่มใหม่ ยาวอย่างน้อย 32 ตัวอักษร ส่งทาง environment หรือที่เก็บความลับ ไม่ใช้ค่าใน repository
- [ ] `Auth__Jwt__Issuer` เป็นโดเมนจริงของ API
- [ ] รหัสผ่าน PostgreSQL ใหม่ และไม่ใช้ค่า `happypaws` หรือ `change-me`
- [ ] `Cors__AllowedOrigins` เป็นโดเมนจริงของหน้าเว็บเท่านั้น
- [ ] `Staff__Invitations__LogUndeliveredLinks` ไม่ตั้ง หรือตั้งเป็น `false`
- [ ] `NODE_ENV=production` ฝั่งหน้าเว็บ เพื่อให้คุกกี้เป็น `Secure`
- [ ] ปิดพอร์ต API และ PostgreSQL จากภายนอก ให้ผู้ใช้เข้าทาง HTTPS ของหน้าเว็บเท่านั้น
- [ ] ระดับ log ไม่ต่ำกว่า `Information` และจำกัดคนที่อ่าน log ได้
- [ ] `DataProtection__KeysDirectory` เป็น volume ถาวร สำรองแยกจากฐานข้อมูล และทุก instance ใช้โฟลเดอร์เดียวกัน

**ต้องทำเป็นงานดูแล**

- [ ] จ้างหรือจัดทดสอบเจาะระบบ และตั้งการสแกนช่องโหว่ของ NuGet และ npm
- [ ] กำหนดช่องทางแจ้งช่องโหว่
- [ ] กำหนดระยะเวลาเก็บข้อมูลและ audit log ร่วมกับที่ปรึกษากฎหมายของคลินิก ดู [ความยินยอมและข้อมูลส่วนบุคคล](../features/privacy-and-consent.md)
