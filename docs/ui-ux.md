# การออกแบบ UI/UX

หลักการที่หน้าจอทุกหน้าใช้ร่วมกัน ใช้ตรวจงานก่อนส่งทุกครั้งที่เพิ่มหรือแก้หน้าจอ ตอนนี้มี 4 หน้าจอ คือ หน้าแรกสาธารณะ เข้าสู่ระบบพนักงาน กระดานคิว และหน้าเก็บเงิน

## ผู้ใช้ของเรา

| ผู้ใช้ | ใช้บนอะไร | ต้องการอะไรจากหน้าจอ |
|---|---|---|
| พนักงานต้อนรับ แคชเชียร์ | คอมพิวเตอร์ที่เคาน์เตอร์ เปิดทั้งวัน มีลูกค้ายืนรอ | เห็นงานตรงหน้าทันที กดน้อย ตัวเลขอ่านง่าย ทำพลาดแล้วแก้ได้ |
| สัตวแพทย์ ผู้ช่วย | คอมพิวเตอร์ในห้องตรวจ | เห็นคิวของตัวเอง ไม่ต้องรีเฟรชเอง |
| เจ้าของและผู้ดูแลคลินิก | คอมพิวเตอร์และมือถือ | ตั้งค่าได้เอง เห็นภาพรวมหลายสาขา |
| เจ้าของสัตว์ | มือถือเป็นหลัก | รู้ว่าคลินิกอยู่ไหน เปิดกี่โมง มีบริการอะไร ราคาเท่าไร จองอย่างไร |

## สองหน้าตา

| | หน้าจอพนักงาน | หน้าสาธารณะ |
|---|---|---|
| route group | `(staff)`, `(auth)` | `(public)` |
| คนอ่าน | คนเดิมทั้งวัน | คนแปลกหน้าที่อ่านครั้งเดียวแล้วตัดสินใจ |
| น้ำเสียง | สงบ เขียวอมฟ้าแบบคลินิก (`brand`) เทาอุ่น (`ink`) | ดังกว่า เขียวอมฟ้าสด ส้ม เขียวเข้ม (`site-*`) |
| ฟอนต์ตัวเนื้อหา | IBM Plex Sans Thai | Prompt ทั้งหน้า |
| พื้นหลัง | `ink-50` | ขาว |

หน้าสาธารณะมีชุดสีของตัวเอง ไม่ยืดชุดสีของหน้าจอพนักงาน เพราะหน้าที่ต่างกัน หน้าที่คนนั่งดูทั้งวันต้องไม่ล้าตา ส่วนหน้าที่คนเปิดครั้งเดียวต้องเด่นพอให้จำได้

## สี

สีทั้งหมดเป็น token ใน `@theme` ของ `frontend/src/app/globals.css` (Tailwind v4 ตั้งค่าใน CSS) ใช้เป็น class เช่น `bg-brand-600`, `text-ink-700`, `bg-site-orange` ห้ามเขียนรหัสสีตรงในหน้าจอ

| กลุ่ม | token | ใช้ทำอะไร |
|---|---|---|
| แบรนด์ของหน้าจอพนักงาน | `brand-50` ถึง `brand-900` | `brand-600` คือสีของปุ่มและการกระทำ ผ่าน AA บนพื้นขาว `brand-700` ตอนชี้เมาส์ วงโฟกัสใช้ `brand-600` |
| เทาอุ่น | `ink-50` ถึง `ink-900` | ตัวอักษร เส้น พื้น ตารางยาว ๆ จึงไม่ดูเย็นชา |
| หน้าสาธารณะ | `site-teal`, `site-orange`, `site-forest`, `site-forest-raised`, `site-border`, `site-muted`, `site-soft`, `site-violet`, `site-footer`, `site-footer-raised` | Hero (teal) ปุ่มหลัก (orange) footer (footer) ปุ่มบนแถบสีส้ม (violet) |
| เฉพาะที่ | `line-green` | สีเขียวของ LINE ใน section ชวนเพิ่มเพื่อน |
| เฉพาะที่ | `site-alert` | แถบสายด่วนฉุกเฉินเหนือ footer |
| การ์ดตัวเลข | `stat-green`, `stat-orange`, `stat-purple`, `stat-gray` | การ์ด 4 ใบใต้ Hero |

- **สีสถานะ** ใช้สีมาตรฐานของ Tailwind ผ่าน `Badge` (`amber`, `green`, `blue`, `red`, `neutral`, `brand`) และ `Alert` (`error` แดง `info` ฟ้า `success` เขียว) ตัวอย่างในหน้าเก็บเงิน ค้างชำระเป็นเหลือง ชำระบางส่วนเป็นฟ้า ชำระแล้วเป็นเขียว
- **จุดที่ยังเขียนสีตรง** วงกลมสองวงใน `hero/avatar-stack.tsx` รูปอุ้งเท้าใน `logo-mark.tsx` และไอคอนแท็บ `public/icon.svg` ทั้งหมดมาจากดีไซน์หรือเป็นของสำรองเมื่อคลินิกยังไม่ตั้งโลโก้ ของใหม่ให้เพิ่ม token แทน
- **โลโก้ของคลินิก** ([ส่วนขยาย § 50](./contract-extensions.md)) ทุกที่ที่เคยวาดรูปอุ้งเท้า (หัวและท้ายหน้าเว็บ หัวหน้าลูกค้า หน้าเข้าสู่ระบบ เมนูของพนักงาน) ใช้ `ClinicLogo` ตัวเดียว ไม่มีโลโก้ก็วาดรูปอุ้งเท้าขนาดเดิมทุกพิกเซล มีโลโก้ก็สูงเท่ารูปอุ้งเท้าของที่นั้น กว้างตามรูปแต่ไม่เกินเพดานของแต่ละที่ และไม่ถูกตัด ชื่อข้างโลโก้ห่อด้วย `ClinicNameSlot` ซึ่งซ่อนชื่อเมื่อคลินิกปิด "แสดงชื่อคลินิกข้างโลโก้" แล้วให้โลโก้มีชื่อคลินิกเป็นข้อความแทนรูป ค่าทั้งหมดมาจาก root layout ผ่าน `ClinicIdentityProvider` ไอคอนแท็บใช้ไอคอนแท็บที่ตั้งแยก แล้วโลโก้ที่ย่อลงกรอบสี่เหลี่ยม (`/brand/tab-icon`) แล้ว `icon.svg`
- **ยังไม่มีธีมมืด** ไม่มีการสลับธีมและไม่ได้รองรับ `prefers-color-scheme`
- **ตอนพิมพ์** ส่วนที่ติด class `no-print` ถูกซ่อน (เมนู แถบบน ฟอร์ม ปุ่ม) พื้นหลังเป็นขาว ใช้กับการพิมพ์ใบเสร็จจากหน้าบิล

## ฟอนต์

โหลดด้วย `next/font` ใน `frontend/src/app/layout.tsx` ไฟล์ฟอนต์ถูกฝังตอน build หน้าจอพนักงานจึงไม่เรียก CDN ฟอนต์จากเครือข่ายของคลินิก และตัวอักษรไม่กระพริบเป็นฟอนต์สำรอง

| ฟอนต์ | token | น้ำหนัก | ใช้ที่ไหน |
|---|---|---|---|
| IBM Plex Sans Thai | `font-sans` | 400 ถึง 700 | ตัวเนื้อหาของหน้าจอพนักงาน (ค่าเริ่มต้นของ `body`) |
| Prompt | `font-display` | 300 ถึง 700 | หัวเรื่องของหน้าจอพนักงาน และทุกตัวอักษรของหน้าสาธารณะ |
| Inter | `font-wordmark` | 700 | ชื่อคลินิกข้างโลโก้เท่านั้น อ่านจาก `GET /clinic` (`ClinicNameText`) ถ้าอ่านไม่ได้ใช้ Happy Paws Clinic |

`font-mono` ตั้งเป็น IBM Plex Mono แต่ไม่ได้โหลด จะได้ก็ต่อเมื่อเครื่องมีฟอนต์นี้ ไม่อย่างนั้นใช้ฟอนต์ monospace ของระบบ ใช้กับรหัสอ้างอิงในหน้า error เท่านั้น

## ภาษา

- **ภาษาไทยทั้งหมด** `<html lang="th">` ชื่อเฉพาะใช้ตามจริง เช่น LINE, PromptPay
- **ข้อความ error มาจาก backend** ซึ่งตอบ `message` เป็นภาษาไทย (และ `message_en`) หน้าจอแสดง `message` ตรง ๆ การปฏิเสธเพราะสถานะหรือสิทธิ์แสดงในหน้าเดิมด้วยคำของ backend ส่วนความผิดพลาดจริง (API ล่ม ตอบ 500) ไปที่หน้า `(staff)/error.tsx` ซึ่งบอกแค่ว่าโหลดไม่สำเร็จพร้อมรหัสอ้างอิงและปุ่มลองใหม่ รายละเอียดอยู่ใน log ของเซิร์ฟเวอร์
- **ข้อความใต้ช่องกรอกบอกสิ่งที่ต้องทำ** เช่น กรอกจำนวนเงินเป็นตัวเลข และบอกยอดค้างเมื่อกรอกเกิน
- **ห้ามใช้ขีดยาวและจุดกึ่งกลางในข้อความบนหน้าจอ** คนไทยไม่ใช้ **ตอนนี้ยังมีหลงอยู่** ใน title ของหน้า (`metadata`) คำแนะนำใต้ช่องเลขอ้างอิงและเหตุผลยกเลิกบิล หัวหน้าบิล ป้ายสถานะการเชื่อมต่อของกระดานคิว และข้อความบางส่วนจากดีไซน์ใน `features/home/content/` ควรเก็บกวาดเมื่อแก้ไฟล์เหล่านั้น
- **วันเวลาเป็นเวลาคลินิกเสมอ** `formatDateTime` และเพื่อนใน `lib/format/datetime.ts` ใช้ `th-TH` กับ `Asia/Bangkok` ไม่ว่าเครื่องที่เปิดตั้งเขตเวลาอะไร
- **เงินแสดงเป็นบาทเฉพาะตอนวาด** `formatBaht` (`th-TH`, THB, ทศนิยม 2 ตำแหน่ง) ตัวเลขเงินใช้ `tabular-nums` ให้หลักตรงกันในตาราง หน้าจอไม่บวกยอดเอง ใช้ยอดที่ API ส่งมา ดู [ใบแจ้งหนี้และการเก็บเงิน](features/billing.md)

เอกสารใน `docs/` ห้ามใช้ขีดยาว ขีดกลาง และจุดกึ่งกลางเช่นกัน ช่วงเวลาเขียน `09:00 ถึง 20:00` หรือ `09:00-20:00`

## หน้าจอพนักงาน

- **โครงเดียวกันทุกหน้า** `StaffShell` มีเมนูด้านซ้ายที่จอ `lg` ขึ้นไป และแถบบนทุกขนาดจอ รายละเอียดอยู่ในหัวข้อ [โครงหน้าจอพนักงาน](#โครงหน้าจอพนักงาน)
- **ทีละสาขา** ทุกหน้าแสดงข้อมูลของสาขาที่เลือกอยู่ ถ้าบัญชีมีสาขาเดียว ตัวเลือกกลายเป็นชื่อสาขาเฉย ๆ บัญชีที่ยังไม่มีสาขาเห็นข้อความบอกให้ติดต่อผู้ดูแลระบบ
- **ป้ายชื่อช่องกรอกแสดงเสมอ** (`Field`) placeholder ไม่ใช่ป้ายชื่อสำหรับคนที่ทำงานหน้าเคาน์เตอร์
- **ปุ่มเป็น `type="button"` โดยค่าเริ่มต้น** ปุ่ม submit ที่หลงอยู่ในฟอร์มรับเงินคือทางที่เงินถูกรับสองครั้ง
- **กดซ้ำต้องปลอดภัย** ฟอร์มที่สร้างหรือรับเงินถือ `Idempotency-Key` ของตัวเองหนึ่งค่าต่อการกระทำ ใช้ค่าเดิมทุกครั้งที่ลองซ้ำ และเปลี่ยนหลังสำเร็จ ระหว่างส่งปุ่มบอกว่ากำลังบันทึก และกดไม่ได้
- **รายการว่างต้องบอกว่าว่าง** (`EmptyState`) ไม่ปล่อยให้ดูเหมือนหน้าพัง
- **ข้อมูลสด** กระดานคิวอัปเดตเองผ่าน SSE และบอกสถานะการเชื่อมต่อ ดู [คิว](features/queue.md) และ [realtime](realtime.md) หน้าจอพนักงานทุกหน้าเป็น `force-dynamic` ไม่มีหน้าไหนถูก render ล่วงหน้า
- **วงโฟกัสเห็นชัดทุกที่** `:focus-visible` ใช้เส้นขอบ `brand-600` กับทุกตัวควบคุม คนที่ใช้แป้นพิมพ์ต้องรู้เสมอว่าอยู่ตรงไหน

## โครงหน้าจอพนักงาน

ส่วนนี้คือเมนูด้านซ้ายกับแถบบนที่ล้อมทุกหน้าใน `(staff)` ทั้งสองส่วนติด `no-print` ตอนพิมพ์จึงหายไป ส่วนเนื้อหาของหน้าอยู่ใน `<main>` ที่มี `min-w-0` เสมอ ตารางกว้างอย่างตารางเวรและรายงานจึงเลื่อนในกล่องของตัวเอง ไม่ดันทั้งหน้าให้กว้างเกินจอ

**เมนูด้านซ้าย (จอ 1024 px ขึ้นไป)**

- **แบ่งเป็นกลุ่มตามงาน** งานวันนี้ (ภาพรวม คิววันนี้ ปฏิทินนัด ข้อความลูกค้า) ดูแลรักษา (ลูกค้าและสัตว์ แล็บ จ่ายยา) การเงินและคลัง (เก็บเงิน สต๊อกยา แพ็กเกจและโปรโมชัน) ลูกค้าสัมพันธ์ (แจ้งเตือนลูกค้า) และจัดการคลินิก (ตารางเวร รายงาน ผู้ช่วย AI ตั้งค่า) ชื่อเมนู ชื่อกลุ่ม ไอคอน และ scope อยู่ใน `features/staff-shell/content/staff-navigation.ts` เมนูที่บัญชีไม่มี scope ไม่แสดง และกลุ่มที่ไม่เหลือเมนูเลยก็ไม่แสดงหัวกลุ่ม เมนูตั้งค่าพาไปหน้าตั้งค่าแรกที่บัญชีใช้ได้ตรง ๆ
- **ไอคอนวาดเอง** ใน `staff-icon.tsx` แบบเดียวกับไอคอนของ portal เส้น 1.8 สีตามตัวอักษร ไม่ใช้ไลบรารีไอคอน
- **เมนูที่เปิดอยู่** พื้นเขียวมิ้นต์อ่อนกับแถบสีเขียวด้านซ้าย และมี `aria-current="page"`
- **อยู่กับที่เมื่อเลื่อนหน้า** เมนูสูงเท่าจอ ถ้ารายการยาวกว่าจอจะเลื่อนในตัวเมนูเอง
- **ย่อเหลือแต่ไอคอนได้** ปุ่มย่อเมนูอยู่ล่างสุด ตอนย่อชื่อเมนูขึ้นเป็น tooltip เมื่อชี้หรือโฟกัส และยังอยู่ให้ screen reader อ่าน ตัวเลขยังเห็นเป็นวงเล็กที่มุมไอคอน การเลือกนี้จำไว้ในคุกกี้ `hp_sidebar` ของเบราว์เซอร์นั้น เซิร์ฟเวอร์จึงวาดความกว้างที่ถูกตั้งแต่แรก เมนูไม่กระตุก ถ้าเบราว์เซอร์ไม่ยอมให้เขียนคุกกี้ เมนูก็ยังย่อได้ แค่ไม่จำ
- **ชื่อและโลโก้คลินิก** ชื่ออ่านจาก `GET /clinic` ระหว่างรอหรืออ่านไม่ได้ใช้คำว่า Happy Paws โลโก้มาจาก `ClinicLogo` เหมือนทุกหน้า ไม่มีโลโก้ใช้รูปอุ้งเท้าเดิม ปิดการแสดงชื่อแล้วชื่อและคำอธิบายใต้ชื่อหาย ตอนย่อเมนูโลโก้แคบลงให้พอดีช่อง

**ตัวเลขบนเมนู**

ตัวเลขบอกงานที่รออยู่หลังเมนูนั้น ใช้การอ่านชุดเดียวกับกล่องต้องจัดการตอนนี้ของ [หน้าภาพรวม](features/dashboard.md) และขอเฉพาะเมื่อบัญชีมี scope ของหน้านั้น

| เมนู | ตัวเลขคือ | อ่านจาก | scope |
|---|---|---|---|
| คิววันนี้ | บัตรคิวในช่องรอเรียก (`waiting` และ `skipped`) ของสาขาที่เลือก | `GET /staff/queue` | `queue:read` |
| ข้อความลูกค้า | บทสนทนาที่ลูกค้าพูดคำสุดท้าย ถ้าเต็มหน้าแสดงเป็น 100+ | `GET /staff/threads?status=awaiting_reply` | `message:read` |
| สต๊อกยา | ยาที่หมด หมดอายุ หรือใกล้หมดอายุ ของสาขาที่เลือก | `GET /staff/inventory/alerts` | `inventory:read` |

- อ่านไม่สำเร็จหรือถูกปฏิเสธ ไม่แสดงตัวเลข และไม่แสดงเลขศูนย์ ถ้าไม่มีงานรอก็ไม่แสดงเช่นกัน
- **ไม่ทำให้หน้าช้า** เซิร์ฟเวอร์เริ่มอ่านตอนวาดหน้าแต่ไม่รอ ส่งเป็น promise ให้เบราว์เซอร์ เมนูขึ้นก่อนแล้วตัวเลขตามมา หลังจากนั้นเบราว์เซอร์ขอใหม่ทุก 60 วินาทีผ่าน server action เฉพาะตอนแท็บนั้นเปิดดูอยู่ กลับมาที่แท็บก็อ่านทันทีหนึ่งครั้ง
- screen reader อ่านชื่อเมนูพร้อมตัวเลขเป็นคำ เช่น "ข้อความลูกค้า, รอตอบ 3"
- รีวิวที่รอตรวจไม่มีตัวเลขบนเมนู เพราะหน้าตรวจรีวิวเป็นหน้าหนึ่งในตั้งค่า ไม่มีเมนูของตัวเอง ยังดูจำนวนได้ที่หน้าภาพรวม

**แถบบน**

- **ช่องค้นหา** แสดงเมื่อบัญชีมี `customer:read` พิมพ์แล้วหยุดราว 0.25 วินาทีจึงค้น ค้นผ่าน server action token จึงอยู่ฝั่งเซิร์ฟเวอร์ ผลมีสองกลุ่ม ลูกค้าจาก `GET /staff/customers?q=` ซึ่งหาจากชื่อ เบอร์โทร และชื่อหรือ HN ของสัตว์ที่ลูกค้าดูแล และสัตว์จาก `GET /staff/pets?q=` ซึ่งหาจากชื่อ HN หรือเลขไมโครชิป กลุ่มสัตว์ขอเฉพาะบัญชีที่มี `patient:read` แต่ละกลุ่มแสดงไม่เกิน 5 รายการ บรรทัดสุดท้ายพาไปผลทั้งหมดในหน้าลูกค้า ต้องพิมพ์อย่างน้อย 2 ตัวอักษร
- **ใช้ด้วยแป้นพิมพ์ได้ทั้งหมด** กด `/` หรือ Ctrl+K (Mac ใช้ ⌘K) จากที่ไหนก็ได้เพื่อไปที่ช่องค้นหา ยกเว้นตอนพิมพ์อยู่ในช่องอื่น ลูกศรขึ้นลงเลือกผล Enter เปิดผลที่เลือก ถ้ายังไม่เลือกจะไปหน้าผลทั้งหมด Esc ครั้งแรกปิดรายการ ครั้งที่สองล้างช่อง ช่องนี้ทำตามรูปแบบ combobox ของ WAI-ARIA
- **สาขาและเวลา** ชื่อสาขามีจุดสีประจำสาขา สีคิดจากรหัสสาขา จึงเป็นสีเดิมทุกหน้าและทุกเครื่อง ข้างกันเป็นวันและเวลาของคลินิก (Asia/Bangkok) เปลี่ยนทุกนาที และสถานะจาก `GET /clinic/hours` ว่า "เปิดอยู่ ปิด 20:00" "ยังไม่เปิด เปิด 09:00" หรือ "ปิดแล้ว" ถ้าคลินิกยังไม่ตั้งเวลาทำการหรืออ่านไม่ได้ จะแสดงแค่วันเวลา ชื่อวันและเดือนใช้ตารางในโค้ด ไม่ใช้ชื่อย่อจาก `Intl` เพราะเซิร์ฟเวอร์กับเบราว์เซอร์ให้คำไม่ตรงกัน
- **ปุ่ม + สร้าง** เปิดเมนูสร้างนัด ออกบัตรคิว ลงทะเบียนลูกค้าใหม่ และรับชำระ ใช้รายการและเงื่อนไข scope เดียวกับทางลัดในหน้าภาพรวม (`features/analytics/lib/quick-actions.ts`) ถ้าไม่เหลือสักรายการ ปุ่มไม่แสดง
- **เมนูบัญชี** ปุ่มเป็นวงกลมอักษรย่อของชื่อ (จอ 1280 px ขึ้นไปมีชื่อด้วย) เปิดแล้วเห็นชื่อ ตำแหน่ง ลิงก์บัญชีของฉัน และปุ่มออกจากระบบ
- เมนู + สร้าง และเมนูบัญชีทำตามรูปแบบ menu button ของ WAI-ARIA เปิดด้วย Enter, Space หรือลูกศรลง ลูกศรเลื่อนรายการ Esc ปิดและคืนโฟกัสให้ปุ่ม คลิกที่อื่นหรือไปหน้าอื่นก็ปิด

**มือถือ (ต่ำกว่า 1024 px)**

- แถบบนมีปุ่ม ☰ ชื่อคลินิก ปุ่มแว่นขยาย ปุ่ม + และวงกลมบัญชี แถวที่สองเป็นสาขาและเวลา จอ 1280 px ขึ้นไปทุกอย่างอยู่แถวเดียว
- ปุ่ม ☰ เปิดลิ้นชักจากซ้ายที่มีเมนูกลุ่มเดียวกันพร้อมตัวเลข ลิ้นชักเป็น `<dialog>` แบบ modal โฟกัสจึงอยู่ในลิ้นชัก Esc ปิดได้ หน้าข้างหลังเลื่อนไม่ได้ระหว่างเปิด และปิดเองเมื่อกดเมนูหรือเปลี่ยนหน้า
- ปุ่มแว่นขยายเปิดช่องค้นหาเป็นแถบใต้แถบบน

## หน้าตั้งค่า

ทุกหน้าใต้ `/settings` ใช้โครงเดียวกันจาก `app/(staff)/settings/layout.tsx` รายละเอียดของแต่ละหน้าอยู่ใน [ตั้งค่าคลินิก](features/clinic-setup.md)

**รายการหน้าตั้งค่า**

- **แบ่งเป็นห้ากลุ่ม** คลินิก (คลินิกและสาขา เวลาทำการและวันหยุด ข้อมูลติดต่อ) การจองและการรักษา (กติกาการจอง คิว และเวชระเบียน นโยบายยกเลิกและประเภทนัด บริการและราคา) ทีมงาน (พนักงานและสิทธิ์) ลูกค้าและเว็บไซต์ (แต้มสะสม รีวิวจากลูกค้า บทความ ประกาศความเป็นส่วนตัว) และเชื่อมต่อ (LINE เชื่อมต่อระบบ) ชื่อกลุ่ม ชื่อหน้า และ scope ของแต่ละหน้าอยู่ใน `features/settings/content/settings-tabs.ts` หน้าที่บัญชีไม่มี scope ไม่แสดง และกลุ่มที่ไม่เหลือหน้าเลยก็ไม่แสดง เมนู **ตั้งค่า** ของพนักงานพาไปหน้าแรกที่ใช้ได้ตามลำดับเดียวกัน
- **จอ 1024 px ขึ้นไป** รายการอยู่ด้านซ้ายของพื้นที่ตั้งค่า กว้าง 15rem ค้างอยู่ระหว่างเลื่อนหน้ายาว หน้าปัจจุบันมีพื้นสีและ `aria-current="page"`
- **ต่ำกว่า 1024 px** รายการกลายเป็นช่องเลือก **หน้าตั้งค่า** ช่องเดียวเหนือหน้า แบ่งกลุ่มด้วย `optgroup` ไม่ใช่ป้ายเรียงเต็มจอ
- **จุดเตือน** หน้าที่ยังต้องตั้งค่ามีจุดสีส้มหลังชื่อ และข้อความ "ต้องตั้งค่า" สำหรับโปรแกรมอ่านหน้าจอ บนโทรศัพท์คำนี้ต่อท้ายชื่อในช่องเลือก ตอนนี้ใช้กับประกาศความเป็นส่วนตัวที่ยังไม่เผยแพร่เท่านั้น เพราะรู้ได้จากการอ่านเส้นเดียวที่แคชไว้แล้ว จุดอื่นที่ต้องอ่าน API เพิ่มทุกหน้าไม่ได้ทำ

**แถบบันทึก (save bar)**

- **ฟอร์มตั้งค่าที่มีการบันทึกแบบเดียว ไม่มีปุ่มบันทึกของตัวเอง** แก้ช่องไหนก็ตาม แถบขึ้นที่ท้ายคอลัมน์เนื้อหาแล้วติดขอบล่างของจอ (`sticky bottom-0`) จึงไม่ทับเมนูของพนักงาน และเว้นที่ให้แถบล่างของโทรศัพท์ (`env(safe-area-inset-bottom)`) ข้อความ "มีการแก้ไขที่ยังไม่บันทึก" ชื่อส่วนที่แก้ ปุ่ม **ยกเลิก** และ **บันทึก** แก้กลับเป็นค่าเดิมแล้วแถบหายเอง
- **หนึ่งหน้า หนึ่งแถบ** หน้าที่มีหลายฟอร์มบอกจำนวนและชื่อส่วนที่แก้ เช่น "2 ส่วน: การจองนัด, เลขคิว" บันทึกส่งทุกส่วนที่แก้ ส่วนละหนึ่งคำขอ (`requestSubmit()` ของแต่ละฟอร์ม ช่องบังคับจึงยังถูกตรวจ) ยกเลิกคืนทุกส่วน การ์ดสองใบที่เป็นฟอร์มเดียวกัน (ข้อมูลคลินิกกับโลโก้ หรือสองการ์ดของ LINE) นับเป็นส่วนเดียว
- **ผลของการบันทึกอยู่ข้างฟอร์ม** "บันทึกแล้ว" (`role="status"`) หรือข้อความจาก API (`role="alert"`) ขึ้นท้ายฟอร์มของส่วนนั้น โปรแกรมอ่านหน้าจอได้ยินจากตรงนั้นครั้งเดียว แถบเองแสดง "บันทึกแล้ว" สามวินาทีสำหรับตาเท่านั้น และถ้าบันทึกไม่ผ่าน แถบบอกว่าให้ดูข้อความที่ส่วนไหน
- **ถามก่อนออก** ระหว่างที่มีส่วนที่ยังไม่บันทึก การกดลิงก์ไปหน้าอื่นของระบบ (ดักคลิกที่ `window` ก่อน `<Link>` ของ Next.js) และการเปลี่ยนหน้าจากช่องเลือกบนโทรศัพท์ ถาม "ออกจากหน้านี้เลยไหม" ส่วนการโหลดหน้าใหม่และการปิดแท็บ เบราว์เซอร์ถามเองผ่าน `beforeunload` ปุ่มย้อนกลับของเบราว์เซอร์ไม่ถูกถาม เพราะ App Router หยุดไว้ไม่ได้
- **ฟอร์มที่ไม่ใช้แถบ** ตัวแก้บทความและตัวแก้ร่างประกาศความเป็นส่วนตัวมีปุ่มบันทึกคู่กับปุ่มอื่น จึงเก็บปุ่มของตัวเองไว้ แต่ยังถามก่อนออก (`useLeaveWarning`) ฟอร์มเพิ่มของใหม่ ฟอร์มในกล่อง (`ModalDialog`) และฟอร์มที่แก้ของทีละรายการในรายการยาว ยังมีปุ่มของตัวเองและไม่ถาม
- **ใช้กับฟอร์มใหม่** ให้ฟอร์มมี `id` แล้วเรียก `useUnsavedChanges` (ค่าที่ฟอร์มจะส่ง ชื่อส่วน และวิธีคืนค่าเดิม) และใช้ `SectionFooter` แทนปุ่มบันทึก หลังบันทึกผ่านเรียก `markSaved` ด้วยค่าที่เก็บแล้ว นอกพื้นที่ตั้งค่าไม่มีแถบ `SectionFooter` จึงวาดปุ่มบันทึกให้เอง

## ซ่อนปุ่มตามสิทธิ์ (UX เท่านั้น)

หน้าจอซ่อนเมนูและปุ่มที่บัญชีนั้นใช้ไม่ได้ เพื่อไม่ให้มีปุ่มที่กดแล้วได้ error **นี่ไม่ใช่การป้องกัน** backend ตรวจ scope และสิทธิ์ระดับข้อมูลทุกคำขอ และเป็นสิ่งเดียวที่ปฏิเสธจริง

- `allows()` ใน `lib/auth/scopes.ts` ใช้กฎเดียวกับ `ScopeSet` ของ backend คือ `*` ได้ทุกอย่าง และ `queue:*` ได้ทุกการกระทำของ `queue` scope ของบัญชีมาจาก `GET /me` หน้าจอเรียกผ่าน `context.can(scope)`
- เมนูใน `StaffShell` แสดงเฉพาะหน้าที่บัญชีมี scope แคชเชียร์ไม่เห็นคิว ผู้ช่วยสัตวแพทย์ไม่เห็นหน้าเก็บเงิน ตัวเลขบนเมนู ช่องค้นหา และเมนู + สร้าง ก็ซ่อนตาม scope เช่นกัน
- ปุ่มในหน้าซ่อนตามทั้งสถานะและ scope เช่น ฟอร์มรับชำระขึ้นเมื่อบิลยังรับเงินได้และบัญชีถือ `payment:collect` ปุ่มยกเลิกบิลขึ้นเฉพาะบิล `open`
- พิมพ์ที่อยู่ของหน้าที่ถูกซ่อนเองได้ แต่ backend ตอบ `403` และหน้าแสดงข้อความปฏิเสธแทนข้อมูล
- ข้อมูลที่ต้องใช้ scope อื่น (เช่น ชื่อลูกค้าซึ่งต้องใช้ `customer:read`) ถูกอ่านแบบไม่บังคับ ไม่มีสิทธิ์ก็แค่ไม่แสดง ไม่ทำให้ทั้งหน้าพัง

## หน้าสาธารณะ

- **เนื้อหาแยกจากหน้าตา** ข้อความ ลิงก์ และรูปอยู่ในไฟล์เนื้อหา component ทำหน้าที่วาดอย่างเดียว แตกไฟล์ละเอียด หนึ่งไฟล์หนึ่งชิ้น
- **รูปที่ยังไม่มีเป็นช่องว่าง** `ImageSlot` วาดกรอบเส้นประพร้อมคำบอกว่ารูปอะไรควรอยู่ตรงนี้ ช่องว่างถูกซ่อนจาก screen reader (`aria-hidden`) เพราะไม่มีความหมาย ใช้ `tone="onDark"` เมื่อช่องอยู่บนพื้นสี
- **ขนาดย่อจากดีไซน์** คอลัมน์เนื้อหา 992 px ผ่าน `SiteContainer` header 1120 px หัวเรื่อง Hero 48 px หัวข้อ section 30 px
- **ปุ่มของหน้าสาธารณะ** ใช้ `CtaLink` แบบ `solidInk` (ส้ม ตัวอักษรเข้ม ปุ่มหลัก) `violet` (ปุ่มหลักบนพื้นส้ม) `glass` (โปร่งบนพื้นสี) `outline` (ขอบขาวโปร่งบนแถบเขียวเข้ม) `outlineForest` (ขอบและตัวอักษรเขียวเข้มบนพื้นขาว ปุ่มรองบนหน้าขาว เช่น บทความก่อนหน้านี้) `dark` (ดำ) `forest` (เขียวเข้ม ปุ่มในการ์ด) ไม่ใช้ `Button` ของหน้าจอพนักงาน ถ้าทั้งการ์ดเป็นลิงก์อยู่แล้ว ปุ่มในการ์ดเป็นแค่ป้ายหน้าตาเหมือนปุ่ม ใช้ `ctaLinkLook(variant, size)` วาด เพราะลิงก์ซ้อนในลิงก์ไม่ได้ ปุ่ม `<button>` จริงที่ต้องหน้าตาเหมือนกัน เช่น ปุ่มส่งฟอร์มตารางวัคซีน ก็ใช้ `ctaLinkLook` เช่นกัน
- **ปุ่มสีส้มของหน้าสาธารณะใช้ตัวอักษรสีเข้มเสมอ** (`solidInk`) ตามดีไซน์ของเจ้าของทุกหน้า รวมถึงปุ่ม **สมัครใช้งานฟรี** และ **บัญชีของฉัน** บน header ปุ่ม **จองนัดหมาย** ใน Hero ปุ่ม **จอง** ในกล่องเวลาว่างเร็วสุด ปุ่ม **เช็กตารางวัคซีน** ในหน้าแรก และปุ่มส่งฟอร์มตารางวัคซีน แบบ `solid` (ส้ม ตัวอักษรขาว) เหลือใช้แค่ปุ่มจองบน header ของ portal ส่วนหน้าเข้าสู่ระบบ (`(auth)`) หน้าจอง และ portal ยังมีปุ่มส้มตัวอักษรขาวที่เขียน class เอง ยังไม่ได้เปลี่ยน
- **ชิ้นส่วนกลางของหน้าสาธารณะ** อยู่ใน `components/site/` หนึ่งไฟล์หนึ่งชิ้น เลือกหน้าตาด้วย prop ที่กำหนดชนิดไว้ (`tone`, `size`, `variant`, `look`) ส่วน `className` ใช้ปรับตำแหน่งหรือระยะเท่านั้น (รวม padding ของการ์ดที่ตั้ง `padding="none"`) `SiteCard` (การ์ด) `CardDivider` (เส้นคั่นในการ์ด) `MetaPill` (ป้ายเล็ก) `PageBanner` (แถบหัวหน้า) `CtaBand` (แถบหรือกล่องสีส้มปิดหน้า) `SectionHeader` (หัวข้อ section พร้อมเส้นคั่น) `SectionHeading` (หัวข้อ section อย่างเดียว ไม่มีเส้น สีตาม section) `DotChip` และ `ChipNav` (แถบปุ่มไปที่ส่วนต่าง ๆ หรือปุ่มกรอง) ทุกหน้าของ `(public)` ใช้ชุดนี้แล้ว ยกเว้นหน้าจอง ดูตารางใน [หน้าไหนใช้ชิ้นไหน](#หน้าไหนใช้ชิ้นไหน)
- **ข้อความของแถบหัวผ่านตัวอ่านกลาง** `loadPageBanner(page)` ใน `features/site-banners/lib/load-page-banner.ts` คืนคำนำ หัวข้อ คำอธิบาย ปุ่ม และรูปของแถบหัวแต่ละหน้า (ตอนนี้ `services` และ `team`) จากค่าตั้งต้นใน `content/page-banners.ts` เพื่อรอวันที่แก้แถบหัวจากหน้าจอพนักงานได้ ดู [หน้าบริการและราคา](features/services-page.md#ส่วนที่รอการอนุมัติ)
- **แบบที่เพิ่มให้หน้าบทความ** แบบเดิมหน้าตาไม่เปลี่ยน
  - `PageBanner` `tone="white"` หัวหน้าบนพื้นขาว ไม่มีแถบสี ตัวอักษรเขียวเข้ม คำนำสีเขียว คู่กับ `size="flush"` ที่เว้นด้านล่างน้อยกว่า เพราะเนื้อหาของหน้าต่อบนพื้นขาวเดียวกัน
  - `PageBanner` prop `aside` วางของอื่นทางขวาแทนรูป เช่น ช่องค้นหา จอกว้างอยู่ระดับเดียวกับคำอธิบาย จอแคบย้ายลงไปใต้ข้อความ ถ้ามี `image` ด้วย ใช้ `image`
  - `CtaBand` `variant="muted"` แถบเทาอ่อนเต็มความกว้าง ตัวอักษรเขียวเข้ม
  - `SiteCard` `radius="xl"` มุมมน 20 px สำหรับการ์ดใหญ่ เช่น การ์ดบทความล่าสุดที่แบ่งรูปกับข้อความ
  - `MetaPill` `tone="sun"` ป้ายเหลือง ตัวอักษรเข้มตัวหนา ใช้บนพื้นเขียวเข้ม
  - `DotChip` prop `current` ปุ่มของสิ่งที่หน้ากำลังแสดง พื้นเขียวเข้ม ตัวอักษรขาว และบอก screen reader ด้วย `aria-current`
- **แบบที่เพิ่มให้หน้าทีมของเรา** แบบเดิมหน้าตาไม่เปลี่ยน
  - `PageBanner` `tone="soft"` แถบหัวพื้นเทาอ่อน (`site-soft`) ตัวอักษรเขียวเข้ม คำนำสีเขียว คำอธิบายสีเทาเข้ม กรอบรูปว่างบนแถบนี้ใช้แบบพื้นสว่าง (`BannerImage` รับ `tone` ตามสีของแถบ แถบเขียวเข้มและแดงยังเป็น `onDark` เหมือนเดิม)
  - `MetaPill` `tone="softForest"` ป้ายเทาอ่อนตัวอักษรเขียวเข้ม ใช้บอกความเชี่ยวชาญใต้ชื่อคน
  - `ImageSlot` `tone="mint"` (กรอบว่างพื้นเขียวอ่อน รูปของสัตวแพทย์) และ `tone="soft"` (พื้นเทาอ่อน รูปของแผนกอื่น) `MemberPhoto` ส่ง `tone` ต่อให้
  - แถบไปที่แผนกใช้ `DotChip` แบบ `soft` ที่มีอยู่แล้ว โดยไม่ใส่จุดสีและจำนวน การ์ดของแต่ละคนไม่มีกรอบ จึงไม่ใช้ `SiteCard` และลิงก์ "จองนัดกับหมอท่านนี้" เป็นลิงก์ตัวอักษรขีดเส้นใต้ ไม่ใช่ `CtaLink`
- **แบบที่เพิ่มให้หน้ารีวิว** แบบเดิมหน้าตาไม่เปลี่ยน
  - `PageBanner` `size="wide"` แถบตัวอักษรอย่างเดียวแบบ `compact` แต่หัวข้อตัวหนา 40 px และคำอธิบายกว้างได้ถึง 680 px ให้ข้อความยาวสองบรรทัดพอดี บนแถบเขียวเข้มคำนำเป็นสีเหลือง (`site-sun`)
  - `SiteCard` `tone="whiteFaint"` การ์ดขาว ขอบเทาอุ่นอ่อน (`ink-200`) สีเดียวกับขอบของ `DotChip` ใช้กับการ์ดรีวิวและการ์ด "เคยพาน้องมาที่คลินิก?"
  - ปุ่มกรองใช้ `ChipNav` แบบ `inline` กับ `DotChip` ที่มี `current` ส่วนการ์ดคะแนนเฉลี่ยใช้ `SiteCard` `tone="muted"` และ `radius="xl"` ที่มีอยู่แล้ว
- **แบบที่เพิ่มในรอบย้ายหน้าที่เหลือ** แบบเดิมหน้าตาไม่เปลี่ยน
  - `SiteCard` `tone="raised"` การ์ดขาวมีเงา ไม่มีขอบ วางบนแถบสี ใช้กับกล่องเวลาว่างเร็วสุดใน Hero และเบอร์โทรในหน้าฉุกเฉิน
  - `SiteCard` `tone="orange"`, `tone="line"` (เขียว LINE) และ `tone="alert"` (แดง) การ์ดสีทึบตัวอักษรขาวแบบเดียวกับ `forest` ใช้กับการ์ดจองฉีดวัคซีน การ์ดเตือนผ่าน LINE และการ์ดสายด่วนในหน้าติดต่อเรา
  - `SiteCard` รับ `as` เพิ่มเป็น `nav`, `dl`, `details` และรับ `role` กับ `ariaLabel` เช่น `role="note"` ของกล่องคำเตือนทางการแพทย์
  - `PageBanner` `size="urgent"` แถบหัวของหน้าฉุกเฉิน เหมือน `compact` แต่ระยะบนล่างบนมือถือน้อยกว่าเล็กน้อย หัวข้อกว้างไม่เกิน 720 px และคำอธิบายน้ำหนักปกติ เบอร์โทรวางใต้คำอธิบายผ่าน `children`
  - `PageBanner` `leadWidth="roomy"` ให้คำอธิบายกว้างได้ 600 px แทนความกว้างของขนาดนั้น ใช้กับหน้านโยบายความเป็นส่วนตัวและหน้าตารางวัคซีน
  - `CtaBand` `variant="slim"` แถบส้มเต็มความกว้างที่เตี้ยกว่า `band` หัวข้อเล็กกว่า ใช้ปิดหน้าติดต่อเรา และ prop `actionsClassName` ปรับระยะระหว่างปุ่ม หน้าแรกใช้ห่างขึ้นเป็น 22 px ที่จอ `lg`
  - `SectionHeading` ย้ายจาก `features/home/components/shared/` มาอยู่ `components/site/section-heading.tsx` และ `SectionContainer` ของหน้าแรกถูกลบ ใช้ `SiteContainer` ตรง ๆ
- **เมนูมือถือใช้ `<details>`** เปิดได้ก่อน JavaScript โหลด
- **ลิงก์ในหน้าเลื่อนนุ่ม** (`scroll-behavior: smooth`) ไปที่ anchor ของ section

**ส่วนที่ยังเป็น component ของหน้าเองโดยตั้งใจ** เพราะหน้าตาไม่ตรงกับแบบไหน และถ้าบังคับเข้าแบบจะเปลี่ยนหน้าตา

- กล่องประกาศในหน้านโยบาย (ยังไม่เผยแพร่ เป็นฉบับเก่า ยังไม่ผ่านนักกฎหมาย) ใช้สีเทามีขอบ ฟ้า และเหลือง ซึ่งไม่มีใน `SiteCard`
- ป้ายในการ์ดบริการหน้าแรก (`ServiceTag`) มุมโค้ง 6 px สูง 26 px ส่วน `MetaPill` เป็นทรงแคปซูลสูง 22 px จึงรวมกันไม่ได้โดยหน้าตาไม่เปลี่ยน
- หน้าบทความแต่ละเรื่องไม่มีการ์ดหรือแถบ จึงไม่มีอะไรต้องย้าย ส่วนหน้าจองมีงานปรับหน้าตาใหม่แยกไว้

รายละเอียด section ลิงก์ที่ยังไม่มีปลายทาง และข้อความในดีไซน์ที่ต้องแก้ ดู [หน้าแรก](features/home-page.md)

## การรองรับจอ

- **ห้ามมีแถบเลื่อนแนวนอนทั้งหน้า** ตารางที่กว้าง (เช่น รายการบิล) เลื่อนได้เฉพาะในกรอบของตาราง (`overflow-x-auto`)
- **หน้าจอพนักงานออกแบบสำหรับคอมพิวเตอร์ก่อน** แต่ต้องใช้ได้บนแท็บเล็ตและมือถือ หน้าบิลแสดงรายการกับการ์ดด้านข้างคู่กันที่ `lg` ต่ำกว่านั้นเรียงลงมาเป็นคอลัมน์เดียว
- **หน้าสาธารณะออกแบบสำหรับมือถือด้วย** header ย่อเป็นปุ่มเมนูต่ำกว่า 1280 px การ์ดและ footer ลดจำนวนคอลัมน์ตามความกว้าง
- **พื้นที่กดบนมือถือ** ปุ่มเมนูของหน้าสาธารณะ 44 px ส่วนปุ่มของหน้าจอพนักงานสูง 32 px (`sm`) และ 40 px (`md`) ซึ่งเล็กกว่า 44 px ถ้าหน้าไหนต้องใช้บนมือถือเป็นหลักให้ขยาย

## การเข้าถึง

- เมนูที่เป็นหน้าปัจจุบันมี `aria-current="page"` ทั้งเมนูพนักงานและแท็บกรองสถานะ
- ปุ่มที่มีแต่ไอคอนต้องมี `aria-label` เช่น ปุ่มเมนูมือถือ
- `Alert` แบบ error เป็น `role="alert"` ประกาศทันที แบบอื่นเป็น `role="status"` ช่องที่ผิดมี `aria-invalid` และข้อความ error ผูกกับช่อง
- section ของหน้าแรกผูกกับหัวข้อด้วย `aria-labelledby`
- จุดสีบอกสถานะการเชื่อมต่อของกระดานคิวมีข้อความกำกับ ไม่ใช้สีอย่างเดียว
