# รีวิวจากลูกค้า

ลูกค้าที่มาใช้บริการจริงให้คะแนนและเล่าประสบการณ์ได้ พนักงานอ่านทุกรีวิวก่อนขึ้นหน้าเว็บ และหน้าเว็บแสดงเฉพาะรีวิวที่เผยแพร่ พร้อมค่าเฉลี่ยที่นับจากรีวิวเหล่านั้นเท่านั้น

ก่อนมีฟีเจอร์นี้ ส่วนรีวิวบนหน้าแรกเป็นข้อความตัวอย่างที่เขียนไว้ในโค้ด ถ้าขึ้นเว็บจริงจะเป็นรีวิวที่ไม่มีลูกค้าคนไหนเขียน ข้อความตัวอย่างถูกลบแล้ว ฟีเจอร์นี้ไม่อยู่ใน contract เป็นส่วนขยายที่อนุมัติแล้ว เหตุผลและทางเลือกที่ไม่เลือกอยู่ใน [ส่วนขยายของสัญญา ข้อ 36](../contract-extensions.md)

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน | อ่านรีวิวที่เผยแพร่และค่าเฉลี่ยที่ `/reviews` และบนหน้าแรก |
| ลูกค้าที่มีบัญชีออนไลน์ | รีวิวการมาของตัวเองใน 60 วันที่ผ่านมาที่ `/portal/reviews` หรือจากการ์ด "รีวิวการมาครั้งล่าสุด" บนหน้าแรกของ portal |
| ลูกค้าที่ไม่มีบัญชี | รีวิวผ่านลิงก์ที่ได้ในข้อความชวนรีวิว (`/review/{token}`) ลิงก์ใช้ได้ครั้งเดียวภายใน 30 วัน |
| พนักงานที่ถือ `content:manage` เช่น `clinic_admin` | อ่านรีวิวทุกสถานะ เผยแพร่ ไม่เผยแพร่ด้วยเหตุผลจากรายการ และตอบรีวิว ที่แท็บ "รีวิวจากลูกค้า" ในหน้าตั้งค่า (`/settings/reviews`) |
| พนักงานที่ถือ `automation:manage` | สร้างกติกาชวนรีวิว (`visit_completed`) และเปิดกติกาเริ่มต้นที่มากับระบบ |

`content:manage` คือ scope เดียวกับการเขียนบทความ เพราะสิ่งที่หน้าเว็บพูดถึงคลินิกเป็นงานของคนกลุ่มเดียวกัน

## การมาใช้บริการหนึ่งครั้ง

การมาหนึ่งครั้งคือหนึ่งวันตามเวลาคลินิก ที่สาขาหนึ่ง ของลูกค้าหนึ่งคน ที่มีอย่างใดอย่างหนึ่ง

- การตรวจที่ปิดเคสแล้ว
- บิลที่ไม่ได้ยกเลิกและมีสัตว์

เป็นนิยามเดียวกับการมาในรายชื่อควรกลับมาแล้วและกลุ่มลูกค้า ตัดแค่การตรวจที่ยังไม่ปิดเคส (การมายังไม่จบ) และบิลที่ไม่มีสัตว์ (ซื้อของที่เคาน์เตอร์) วันที่มีทั้งการตรวจและบิลนับเป็นการมาครั้งเดียว ชื่อของการมา (`visit_id`) คือการตรวจที่ปิดแล้วอันแรกของวัน ถ้าไม่มีคือบิลแรก

- รีวิวได้ภายใน 60 วันหลังการมา
- หนึ่งรีวิวต่อการมาหนึ่งครั้ง ไม่ว่าจะเขียนใน portal หรือผ่านลิงก์
- การมาของสัตว์ที่ถูกบันทึกว่าเสียชีวิตแล้วไม่อยู่ในรายการรอรีวิว และไม่ได้ข้อความชวนรีวิว

## สถานะของรีวิว

| สถานะ | ความหมาย | ทำอะไรต่อได้ |
|---|---|---|
| `pending` รอตรวจ | ลูกค้าส่งแล้ว ยังไม่มีใครนอกคลินิกเห็น | เผยแพร่ ไม่เผยแพร่ ตอบ |
| `published` เผยแพร่แล้ว | อยู่บนหน้าเว็บและนับในค่าเฉลี่ย | นำออก (ไม่เผยแพร่) ตอบ |
| `rejected` ไม่เผยแพร่ | ไม่อยู่บนหน้าเว็บและไม่นับในค่าเฉลี่ย | ไม่มี สถานะนี้จบแล้ว |

## กติกาความซื่อตรง

- รีวิวทุกอันรอพนักงานอ่านก่อนขึ้นหน้าเว็บ
- ไม่เผยแพร่ได้เฉพาะเหตุผลในรายการด้านล่าง ไม่มีช่องเหตุผลอื่น
- ค่าเฉลี่ยบนหน้าเว็บนับเฉพาะรีวิวที่เผยแพร่ **การไม่เผยแพร่เฉพาะเหตุผลในรายการคือสิ่งที่ทำให้ค่าเฉลี่ยตรงกับที่ลูกค้าให้จริง** คะแนนต่ำไม่ใช่เหตุผล
- พนักงานแก้คะแนนหรือข้อความของลูกค้าไม่ได้ ลูกค้าก็แก้หลังส่งไม่ได้
- คลินิกตอบได้หนึ่งข้อความใต้รีวิว แก้คำตอบได้โดยเขียนใหม่
- ทุกการเผยแพร่ ไม่เผยแพร่ และตอบ บันทึกใน audit log พร้อมรหัสพนักงานที่ทำ

| เหตุผล | ใช้เมื่อ |
|---|---|
| มีข้อมูลส่วนบุคคล (`personal_data`) | ข้อความมีเบอร์โทร ที่อยู่ ชื่อเต็มของใคร หรือข้อมูลส่วนตัวของพนักงาน |
| ภาษาไม่สุภาพ (`offensive`) | คำหยาบ คำด่า หรือคำที่สร้างความเกลียดชัง |
| ไม่เกี่ยวกับบริการของคลินิก (`off_topic`) | เรื่องของธุรกิจอื่น การเมือง หรือเรื่องที่ไม่เกี่ยวกับการมาใช้บริการ |
| สแปมหรือซ้ำ (`spam`) | โฆษณา ลิงก์ขายของ หรือข้อความเดิมซ้ำ |
| ลูกค้าขอให้นำออก (`customer_request`) | เจ้าของรีวิวขอให้นำออก |

## ลูกค้าขอให้นำรีวิวออก

ลูกค้าขอได้ทุกเมื่อ ทางโทรศัพท์ แชท หรือที่เคาน์เตอร์ คลินิกทำให้ทุกครั้ง

1. พนักงานที่ถือ `content:manage` เปิด `/settings/reviews` แท็บ "เผยแพร่แล้ว" (หรือ "รอตรวจ" ถ้ายังไม่ได้เผยแพร่)
2. หารีวิวของลูกค้าคนนั้น หน้าพนักงานแสดงชื่อเต็มและชื่อสัตว์ไว้ให้หา
3. กด "นำออกจากหน้าเว็บ" เลือกเหตุผล "ลูกค้าขอให้นำออก" แล้วยืนยัน

รีวิวหายจากหน้าเว็บและจากค่าเฉลี่ยทันที แถวยังอยู่พร้อมเหตุผลและ audit log เพื่อตอบได้ว่าใครนำออกเมื่อไร ถ้าลูกค้าขอลบข้อมูลทั้งหมด ใช้ขั้นตอนคำขอเรื่องข้อมูลใน [ความยินยอมและข้อมูลส่วนบุคคล](privacy-and-consent.md)

## ชื่อที่แสดงบนหน้าเว็บ

ลูกค้าเลือกตอนเขียน

| ตัวเลือก | หน้าเว็บแสดง |
|---|---|
| ชื่อจริง (`first_name`) | คำแรกของชื่อที่คลินิกบันทึกไว้ ตัดคำนำหน้าออก เช่น "คุณสมชาย ใจดี" แสดงว่า "สมชาย" |
| ไม่แสดงชื่อ (`anonymous`) | "ลูกค้า" |

คำนำหน้าที่ตัดคือ คุณ นาย นาง นางสาว น.ส. ด.ช. ด.ญ. ดร. และ Mr Mrs Ms Miss Dr ชื่อที่ขึ้นต้นเหมือนคำนำหน้าแต่ไม่ใช่ เช่น "คุณากร" ไม่ถูกตัด ถ้าตัดแล้วไม่เหลืออะไร แสดงว่า "ลูกค้า" ระบบคิดชื่อตอนเขียนแล้วเก็บไว้กับรีวิว ฟอร์มใน portal บอกชื่อที่จะแสดงก่อนส่ง หน้าลิงก์รีวิวไม่บอก เพราะหน้านั้นไม่แสดงข้อมูลส่วนตัวของใครเลย

นอกจากชื่อ หน้าเว็บแสดงชนิดของสัตว์ (เช่น "เจ้าของสุนัข") คะแนน ข้อความ วันที่เขียน และคำตอบของคลินิก **ไม่แสดงนามสกุล เบอร์โทร อีเมล หรือชื่อสัตว์** ชื่อสัตว์กับชื่อแรกของเจ้าของรวมกันทำให้คนในละแวกเดียวกันรู้ได้ว่าเป็นใคร

## ข้อความ

- คะแนน 1 ถึง 5 ดาว บังคับ
- ข้อความไม่บังคับ ยาวได้ไม่เกิน 1,000 ตัวอักษร เป็นตัวอักษรธรรมดา ระบบทำความสะอาดแบบบทความ คือตัดตัวอักษรควบคุมและตัวกลับทิศทางออก และบรรทัดว่างติดกันเหลือบรรทัดเดียว อะไรที่หน้าตาเป็นแท็ก HTML ถูกปฏิเสธ แต่ "ไข้ < 39" หรือ "<3" ใช้ได้
- คำตอบของคลินิกใช้กติกาเดียวกัน แต่ต้องมีข้อความ

หน้าเว็บแสดงข้อความเป็นตัวอักษรเสมอ ไม่มีอะไรในรีวิวที่ทำงานในเบราว์เซอร์ได้

## ชวนรีวิวอัตโนมัติ

กติกาเตือนอัตโนมัติมีตัวกระตุ้นใหม่ "หลังมาใช้บริการ (ชวนรีวิว)" (`visit_completed`) รายละเอียดของกติกาเตือนทั่วไปอยู่ใน [เตือนอัตโนมัติ](automation.md)

- ส่ง 1 ถึง 30 วันหลังการมา (`offset_days` -1 ถึง -30) ค่าที่อนุมัติคือ 2 วันหลังการมา เวลา 09:00
- **ใช้ความยินยอมรับข่าวสาร** การขอรีวิวเป็นการตลาด ลูกค้าที่ไม่เคยบันทึกความยินยอม หรือยินยอมเฉพาะข้อความเรื่องการรักษา ถูกข้ามและบันทึกว่าไม่มีความยินยอม
- ส่งหนึ่งครั้งต่อการมาหนึ่งครั้ง และไม่ส่งถ้าการมานั้นรีวิวแล้ว
- ลูกค้าที่มีบัญชีออนไลน์ได้ลิงก์หน้ารีวิวใน portal ลูกค้าคนอื่นได้ลิงก์ที่ใช้ได้ครั้งเดียว ลิงก์ถูกสร้างตอนส่งจริง การดูตัวอย่างผู้รับไม่สร้างอะไร
- ระบบมีกติกาเริ่มต้น "ชวนรีวิวหลังมาใช้บริการ 2 วัน" ใส่ไว้แบบปิด คลินิกดูตัวอย่างผู้รับก่อนแล้วเปิดเอง

ที่อยู่ของลิงก์ตั้งได้ที่ `Reviews:PortalUrl` (ค่าตั้งต้น `http://localhost:3000/portal/reviews`) และ `Reviews:InvitationUrlTemplate` (ค่าตั้งต้น `http://localhost:3000/review/{token}`) ต้องตั้งเป็นที่อยู่จริงของเว็บคลินิกก่อนเปิดใช้

## ลิงก์รีวิวที่ใช้ได้ครั้งเดียว

- token ขึ้นต้นด้วย `hprv_` ตามด้วยค่าสุ่ม 256 bit อยู่ในข้อความครั้งเดียว ฐานข้อมูลเก็บแค่ SHA-256 ของ token แบบเดียวกับ API key และจอห้องรอ
- ใช้ได้ 30 วันนับจากตอนส่ง และเขียนรีวิวได้ครั้งเดียว ถ้าการมาครั้งนั้นได้รีวิวใน portal ไปแล้ว ลิงก์ก็นับว่าใช้แล้ว
- หน้าลิงก์แสดงแค่วันที่มา บริการ และชื่อสัตว์ ไม่มีชื่อ เบอร์ หรือรหัสของลูกค้า
- หน้าลิงก์ไม่ขอความยินยอม การเขียนรีวิวคือการกระทำของลูกค้าเอง
- การส่งรีวิวผ่านลิงก์จำกัด 20 ครั้งต่อชั่วโมงต่อที่อยู่ IP (`RateLimits:ReviewSubmitsPerIpPerHour`)
- token อยู่ในที่อยู่ของหน้า จึงอาจอยู่ใน log ของเว็บเซิร์ฟเวอร์ ยอมรับได้เพราะใช้ได้ครั้งเดียวและเปิดได้แค่ฟอร์มรีวิวของการมาครั้งเดียว หน้านี้ไม่ให้เครื่องมือค้นหาเก็บ และไม่ส่งที่อยู่ของตัวเองต่อไปยังเว็บอื่น

## หน้าเว็บ

| หน้า | มีอะไร |
|---|---|
| หน้าแรก | รีวิวที่เผยแพร่ล่าสุดสองอันในการ์ดแบบเดิม และลิงก์ "ดูรีวิวทั้งหมด" ถ้ายังไม่มีรีวิวที่เผยแพร่ ส่วนนี้ไม่แสดงเลย ดู [หน้าแรกสาธารณะ](home-page.md) |
| `/reviews` | ค่าเฉลี่ย จำนวนรีวิว และจำนวนของแต่ละคะแนน แล้วรีวิวทีละ 10 อัน ใหม่สุดก่อน อยู่ใน sitemap และลิงก์ท้ายเว็บ |
| `/review/{token}` | ข้อมูลการมา ดาว ช่องข้อความ ตัวเลือกชื่อ หน้าขอบคุณ และหน้าลิงก์ใช้แล้ว หมดอายุ หรือไม่พบ |
| `/portal/reviews` | การมาที่รอรีวิว อันล่าสุดเปิดฟอร์มไว้แล้ว และหน้าขอบคุณหลังส่ง |
| หน้าแรกของ portal | การ์ด "รีวิวการมาครั้งล่าสุด" เมื่อมีการมาที่รอรีวิว |
| `/settings/reviews` | แท็บรอตรวจ เผยแพร่แล้ว ไม่เผยแพร่ ปุ่มเผยแพร่ ตัวเลือกเหตุผล และช่องตอบ |

หน้าแรกเก็บรีวิวไว้ 5 นาที การตัดสินจากหน้าตั้งค่าทำให้หน้าแรกและ `/reviews` โหลดใหม่ทันที ทุกหน้าใช้ได้บนจอกว้าง 390px โดยไม่ต้องเลื่อนหน้าไปด้านข้าง

**ไม่มีดาวรีวิวในผลค้นหา** หน้าเว็บไม่ใส่ข้อมูลโครงสร้าง `AggregateRating` เพราะ Google ไม่แสดงดาวของรีวิวที่ธุรกิจแสดงบนเว็บของตัวเอง

## Endpoint

| Method | Path | สิทธิ์ | ตอบ |
|---|---|---|---|
| GET | `/portal/reviews/pending` | `portal` | การมาที่รอรีวิว และชื่อแรกที่จะแสดง |
| POST | `/portal/reviews` | `portal` | `201` รีวิวสถานะ `pending` ของคนอื่นหรือไม่ใช่การมาได้ `404` รีวิวแล้วได้ `409 review_already_submitted` เกิน 60 วันได้ `422` |
| GET | `/reviews/invitations/{token}` | token | `status` เป็น `usable`, `used` หรือ `expired` วันที่มา บริการ และชื่อสัตว์ ไม่พบได้ `404` |
| POST | `/reviews/invitations/{token}` | token | `201` ใช้แล้วได้ `409 review_already_submitted` หมดอายุได้ `409 review_invitation_expired` เกินเพดานได้ `429` |
| GET | `/staff/reviews?status=&cursor=` | `content:manage` | รีวิวพร้อมชื่อเต็ม ชื่อสัตว์ และการตัดสินล่าสุด สถานะที่ไม่รู้จักได้ `422` |
| POST | `/staff/reviews/{id}/publish` | `content:manage` | รีวิวที่เผยแพร่แล้ว ไม่ได้รอตรวจได้ `409 state_conflict` |
| POST | `/staff/reviews/{id}/reject` | `content:manage` | `{ "reason": "..." }` ไม่มีเหตุผลหรือเหตุผลนอกรายการได้ `422` ไม่เผยแพร่ไปแล้วได้ `409 state_conflict` |
| POST | `/staff/reviews/{id}/reply` | `content:manage` | `{ "text": "..." }` รีวิวที่ไม่เผยแพร่ได้ `409 state_conflict` |
| GET | `/reviews?cursor=&limit=` | สาธารณะ | รีวิวที่เผยแพร่และ `summary` (`average`, `count`, `by_rating`) แคชได้ 60 วินาที |

รูปของคำขอและคำตอบอยู่ใน [ส่วนขยายของสัญญา ข้อ 36](../contract-extensions.md)

## ประวัติการทำงาน

| action | เมื่อไร |
|---|---|
| `review.published` | เผยแพร่รีวิว |
| `review.rejected` | ไม่เผยแพร่ หรือนำออก พร้อมเหตุผล |
| `review.replied` | เขียนหรือแก้คำตอบ |

ไม่มีข้อความของลูกค้าหรือคำตอบใน audit log

## ตาราง

`customer_reviews` หนึ่งแถวต่อรีวิว และ `review_invitations` หนึ่งแถวต่อคำเชิญ ทั้งสองตารางมี unique `(customer_id, branch_id, visit_on)` migration `CustomerReviews` ดู [ฐานข้อมูล](../database.md#migration)

## ข้อจำกัด

- ไม่มีเส้นลบรีวิว การนำออกคือไม่เผยแพร่ด้วยเหตุผล "ลูกค้าขอให้นำออก"
- รีวิวที่ไม่เผยแพร่แล้วกลับมาเผยแพร่ไม่ได้ และลูกค้าเขียนรีวิวใหม่ให้การมาครั้งนั้นไม่ได้ เพราะมีรีวิวแล้ว จึงควรอ่านให้แน่ใจก่อนยืนยัน
- ไม่ส่งคำเชิญซ้ำเมื่อลูกค้าไม่ตอบ
- ไม่มีการแจ้งพนักงานเมื่อมีรีวิวใหม่
- ไม่มีคะแนนแยกตามหมอหรือสาขาบนหน้าเว็บ
- จนกว่า API จะอ่านที่อยู่ IP จริงผ่าน proxy ได้ เพดานการส่งรีวิวผ่านลิงก์เป็นถังเดียวของทุกคนที่ส่งผ่านหน้าเว็บ
