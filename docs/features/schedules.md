# ตารางเวร

ตารางเวรบอกว่าใครทำงานที่สาขาไหน เมื่อไร และเป็นสิ่งเดียวที่ทำให้เวลาจองได้ contract เขียนไว้ว่า "ตารางเวรเป็นตัวกำหนด slot ที่ /booking/availability คำนวณ" สาขาที่เปิดอยู่แต่ไม่มีใครเข้าเวรจึงไม่มีช่วงให้จอง

ฟีเจอร์นี้มีห้า endpoint ครบตาม contract คือ สร้างเวร บันทึกวันลา ดูตารางรวม ดูช่วงว่างจริง และตั้งกติกาจ่ายเคส ส่วนที่ contract ไม่ได้เขียนไว้และเราตีความเอง อยู่ใน [ข้อสมมติ § 33](../assumptions.md) และมีส่วนขยายอีกสี่เส้นที่เจ้าของงานขอเพิ่ม คือแก้และลบเวรทีละเวร อ่านกติกาจ่ายเคส และคัดลอกเวรทั้งสัปดาห์ ([ส่วนขยาย § 47 ถึง 49](../contract-extensions.md))

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| คนที่มี `schedule:read` | ดูตารางเวรรวม ช่วงว่างของทุกคนในสาขาของตัวเอง และกติกาจ่ายเคส |
| คนที่มี `schedule:write` | สร้าง แก้ ลบ และคัดลอกเวร บันทึกวันลา และตั้งกติกาจ่ายเคส |
| ลูกค้า | ไม่เห็นตารางเวรโดยตรง เห็นแค่ช่องที่จองได้ใน `GET /booking/availability` |

ใน role ตั้งต้น มีแค่ `clinic_owner` และ `clinic_admin` ที่ถือ `schedule:*` คลินิกที่อยากให้หัวหน้าเคาน์เตอร์จัดเวรได้ ต้องเพิ่ม scope นี้ให้ role ของเขา

ผู้ที่ผูกกับสาขาจัดเวรได้เฉพาะคนที่ทำงานในสาขาเดียวกัน คนในสาขาอื่นได้ `404` เหมือนไม่มีคนนั้นอยู่

## เวร

เวรหนึ่งเวรคือหนึ่งคน หนึ่งสาขา ช่วงเวลาหนึ่งช่วง ยาวไม่เกิน 24 ชั่วโมง

```http
POST /v1/staff/schedules/shifts
{
  "staff_id": "stf_...",
  "branch_id": "brn_sukhumvit39",
  "starts_at": "2026-10-05T09:00:00+07:00",
  "ends_at": "2026-10-05T18:00:00+07:00",
  "break": { "starts_at": "2026-10-05T12:00:00+07:00", "ends_at": "2026-10-05T13:00:00+07:00" },
  "rrule": "FREQ=WEEKLY;BYDAY=MO,TU,TH,FR;UNTIL=20261231"
}
```

ตอบ `201` พร้อมรายการเวรที่สร้าง ทั้ง `break` และ `rrule` ไม่ส่งก็ได้

**เวรซ้ำด้วย RRULE** รองรับเฉพาะส่วนที่ตารางเวรต้องใช้

| ส่วน | ความหมาย | ตัวอย่าง |
|---|---|---|
| `FREQ` | `DAILY` ทุกวัน หรือ `WEEKLY` ทุกสัปดาห์ | `FREQ=WEEKLY` |
| `BYDAY` | วันในสัปดาห์ ใช้กับ `WEEKLY` เท่านั้น | `BYDAY=MO,WE,FR` |
| `INTERVAL` | ทุกกี่วันหรือกี่สัปดาห์ | `INTERVAL=2` คือเว้นสัปดาห์ |
| `COUNT` หรือ `UNTIL` | จบเมื่อครบกี่เวร หรือถึงวันไหน ต้องมีอย่างใดอย่างหนึ่ง | `COUNT=10`, `UNTIL=20261231` |

- เวลาตามนาฬิกาของคลินิก "09:00 ทุกวันจันทร์" คือ 09:00 ที่กรุงเทพทุกวันจันทร์
- ครั้งหนึ่งสร้างได้ไม่เกิน 200 เวร และไกลไม่เกิน 366 วันนับจากเวรแรก
- กฎที่อ่านไม่ได้หรือมีส่วนที่ยังไม่รองรับ เช่น `FREQ=MONTHLY` ตอบ `422` ที่ `rrule` ระบบไม่อ่านแค่บางส่วนแล้วสร้างเวรที่ไม่ตรงกับที่ตั้งใจ

**เวลาพัก** เวรที่มีเวลาพักถูกเก็บเป็นสองเวร คือก่อนพักและหลังพัก เวลาพักจึงเป็นช่องว่างที่ไม่มีใครจองได้ และในตารางรวมก็เห็นเป็นช่องว่าง ส่งเวลาพักมากับเวรแรกครั้งเดียว ทุกเวรที่ซ้ำได้เวลาพักที่ตำแหน่งเดียวกัน

**เวรทับกันไม่ได้** ถ้าเวรใดในคำขอทับเวรที่คนนั้นมีอยู่แล้ว (สาขาไหนก็ตาม) คำขอทั้งหมดถูกปฏิเสธด้วย `409 shift_overlap` และ `details.conflicts` บอกเวรที่ทับ ถ้าทับวันลาได้ `409 staff_on_time_off` ไม่มีการสร้างแค่บางส่วน คำขอที่ส่งซ้ำเพราะเน็ตหลุดจึงถูกปฏิเสธแทนที่จะสร้างเวรซ้ำ

**เงื่อนไขอื่น** พนักงานต้องยังทำงานอยู่ สาขาต้องเปิดอยู่ และถ้าพนักงานผูกกับสาขา สาขาของเวรต้องเป็นสาขาของเขา

เวรทุกเวรในคำตอบมีช่อง `version` สำหรับส่งกลับใน `If-Match` ตอนแก้หรือลบ

## แก้และลบเวร

ส่วนขยาย [§ 47](../contract-extensions.md) แก้หรือลบได้ทีละช่วง

```http
PATCH /v1/staff/schedules/shifts/shf_...
If-Match: "812"
{ "starts_at": "2026-10-12T10:00:00+07:00", "ends_at": "2026-10-12T16:00:00+07:00" }

DELETE /v1/staff/schedules/shifts/shf_...
```

- `PATCH` ส่งทั้งเวลาเริ่มและเลิก ตอบเวรที่แก้แล้วพร้อม `version` ใหม่ และ `conflicts` `DELETE` ตอบ `shift_id` และ `conflicts`
- กติกาเหมือนตอนสร้าง ช่วงใหม่ยาวไม่เกิน 24 ชั่วโมง ห้ามทับเวรอื่นของคนเดียวกัน (`409 shift_overlap`) และห้ามทับวันลา (`409 staff_on_time_off`)
- **ไม่แก้ประวัติ** เวรที่จบแล้วได้ `409 shift_ended` เวรที่เริ่มไปแล้วแก้ได้แค่เวลาเลิก และลบไม่ได้ (`409 shift_started`) ให้แก้เวลาเลิกหรือบันทึกวันลาแทน
- **นัดที่จองไว้ไม่ทำให้ถูกปฏิเสธ** `conflicts` คือนัดในเวลาที่ถูกตัดออก พร้อมคนที่รับแทนได้ รูปเดียวกับวันลา นัดไม่ถูกย้าย
- **เวรที่มีพักคือสองช่วง** ทั้งสองเส้นทำกับช่วงที่ระบุเท่านั้น ลบทั้งวันคือลบสองครั้ง
- เวรที่ลบถูกเก็บไว้เป็นเวรที่ยกเลิก เหมือนเวรที่วันลาตัด ลบซ้ำได้ `404` เวรของสาขาที่ผู้เรียกไม่ได้ประจำก็ได้ `404`

## คัดลอกเวรทั้งสัปดาห์

ส่วนขยาย [§ 49](../contract-extensions.md)

```http
POST /v1/staff/schedules/shifts/copy-week
{ "branch_id": "brn_sukhumvit39", "from_week": "2026-10-05", "to_week": "2026-10-12" }
```

- สัปดาห์ระบุด้วยวันจันทร์ คัดลอกเวรทุกช่วงของสาขานั้นที่เริ่มในสัปดาห์ต้นทาง ไปเวลาเดิมของวันเดียวกันในสัปดาห์ปลายทาง ส่ง `staff_ids` เพื่อคัดลอกเฉพาะบางคน
- **ได้ทั้งหมดหรือไม่ได้เลย** ถ้าช่วงใดชนเวรหรือวันลาที่มีอยู่ ไม่สร้างเลยสักช่วง และตอบรายการที่ชนแบบเดียวกับตอนสร้าง พร้อม `staff_id` ของแต่ละรายการ
- ไม่เกิน 200 ช่วงต่อครั้ง ช่วงที่เวลาเริ่มผ่านไปแล้วถูกข้ามและนับไว้ใน `skipped_started`
- ตอบ `201` พร้อม `data` คือเวรที่สร้าง

## วันลา

```http
POST /v1/staff/schedules/time-off
{
  "staff_id": "stf_...",
  "starts_at": "2026-10-05T13:00:00+07:00",
  "ends_at": "2026-10-05T18:00:00+07:00",
  "reason": "ลาป่วยครึ่งวัน"
}
```

การบันทึกวันลาคือการอนุมัติ contract ไม่มีขั้นขออนุมัติ จึงให้คนที่มี `schedule:write` เป็นผู้อนุมัติไปในตัว มีผลทันที

1. **เวรที่ถูกทับถูกยกเลิก** และเก็บไว้ในประวัติ ส่วนที่ยังทำงานอยู่กลายเป็นเวรใหม่ เช่น เวร 09:00 ถึง 18:00 กับวันลา 13:00 ถึง 18:00 เหลือเวร 09:00 ถึง 13:00
2. **ไม่มีใครจองช่วงนั้นได้อีก** เพราะไม่มีเวรแล้ว
3. **นัดที่จองไว้แล้วไม่ถูกย้าย** คำตอบบอกนัดที่อยู่ในช่วงลา พร้อมเพื่อนร่วมงานที่รับแทนได้

```json
{
  "time_off": { "id": "tof_...", "staff_id": "stf_...", "starts_at": "...", "ends_at": "...", "reason": "ลาป่วยครึ่งวัน" },
  "shifts_cancelled": 1,
  "shifts_remaining": [ { "id": "shf_...", "starts_at": "...09:00...", "ends_at": "...13:00..." } ],
  "conflicts": [
    {
      "appointment_id": "apt_...",
      "branch_id": "brn_sukhumvit39",
      "service_id": "svc_...",
      "starts_at": "...",
      "ends_at": "...",
      "suggested_staff_ids": ["stf_..."]
    }
  ]
}
```

คนที่ถูกเสนอให้รับแทนต้องเข้าเวรที่สาขานั้นตลอดช่วงของนัด ให้บริการนั้นได้ และไม่มีนัดหรือ hold ทับ เรียงตามกติกาจ่ายเคส ถ้าไม่มีใครเลย รายการเป็นค่าว่าง การย้ายนัดจริงใช้ `PATCH /staff/appointments/{id}` เพราะเจ้าของสัตว์ได้รับแจ้งชื่อหมอไปแล้ว การเปลี่ยนจึงเป็นเรื่องที่เคาน์เตอร์ต้องโทรคุย

ลาได้ครั้งละไม่เกิน 90 วัน เหตุผลยาวไม่เกิน 200 ตัวอักษร และลูกค้าไม่เห็น

## ตารางรวม

```http
GET /v1/staff/schedules?from=2026-10-05&to=2026-10-11&branch=brn_sukhumvit39&staff_id=stf_...
```

ทุกตัวกรองไม่ส่งก็ได้ ไม่ส่ง `from` ได้วันนี้ ไม่ส่ง `to` ได้หกวันถัดไป ดูได้ครั้งละไม่เกิน 31 วัน คำตอบจัดกลุ่มตามคน แต่ละคนมีชื่อ แผนก เวร และวันลาในช่วงนั้น เหมาะกับการวาดปฏิทิน

## ช่วงว่างจริง

```http
GET /v1/staff/schedules/availability?date=2026-10-05&branch=brn_sukhumvit39&staff_id=stf_...
```

สำหรับแต่ละคนที่เข้าเวรวันนั้นที่สาขานั้น คำตอบบอกเวร (`shifts`) สิ่งที่จองเวลาไว้แล้ว (`booked` คือนัดที่ยังกันเวลาและ hold ที่ยังไม่หมดอายุ) ช่วงว่างที่เหลือ (`free`) และรวมเป็นนาที (`free_minutes`)

- ต่างจาก `GET /booking/availability` ที่ตอบเป็นช่องของบริการเดียว เส้นนี้ตอบว่าใครว่างตอนไหน ไม่ผูกกับบริการ
- วันหยุดของสาขาตอบ `closed: true` พร้อมชื่อวันหยุด
- คลินิกสาขาเดียวไม่ต้องส่ง `branch`

## กติกาจ่ายเคส

```http
PUT /v1/staff/schedules/assignment-rules
{
  "rules": [
    { "species": "แมว", "service_id": "svc_dental", "staff_ids": ["stf_dentist"] },
    { "species": "แมว", "staff_ids": ["stf_catvet", "stf_backup"] }
  ]
}
```

- **เป็นลำดับความชอบ ไม่ใช่ข้อจำกัด** "หมอแมวรับเคสแมวก่อน" แปลว่าก่อน ไม่ใช่เท่านั้น ถ้าคนในกติกาไม่ว่าง เคสไปที่คนอื่นที่ว่างตามปกติ กติกาไม่เคยทำให้ช่วงที่ว่างอยู่จองไม่ได้
- **ข้อแรกที่ตรงชนะ** วางกติกาที่แคบกว่าไว้ข้างบน
- แต่ละข้อต้องระบุชนิดสัตว์ บริการ หรือทั้งสองอย่าง ชนิดสัตว์เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่กับค่า `species` ของสัตว์ เช่น `แมว` หรือ `cat` ตามที่คลินิกบันทึก
- ใครให้บริการไหนได้ ยังเป็นรายชื่อผู้ให้บริการของบริการนั้น กติกาแค่เรียงลำดับคนที่ได้รับอนุญาตอยู่แล้ว
- `PUT` แทนที่ทั้งชุด ส่ง `rules: []` เพื่อลบทั้งหมด ใช้ `If-Match` ได้ ทุกคนที่ระบุต้องยังทำงานอยู่ และทุกบริการต้องมีอยู่ ไม่อย่างนั้นได้ `422`
- `GET /v1/staff/schedules/assignment-rules` (ส่วนขยาย [§ 48](../contract-extensions.md)) อ่านกติกาที่บันทึกไว้ในรูปเดียวกับคำตอบของ `PUT` พร้อม `version` ใช้ `schedule:read` คลินิกที่ยังไม่เคยบันทึกได้รายการว่างและ `version: 0`
- มีได้ไม่เกิน 50 ข้อ แต่ละข้อไม่เกิน 20 คน

**กติกาถูกใช้ที่ไหน**

| ที่ | ใช้ไหม |
|---|---|
| จองโดยไม่ระบุหมอ จากเคาน์เตอร์หรือลูกค้า | ใช้ ทั้งชนิดสัตว์และบริการ |
| ถือ slot ระหว่างลูกค้ากรอกฟอร์ม | ใช้เฉพาะกติกาตามบริการ เพราะยังไม่รู้ว่าเป็นสัตว์ตัวไหน |
| เสนอหมอแทนตอนบันทึกวันลา | ใช้กติกาตามบริการ |
| จ่ายคิวให้หมอ | ไม่ใช้ ยังจ่ายด้วยมือที่ `POST /staff/queue/{id}/assign` |

## หน้าจอพนักงาน

`/schedules` เมนู **ตารางเวร** เห็นเฉพาะบัญชีที่ถือ `schedule:read`

- **หัวหน้า** ปุ่ม **+ ลงเวร** **บันทึกวันลา** และ **คัดลอกเวรสัปดาห์ก่อน** (ต้องถือ `schedule:write`) แต่ละปุ่มเปิดฟอร์มในกล่อง และปุ่ม **คาดการณ์ความหนาแน่น** เมื่อถือ `stats:read`
- **เปลี่ยนสัปดาห์** ปุ่ม **สัปดาห์ก่อน** **สัปดาห์ถัดไป** และ **สัปดาห์นี้** หรือเลือกวันที่ในช่องวันที่เพื่อไปสัปดาห์ของวันนั้น ใช้ `?week=` ใส่วันไหนของสัปดาห์ก็ได้ ระบบเลื่อนไปวันจันทร์ให้
- **ตารางรายสัปดาห์** (จอกว้าง) ของสาขาที่เลือกไว้ที่แถบบน คอลัมน์ละหนึ่งวัน คอลัมน์วันนี้มีพื้นสีอ่อนทั้งคอลัมน์
  - **ทุกคนในสาขา** ถ้าถือ `staff:read` ตารางรวมรายชื่อจาก `GET /staff/members` คนที่ไม่มีเวรในสัปดาห์นั้นก็ขึ้นเป็นแถวว่าง ถ้าไม่ถือ ขึ้นเฉพาะคนที่มีเวรหรือวันลา
  - **จัดกลุ่มตามแผนก** สัตวแพทย์ ต้อนรับ ผู้ช่วยสัตวแพทย์ และฝ่ายอื่น อ่านจากรหัสแผนก ไม่ได้ดูจากชื่อ แถวของคนที่เข้าสู่ระบบอยู่ขึ้นก่อนในกลุ่มของตัวเอง พร้อมป้าย **คุณ**
  - **ป้ายเวร** บอกเวลาเริ่มและเลิก เวรที่ลงพร้อมเวลาพักถูกเก็บเป็นสองช่วง ถ้าสองช่วงอยู่วันเดียวกัน สาขาเดียวกัน และห่างกันไม่เกินสามชั่วโมง หน้าจอแสดงเป็นป้ายเดียว เช่น "09:00-18:00" และใต้นั้น "พัก 12:00-13:00" ป้าย **ลา** พร้อมเหตุผลเมื่อวันนั้นมีวันลา
  - **หัวคอลัมน์** บอกจำนวนหมอที่เข้าเวร (สีแดง "ไม่มีหมอ" เมื่อไม่มี) และป้าย **คาดคนไข้มาก** เมื่อการคาดการณ์ความหนาแน่น ([§ 33](../contract-extensions.md)) บอกว่าวันนั้นมีชั่วโมงที่หนาแน่น อ่านเฉพาะเมื่อถือ `stats:read` และเฉพาะวันนี้ถึง 14 วันข้างหน้า อ่านไม่ได้ก็ไม่แสดง
  - **คอลัมน์รวม** ชั่วโมงทำงานทั้งสัปดาห์ของแต่ละคน ไม่นับเวลาพัก
  - **แถวคนเข้าเวร** ด้านล่าง บอกจำนวนหมอและพนักงานต้อนรับของแต่ละวัน วันที่ไม่มีหมอมีพื้นสีแดง
- **มุมมองรายวัน** (มือถือ) แทนตารางที่ต้องเลื่อนด้านข้าง เลือกวันจากปุ่มเจ็ดวัน แล้วเห็นรายชื่อคนที่ทำงานวันนั้นตามกลุ่มแผนก พร้อมจำนวนหมอ พนักงานต้อนรับ และป้ายคาดคนไข้มาก
- **ลงเวร** (ต้องถือ `schedule:write`) กดช่องว่างในตารางเพื่อเปิดฟอร์มที่เลือกคนและวันไว้แล้ว หรือกดปุ่มบนหัวหน้า เลือกพนักงาน วันที่ เวลาเริ่มและเลิก ใส่เวลาพักได้หนึ่งช่วง ถ้าเลือก **ลงซ้ำทุกสัปดาห์** ให้เลือกวันที่ทำงานและวันสุดท้าย หน้าจอสร้าง RRULE แบบ `FREQ=WEEKLY;BYDAY=MO,WE;UNTIL=20261231` ให้เอง ถ้ามีเวรไหนชนของเดิม ระบบไม่สร้างเลยสักเวร บันทึกแล้วกล่องปิดและตารางแสดงเวรใหม่ ช่องของวันที่ผ่านไปแล้วไม่มีปุ่มลงเวร
- **แก้หรือลบเวร** กดป้ายเวรที่ยังไม่จบ แก้เวลาเริ่มและเลิก หรือลบ (ต้องกดยืนยันอีกครั้ง) เวรที่มีพักให้เลือกช่วงก่อนหรือหลังพัก และมีปุ่ม **ลบทั้งเวร** เวรที่เริ่มไปแล้วแก้ได้แค่เวลาเลิกและลบไม่ได้ ถ้ามีนัดอยู่ในเวลาที่ถูกตัด กล่องแสดงรายการนัดพร้อมหมอที่รับแทนได้ ถ้าไม่มี กล่องปิดเอง
- **บันทึกวันลา** เลือกพนักงาน วันเวลาเริ่มและสิ้นสุด และเหตุผล บันทึกแล้วกล่องบอกว่าตัดเวรออกกี่เวร และแสดงนัดที่จองไว้ในช่วงลา พร้อมชื่อหมอที่รับแทนได้ และลิงก์ไปปฏิทินนัดของวันนั้น
- **คัดลอกเวรสัปดาห์ก่อน** กล่องบอกก่อนว่าจะคัดลอกกี่เวรของกี่คนจากสัปดาห์ไหนมาสัปดาห์ที่เปิดอยู่ และกติกาทั้งหมดหรือไม่ได้เลย ถ้าถูกปฏิเสธแสดงรายการที่ชนพร้อมชื่อคน ถ้าสำเร็จบอกจำนวนที่คัดลอกและจำนวนที่ข้ามเพราะวันผ่านไปแล้ว
- รายชื่อพนักงานในฟอร์มคือคนในตาราง เรียงตามกลุ่มแผนก
- คนที่มีแค่ `schedule:read` เห็นตารางเหมือนกัน แต่ไม่มีปุ่ม ช่องว่างกดไม่ได้ และป้ายเวรกดไม่ได้
- **กติกาจ่ายเคสให้หมอ** ส่วนที่พับไว้ใต้ตาราง ขึ้นเมื่อถือ `schedule:write`
  - อธิบายก่อนว่ากติกาบอกลำดับว่าใครได้ก่อน ไม่ได้ห้ามใคร กติกาแรกที่ตรงถูกใช้ และใช้ทั้งคลินิกตอนจองโดยไม่ระบุหมอและตอนเสนอหมอแทนวันลา
  - ฟอร์มเริ่มจากกติกาที่บันทึกไว้ (`GET /staff/schedules/assignment-rules`) ถ้ายังไม่มีกติกา เริ่มจากตัวอย่างใน contract คือหนึ่งกติกาสำหรับแมวที่ยังไม่ได้เลือกหมอ พร้อมกล่องสีเหลืองบอกว่าเป็นตัวอย่าง ถ้าอ่านไม่สำเร็จก็เริ่มจากตัวอย่างและบอกว่าการบันทึกจะแทนที่ของเดิม
  - แต่ละกติกาเลือกชนิดสัตว์ (พิมพ์เองได้) บริการ และรายชื่อหมอตามลำดับ เลื่อนขึ้นลงหรือลบได้ทั้งกติกาและหมอ
  - ตรวจในหน้าเว็บก่อนบันทึก ต้องมีชนิดสัตว์หรือบริการ หมอ 1 ถึง 20 คน และไม่เกิน 50 กติกา ต้องติ๊กยืนยันก่อนบันทึก ฟอร์มว่างหมายถึงลบกติกาทั้งหมด
  - บันทึกพร้อม `If-Match` ของ `version` ที่อ่านมา ถ้ามีคนบันทึกก่อน หน้าจอบอกให้โหลดหน้าใหม่ บันทึกแล้วฟอร์มแสดงกติกาตามที่ backend เก็บจริง
  - บริการมาจาก `GET /staff/services` ถ้าถือ `service:manage` ไม่อย่างนั้นมาจากเมนูบริการสาธารณะของสาขา

## คาดการณ์ความหนาแน่น

ส่วนขยาย [§ 33](../contract-extensions.md) หน้า `/schedules/forecast` เปิดจากปุ่ม **คาดการณ์ความหนาแน่น** บนหัวหน้าตารางเวร ปุ่มและหน้าขึ้นเฉพาะบัญชีที่ถือ `stats:read` เพราะอ่านจาก `GET /staff/stats/demand-forecast` ซึ่งอยู่ในหมวดสถิติ

- แต่ละวันข้างหน้าเป็นการ์ดหนึ่งใบ รายชั่วโมงบอกนัดที่จองแล้ว walk-in ที่คาดไว้ หมอที่ลงเวร และคนไข้ต่อหมอ
- walk-in ที่คาดไว้คือค่าเฉลี่ยของวันเดียวกันในสัปดาห์และชั่วโมงเดียวกันย้อนหลัง 8 สัปดาห์ หมอที่ลงเวรนับจากเวรในหน้านี้ วันลาตัดเวรออกอยู่แล้ว
- ชั่วโมงที่คนไข้ต่อหมอสูงกว่าปกติของสาขา (เปอร์เซ็นไทล์ที่ 80 ของ 8 สัปดาห์ที่ผ่านมา) หรือมีคนไข้แต่ไม่มีหมอลงเวร มีพื้นแดงอ่อนและป้าย **หนาแน่น** ใช้ตัดสินใจว่าควรลงเวรเพิ่มชั่วโมงไหน
- เลือกวันเริ่ม (วันนี้หรือหลังจากนั้น) และดู 7 หรือ 14 วัน

กติกาทั้งหมดอยู่ใน [คาดการณ์จากข้อมูลของคลินิก](forecasts.md)

## ข้อจำกัดที่รู้อยู่

- รายชื่อหมอในกติกามาจากสาขาที่เลือกไว้เท่านั้น แม้กติกาใช้ทั้งคลินิก
- ยังไม่มีการยกเลิกวันลา
- แก้เวรได้แค่เวลา ย้ายไปคนอื่นหรือสาขาอื่นไม่ได้ ให้ลบแล้วลงใหม่
- ป้ายเวรที่รวมสองช่วงเป็นการเดาจากช่องว่าง ระบบไม่ได้เก็บว่าสองช่วงมาจากคำขอเดียวกัน เวรสองเวรที่ตั้งใจลงแยกแต่ห่างกันไม่เกินสามชั่วโมงจึงแสดงเป็นป้ายเดียวที่มีช่วงพัก
- การคัดลอกทำได้แค่จากสัปดาห์ก่อนหน้าบนหน้าจอ backend รับสัปดาห์ใดก็ได้
- เวลาพักมีได้ช่วงเดียวต่อเวร
