# ตารางเวร

ตารางเวรบอกว่าใครทำงานที่สาขาไหน เมื่อไร และเป็นสิ่งเดียวที่ทำให้เวลาจองได้ contract เขียนไว้ว่า "ตารางเวรเป็นตัวกำหนด slot ที่ /booking/availability คำนวณ" สาขาที่เปิดอยู่แต่ไม่มีใครเข้าเวรจึงไม่มีช่วงให้จอง

ฟีเจอร์นี้มีห้า endpoint ครบตาม contract คือ สร้างเวร บันทึกวันลา ดูตารางรวม ดูช่วงว่างจริง และตั้งกติกาจ่ายเคส ส่วนที่ contract ไม่ได้เขียนไว้และเราตีความเอง อยู่ใน [ข้อสมมติ § 33](../assumptions.md)

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| คนที่มี `schedule:read` | ดูตารางเวรรวมและช่วงว่างของทุกคนในสาขาของตัวเอง |
| คนที่มี `schedule:write` | สร้างเวร บันทึกวันลา และตั้งกติกาจ่ายเคส |
| ลูกค้า | ไม่เห็นตารางเวรโดยตรง เห็นแค่ช่องที่จองได้ใน `GET /booking/availability` |

ใน role ตั้งต้น มีแค่ `clinic_owner` และ `clinic_admin` ที่ถือ `schedule:*` คลินิกที่อยากให้หัวหน้าเคาน์เตอร์จัดเวรได้ ต้องเพิ่ม scope นี้ให้ role ของเขา

ผู้ที่ผูกกับสาขาจัดเวรได้เฉพาะคนที่ทำงานในสาขาเดียวกัน คนในสาขาอื่นได้ `404` เหมือนไม่มีคนนั้นอยู่

## เวร

เวรหนึ่งเวรคือหนึ่งคน หนึ่งสาขา ช่วงเวลาหนึ่งช่วง ยาวไม่เกิน 24 ชั่วโมง

```http
POST /v1/staff/schedules/shifts
{
  "staff_id": "stf_...",
  "branch_id": "brn_sukhumvit39",
  "starts_at": "2026-10-05T09:00:00+07:00",
  "ends_at": "2026-10-05T18:00:00+07:00",
  "break": { "starts_at": "2026-10-05T12:00:00+07:00", "ends_at": "2026-10-05T13:00:00+07:00" },
  "rrule": "FREQ=WEEKLY;BYDAY=MO,TU,TH,FR;UNTIL=20261231"
}
```

ตอบ `201` พร้อมรายการเวรที่สร้าง ทั้ง `break` และ `rrule` ไม่ส่งก็ได้

**เวรซ้ำด้วย RRULE** รองรับเฉพาะส่วนที่ตารางเวรต้องใช้

| ส่วน | ความหมาย | ตัวอย่าง |
|---|---|---|
| `FREQ` | `DAILY` ทุกวัน หรือ `WEEKLY` ทุกสัปดาห์ | `FREQ=WEEKLY` |
| `BYDAY` | วันในสัปดาห์ ใช้กับ `WEEKLY` เท่านั้น | `BYDAY=MO,WE,FR` |
| `INTERVAL` | ทุกกี่วันหรือกี่สัปดาห์ | `INTERVAL=2` คือเว้นสัปดาห์ |
| `COUNT` หรือ `UNTIL` | จบเมื่อครบกี่เวร หรือถึงวันไหน ต้องมีอย่างใดอย่างหนึ่ง | `COUNT=10`, `UNTIL=20261231` |

- เวลาตามนาฬิกาของคลินิก "09:00 ทุกวันจันทร์" คือ 09:00 ที่กรุงเทพทุกวันจันทร์
- ครั้งหนึ่งสร้างได้ไม่เกิน 200 เวร และไกลไม่เกิน 366 วันนับจากเวรแรก
- กฎที่อ่านไม่ได้หรือมีส่วนที่ยังไม่รองรับ เช่น `FREQ=MONTHLY` ตอบ `422` ที่ `rrule` ระบบไม่อ่านแค่บางส่วนแล้วสร้างเวรที่ไม่ตรงกับที่ตั้งใจ

**เวลาพัก** เวรที่มีเวลาพักถูกเก็บเป็นสองเวร คือก่อนพักและหลังพัก เวลาพักจึงเป็นช่องว่างที่ไม่มีใครจองได้ และในตารางรวมก็เห็นเป็นช่องว่าง ส่งเวลาพักมากับเวรแรกครั้งเดียว ทุกเวรที่ซ้ำได้เวลาพักที่ตำแหน่งเดียวกัน

**เวรทับกันไม่ได้** ถ้าเวรใดในคำขอทับเวรที่คนนั้นมีอยู่แล้ว (สาขาไหนก็ตาม) คำขอทั้งหมดถูกปฏิเสธด้วย `409 shift_overlap` และ `details.conflicts` บอกเวรที่ทับ ถ้าทับวันลาได้ `409 staff_on_time_off` ไม่มีการสร้างแค่บางส่วน คำขอที่ส่งซ้ำเพราะเน็ตหลุดจึงถูกปฏิเสธแทนที่จะสร้างเวรซ้ำ

**เงื่อนไขอื่น** พนักงานต้องยังทำงานอยู่ สาขาต้องเปิดอยู่ และถ้าพนักงานผูกกับสาขา สาขาของเวรต้องเป็นสาขาของเขา

## วันลา

```http
POST /v1/staff/schedules/time-off
{
  "staff_id": "stf_...",
  "starts_at": "2026-10-05T13:00:00+07:00",
  "ends_at": "2026-10-05T18:00:00+07:00",
  "reason": "ลาป่วยครึ่งวัน"
}
```

การบันทึกวันลาคือการอนุมัติ contract ไม่มีขั้นขออนุมัติ จึงให้คนที่มี `schedule:write` เป็นผู้อนุมัติไปในตัว มีผลทันที

1. **เวรที่ถูกทับถูกยกเลิก** และเก็บไว้ในประวัติ ส่วนที่ยังทำงานอยู่กลายเป็นเวรใหม่ เช่น เวร 09:00 ถึง 18:00 กับวันลา 13:00 ถึง 18:00 เหลือเวร 09:00 ถึง 13:00
2. **ไม่มีใครจองช่วงนั้นได้อีก** เพราะไม่มีเวรแล้ว
3. **นัดที่จองไว้แล้วไม่ถูกย้าย** คำตอบบอกนัดที่อยู่ในช่วงลา พร้อมเพื่อนร่วมงานที่รับแทนได้

```json
{
  "time_off": { "id": "tof_...", "staff_id": "stf_...", "starts_at": "...", "ends_at": "...", "reason": "ลาป่วยครึ่งวัน" },
  "shifts_cancelled": 1,
  "shifts_remaining": [ { "id": "shf_...", "starts_at": "...09:00...", "ends_at": "...13:00..." } ],
  "conflicts": [
    {
      "appointment_id": "apt_...",
      "branch_id": "brn_sukhumvit39",
      "service_id": "svc_...",
      "starts_at": "...",
      "ends_at": "...",
      "suggested_staff_ids": ["stf_..."]
    }
  ]
}
```

คนที่ถูกเสนอให้รับแทนต้องเข้าเวรที่สาขานั้นตลอดช่วงของนัด ให้บริการนั้นได้ และไม่มีนัดหรือ hold ทับ เรียงตามกติกาจ่ายเคส ถ้าไม่มีใครเลย รายการเป็นค่าว่าง การย้ายนัดจริงใช้ `PATCH /staff/appointments/{id}` เพราะเจ้าของสัตว์ได้รับแจ้งชื่อหมอไปแล้ว การเปลี่ยนจึงเป็นเรื่องที่เคาน์เตอร์ต้องโทรคุย

ลาได้ครั้งละไม่เกิน 90 วัน เหตุผลยาวไม่เกิน 200 ตัวอักษร และลูกค้าไม่เห็น

## ตารางรวม

```http
GET /v1/staff/schedules?from=2026-10-05&to=2026-10-11&branch=brn_sukhumvit39&staff_id=stf_...
```

ทุกตัวกรองไม่ส่งก็ได้ ไม่ส่ง `from` ได้วันนี้ ไม่ส่ง `to` ได้หกวันถัดไป ดูได้ครั้งละไม่เกิน 31 วัน คำตอบจัดกลุ่มตามคน แต่ละคนมีชื่อ แผนก เวร และวันลาในช่วงนั้น เหมาะกับการวาดปฏิทิน

## ช่วงว่างจริง

```http
GET /v1/staff/schedules/availability?date=2026-10-05&branch=brn_sukhumvit39&staff_id=stf_...
```

สำหรับแต่ละคนที่เข้าเวรวันนั้นที่สาขานั้น คำตอบบอกเวร (`shifts`) สิ่งที่จองเวลาไว้แล้ว (`booked` คือนัดที่ยังกันเวลาและ hold ที่ยังไม่หมดอายุ) ช่วงว่างที่เหลือ (`free`) และรวมเป็นนาที (`free_minutes`)

- ต่างจาก `GET /booking/availability` ที่ตอบเป็นช่องของบริการเดียว เส้นนี้ตอบว่าใครว่างตอนไหน ไม่ผูกกับบริการ
- วันหยุดของสาขาตอบ `closed: true` พร้อมชื่อวันหยุด
- คลินิกสาขาเดียวไม่ต้องส่ง `branch`

## กติกาจ่ายเคส

```http
PUT /v1/staff/schedules/assignment-rules
{
  "rules": [
    { "species": "แมว", "service_id": "svc_dental", "staff_ids": ["stf_dentist"] },
    { "species": "แมว", "staff_ids": ["stf_catvet", "stf_backup"] }
  ]
}
```

- **เป็นลำดับความชอบ ไม่ใช่ข้อจำกัด** "หมอแมวรับเคสแมวก่อน" แปลว่าก่อน ไม่ใช่เท่านั้น ถ้าคนในกติกาไม่ว่าง เคสไปที่คนอื่นที่ว่างตามปกติ กติกาไม่เคยทำให้ช่วงที่ว่างอยู่จองไม่ได้
- **ข้อแรกที่ตรงชนะ** วางกติกาที่แคบกว่าไว้ข้างบน
- แต่ละข้อต้องระบุชนิดสัตว์ บริการ หรือทั้งสองอย่าง ชนิดสัตว์เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่กับค่า `species` ของสัตว์ เช่น `แมว` หรือ `cat` ตามที่คลินิกบันทึก
- ใครให้บริการไหนได้ ยังเป็นรายชื่อผู้ให้บริการของบริการนั้น กติกาแค่เรียงลำดับคนที่ได้รับอนุญาตอยู่แล้ว
- `PUT` แทนที่ทั้งชุด ส่ง `rules: []` เพื่อลบทั้งหมด ใช้ `If-Match` ได้ ทุกคนที่ระบุต้องยังทำงานอยู่ และทุกบริการต้องมีอยู่ ไม่อย่างนั้นได้ `422`
- มีได้ไม่เกิน 50 ข้อ แต่ละข้อไม่เกิน 20 คน

**กติกาถูกใช้ที่ไหน**

| ที่ | ใช้ไหม |
|---|---|
| จองโดยไม่ระบุหมอ จากเคาน์เตอร์หรือลูกค้า | ใช้ ทั้งชนิดสัตว์และบริการ |
| ถือ slot ระหว่างลูกค้ากรอกฟอร์ม | ใช้เฉพาะกติกาตามบริการ เพราะยังไม่รู้ว่าเป็นสัตว์ตัวไหน |
| เสนอหมอแทนตอนบันทึกวันลา | ใช้กติกาตามบริการ |
| จ่ายคิวให้หมอ | ไม่ใช้ ยังจ่ายด้วยมือที่ `POST /staff/queue/{id}/assign` |

## ข้อจำกัดที่รู้อยู่

- contract ไม่มีทางอ่านกติกาจ่ายเคสกลับ รู้ได้จากคำตอบของ `PUT` ครั้งล่าสุดเท่านั้น ถ้าหน้าจอต้องการ ต้องขอเพิ่ม `GET` เป็นส่วนขยาย
- ยังไม่มีการลบหรือแก้เวรทีละเวร และยังไม่มีการยกเลิกวันลา contract ไม่มี endpoint ของทั้งสองเรื่อง
- เวลาพักมีได้ช่วงเดียวต่อเวร
- ยังไม่มีหน้าจอ ทุกอย่างทำผ่าน API
