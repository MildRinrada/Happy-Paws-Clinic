# หน้าแรกสาธารณะ

หน้าแรก (`/`) คือหน้าที่เจ้าของสัตว์เปิดก่อนตัดสินใจมาคลินิก ไม่ต้องเข้าสู่ระบบ ทำตามดีไซน์ที่ได้รับเป็นรูปภาพ เนื้อหาทั้งหมดเป็นข้อความคงที่ในโค้ด **ไม่ได้อ่านจาก API** รูปทุกรูปยังเป็นช่องว่าง และลิงก์หลายตัวยังชี้ `#`

## เวลาว่างเร็วสุด

ใต้ปุ่มใน Hero มีกล่องสีขาวบอกเวลาที่จองออนไลน์ได้เร็วที่สุด เช่น "ว่างเร็วสุดวันนี้ 14:30" พร้อมปุ่ม **จองเวลานี้** ที่เปิดหน้า `/book` บนเวลานั้นเลย

**บริการที่ใช้** ตั้งที่ `featuredService` ใน `content/next-free-time.ts` ค่าเริ่มต้นคือบริการรหัส `checkup` (ตรวจสุขภาพทั่วไป) ระบบหาจากเมนูสาธารณะ `GET /services` ซึ่งมีเฉพาะบริการที่เปิดจองออนไลน์ ตามลำดับนี้

1. บริการที่ `code` ตรงกับ `featuredService.code`
2. บริการแรกในหมวด `featuredService.category`
3. บริการแรกในเมนู

**วันที่ดู** วันนี้และพรุ่งนี้ตามเวลาของคลินิก ถ้าวันนี้ยังมีเวลาว่างเหลือ กล่องบอก "วันนี้" ถ้าไม่เหลือแล้วบอก "พรุ่งนี้" ถ้าไม่มีเวลาว่างทั้งสองวัน กล่องบอกว่าคิวเต็มแล้ว พร้อมลิงก์ **ดูเวลาว่างทั้งหมด** ไปที่ `/book?service=` ของบริการนั้น

**หลายสาขา** กล่องแสดงหนึ่งบรรทัดต่อสาขาที่มีบริการนี้ เรียงจากสาขาที่ว่างเร็วสุด บรรทัดละหนึ่งปุ่ม แสดงไม่เกิน 3 สาขา (`maxBranches`) สาขาที่ไม่มีเวลาว่างทั้งสองวันไม่ขึ้น คลินิกสาขาเดียวไม่แสดงชื่อสาขา เลือกแบบนี้เพราะผู้เยี่ยมชมเห็นทุกสาขาในทีเดียวโดยไม่ต้องกดเลือกก่อน

**ปุ่มจองเวลานี้** ไปที่ `/book?service=&branch=&date=&time=` หน้าจองตรวจอีกครั้งว่าเวลายังว่าง ถ้ายังว่างเปิดที่ขั้นเบอร์โทร ถ้าไม่ว่างแล้วเปิดที่ตารางเวลาของวันนั้นพร้อมข้อความบอก ลูกค้าที่เข้าสู่ระบบอยู่แล้วถูกส่งต่อไป `/portal/book` พร้อมวันและเวลาเดิม และยังต้องเลือกน้องก่อน ดู [ลิงก์ที่เลือกเวลาให้ล่วงหน้า](booking-and-appointments.md#ลิงก์ที่เลือกเวลาให้ล่วงหน้า)

**ความสดของข้อมูล**

- อ่านบนเซิร์ฟเวอร์ด้วย `GET /booking/availability` สาขาละสองครั้ง (วันนี้และพรุ่งนี้) แล้วเก็บผลไว้ใช้ร่วมกันทุกคนนาน 60 วินาที (`unstable_cache` ใน `lib/load-next-free-times.ts` ผูกกับวันของคลินิก ขึ้นวันใหม่อ่านใหม่) endpoint จึงไม่ถูกเรียกทุกครั้งที่มีคนเปิดหน้า
- ทุกครั้งที่วาดกล่อง ทั้งบนเซิร์ฟเวอร์และในเบราว์เซอร์ เวลาที่ผ่านไปแล้วถูกตัดทิ้ง (`lib/pick-next-free.ts`) หน้าที่เปิดค้างไว้ตรวจกับนาฬิกาทุก 30 วินาที จึงไม่เคยเสนอเวลาที่ผ่านไปแล้ว
- กล่องโหลดแยกจากส่วนอื่นของหน้า (`Suspense`) การอ่านที่ช้าไม่ทำให้หน้าแรกช้า

**เมื่อไม่มีกล่อง** อ่าน API ไม่ได้ คลินิกไม่มีบริการที่จองออนไลน์ได้ หรือบริการนั้นไม่เปิดที่สาขาใดเลย กล่องหายไปทั้งกล่อง ไม่มีข้อความผิดพลาดบนหน้าแรก

การเปิดดูหน้าแรกไม่กันเวลาและไม่สร้างการจอง มีแต่การอ่าน เวลาจะถูกกันเมื่อผู้ใช้กดส่งรหัสในหน้าจองเท่านั้น

## เวลารอ walk-in

ใต้กล่องเวลาว่างเร็วสุดมีกล่องโปร่งแสงเล็ก ๆ หัวข้อ "เวลารอ walk-in ตอนนี้" บอกคนที่จะมาโดยไม่ได้นัดว่าตอนนี้น่าจะรอนานเท่าไร เช่น "ตอนนี้รอประมาณ 20 ถึง 30 นาที (3 คิว)" "ตอนนี้ไม่มีคิวรอ เข้ามาได้เลย" หรือ "ตอนนี้ปิดอยู่ เปิดอีกครั้งพรุ่งนี้ 09:00" คลินิกหลายสาขาแสดงบรรทัดละสาขาพร้อมชื่อสาขา ไม่เกิน 5 สาขา

- ตัวเลขมาจาก `GET /queue/wait-estimate` ซึ่งตอบแค่จำนวน วิธีคิดอยู่ใน [คิว](queue.md#เวลารอ-walk-in-ส่วนขยาย)
- อ่านบนเซิร์ฟเวอร์และใช้ร่วมกันทุกคน 30 วินาที (`unstable_cache` ใน `frontend/src/features/wait-estimate/lib/load-wait-estimates.ts`) โหลดแยกจากส่วนอื่นของหน้า (`Suspense`)
- อ่าน API ไม่ได้ หรือข้อมูลที่เก็บไว้เก่าเกิน 90 วินาที กล่องหายไปทั้งกล่อง
- ข้อความแก้ได้ที่ `frontend/src/features/wait-estimate/content/wait-estimate.ts` กล่องเดียวกันนี้อยู่ในหน้าติดต่อและหน้าฉุกเฉินด้วย
- บนจอแคบสองกล่องเรียงต่อกันเต็มความกว้าง กว้างสุด 520 px เท่ากัน

## รีวิว

คอลัมน์รีวิวแสดงรีวิวจริงที่พนักงานเผยแพร่แล้วล่าสุดสองอัน ในการ์ดแบบเดิม (ดาว ข้อความในเครื่องหมายคำพูด ชื่อแรกหรือ "ลูกค้า" และชนิดสัตว์ คำตอบของคลินิกถ้ามี) ใต้คอลัมน์มีลิงก์ "ดูรีวิวทั้งหมด" ไปหน้า `/reviews`

- อ่านบนเซิร์ฟเวอร์ด้วย `GET /reviews` และเก็บผลไว้ 5 นาที การเผยแพร่ ไม่เผยแพร่ หรือตอบรีวิวจากหน้าตั้งค่าทำให้หน้าแรกโหลดใหม่ทันที
- **ยังไม่มีรีวิวที่เผยแพร่ หรืออ่าน API ไม่ได้ คอลัมน์รีวิวหายไปทั้งคอลัมน์** และบทความใช้แถวเต็มความกว้าง ไม่มีข้อความตัวอย่างให้แสดงแทน ข้อความตัวอย่างเดิมใน `content/testimonials.ts` ถูกลบแล้ว เพราะการแสดงคำชมที่ไม่มีลูกค้าเขียนเหมือนเป็นรีวิวจริงคือรีวิวปลอม
- `content/testimonials.ts` เหลือหัวข้อ ป้ายของลิงก์ และจำนวนรีวิวที่แสดง
- หน้าแรกไม่ใส่ข้อมูลโครงสร้างคะแนนรีวิว (`AggregateRating`) เหตุผลอยู่ใน [รีวิวจากลูกค้า](reviews.md)

## เปลี่ยนรูป

ทุกที่ที่ดีไซน์มีรูปใช้ `ImageSlot` ถ้าไม่มี `src` จะวาดกรอบเส้นประพร้อมคำบอกว่ารูปอะไรควรอยู่ตรงนี้ หน้าถูกจัดรอบช่อง ไม่ใช่รอบรูป ใส่รูปภายหลังจึงแก้แค่ `src` โดยไม่มีอะไรขยับ

1. ใส่ไฟล์ใน `frontend/public/images/home/` (ตอนนี้ `public/` ยังว่าง ต้องสร้างโฟลเดอร์เอง)
2. ตั้ง `src: '/images/home/<ชื่อไฟล์>'` ในไฟล์เนื้อหา
3. ตรวจ `alt` ให้บอกว่าในรูปมีอะไร

| ช่อง | ตั้งที่ | หมายเหตุ |
|---|---|---|
| รูป banner (สุนัขและแมว) | `heroImage` ใน `content/hero.ts` | รูปตัดพื้นหลัง วางชิดขอบล่างแบบไม่ครอป (`object-contain`) โหลดก่อนอย่างอื่น (`priority`) |
| รูปข้างคำสัญญา | `careImage` ใน `content/care.ts` | |
| รูปบริการ 3 รูป | `image` ของแต่ละการ์ดใน `content/services.ts` | การ์ดเล็กใช้ไอคอนวาดเองใน `services/icons/` ไม่ใช่รูป |
| รูปหมอ | `photo_path` ในโปรไฟล์สาธารณะของแต่ละคน ดู [ทีมของเรา](team.md) | วางไฟล์ใต้ `frontend/public/images/team/` |
| รูปบทความ | `cover_image_path` ของบทความในฐานข้อมูล ดู [บทความ](articles.md) | วางไฟล์ใต้ `frontend/public/` |
| แผนที่ใน section ที่ตั้งและใน footer | ลิงก์ฝังแผนที่ของรายการแผนที่ ในหน้า **ข้อมูลติดต่อ** | มีลิงก์ฝังจะแสดงแผนที่สด ถ้าไม่มีใช้รูปจาก `locationMap.imageSrc` (`content/location.ts`) และ `footerAddress.map.imageSrc` (`config/site-footer.ts`) |

วงกลมสีข้างตัวเลข 9k+ ใน Hero ไม่ใช่รูป เป็นวงกลมสีที่วาดใน `hero/avatar-stack.tsx` ถ้าต้องการรูปลูกค้าจริงต้องแก้ component

## โลโก้ชั่วคราว

- โลโก้บน header และ footer เป็นรูปวาด SVG ชั่วคราว (อุ้งเท้าที่มีคลินิกและกากบาท) ใน `components/layout/site-header/logo-mark.tsx` สีเขียนตายตัวในไฟล์
- เมื่อได้โลโก้จริง ใส่ไฟล์ใน `public/` แล้วแทน `<LogoMark />` ใน `site-logo.tsx` ไฟล์เดียว ไม่มีที่อื่นอ้างถึง `LogoMark`
- ชื่อข้างโลโก้ (Happy Paws Clinic) ใช้ฟอนต์ Inter ตัวหนา อยู่ใน `site-logo.tsx` บน footer ใช้ `tone="light"` เป็นตัวอักษรสีขาว ตัวรูปวาดชั่วคราวมีอุ้งเท้าสีเทาเข้มซึ่งเห็นยากบนพื้น footer สีเข้ม โลโก้จริงต้องมีแบบที่ใช้บนพื้นเข้มได้
- ไอคอนแท็บเบราว์เซอร์ (`frontend/src/app/icon.svg`) เป็นอีกรูปวาดหนึ่ง (อุ้งเท้าขาวบนพื้นเขียว) ต้องเปลี่ยนแยก

## ลิงก์ที่ยังชี้ `#`

ปลายทางเหล่านี้ยังไม่มี เมื่อมีแล้วให้แก้ `href` ในไฟล์ที่บอก

| ลิงก์ | ไฟล์ | ควรไปที่ไหน |
|---|---|---|
| ปุ่มจองนัดหมายใน Hero | `content/hero.ts` (`primaryAction`) | หน้าจองออนไลน์ (ยังไม่มี) |

## ขนาดเมื่อเทียบกับดีไซน์

ดีไซน์ส่งมาเป็นรูปขนาดใหญ่ (กว้าง 1568 และ 1394 px) ทำตามขนาดพิกเซลของดีไซน์แล้วใหญ่เกินไป หน้าจริงจึงย่อลงราว 0.73 ถึง 0.82 เท่า ส่วนสัดส่วน ข้อความ และสียึดตามดีไซน์

- คอลัมน์เนื้อหากว้าง 992 px คือ `SiteContainer` (`max-w-[1040px]` รวม padding ข้างละ 24 px) ใน `components/layout/site-container.tsx` ทุก section และ footer ใช้ตัวนี้ ขอบซ้ายขวาจึงตรงกัน
- header กว้างกว่า (`max-w-[1120px]`)
- หัวเรื่อง Hero สูงสุด 48 px หัวข้อ section 30 px ผ่าน `SectionHeading`
- section ใหม่ให้วัดความกว้างคอลัมน์เนื้อหาในดีไซน์ แล้วคูณทุกระยะด้วย 992 หารด้วยความกว้างนั้น และใช้ `SectionContainer` กับ `SectionHeading` เพื่อให้ได้ขนาดเดียวกัน

## จอเล็ก

- **header** เมนูเต็มแถวแสดงที่ 1280 px ขึ้นไป (`xl`) ต่ำกว่านั้นเป็นปุ่มเมนู ซึ่งเป็น `<details>` เปิดปิดได้โดยไม่ใช้ JavaScript ใช้ได้ก่อนหน้าโหลดเสร็จ ต่ำกว่า 640 px ปุ่มเข้าสู่ระบบและสมัครย้ายเข้าไปในเมนู ปุ่มสีแดง **ฉุกเฉิน** (ไปหน้า `/emergency`) อยู่ทางขวาข้างปุ่มเข้าสู่ระบบทุกขนาดจอ ไม่ได้อยู่ในแถวเมนูเพราะแถวเต็มแล้วที่ 1280 px ต่ำกว่า 640 px เหลือแต่ไอคอนโทรศัพท์ข้างปุ่มเมนู (ผู้ใช้โปรแกรมอ่านหน้าจอได้ยินว่า "ฉุกเฉิน สัตว์เลี้ยงป่วยด่วน")
- **Hero** จอกว้างรูป banner ยืนบนขอบล่างและล้นขวา จอแคบรูปอยู่ใต้ข้อความ
- **การ์ด** บริการ 1 คอลัมน์ 2 คอลัมน์ (`md`) แล้ว 3 คอลัมน์ (`lg`) หมอ 1, 2 แล้ว 4 คอลัมน์ บทความกับรีวิววางคู่กันที่ `lg`
- **footer** 1 คอลัมน์ 2 คอลัมน์ (`sm`) แล้ว 4 คอลัมน์ (`xl`) ความกว้างสี่คอลัมน์ไม่เท่ากันตามดีไซน์

สี ฟอนต์ และหลักการทั่วไปของหน้าสาธารณะดู [UI/UX](../ui-ux.md)
