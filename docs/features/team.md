# ทีมของเรา

หน้ารวมบุคลากรของคลินิกบนเว็บไซต์สาธารณะ แยกตามแผนกชัดเจน คือ สัตวแพทย์ ผู้ช่วยสัตวแพทย์ ต้อนรับ การเงิน บริหาร และทีมสนับสนุน การ์ดสัตวแพทย์บนหน้าแรกก็อ่านจากข้อมูลชุดเดียวกัน ฝั่งพนักงานกรองรายชื่อได้ทั้งตามแผนกและตาม role

ฟีเจอร์นี้ไม่อยู่ใน contract เป็นส่วนขยายที่เจ้าของงานขอเพิ่ม เหตุผลและสิ่งที่ตั้งใจไม่ทำอยู่ใน [ส่วนขยายของสัญญา § 10](../contract-extensions.md)

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน | ดูหน้าทีมของเรา และการ์ดสัตวแพทย์บนหน้าแรก |
| พนักงานที่มี `staff:read` | ดูรายชื่อพนักงาน กรองตามแผนกหรือ role และดูจำนวนคนในแต่ละแผนก |
| พนักงานที่มี `staff:manage` | ย้ายคนไปแผนกอื่น แก้โปรไฟล์สาธารณะ และเปิดปิดการแสดงบนเว็บ |
| ผู้ดูแลเซิร์ฟเวอร์ | ใส่บุคลากรตัวอย่างด้วยคำสั่ง `seed-staff` |

## แผนกกับ role ต่างกันอย่างไร

สองคำนี้ฟังคล้ายกันแต่ตอบคนละคำถาม

- **role** คือสิ่งที่คนนั้นทำได้ในระบบ เช่น `veterinarian` เซ็นเวชระเบียนได้ ระบบตรวจ role (ผ่าน scope) ทุกครั้งที่มีคำขอ
- **แผนก** คือทีมที่คนนั้นสังกัด ใช้จัดกลุ่มบนหน้าเว็บและในรายชื่อ ระบบไม่เคยใช้แผนกตัดสินว่าใครทำอะไรได้

ปกติสองอย่างนี้ไปด้วยกัน หมออยู่แผนกสัตวแพทย์และถือ role `veterinarian` แต่ไม่จำเป็นต้องตรงกัน หัวหน้าผู้ช่วยอาจได้สิทธิ์เพิ่มโดยยังอยู่แผนกผู้ช่วย และพนักงานทำความสะอาดอยู่แผนกทีมสนับสนุนโดยไม่มี role เลยก็ได้ การย้ายแผนกจึงไม่เปลี่ยนสิทธิ์ และการเปลี่ยน role ก็ไม่ย้ายแผนก

## แผนก

| รหัส | ชื่อที่แสดง | `staff_type` ที่เริ่มในแผนกนี้ |
|---|---|---|
| `veterinary` | ทีมสัตวแพทย์ | `veterinarian` |
| `nursing` | ผู้ช่วยสัตวแพทย์ | `vet_assistant` |
| `front_desk` | ต้อนรับและนัดหมาย | `receptionist` |
| `finance` | การเงิน | `cashier` |
| `management` | บริหารคลินิก | `owner`, `clinic_admin` |
| `support` | ทีมสนับสนุน | ตำแหน่งอื่นทั้งหมด |

หน้าเว็บเรียงแผนกตามลำดับในตารางนี้ รายการแผนกอยู่ใน `Departments.cs` เป็นรายการตายตัว คลินิกสร้างแผนกเองไม่ได้

**คนใหม่อยู่แผนกไหน** คำเชิญพนักงานไม่มีช่องแผนก คนที่รับคำเชิญจึงเริ่มที่แผนกตาม `staff_type` ในคอลัมน์ขวาของตาราง เจ้าของที่สร้างด้วย `bootstrap` เริ่มที่ `management` ย้ายแผนกทีหลังได้ด้วย `PATCH /staff/members/{id}`

## โปรไฟล์สาธารณะ

สิ่งที่หน้าเว็บพูดถึงพนักงานแต่ละคน แยกจากข้อมูลภายในทั้งหมด

| ช่อง | กติกา |
|---|---|
| `job_title` | ตำแหน่งที่คนทั่วไปอ่าน เช่น สัตวแพทย์ประจำ ไม่เกิน 120 ตัวอักษร |
| `specialty` | ความเชี่ยวชาญ เช่น อายุรกรรมสัตว์เล็ก ไม่เกิน 120 ตัวอักษร |
| `bio` | แนะนำตัวสั้น ๆ ไม่เกิน 600 ตัวอักษร |
| `photo_path` | รูป เป็น path ใต้ `/public` ของหน้าเว็บ ขึ้นต้นด้วย `/` ไม่รับ URL ภายนอก |
| `career_start_year` | ปี ค.ศ. ที่เริ่มทำงานสายนี้ ตั้งแต่ 1950 ถึงปีปัจจุบัน หน้าเว็บคำนวณเป็นจำนวนปีประสบการณ์ |
| `show_on_website` | แสดงบนเว็บหรือไม่ **ปิดไว้ก่อนเสมอ** |

- `PUT` แทนที่ทั้งก้อน ช่องที่ไม่ส่งถูกล้าง ข้อความที่เป็นช่องว่างถือเป็นค่าว่าง
- ค่าที่ผิดกติกาตอบ `409 invalid_public_profile`
- ทุกการแก้บันทึก audit `staff.public_profile_updated` พร้อมค่าก่อนและหลัง เพราะเป็นการเผยแพร่ชื่อและหน้าของคนจริง
- คนที่แก้ได้ต้องมี `staff:manage` และอยู่ภายใต้กติกาเดิมของการแก้พนักงาน คือแก้ได้เฉพาะคนในสาขาของตัวเอง และแก้คนที่มีสิทธิ์มากกว่าตัวเองไม่ได้

## Endpoint

| Method | Endpoint | Scope | ทำอะไร |
|---|---|---|---|
| GET | `/team?department=` | ไม่ต้องเข้าสู่ระบบ | แผนกที่มีคนแสดงบนเว็บ แต่ละแผนกมีรายชื่อ ไม่ส่ง `department` ได้ทุกแผนก แผนกที่ไม่มีในรายการตอบ `422` |
| GET | `/staff/departments` | `staff:read` | ทุกแผนกพร้อมจำนวนคนที่ทำงานอยู่ รวมแผนกที่ว่าง |
| GET | `/staff/members?department=&role=` | `staff:read` | endpoint เดิมของ contract ที่เพิ่มตัวกรองสองตัว |
| PATCH | `/staff/members/{id}` | `staff:manage` | endpoint เดิม เพิ่มช่อง `department` |
| PUT | `/staff/members/{id}/public-profile` | `staff:manage` | แทนที่โปรไฟล์สาธารณะ ใช้ `If-Match` ได้ |

**ใครขึ้นใน `GET /team`** ต้องครบสามข้อ คือยังทำงานอยู่ (ไม่ถูกปิดใช้งาน) บัญชียังใช้งานได้ และ `show_on_website` เป็น `true`

**ลำดับในแผนก** คนที่เริ่มทำงานก่อนขึ้นก่อน ปีเท่ากันเรียงตามชื่อ คนที่ไม่ได้ใส่ปีอยู่ท้าย

**สิ่งที่ `GET /team` ส่ง** มีแค่ `id`, `display_name`, `job_title`, `specialty`, `bio`, `photo_path` และ `years_of_experience` ไม่มีอีเมล เบอร์โทร role สาขา เลขใบอนุญาต หรือสถานะบัญชี มีเทสต์ยืนยันเรื่องนี้

ตัวอย่างคำตอบ

```json
{
  "data": [
    {
      "department": "veterinary",
      "name": "ทีมสัตวแพทย์",
      "members": [
        {
          "id": "stf_06GFF...",
          "display_name": "น.สพ. กิตติ วรกุล",
          "job_title": "ผู้อำนวยการคลินิก",
          "specialty": "ศัลยกรรมกระดูกและข้อ",
          "bio": "ดูแลงานผ่าตัดกระดูกและข้อของคลินิกมาตั้งแต่วันแรก",
          "years_of_experience": 20
        }
      ]
    }
  ]
}
```

**ตัวกรองของรายชื่อพนักงาน** `?department=nursing` ได้คนในแผนกผู้ช่วย `?role=veterinarian` ได้คนที่ถือ role นั้น ใช้ร่วมกับ `branch`, `staff_type` และ `status` ได้ แผนกที่ไม่มีในรายการตอบ `422` แต่ชื่อ role ที่ไม่มีใครถือได้รายการว่าง เพราะ role เป็นสิ่งที่คลินิกสร้างเองได้ เหมือน `staff_type` ที่ยังไม่มีใครใช้ ถ้าใช้คู่กับ `status=invited` คำเชิญถูกกรองตามแผนกที่ `staff_type` ของมันจะเริ่ม

## ใส่บุคลากรตัวอย่าง

```sh
dotnet run --project backend/src/HappyPaws.Api -- seed-staff
# หรือใน Docker
docker compose run --rm api seed-staff
```

ใส่ 14 คนจาก `SampleStaff.cs` ครบทุกแผนก ชื่อและเลขใบอนุญาตเป็นของสมมติ

- ต้องรัน `bootstrap` ก่อน เพราะทุกคนได้ role ตั้งต้นและอยู่ทุกสาขาที่เปิดอยู่
- **บัญชีตัวอย่างเข้าสู่ระบบไม่ได้** รหัสผ่านถูกสุ่มแล้วทิ้งทันที และไม่มีรหัส 2FA อยากใช้บัญชีไหน รัน `reset-credentials --email <อีเมล>` ก่อน
- อีเมลลงท้ายด้วย `@staff.happypaws.test` โดเมน `.test` ถูกสงวนไว้ จึงไม่มีอีเมลหลุดไปถึงใครจริง
- รันซ้ำได้ อีเมลที่มีบัญชีอยู่แล้วถูกข้าม ไม่ถูกเขียนทับ ถ้าแก้ข้อความใน `SampleStaff.cs` ทีหลัง คนที่ใส่ไปแล้วจะไม่เปลี่ยนตาม
- หนึ่งคนในตัวอย่าง (ภานุพงศ์ แผนกต้อนรับ) ตั้งไม่ให้แสดงบนเว็บ เพื่อให้เห็นว่าการเป็นพนักงานไม่ได้แปลว่าขึ้นเว็บ
- ทุกคนที่ใส่บันทึก audit `staff.seeded`

## หน้าเว็บ

| หน้า | ที่อยู่ | แสดงอะไร |
|---|---|---|
| หน้าแรก | `/` ส่วน "คนที่จะดูแลน้องของคุณ" | สัตวแพทย์สี่คนแรกของแผนก `veterinary` จำนวนตั้งที่ `homeVetCount` ใน `features/home/content/vets.ts` มีลิงก์ "ดูทีมทั้งหมด" |
| ทีมของเรา | `/team` | แถบลิงก์ไปแต่ละแผนก แล้วตามด้วยหนึ่งส่วนต่อหนึ่งแผนก บอกชื่อแผนก จำนวนคน คำอธิบายสั้น และการ์ดของแต่ละคน |

- เมนู "ทีมของเรา" บน header และลิงก์ใน footer พามาที่ `/team`
- ปุ่ม "ดูโปรไฟล์" บนการ์ดหน้าแรกพาไปที่การ์ดของคนนั้นบนหน้าทีม (`/team#stf_...`)
- คำอธิบายใต้ชื่อแต่ละแผนกและข้อความอื่นที่ไม่ได้มาจาก API แก้ได้ที่ `features/team/content/team-page.ts`
- ถ้าเรียก API ไม่ได้ หน้ายังเปิดได้และบอกว่าโหลดรายชื่อไม่ได้ ถ้าคลินิกยังไม่ได้ตั้งให้ใครแสดงเลย ส่วนสัตวแพทย์บนหน้าแรกถูกซ่อน และหน้าทีมบอกว่ายังไม่มีรายชื่อ
- รูปที่ยังไม่มีแสดงเป็นกรอบเส้นประ ใส่รูปจริงโดยวางไฟล์ใต้ `frontend/public/images/team/` แล้วตั้ง `photo_path` เช่น `/images/team/mint.jpg`
- การ์ดสัตวแพทย์บนหน้าแรกเดิมมีป้าย "ว่างวันนี้" ตอนนี้เป็นตำแหน่งแทน เพราะยังไม่มีข้อมูลกะทำงานจริงให้คำนวณ

## ข้อจำกัดที่รู้อยู่

- ยังไม่มีหน้าจอฝั่งพนักงานสำหรับแก้แผนกหรือโปรไฟล์ ต้องเรียก API ตรง
- ยังไม่มีการอัปโหลดรูป ต้องวางไฟล์ในโฟลเดอร์ของหน้าเว็บเอง
- พนักงานแก้โปรไฟล์ของตัวเองไม่ได้ ต้องให้คนที่มี `staff:manage` แก้ให้
- แผนกเป็นรายการตายตัวหกแผนก คลินิกเพิ่มเองไม่ได้
- ยังไม่มีหน้าแยกของแต่ละคน และยังจองนัดกับหมอคนที่เลือกจากหน้าทีมไม่ได้
