# สต๊อกยาและเวชภัณฑ์

โมดูลนี้เก็บว่าคลินิกมียาและเวชภัณฑ์อะไร แต่ละสาขามีเหลือเท่าไร ล็อตไหนหมดอายุเมื่อไร และของเข้าออกอย่างไร การจ่ายยาตัดสต๊อกจากโมดูลนี้ และคิดค่ายาตามราคาในคลังลงบิลของเคส ผู้ใช้หลักคือคนดูแลห้องยา คนสั่งซื้อ และห้องยาที่จ่ายยาให้เจ้าของ

## endpoint

| Method | Path | Scope | ทำอะไร |
|---|---|---|---|
| GET | `/staff/inventory/items` | `inventory:read` | รายการยาและเวชภัณฑ์ พร้อมคงเหลือรายสาขา |
| POST | `/staff/inventory/movements` | `inventory:write` | รับเข้า จ่ายออก โอนสาขา ต้องมี `Idempotency-Key` |
| POST | `/staff/inventory/adjustments` | `inventory:adjust` | ปรับยอดหลังนับสต๊อก ต้องระบุเหตุผล |
| GET | `/staff/inventory/alerts` | `inventory:read` | ใกล้หมด หมด ใกล้หมดอายุ และล็อตที่หมดอายุแล้ว |
| POST | `/staff/inventory/purchase-orders` | `inventory:purchase` | ใบสั่งซื้อจากซัพพลายเออร์ ต้องมี `Idempotency-Key` |
| GET | `/staff/prescriptions/drug-options` | `rx:write` | ส่วนขยาย ([contract-extensions.md § 20](../contract-extensions.md)) ยาในคลังให้สัตวแพทย์เลือกตอนสั่งยา พร้อมราคาขายและสถานะสต๊อกของสาขาเดียว |
| PATCH | `/staff/inventory/items/{id}` | `inventory:write` | ส่วนขยาย ([contract-extensions.md § 25](../contract-extensions.md)) แก้ชื่อ หน่วย ราคาขาย จุดสั่งซื้อ และเลิกใช้หรือกลับมาใช้รายการ |
| GET | `/staff/inventory/purchase-orders` | `inventory:purchase` | ส่วนขยาย (§ 25) ใบสั่งซื้อพร้อมรายการ ใหม่สุดก่อน กรองสถานะ สาขา และซัพพลายเออร์ แบ่งหน้าด้วย cursor |
| POST | `/staff/inventory/purchase-orders/{id}/cancel` | `inventory:purchase` | ส่วนขยาย (§ 25) ยกเลิกส่วนที่ยังค้างรับ |

contract ให้แต่บรรทัดอธิบายของห้าเส้นนี้ ไม่มีรูป body หรือคำตอบ รูปที่ใช้และเหตุผลอยู่ในเอกสารนี้ และจุดที่ต้องตีความอยู่ใน [assumptions.md § 42](../assumptions.md) role ตั้งต้นที่ถือ scope กลุ่มนี้มีแค่ `clinic_owner` (`*`) และ `clinic_admin` ถ้าต้องการให้พนักงานคนอื่นใช้ ให้เพิ่ม scope ให้ role ผ่าน `PUT /staff/roles/{id}/permissions`

## ข้อมูลมีสามชั้น

```text
inventory_items      รายการในคลัง หนึ่งแถวต่อยาหนึ่งตัว ใช้ทั้งคลินิก มีราคาขายและจุดสั่งซื้อ
  stock_lots         ล็อตของรายการนั้นในแต่ละสาขา มีเลขล็อต วันหมดอายุ และยอดคงเหลือ
    stock_movements  สมุดสต๊อก หนึ่งแถวต่อการเคลื่อนไหวหนึ่งครั้งของหนึ่งล็อต เพิ่มได้อย่างเดียว
purchase_orders      ใบสั่งซื้อของสาขาหนึ่ง กับ purchase_order_lines จำนวนที่สั่งและที่รับแล้ว
```

- **รายการเป็นของทั้งคลินิก สต๊อกเป็นของสาขา** ชื่อและราคาเดียวกันทุกสาขา จำนวนแยกตามสาขาในล็อต
- **ทำไมต้องมีล็อต** การแจ้งเตือนถามเรื่องใกล้หมดอายุและล็อตที่ต้องเรียกคืน ซึ่งเป็นเรื่องของล็อต ไม่ใช่ของยา กล่องหนึ่งหมดอายุเดือนหน้า อีกกล่องใช้ได้อีกสองปี
- **สมุดสต๊อกแก้ไม่ได้** ไม่มีคำสั่งแก้หรือลบแถว ของที่บันทึกผิดแก้ด้วยแถวใหม่ เช่นจ่ายออกหรือปรับยอด ทั้งของผิดและการแก้จึงอยู่ในประวัติ
- **ยอดในล็อตเท่ากับผลรวมของสมุดเสมอ** ทุกครั้งที่ยอดเปลี่ยน ระบบเขียนแถวในสมุดที่มีจำนวนเท่ากันใน transaction เดียวกัน แต่ละแถวเก็บยอดหลังเปลี่ยน (`balance_after`) ไว้ด้วย อ่านย้อนได้โดยไม่ต้องบวกเอง
- **ยอดติดลบไม่ได้** ฐานข้อมูลมี check constraint `ck_stock_lots_quantity_not_negative`

## รายการในคลังเกิดจากไหน

contract ไม่มี endpoint สร้างรายการ รายการจึงเกิดครั้งแรกที่คลินิกสั่งซื้อหรือรับของ ทั้งการรับเข้าและแต่ละแถวของใบสั่งซื้อส่ง `item_id` ของรายการที่มีอยู่ หรือ `new_item` ของรายการใหม่ก็ได้

```json
{ "name": "Amoxicillin 250mg", "kind": "medicine", "unit": "เม็ด", "unit_price_satang": 500, "reorder_level": 50 }
```

- `kind` เป็น `medicine` (ค่าเริ่มต้น) หรือ `supply`
- `unit_price_satang` คือราคาขายต่อหน่วยที่คิดเงินลูกค้าตอนจ่ายยา ใส่ `0` คือไม่คิดเงิน
- `reorder_level` เหลือเท่านี้หรือน้อยกว่าคือใกล้หมด `0` คือไม่เตือนใกล้หมด แต่ยังเตือนเมื่อหมด
- ชื่อซ้ำกับรายการที่มีแล้วตอบ `409 inventory_item_exists` พร้อม `details.item_id` ของรายการเดิม ระบบไม่เอารายการเดิมมาใช้แทนเงียบ ๆ เพราะคำขอมีราคาและหน่วยมาด้วย คนส่งจะเข้าใจผิดว่าบันทึกแล้ว ฐานข้อมูลกันชื่อซ้ำอีกชั้นด้วย unique index `ux_inventory_items_name_key` ถ้าสองคนสร้างพร้อมกัน คนที่สองได้ `409` แบบเดียวกัน
- การสร้างรายการเขียน audit `inventory.item_created` พร้อมราคา
- แก้ชื่อ ราคา หน่วย จุดสั่งซื้อ หรือเลิกใช้ภายหลัง ทำได้ด้วยส่วนขยาย § 25 ดูหัวข้อถัดไป

## แก้และเลิกใช้รายการ

ส่วนขยาย [contract-extensions.md § 25](../contract-extensions.md) `PATCH /staff/inventory/items/{id}` scope `inventory:write` รองรับ `If-Match`

```json
{ "name": "Amoxicillin 250mg tab", "unit": "เม็ด", "unit_price_satang": 550, "reorder_level": 40, "active": false }
```

- ช่องที่ไม่ส่งไม่เปลี่ยน กติกาของแต่ละช่องเหมือนตอนสร้าง คำตอบคือรายการพร้อมคงเหลือ แก้แล้วไม่มีอะไรเปลี่ยนไม่เขียน audit ที่เปลี่ยนเขียน `inventory.item_updated` พร้อมค่าก่อนและหลัง
- **ราคา** ใช้กับการจ่ายยาครั้งถัดไป ราคาที่คิดไปแล้วเก็บอยู่ที่ใบสั่งยา (`charged_unit_price_satang`) จึงไม่เปลี่ยน แม้เคสยังไม่ปิด
- **ชื่อ** เปลี่ยนชื่อที่ใช้จับคู่ด้วย ชื่อที่ซ้ำกับรายการอื่นตอบ `409 inventory_item_exists` ใบสั่งยาที่พิมพ์ชื่อเองและยังไม่จ่ายจะจับคู่กับชื่อใหม่ ใบที่เลือกจากคลังผูกด้วยรหัสจึงไม่กระทบ
- **หน่วย** แก้ชื่อหน่วยเท่านั้น จำนวนในคลังไม่ถูกแปลง
- **เลิกใช้** (`active: false`) และ **กลับมาใช้** (`active: true`)

| เรื่อง | รายการที่เลิกใช้ |
|---|---|
| ตัวเลือกยาของหมอ (§ 20) | ไม่ขึ้น |
| สั่งยาด้วย `inventory_item_id` | `409 inventory_item_retired` |
| รับเข้า และแถวของใบสั่งซื้อ | `409 inventory_item_retired` หน้าสั่งซื้อไม่เสนอรายการนี้ |
| จ่ายออก โอน ปรับยอด | ทำได้ ของที่เหลือบนชั้นต้องเอาออกได้ |
| จ่ายยาตามใบสั่งยาที่สั่งไว้ก่อน ทั้งด้วยรหัสและด้วยชื่อ | ทำได้ ตัดสต๊อกและคิดเงินตามปกติ |
| แจ้งเตือนใกล้หมดและหมด และ webhook `inventory.low_stock` | ไม่มี |
| แจ้งเตือนวันหมดอายุของล็อต | ยังมี |
| รายการในคลัง `GET /staff/inventory/items` | ยังขึ้น พร้อม `active: false` และ `retired_at` กรองด้วย `?active=true` หรือ `false` ได้ |
| สร้างรายการใหม่ชื่อเดียวกัน | `409 inventory_item_exists` พร้อม `details.retired: true` |

ประวัติทุกแถว ล็อต สมุดสต๊อก ใบสั่งยา และใบสั่งซื้อ ยังชี้มาที่รายการเดิม การเลิกใช้จึงไม่ใช่การลบ

## รายการและคงเหลือ

`GET /staff/inventory/items?q=&branch=&status=` คืน `{ "data": [...] }` ทั้งแคตตาล็อกเรียงตามชื่อ ไม่แบ่งหน้า แบบเดียวกับรายการบริการ เพราะคลินิกมียาเป็นร้อย ไม่ใช่เป็นแสน

```json
{
  "id": "itm_...", "name": "Amoxicillin 250mg", "kind": "medicine", "unit": "เม็ด",
  "unit_price_satang": 500, "reorder_level": 50, "on_hand": 140, "available": 120,
  "branches": [
    {
      "branch_id": "brn_...", "on_hand": 140, "available": 120, "status": "ok", "on_order": 200,
      "next_expiry": "2027-01-31",
      "lots": [ { "id": "lot_...", "lot_number": "A2310", "expires_on": "2027-01-31", "quantity_on_hand": 120, "expired": false } ],
      "open_orders": [ { "purchase_order_id": "po_...", "number": "PO-202610-0007", "supplier_name": "...", "outstanding": 200 } ]
    }
  ]
}
```

- `on_hand` คือทุกหน่วยที่อยู่ในยอด รวมล็อตที่หมดอายุแล้ว `available` คือส่วนที่ใช้ได้ ไม่นับล็อตที่หมดอายุ
- `status` ตัดสินจาก `available` เทียบ `reorder_level` ได้ `ok`, `low` (เหลือแต่ไม่เกินจุดสั่งซื้อ) หรือ `out` (ใช้ได้ศูนย์)
- `on_order` และ `open_orders` คือของที่สั่งแล้วยังไม่มา หน้ารับเข้าใช้ `open_orders` ให้เลือกใบสั่งซื้อ
- แต่ละรายการมีหนึ่งแถวต่อสาขาในขอบเขต แม้สาขานั้นไม่เคยมีของ (ยอดเป็นศูนย์และ `out`)
- `q` ค้นส่วนของชื่อ `status` กรองรายการที่มีอย่างน้อยหนึ่งสาขาในสถานะนั้น ค่าอื่นตอบ `422`

## รับเข้า จ่ายออก โอนสาขา

`POST /staff/inventory/movements` ตอบ `201` พร้อมแถวที่เขียนลงสมุด (`movements`) คงเหลือของรายการหลังเปลี่ยน (`item`) และใบสั่งซื้อ (`purchase_order`) เมื่อรับตามใบสั่งซื้อ

```json
{ "type": "receive", "item_id": "itm_...", "quantity": 100, "lot_number": "A2310", "expires_on": "2027-06-30",
  "unit_cost_satang": 250, "purchase_order_id": "po_...", "reference": "DN-55120" }
{ "type": "issue", "item_id": "itm_...", "quantity": 2, "note": "ใช้ในห้องผ่าตัด" }
{ "type": "transfer", "branch_id": "brn_a", "to_branch_id": "brn_b", "item_id": "itm_...", "quantity": 20 }
```

| ชนิด | ทำอะไร | แถวในสมุด |
|---|---|---|
| `receive` | ของเข้า เพิ่มลงล็อตที่เลขล็อตและวันหมดอายุตรงกัน หรือเปิดล็อตใหม่ | `receive` |
| `issue` | ของออกด้วยมือ เช่นใช้ในหัตถการ แตก ทิ้ง | `issue` หนึ่งแถวต่อล็อต |
| `transfer` | ย้ายไปสาขาอื่น ล็อตที่ปลายทางมีเลขล็อตและวันหมดอายุเดิม | `transfer_out` และ `transfer_in` ต่อล็อต จับคู่ด้วย `transfer_id` |

- **สาขา** `branch_id` คือสาขาที่ของเข้า (รับ) หรือออก (จ่าย โอน) ไม่ส่งก็ได้ถ้าผู้เรียกมีสาขาเดียว สาขาที่ไม่ได้สังกัดตอบ `403` สาขาปลายทางของการโอนเป็นสาขาที่เปิดอยู่สาขาไหนก็ได้ ผู้โอนไม่ต้องสังกัดสาขาปลายทาง
- **หมดอายุก่อน ออกก่อน** การจ่ายออกและโอนที่ไม่ระบุ `lot_id` หยิบล็อตที่หมดอายุเร็วสุดก่อน ล็อตที่ไม่มีวันหมดอายุไปท้ายสุด ล็อตที่หมดอายุแล้วไม่ถูกหยิบเอง ต้องระบุ `lot_id` ของล็อตนั้น ซึ่งเป็นวิธีเอาล็อตหมดอายุออกจากคลัง
- **ขอมากกว่าที่ใช้ได้ถูกปฏิเสธ** ตอบ `409 insufficient_stock` พร้อม `details.available` เพราะยังไม่มีอะไรเกิดขึ้นจริง ต่างจากการจ่ายยา (ดูด้านล่าง)
- รับล็อตที่หมดอายุแล้วไม่ได้ ตอบ `422` ที่ `expires_on`
- **อ้างอิงเอกสารต้นทาง** `reference` คือเลขใบส่งของหรือใบโอน ถ้ารับตามใบสั่งซื้อแล้วไม่ใส่ ระบบใช้เลขใบสั่งซื้อ
- ฟิลด์ที่ใช้กับชนิดอื่น เช่น `lot_number` ในการจ่ายออก ถูกปฏิเสธด้วย `422` แทนการเงียบทิ้ง
- **ต้องส่ง `Idempotency-Key`** ใบส่งของที่ส่งซ้ำหลัง timeout ต้องไม่เข้าคลังสองครั้ง
- ไม่เขียน audit เพราะแถวในสมุดคือบันทึกอยู่แล้ว ใคร เมื่อไร กี่หน่วย ล็อตไหน เอกสารอะไร

## รับของตามใบสั่งซื้อ

`POST /staff/inventory/purchase-orders` ตอบ `201` พร้อมใบสั่งซื้อ

```json
{ "supplier_name": "บริษัท ยาสัตว์ จำกัด", "expected_on": "2026-10-20",
  "lines": [ { "item_id": "itm_...", "quantity": 200, "unit_cost_satang": 250 },
             { "new_item": { "name": "Meloxicam 1mg", "unit": "เม็ด", "unit_price_satang": 800 }, "quantity": 100, "unit_cost_satang": 300 } ] }
```

- เลขใบสั่งซื้อ `PO-YYYYMM-NNNN` นับเดือนตามเวลาคลินิก ขอเลขใน transaction ด้วย advisory lock แบบเดียวกับเลขบิล
- หนึ่งใบมี 1 ถึง 50 รายการ รายการเดียวกันซ้ำในใบเดียวไม่ได้
- **ใบสั่งซื้อยังไม่ใช่สต๊อก** ออกใบแล้วยอดในคลังไม่เปลี่ยน แต่รายการแสดงใน `on_order`
- **รับของบางส่วนได้** เมื่อของมา ให้บันทึก `receive` พร้อม `purchase_order_id` แถวของรายการนั้นนับจำนวนที่รับ สถานะเดินจาก `ordered` เป็น `partially_received` แล้ว `received` เอง ไม่มีใครตั้งสถานะ ต้นทุนต่อหน่วยใช้ของใบสั่งซื้อถ้าการรับไม่ระบุ
- รับเกินจำนวนที่ค้างตอบ `409 over_receipt` รับรายการที่ไม่อยู่ในใบตอบ `409 invalid_movement` รับลงสาขาอื่นที่ไม่ใช่สาขาของใบตอบ `422`
- การรับสองครั้งที่อ้างใบเดียวกันล็อกแถวใบสั่งซื้อ (`FOR UPDATE`) จึงทำทีละครั้ง และไม่มีทางรับเกิน
- ต้องส่ง `Idempotency-Key` และเขียน audit `inventory.purchase_order_raised` พร้อมยอดรวม
- **อ่านและยกเลิก** เป็นส่วนขยาย § 25 แก้ใบสั่งซื้อยังทำไม่ได้

### อ่านและยกเลิกใบสั่งซื้อ

`GET /staff/inventory/purchase-orders?status=&branch=&supplier=&limit=&cursor=` scope `inventory:purchase` คืนใบสั่งซื้อพร้อมรายการ ใหม่สุดก่อน ครอบคลุมสาขาที่ผู้เรียกเห็น ขอสาขาอื่นตอบ `403` แต่ละใบมี `received_cost_satang` คือต้นทุนของที่รับแล้ว

`POST /staff/inventory/purchase-orders/{id}/cancel` scope `inventory:purchase` รองรับ `If-Match` เหตุผล (`reason`) ไม่บังคับ

- **ยกเลิกส่วนที่ค้าง ไม่ใช่ทั้งใบ** ทำได้เมื่อยังมีของค้าง ไม่ว่ายังไม่ได้รับเลยหรือรับมาบางส่วน สถานะเป็น `cancelled` จำนวนที่รับแล้วอยู่ในแถวเหมือนเดิม และของนั้นยังอยู่ในคลัง แต่ละแถวมี `cancelled_quantity` คือจำนวนที่ค้างตอนยกเลิก และ `outstanding` เป็นศูนย์
- ส่วนที่ค้างหายจาก `on_order` และ `open_orders` ของรายการสต๊อก
- รับของตามใบที่ยกเลิกแล้ว ใบที่รับครบแล้ว และการยกเลิกซ้ำ ตอบ `409 state_conflict`
- การยกเลิกถือ row lock ของใบตัวเดียวกับการรับของ จึงทำทีละครั้งกับการรับ
- audit `inventory.purchase_order_cancelled`

## ปรับยอดหลังนับสต๊อก

`POST /staff/inventory/adjustments` ตอบ `201`

```json
{ "item_id": "itm_...", "lot_id": "lot_...", "counted_quantity": 37, "reason": "นับสิ้นเดือน พบเม็ดแตก 3 เม็ด" }
```

- **ส่งจำนวนที่นับได้ ไม่ใช่ส่วนต่าง** คนนับรู้ว่านับได้เท่าไร ส่วนต่างคำนวณที่ระบบ ภายใต้ lock ของสต๊อก เทียบกับยอดตอนบันทึก แล้วเขียนเป็นแถว `adjustment` แถวเดียว นับซ้ำได้ยอดเดิมคือแถวที่มีจำนวนศูนย์ ซึ่งเป็นบันทึกว่าได้นับแล้ว
- `reason` บังคับ
- **ล็อตไหน** ถ้าสาขามีของในล็อตเดียว ใช้ล็อตนั้น ถ้าไม่มีของเลย ของที่นับเจอเข้าล็อตที่ไม่มีเลขล็อต ถ้ามีหลายล็อต ต้องส่ง `lot_id` ไม่อย่างนั้นตอบ `422`
- เขียน audit `inventory.adjusted` พร้อมยอดก่อน ยอดที่นับ ส่วนต่าง และเหตุผล เพราะการปรับยอดเป็นการเปลี่ยนสต๊อกอย่างเดียวที่ไม่มีเอกสารรองรับ
- **ข้อควรรู้** ถ้ามีการจ่ายยาระหว่างที่นับกับที่กดบันทึก ยอดที่นับจะทับการจ่ายนั้น ควรนับตอนห้องยาไม่ได้จ่าย

## แจ้งเตือน

`GET /staff/inventory/alerts?branch=&within_days=` คืน `{ "data": [...] }` เรียงจากเรื่องที่ต้องทำก่อน

| `kind` | เมื่อไร |
|---|---|
| `expired` | ล็อตที่เลยวันหมดอายุแล้วแต่ยังมีของในยอด ต้องเก็บออกจากชั้น |
| `out_of_stock` | รายการที่สาขาเคยมีแต่ตอนนี้ใช้ได้ศูนย์ |
| `near_expiry` | ล็อตที่จะหมดอายุภายใน `within_days` วัน (1 ถึง 365 ค่าเริ่มต้น 90) เรียงจากใกล้สุด |
| `low_stock` | ใช้ได้ไม่เกินจุดสั่งซื้อ |

- ทุกแถวมี `available`, `reorder_level` และ `on_order` แถวที่ใกล้หมดแต่สั่งไว้พอแล้วจึงแยกออกจากแถวที่ต้องสั่งได้
- แถวเรื่องวันหมดอายุมี `lot_id`, `lot_number`, `expires_on`, `lot_quantity` และ `days_to_expiry` (ติดลบเมื่อเลยมาแล้ว)
- รายการที่สาขาไม่เคยมีไม่ขึ้นว่าหมด เพราะสาขานั้นแค่ไม่ได้เก็บยานี้
- **ล็อตที่ต้องเรียกคืน** contract ไม่มีทางบอกว่าผู้ผลิตเรียกคืนล็อตไหน ตอนนี้จึงถือว่าล็อตที่ต้องเรียกคืนคือล็อตที่หมดอายุแล้ว ([assumptions.md § 42](../assumptions.md))
- **ยังไม่มีการแจ้งเตือนพนักงานอัตโนมัติ** ระบบส่งข้อความถึงลูกค้าอย่างเดียว ยังไม่มีช่องทางถึงพนักงาน และ webhook `inventory.low_stock` ของ contract ยังไม่ได้ทำ หน้านี้จึงเป็นที่ดู

## เลือกยาจากคลังตอนสั่งยา

ส่วนขยาย [contract-extensions.md § 20](../contract-extensions.md) ฟอร์มสั่งยาในหน้าตรวจค้นยาในคลังขณะพิมพ์ เลือกแล้วใบสั่งยาผูกกับรายการนั้นด้วยรหัส ไม่ต้องพึ่งชื่อที่พิมพ์อีก

`GET /staff/prescriptions/drug-options?q=&branch=&limit=` ใช้ `rx:write` คืน

```json
{ "branch_id": "brn_...",
  "data": [ { "item_id": "itm_...", "name": "Amoxicillin 250mg", "unit": "เม็ด", "unit_price_satang": 500, "available": 36, "status": "ok" } ] }
```

- **เฉพาะยา** (`kind: medicine`) เวชภัณฑ์ไม่ถูกสั่งจ่าย เรียงตามชื่อ `q` ค้นส่วนของชื่อ `limit` 1 ถึง 50 ค่าเริ่มต้น 20
- **สาขาเดียว** สาขาที่ขอ (ต้องเปิดอยู่และผู้เรียกสังกัด ไม่อย่างนั้นตอบ `403`) ถ้าไม่ส่ง ใช้สาขาเดียวของผู้เรียก หรือสาขาเดียวของคลินิก ไม่อย่างนั้นตอบ `422` หน้าตรวจส่งสาขาของเคส
- `available` และ `status` คิดแบบเดียวกับรายการในคลัง ยาที่หมดยังขึ้นพร้อม `out` เพื่อให้หมอรู้ ไม่ใช่ซ่อนไว้
- **ไม่มีต้นทุน ล็อต ซัพพลายเออร์ ใบสั่งซื้อ หรือสาขาอื่น** เทสต์ตรวจว่าคำตอบไม่มีคำว่า cost, lot หรือ supplier เลย

`POST /staff/consultations/{id}/prescriptions` รับ `inventory_item_id` เพิ่ม ไม่บังคับ

- รหัสที่ไม่มีในคลังตอบ `404` รหัสของเวชภัณฑ์ตอบ `422` ที่ `inventory_item_id` รายการที่เลิกใช้ตอบ `409 inventory_item_retired` (§ 25)
- ไม่ส่ง `drug_name` ระบบใช้ชื่อของรายการ ส่งมาด้วยระบบเก็บตามที่พิมพ์ เพราะเป็นข้อความบนฉลาก รหัสคือสิ่งที่ใช้ตัดสต๊อก
- การตรวจแพ้ยาเทียบทั้งชื่อที่พิมพ์และชื่อของรายการ
- รหัสเก็บในคอลัมน์ `prescriptions.inventory_item_id` ตัวเดิมที่การจ่ายยาใช้บันทึกว่าจับคู่กับรายการไหน จึงไม่มี migration
- คำขอที่ไม่มี `inventory_item_id` ทำงานเหมือนเดิมทุกอย่าง

## การจ่ายยาตัดสต๊อก

`POST /staff/prescriptions/{id}/dispense` ทำสามอย่างใน transaction เดียว คือบันทึกว่าจ่ายแล้ว ตัดสต๊อกของสาขาที่เปิดเคส และคิดค่ายา ได้ทั้งหมดหรือไม่ได้เลย

**ผูกใบสั่งยากับรายการในคลัง รหัสก่อน ชื่อทีหลัง** ใบสั่งยาที่เลือกยาจากคลังมีรหัสรายการ การจ่ายใช้รายการนั้นเสมอ แม้ชื่อในใบจะต่างจากชื่อรายการ และไม่เทียบชื่อเลย ใบที่พิมพ์ชื่อเองไม่มีรหัส ระบบจึงเทียบชื่อยากับชื่อรายการแบบตรงทั้งชื่อ หลังตัดช่องว่างซ้ำและไม่สนตัวพิมพ์เล็กใหญ่ "amoxicillin  250mg" ตรงกับ "Amoxicillin 250mg" แต่ "Amoxicillin 250 mg" ไม่ตรง ไม่ใช้การเทียบคำแรกแบบตรวจยาซ้ำ เพราะการผูกผิดคือหยิบยาผิดตัวออกจากคลังและคิดราคาผิด ซึ่งแย่กว่าไม่หยิบเลยแล้วบอกตรง ๆ

**การจ่ายยาไม่เคยถูกปฏิเสธเพราะสต๊อก** ยาอยู่ในมือเจ้าของแล้ว และ contract ไม่ได้บอกว่าปฏิเสธได้

| `stock.status` | เมื่อไร | สต๊อก | ค่ายา |
|---|---|---|---|
| `deducted` | ผูกกับรายการหรือชื่อตรง และสาขามีของที่ใช้ได้พอ | ตัดตามหมดอายุก่อนออกก่อน หนึ่งแถว `dispense` ต่อล็อต อ้าง `prescription_id` | คิด |
| `not_matched` | พิมพ์ชื่อเองและไม่มีรายการชื่อนี้ | ไม่แตะ | ไม่คิด |
| `insufficient` | ผูกกับรายการหรือชื่อตรง แต่ของที่ใช้ได้น้อยกว่าที่จ่าย | ไม่แตะ ไม่ตัดบางส่วน | คิด เพราะยาถูกจ่ายไปจริง |

- `stock_deducted` เป็น `true` เฉพาะ `deducted`
- ไม่ตัดบางส่วน เพราะยอดในระบบผิดอยู่แล้ว การตัดเท่าที่มีจะซ่อนว่าผิดไปเท่าไร คนดูแลควรนับและปรับยอด
- ล็อตที่หมดอายุแล้วไม่ถูกนับว่าใช้ได้ และไม่ถูกตัด
- **จ่ายพร้อมกันสองเคาน์เตอร์** ทั้งคู่รอ lock เดียวกัน คนแรกได้ของ คนที่สองเห็นว่าหมดแล้วได้ `insufficient` ยอดไม่ติดลบ
- จ่ายใบเดิมซ้ำยังตอบ `409 state_conflict` เหมือนเดิม และต้องถือ `rx:dispense` scope กลุ่ม inventory จ่ายยาไม่ได้

คำตอบเพิ่มสองส่วน

```json
{
  "prescription": { "...": "...", "inventory_item_id": "itm_...", "stock_deducted": true, "charged_unit_price_satang": 500 },
  "label": { "...": "..." },
  "stock_deducted": true,
  "stock": { "status": "deducted", "item_id": "itm_...", "item_name": "Amoxicillin 250mg", "unit": "เม็ด", "available": 50,
             "lots": [ { "lot_id": "lot_...", "lot_number": "L1", "expires_on": "2027-04-25", "quantity": 14 } ] },
  "charge": { "placement": "on_close", "unit_price_satang": 500, "amount_satang": 7000 }
}
```

## ค่ายาขึ้นบิลเดียวกับการรักษา

ค่ายาคือราคาขายของรายการ ณ ตอนจ่าย คูณจำนวนในใบสั่งยา ราคาถูกเก็บไว้ที่ใบสั่งยา (`charged_unit_price_satang`) ราคาที่แก้ภายหลังจึงไม่เปลี่ยนค่ายาที่คิดไปแล้ว ค่ายาเป็นรายการชนิด `medicine` ที่มี `source_id` เป็นรหัสใบสั่งยา

| ตอนจ่าย เคสอยู่ในสภาพไหน | `charge.placement` | เกิดอะไร |
|---|---|---|
| เคสยังเปิด | `on_close` | ค่ายารอไว้ที่ใบสั่งยา ตอนปิดเคส บิลที่ออกมีทั้งหัตถการและค่ายา |
| ปิดแล้ว บิลของเคสยัง `open` | `invoiced` | เพิ่มรายการค่ายาลงบิลนั้น เขียน audit `invoice.line_added` |
| ปิดแล้ว ไม่มีบิล (เคสไม่มีอะไรให้คิดเงินตอนปิด) | `invoiced` | ออกบิลของเคสตอนนี้ ผูก `consultation_id` |
| ปิดแล้ว บิลของเคสรับเงินไปแล้วหรือถูกยกเลิก | `separate_invoice` | ไม่แตะบิลเดิม ออกบิลค่ายาใบใหม่ให้ลูกค้าและสัตว์ตัวเดิม ไม่ผูก `consultation_id` (หนึ่งเคสผูกได้บิลเดียว) หมายเหตุของบิลบอกว่ามาจากเคสไหน |

- เป็นไปตามกฎเดิมของบิล คือเพิ่มรายการได้เฉพาะบิล `open` บิลที่รับเงินแล้วคือยอดที่ตกลงกันแล้ว ของที่ลืมคิดเป็นบิลใบที่สอง ดู [ใบแจ้งหนี้](billing.md)
- รายการที่ราคาขายเป็นศูนย์ และยาที่ไม่พบในคลัง ไม่ขึ้นบิล คำตอบไม่มี `charge`
- เคสที่ไม่มีหัตถการแต่มีค่ายาที่จ่ายแล้ว ตอนปิดเคสได้บิล เพราะมีสิ่งที่ต้องคิดเงิน
- **การจ่ายยากับการปิดเคสที่เกิดพร้อมกัน** ทั้งสองถือ lock การออกบิลของเคสเดียวกัน (advisory lock ต่อเคส) และอ่านสถานะเคสกับใบสั่งยาใหม่หลังได้ lock ค่ายาจึงอยู่ในบิลเสมอ ไม่มีกรณีที่ต่างฝ่ายคิดว่าอีกฝ่ายจะคิดเงินให้
- **การเพิ่มรายการกับการรับเงินที่เกิดพร้อมกัน** การเพิ่มรายการเปลี่ยนเวอร์ชันของบิล ถ้าแคชเชียร์รับเงินด้วยยอดเดิมระหว่างนั้น ฝ่ายที่บันทึกทีหลังได้ `409 version_conflict` แล้วลองใหม่กับยอดใหม่ ถ้าเป็นการจ่ายยาที่ลองใหม่ บิลจะเป็นรับเงินแล้ว ค่ายาจึงไปบิลใบใหม่

## รายงานบริการทำเงิน

`GET /staff/analytics/services` แยกค่ายาในบิลเดียวกันไว้ข้างบริการอยู่แล้ว ([ภาพรวมและรายงาน](dashboard.md)) ตอนนี้ค่ายาขึ้นบิลเองจากการจ่ายยา ตัวเลขชุดเดิมจึงมีค่าจริง ความหมายไม่เปลี่ยน

- ค่ายาที่อยู่บนบิลของเคสถูกแบ่งให้บริการในบิลนั้นตามสัดส่วน
- ค่ายาที่ไปอยู่บิลใบใหม่ (`separate_invoice`) ไม่มีบริการในบิลเดียวกัน จึงนับใน `by_kind` ของ `medicine` แต่ไม่ขึ้นข้างบริการใด
- **ต้นทุนยามีแล้ว แต่รายงานยังไม่ใช้** การรับเข้าเก็บ `unit_cost_satang` ต่อแถว และใบสั่งซื้อเก็บต้นทุนต่อหน่วย การคำนวณกำไรจริงต้องมีส่วนขยายของรายงาน ดูข้อเสนอด้านล่าง

| แท็บ | path | scope | มีอะไร |

| รายการยา | `/inventory` | `inventory:read` | ค้นหาชื่อ กรองสถานะ ราคาขาย ใช้ได้ สถานะ สั่งไว้ วันหมดอายุที่ใกล้สุด และล็อต รายการที่เลิกใช้มีป้าย "เลิกใช้" ผู้ถือ `inventory:write` มีปุ่มแก้ไข (ฟอร์มในแถว ส่งเฉพาะช่องที่เปลี่ยน) และปุ่มเลิกใช้หรือกลับมาใช้ที่ถามยืนยันก่อน (§ 25) |
| แจ้งเตือน | `/inventory/alerts` | `inventory:read` | รายการแจ้งเตือน เลือกดูวันหมดอายุล่วงหน้า 30 ถึง 180 วัน |
| รับเข้า จ่ายออก | `/inventory/movements` | `inventory:write` | ฟอร์มเดียวสามชนิด รับรายการใหม่ได้ เลือกล็อตหรือให้ระบบเลือก เลือกใบสั่งซื้อที่ค้างรับ |
| ปรับยอด | `/inventory/adjustments` | `inventory:adjust` | เลือกรายการและล็อต กรอกจำนวนที่นับและเหตุผล ต้องถือ `inventory:read` ด้วย |
| สั่งซื้อ | `/inventory/purchase-orders` | `inventory:purchase` | ซัพพลายเออร์ วันที่คาดว่าได้ของ และหลายรายการ แสดงยอดรวมระหว่างกรอก ไม่เสนอรายการที่เลิกใช้ ใต้ฟอร์มมีใบสั่งซื้อของสาขา กรองซัพพลายเออร์และสถานะ แต่ละใบมีความคืบหน้าของแต่ละรายการ และปุ่ม "ยกเลิกส่วนที่ค้าง" ที่ถามยืนยันก่อน (§ 25) |

- บัญชีที่ไม่มี `inventory:read` แต่มี scope อื่นของกลุ่มนี้ เปิด `/inventory` แล้วถูกพาไปแท็บแรกที่ใช้ได้ ฟอร์มรับเข้าและสั่งซื้อของบัญชีนี้เลือกได้เฉพาะรายการใหม่
- ฟอร์มรับเข้าและสั่งซื้อสร้าง `Idempotency-Key` ครั้งเดียวต่อหนึ่งรายการที่บันทึก และใช้ key เดิมเมื่อลองซ้ำ
- ฟอร์มสั่งยาในหน้าตรวจ (`/consultations/{id}`) ค้นยาในคลังของสาขาของเคสขณะพิมพ์ แต่ละตัวมีป้ายสถานะ (มีของ ใกล้หมด หมด) จำนวนที่เหลือ และราคาต่อหน่วย เลือกแล้วชื่อถูกเติมให้ และบอกว่าผูกกับสต๊อก พิมพ์ชื่อเองยังได้ ใต้ช่องขึ้นว่า "ไม่ผูกกับสต๊อก ตอนจ่ายจะจับคู่ด้วยชื่อ ถ้าชื่อไม่ตรงกับในคลังทุกตัวอักษร จะไม่ตัดสต๊อกและไม่คิดเงิน" พิมพ์ทับชื่อที่เลือกแล้วคือยกเลิกการผูก รายการยาในเคสมีป้าย **ผูกกับสต๊อก** หรือ **ไม่ผูกกับสต๊อก** ทุกแถว
- หน้าจ่ายยา (`/prescriptions`) ใบที่รอจ่ายมีป้าย **ผูกกับสต๊อก** หรือ **ชื่อพิมพ์เอง จับคู่ด้วยชื่อตอนจ่าย** ห้องยาจึงรู้ก่อนกดว่าใบไหนอาจไม่ถูกตัดสต๊อก
- หน้าจ่ายยา (`/prescriptions`) หลังจ่ายแสดงฉลาก พร้อมบรรทัดบอกว่าตัดสต๊อกแล้วกี่หน่วย หรือทำไมไม่ได้ตัด และค่ายาไปอยู่บิลไหน ประวัติยาแสดงป้าย **ไม่ได้ตัดสต๊อก** ที่ใบที่จ่ายแล้วแต่ไม่ได้ตัด

## ความพร้อมกันและความถูกต้อง

- **ทุกการเปลี่ยนสต๊อกถือ lock ต่อรายการต่อสาขา** (`pg_advisory_xact_lock`) ก่อนอ่านล็อต แล้วเขียนยอดกับแถวในสมุดพร้อมกัน lock คลายเมื่อ transaction จบ ใช้ advisory lock แทน `SELECT ... FOR UPDATE` เพราะการรับครั้งแรกของสาขายังไม่มีแถวให้ล็อก
- การโอนล็อกทั้งสองสาขาตามลำดับเดียวกันเสมอ การโอนสวนทางกันจึงไม่ติด deadlock
- ล็อตมี `xmin` เป็นเวอร์ชันเหมือนทุกตาราง และมี check constraint กันยอดติดลบ เป็นด่านสุดท้ายถ้าวันหนึ่งมีโค้ดที่ลืม lock
- เทสต์จ่ายยาพร้อมกันสองใบกับของชิ้นสุดท้าย และจ่ายออกพร้อมกันหกครั้งกับของห้าชิ้น ยืนยันว่ายอดไม่ติดลบ และยอดในล็อตเท่ากับผลรวมของสมุด

## ข้อจำกัดที่รู้อยู่

- ลบรายการไม่ได้ เลิกใช้ได้ (§ 25) และแก้ชนิดรายการไม่ได้
- แก้ใบสั่งซื้อไม่ได้ ยกเลิกได้เฉพาะส่วนที่ค้าง (§ 25)
- อ่านสมุดสต๊อกย้อนหลังผ่าน API ไม่ได้ แถวอยู่ในฐานข้อมูลครบ
- ใบสั่งยาที่พิมพ์ชื่อเองยังต้องมีชื่อตรงกับชื่อรายการถึงจะตัดสต๊อก ใบสั่งยาที่สร้างก่อนมีส่วนขยาย § 20 เป็นแบบนี้ทั้งหมด role `veterinarian` ยังไม่มี `inventory:read` และไม่ต้องมี เพราะตัวเลือกยาใช้ `rx:write`
- จำนวนในใบสั่งยาถือว่าเป็นหน่วยเดียวกับหน่วยของรายการ
- การปรับยอดทับการจ่ายที่เกิดระหว่างนับ
- ไม่มีการเรียกคืนล็อตโดยผู้ผลิต และไม่มีการแจ้งเตือนพนักงานหรือ webhook `inventory.low_stock`

## ข้อเสนอส่วนขยาย (ยังไม่ได้ขออนุมัติ ยังไม่ได้ทำ)

| ข้อเสนอ | เหตุผล |
|---|---|
| `GET /staff/inventory/movements?item_id=&branch=` | ดูสมุดสต๊อกของรายการหนึ่ง สำหรับตรวจสอบและตามหาล็อตตอนเรียกคืน |
| `POST /staff/inventory/lots/{id}/recall` | บันทึกล็อตที่ผู้ผลิตเรียกคืน ให้ขึ้นในแจ้งเตือนแยกจากล็อตหมดอายุ |
| ต้นทุนยาในรายงานบริการ เช่น `medicine_cost_satang` | กำไรจริงหลังหักต้นทุนยา ใช้ต้นทุนจากล็อตที่ถูกตัดตอนจ่าย |

ข้อเสนอ `inventory_item_id` ในคำขอสั่งยาได้รับอนุมัติและทำแล้ว เป็น [contract-extensions.md § 20](../contract-extensions.md) ข้อเสนอแก้รายการ และอ่านกับยกเลิกใบสั่งซื้อ ได้รับอนุมัติและทำแล้ว เป็น [§ 25](../contract-extensions.md)
