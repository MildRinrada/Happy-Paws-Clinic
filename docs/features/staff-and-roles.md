# พนักงานและสิทธิ์

รายชื่อคนที่ทำงานในคลินิก การเชิญคนใหม่ การแก้ตำแหน่ง แผนก role และสาขา การปิดใช้งาน และ role ที่รวม scope เป็นชุดเพื่อกำหนดว่าแต่ละคนทำอะไรในระบบได้

สามคำที่ต้องแยกกันให้ออก

| คำ | คืออะไร | มีผลกับสิทธิ์ไหม |
|---|---|---|
| role | ชุดของ scope เช่น `veterinarian` ถือ `consult:*` `record:write` `lab:*` `rx:write` `queue:call` | มี ระบบตรวจ scope ทุกครั้งที่เรียก API |
| ตำแหน่ง (`staff_type`) | ป้ายชื่อ เช่น `veterinarian` `receptionist` คลินิกพิมพ์ตำแหน่งใหม่เองได้ | ไม่มี |
| แผนก (`department`) | ทีมที่คนนั้นอยู่ ใช้จัดกลุ่มในรายชื่อและหน้าทีมของเรา มีหกแผนกตายตัว | ไม่มี |

scope ที่แต่ละ role ตั้งต้นถืออยู่ และวิธีที่ API ตรวจ scope ดูที่ [สิทธิ์](../authorization.md)

## ใครใช้

| ใคร | ทำอะไร |
|---|---|
| พนักงานที่ถือ `staff:read` | ดูรายชื่อพนักงาน คำเชิญที่รอตอบรับ และกรองตามสถานะ สาขา แผนก role |
| พนักงานที่ถือ `staff:manage` | เชิญพนักงาน ส่งคำเชิญซ้ำ แก้ตำแหน่ง แผนก เลขใบประกอบวิชาชีพ role และสาขา และปิดใช้งาน |
| พนักงานที่ถือ `role:read` | ดู role ทั้งหมดและ scope ในแต่ละ role |
| พนักงานที่ถือ `role:manage` | สร้าง role ใหม่ และแก้ชุด scope ของ role |
| คนที่ถูกเชิญ | เปิดลิงก์ในคำเชิญ ตั้งรหัสผ่านและ 2FA ที่หน้า `/invitations/{id}` ดู [การเข้าสู่ระบบและเซสชัน](../authentication.md) |

role ตั้งต้นที่ถือทั้งสี่ scope คือ `clinic_owner` (ถือ `*`) และ `clinic_admin`

## API

| Method | Endpoint | Scope |
|---|---|---|
| GET | `/staff/members` | `staff:read` กรองด้วย `status` (`active` `invited` `deactivated`) `branch` `staff_type` `department` `role` แบ่งหน้าด้วย `cursor` หน้าละไม่เกิน 100 |
| POST | `/staff/members/invitations` | `staff:manage` |
| PATCH | `/staff/members/{id}` | `staff:manage` ต้องส่ง `If-Match` |
| POST | `/staff/members/{id}/deactivate` | `staff:manage` |
| GET | `/staff/staff-types` | `staff:read` |
| GET | `/staff/departments` | `staff:read` (ส่วนขยาย ดู [contract-extensions.md § 10](../contract-extensions.md)) |
| GET | `/staff/roles` | `role:read` |
| POST | `/staff/roles` | `role:manage` |
| PUT | `/staff/roles/{id}/permissions` | `role:manage` ต้องส่ง `If-Match` |
| GET | `/staff/permissions` | `role:read` |

**รายชื่อ** ถ้าไม่ส่ง `status` ได้ทุกคนที่เคยเป็นพนักงาน ทั้งที่ใช้งานอยู่และปิดใช้งานแล้ว คำเชิญที่ยังไม่มีใครตอบรับอยู่แยกกัน ต้องส่ง `status=invited` แถวคำเชิญมีรูปแบบเดียวกับแถวพนักงาน แต่ `id` เป็นรหัสคำเชิญ ไม่มี `user_id` และมี `invitation_expires_at`

**เชิญ** ส่ง `email` (ไม่เกิน 256 ตัวอักษร) `display_name` (ไม่เกิน 200) `staff_type` (ไม่เกิน 64) `roles` (ชื่อ role อย่างน้อยหนึ่งชื่อ) `branches` (รหัสสาขา ไม่บังคับ) และ `license_no` (ไม่เกิน 64 ไม่บังคับ) คำเชิญไม่มีช่องแผนก แผนกตั้งจากตำแหน่งให้ก่อน เช่น `veterinarian` อยู่ทีมสัตวแพทย์ ตำแหน่งที่ไม่รู้จักอยู่ทีมสนับสนุน อีเมลที่มีบัญชีในคลินิกอยู่แล้วได้ `409 staff_already_exists`

**แก้ไข** ส่งเฉพาะช่องที่จะเปลี่ยน ช่องที่ไม่ส่งคงเดิม `roles` และ `branches` แทนทั้งชุด `roles` ต้องมีอย่างน้อยหนึ่งชื่อ `license_no` เป็นสตริงว่างคือล้าง `department` ต้องเป็นหนึ่งใน `veterinary` `nursing` `front_desk` `finance` `management` `support` ชื่อและอีเมลแก้ที่นี่ไม่ได้ เจ้าของบัญชีแก้เองที่ `PATCH /me`

**สร้าง role** ชื่อยาว 2 ถึง 64 ตัวอักษร ห้ามขึ้นต้นหรือลงท้ายด้วยช่องว่าง ต้องมี scope อย่างน้อยหนึ่งรายการ ชื่อซ้ำได้ `409 duplicate_role`

**แก้ชุด scope** ส่งชุดทั้งหมดที่ role ควรมีหลังแก้ ไม่ใช่รายการที่เพิ่มหรือลด ชุดว่างใช้ได้ คือวิธีเลิกใช้ role เพราะไม่มีการลบ role scope ที่ไม่อยู่ในแค็ตตาล็อกได้ `422` พร้อมชื่อ scope นั้น role `customer` แก้ไม่ได้ (`409 role_not_editable`)

role เก็บ scope แบบ wildcard ได้สองแบบ `*` คือทุกอย่าง และ `consult:*` คือทุก action ในหมวด `consult` รวม action ที่จะเพิ่มในอนาคต

## คำเชิญ

- ลิงก์ในคำเชิญใช้ได้ 7 วัน คำตอบของ API บอกรายละเอียดคำเชิญแต่ไม่มีลิงก์ ลิงก์ไปถึงคนที่ถูกเชิญคนเดียว
- ถ้าเซิร์ฟเวอร์ตั้งค่าอีเมลไว้ ลิงก์ส่งไปทางอีเมล ถ้ายังไม่ได้ตั้ง (ระหว่างพัฒนา) ระบบเขียนลง log ของ API แทน ลิงก์จะอยู่ใน log เฉพาะเมื่อเปิด `Staff:Invitations:LogUndeliveredLinks` ดู [การแจ้งเตือน](notifications.md)
- เชิญอีเมลเดิมซ้ำระหว่างที่คำเชิญยังเปิดอยู่ คือส่งลิงก์ใหม่ ลิงก์เก่าใช้ไม่ได้ และนับ 7 วันใหม่ ใช้วิธีนี้แก้ role หรือสาขาที่เลือกผิดก่อนมีคนตอบรับ
- ยังไม่มีบัญชีหรือสิทธิ์ใดเกิดขึ้นจนกว่าคนที่ถูกเชิญจะตั้งรหัสผ่านและ 2FA เสร็จ

## กติกาที่ระบบบังคับ

- **ให้สิทธิ์ที่ตัวเองไม่มีไม่ได้** การสร้าง role การแก้ scope ของ role การเชิญ และการเปลี่ยน role ของพนักงาน ผู้ทำต้องถือทุก scope ที่กำลังให้ ไม่อย่างนั้นได้ `403 insufficient_scope` การแก้ scope ของ role ต้องถือทุก scope ที่ role มีอยู่เดิมด้วย และ wildcard เช่น `invoice:*` ให้ได้เฉพาะคนที่ถือ `invoice:*` หรือ `*` เท่านั้น ถือทุก scope ในหมวดทีละตัวยังไม่พอ
- **แก้คนที่มีสิทธิ์มากกว่าไม่ได้** การแก้หรือปิดใช้งานพนักงานที่ถือ scope ที่ผู้ทำไม่มีได้ `403` ผู้ดูแลคลินิกจึงปิดใช้งานเจ้าของคลินิกไม่ได้
- **ต้องเหลือคนที่ถือ `*` อย่างน้อยหนึ่งคนเสมอ** การปิดใช้งาน การเปลี่ยน role และการแก้ scope ของ role ที่จะทำให้ไม่เหลือบัญชีที่ใช้งานอยู่และถือ `*` ได้ `409 last_owner` ข้อความ "ต้องมีผู้ใช้ที่มีสิทธิ์ทั้งหมด (*) อย่างน้อยหนึ่งคนเสมอ"
- **ปิดใช้งานตัวเองไม่ได้** ได้ `409 cannot_deactivate_self`
- **สาขา** พนักงานที่ผูกกับบางสาขาเห็นและแก้ได้เฉพาะคนที่อยู่สาขาเดียวกัน และต้องเลือกสาขาอย่างน้อยหนึ่งสาขาเมื่อเชิญหรือแก้ เพราะรายการสาขาว่างแปลว่าทุกสาขา ซึ่งกว้างกว่าสิทธิ์ของผู้ทำเอง
- **มีผลภายใน 15 นาที** role และสาขาเดินทางไปกับ access token การเปลี่ยน role ของคนหนึ่งหรือแก้ scope ของ role มีผลเมื่อ token ใบถัดไปออก ไม่ต้องออกจากระบบ การปิดใช้งานยกเลิกทุกเซสชันทันที token ที่ออกไปแล้วใช้ได้ไม่เกิน 15 นาที
- **ปิดใช้งานไม่ใช่ลบ** บัญชีและแถวพนักงานยังอยู่ ชื่อในเวชระเบียนที่คนนั้นเซ็นไว้ยังแสดงตามเดิม

## หน้าจอพนักงาน

`/settings/staff` แท็บ **พนักงานและสิทธิ์** ในเมนู **ตั้งค่า** เห็นเฉพาะบัญชีที่ถือ `staff:read` ปุ่มที่เปลี่ยนข้อมูลขึ้นเฉพาะบัญชีที่ถือ scope ของการเปลี่ยนนั้น

**รายชื่อพนักงาน**

- แท็บสถานะ **ทั้งหมด** **ใช้งานอยู่** **รอตอบรับคำเชิญ** **ปิดใช้งาน** แท็บทั้งหมดในหน้าแรกแสดงคำเชิญที่รอตอบรับไว้บนสุด แล้วตามด้วยพนักงาน
- กรองตามสาขา (ขึ้นเมื่อมีมากกว่าหนึ่งสาขา) แผนก และ role ตัวกรองอยู่ใน URL จึงบุ๊กมาร์กได้
- แต่ละแถวบอกชื่อ อีเมล ตำแหน่ง แผนก เลขใบประกอบวิชาชีพ role สาขา สถานะ และ 2FA เปิดหรือยัง แถวคำเชิญบอกเวลาที่ลิงก์หมดอายุ
- หน้าละ 100 คน ปุ่ม **หน้าถัดไป** ไปต่อ และ **กลับหน้าแรก**

**เชิญพนักงาน** ปุ่ม **+ เชิญพนักงาน** เปิดฟอร์มอีเมล ชื่อที่แสดง ตำแหน่ง (เลือกจากรายการหรือพิมพ์ใหม่) เลขใบประกอบวิชาชีพ role และสาขา ส่งแล้วหน้าจอบอกว่าส่งถึงใคร ลิงก์ใช้ได้ถึงเมื่อไร และลิงก์ไปที่อีเมลหรือ log ของ API หน้านี้ไม่แสดงลิงก์ เพราะลิงก์คือรหัสเข้าใช้ของคนที่ถูกเชิญ

**แถวพนักงานที่ใช้งานอยู่**

- **แก้ไข** เปิดฟอร์มตำแหน่ง แผนก เลขใบประกอบวิชาชีพ role และสาขา บันทึกเฉพาะช่องที่เปลี่ยน ถ้าไม่ได้เปลี่ยนอะไรฟอร์มปิดเฉย ๆ
- **ปิดใช้งาน** ถามยืนยันอีกครั้งพร้อมบอกผล ถ้าระบบไม่ยอม เช่นเป็นเจ้าของคลินิกคนสุดท้าย ข้อความภาษาไทยจากระบบขึ้นในกรอบยืนยัน แถวของตัวเองไม่มีปุ่มนี้
- พนักงานที่ถือสิทธิ์มากกว่าบัญชีที่เปิดหน้าอยู่ไม่มีปุ่มแก้ไขและปิดใช้งาน มีข้อความบอกเหตุผลแทน

**แถวคำเชิญ** มีปุ่ม **ส่งคำเชิญอีกครั้ง** ส่งคำเชิญเดิมซ้ำด้วยข้อมูลเดิม ลิงก์เก่าใช้ไม่ได้

**role ในฟอร์ม** role ที่มี scope ที่บัญชีนี้ไม่มีขึ้นเป็นช่องเลือกไม่ได้ role `customer` ไม่อยู่ในรายการ ถ้าบัญชีไม่มี `role:read` ฟอร์มแก้ไขเปลี่ยน role ไม่ได้ และเชิญจากหน้านี้ไม่ได้

**Role และสิทธิ์** การ์ดล่างสุด เห็นเมื่อถือ `role:read`

- role ตั้งต้นขึ้นก่อน ตามด้วย role ที่สร้างเอง และ role `customer` (แก้ไม่ได้) แต่ละ role บอกชื่อภาษาไทย รหัส ป้ายประเภท จำนวน scope และ scope ทั้งหมด (ถ้าเกิน 12 รายการพับไว้) ลิงก์ **ดูพนักงานใน role นี้** กรองรายชื่อด้านบน
- **+ สร้าง role** และ **แก้สิทธิ์** ขึ้นเมื่อถือ `role:manage` ตัวเลือก scope แบ่งกลุ่มตามหมวด แต่ละหมวดมีช่อง **ทุกอย่างในหมวดนี้** (`หมวด:*`) และช่องแยกแต่ละ action ช่อง **ทุกสิทธิ์ (*)** อยู่บนสุด ช่องที่บัญชีนี้ไม่มีสิทธิ์ให้ขึ้นเป็นช่องเลือกไม่ได้
- role ที่มี scope ที่บัญชีนี้ไม่มีแก้ไม่ได้ มีข้อความบอกเหตุผล เช่นผู้ดูแลคลินิกแก้ role `clinic_owner` ไม่ได้
- ล้างทุกช่องแล้วบันทึกได้ หน้าจอเตือนว่าคนที่ถือ role นี้จะทำอะไรไม่ได้

## ข้อจำกัด

ส่วนที่หน้าจอไม่มีเพราะ API ยังไม่มี endpoint

- **เปิดใช้งานคืน** คนที่ปิดใช้งานแล้วเปิดกลับไม่ได้ และเชิญอีเมลเดิมใหม่ก็ไม่ได้เพราะอีเมลมีบัญชีอยู่แล้ว
- **ยกเลิกคำเชิญ** ทำไม่ได้ ต้องรอลิงก์หมดอายุใน 7 วัน
- **แก้คำเชิญ** ทำได้ทางเดียวคือเชิญอีเมลเดิมซ้ำด้วยข้อมูลใหม่ หน้าจอยังไม่มีฟอร์มแก้คำเชิญ มีแค่ส่งซ้ำด้วยข้อมูลเดิม ถ้าจะเปลี่ยนให้กรอกฟอร์มเชิญด้วยอีเมลเดิม
- **ชื่อและอีเมลของพนักงาน** ผู้ดูแลแก้ให้ไม่ได้ เจ้าของบัญชีแก้เองที่หน้าบัญชีของตัวเอง
- **ลบหรือเปลี่ยนชื่อ role** ทำไม่ได้ เลิกใช้ role ด้วยการล้าง scope ทั้งหมด
- **จำนวนคนในแต่ละ role** API ไม่ส่งมา หน้าจอจึงมีแค่ลิงก์ไปกรองรายชื่อ
- **โปรไฟล์สาธารณะ** (`PUT /staff/members/{id}/public-profile`) มี endpoint แล้ว แต่หน้านี้ยังไม่มีฟอร์ม ดู [ทีมของเรา](team.md)
- **พนักงานที่ผูกกับบางสาขา** แก้สาขาของคนที่มีสาขาอื่นที่ตัวเองเข้าไม่ถึง สาขานั้นแสดงเป็นรหัส และระบบอาจไม่ยอมบันทึก
