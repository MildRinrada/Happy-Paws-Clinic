# บทความ

บทความสุขภาพสัตว์ที่ทีมสัตวแพทย์เขียนให้เจ้าของสัตว์อ่าน แสดงสามเรื่องล่าสุดบนหน้าแรก มีหน้ารวมบทความทั้งหมด และหน้าอ่านแต่ละเรื่อง ทุกคนอ่านได้โดยไม่ต้องเข้าสู่ระบบ

ฟีเจอร์นี้ไม่อยู่ใน contract เป็นส่วนขยายที่เจ้าของงานขอเพิ่ม การอ่านอยู่ใน [ส่วนขยายของสัญญา § 9](../contract-extensions.md) การเขียนและเผยแพร่โดยพนักงานอยู่ใน [§ 26](../contract-extensions.md) เหตุผลและสิ่งที่ตั้งใจไม่ทำอยู่ที่นั่น

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน | อ่านรายการบทความและบทความแต่ละเรื่องที่เผยแพร่อยู่ |
| พนักงานที่ถือ `content:manage` | เขียนร่าง แก้ ใส่รูปปก เผยแพร่ นำลง และลบบทความ ที่แท็บ "บทความ" ในหน้าตั้งค่า (`/settings/articles`) |
| ผู้ดูแลเซิร์ฟเวอร์ | ใส่บทความตัวอย่างด้วยคำสั่ง `seed-articles` |

`content:manage` เป็น scope แรกที่ไม่อยู่ในรายการของ contract ได้รับอนุมัติพร้อมเส้นเขียนบทความ เจ้าของคลินิกถือผ่าน `*` และ `clinic_admin` ได้ตั้งแต่ตั้งระบบ (คลินิกที่ตั้งไว้ก่อนได้จาก migration `StaffArticles`) role อื่นต้องให้เองที่หน้าพนักงานและสิทธิ์ ดู [สิทธิ์และการให้สิทธิ์](../authorization.md)

## ข้อมูลของบทความ

| ช่อง | กติกา |
|---|---|
| `slug` | ที่อยู่ของบทความ เช่น `/articles/cat-vaccine-schedule` ใช้ได้แค่ตัวพิมพ์เล็กภาษาอังกฤษ ตัวเลข และขีดคั่นคำ ยาวไม่เกิน 80 ตัวอักษร ห้ามซ้ำกับบทความอื่น รวมบทความที่ลบแล้ว เปลี่ยนได้จนกว่าจะเผยแพร่ครั้งแรก |
| `title` | ชื่อเรื่อง ไม่เกิน 200 ตัวอักษร |
| `summary` | คำโปรยหนึ่งถึงสองประโยค ไม่เกิน 500 ตัวอักษร |
| `body` | เนื้อหาเป็นข้อความล้วน บรรทัดว่างหนึ่งบรรทัดคือขึ้นย่อหน้าใหม่ ไม่เกิน 20,000 ตัวอักษร ไม่ใช่ Markdown หรือ HTML |
| `author_name` | ชื่อผู้เขียนตามที่ผู้อ่านเห็น เช่น สพ.ญ. มินท์ เก็บเป็นชื่อ ไม่ผูกกับบัญชีพนักงาน เพราะบทความอยู่นานกว่าสัญญาจ้าง |
| `reading_minutes` | เวลาอ่านโดยประมาณ 1 ถึง 120 นาที ไม่ใส่ตอนเขียนร่าง ระบบประมาณจากความยาว 800 ตัวอักษรต่อนาที |
| `cover_image_path` | รูปปกจาก seed เป็น path ใต้ `/public` ของหน้าเว็บ ขึ้นต้นด้วย `/` ไม่รับ URL ภายนอก |
| `cover_image_key` | รูปปกที่พนักงานอัปโหลด เป็น key ในที่เก็บไฟล์ แทนที่ `cover_image_path` เมื่อไฟล์มาถึง |
| `published_at` | เวลาเผยแพร่ ว่างคือร่าง เวลาในอนาคตคือยังไม่แสดง |
| `first_published_at` | ครั้งแรกที่เผยแพร่ ตั้งแต่นั้น slug เปลี่ยนไม่ได้ และการเผยแพร่ซ้ำใช้วันที่นี้ |
| `deleted_at` | เวลาที่ถูกลบ แถวยังอยู่เพื่อจอง slug ไว้ |

ค่าที่ผิดกติกาถูก entity ปฏิเสธด้วย `invalid_article` ตั้งแต่ตอนสร้าง ส่วนเส้นของพนักงานตรวจก่อนถึง entity และตอบ `422` ที่ช่องนั้น

**ข้อความถูกทำความสะอาดก่อนเก็บ** (`ArticleText`) ตัดอักขระควบคุม (ยกเว้นการขึ้นบรรทัด) อักขระสลับทิศทาง BOM และ surrogate ที่ขาดครึ่ง เปลี่ยนการขึ้นบรรทัดทุกแบบเป็นแบบเดียว ตัดช่องว่างท้ายบรรทัด และรวมบรรทัดว่างที่ติดกันเหลือหนึ่ง ชื่อเรื่อง คำโปรย และชื่อผู้เขียนเป็นบรรทัดเดียว แท็ก HTML ไม่ถูกตัด เพราะหน้าเว็บแสดงเป็นตัวอักษรอยู่แล้ว

## Endpoint

| Method | Endpoint | ทำอะไร |
|---|---|---|
| GET | `/articles?limit=` | บทความที่เผยแพร่แล้ว เรียงใหม่สุดก่อน ไม่มีเนื้อหาเต็ม `limit` 1 ถึง 50 ไม่ส่งได้ 10 นอกช่วงตอบ `422 validation_failed` |
| GET | `/articles/{slug}` | บทความหนึ่งเรื่องพร้อมเนื้อหา |

- ร่าง บทความที่ยังไม่ถึงเวลาเผยแพร่ และบทความที่ลบแล้ว ไม่อยู่ในรายการ และเปิดตรง ๆ ได้ `404` เหมือนบทความที่ไม่มีอยู่ คนนอกจึงรู้ไม่ได้ว่ามีเรื่องอะไรรอเผยแพร่
- บทความที่มีรูปปกอัปโหลดมีช่อง `cover_image_url` เป็นลิงก์ที่ลงชื่อแล้ว อายุหนึ่งชั่วโมง สร้างใหม่ทุกครั้งที่อ่าน และสร้างเฉพาะตอนที่บทความเผยแพร่อยู่
- รายการใช้ `limit` ไม่ใช้ cursor เพราะบทความมีไม่มาก ถ้าวันหนึ่งเยอะขึ้น เพิ่ม cursor ได้โดยไม่ทำให้ผู้ใช้เดิมพัง
- บทความสองเรื่องที่เผยแพร่เวลาเดียวกัน เรียงด้วย id ซึ่งเรียงตามเวลาที่สร้างอยู่แล้ว

### เส้นของพนักงาน

ทุกเส้นต้องมี `content:manage` รายละเอียดเต็มอยู่ใน [ส่วนขยายของสัญญา § 26](../contract-extensions.md)

| Method | Endpoint | ทำอะไร |
|---|---|---|
| GET | `/staff/articles?status=&q=&limit=&cursor=` | ทุกบทความที่ยังไม่ถูกลบ รวมร่าง เขียนใหม่สุดก่อน กรองสถานะ `draft` `scheduled` `published` และค้นชื่อเรื่องหรือ slug |
| GET | `/staff/articles/{id}` | บทความเดียวพร้อมเนื้อหาและลิงก์ดูรูปปก |
| POST | `/staff/articles` | เขียนร่าง ไม่ส่ง `slug` ระบบสร้างจากชื่อเรื่องภาษาอังกฤษ ชื่อเรื่องภาษาไทยต้องตั้ง slug เอง |
| PATCH | `/staff/articles/{id}` | แก้ช่องที่ส่งมา และ `remove_cover` ต้องส่ง `If-Match` |
| POST | `/staff/articles/{id}/publish` | ขึ้นเว็บทันที เคยเผยแพร่แล้วใช้วันที่ครั้งแรก |
| POST | `/staff/articles/{id}/unpublish` | นำลงจากเว็บ กลับเป็นร่าง |
| DELETE | `/staff/articles/{id}` | ลบได้ทุกสถานะ แถวยังอยู่และ slug ยังถูกจอง กู้คืนไม่ได้ |
| POST | `/staff/articles/{id}/cover` | URL ที่ลงชื่อแล้วสำหรับส่งรูป JPEG, PNG หรือ WebP ไม่เกิน 5 MB รูปเดิมแสดงจนไฟล์ใหม่มาถึง |

| ผลที่ควรรู้ | คำตอบ |
|---|---|
| slug ซ้ำกับบทความอื่น รวมที่ลบแล้ว | `409 article_slug_taken` พร้อม `details.article_id` และ `details.deleted` |
| เปลี่ยน slug ของบทความที่เคยเผยแพร่ | `409 state_conflict` |
| ชื่อเรื่องภาษาไทยโดยไม่ตั้ง slug หรือ slug ผิดกติกา | `422` ที่ช่อง `slug` |
| `PATCH` ไม่ส่ง `If-Match` | `422` ที่ช่อง `If-Match` |
| version ไม่ตรง | `409 version_conflict` |
| เผยแพร่ซ้ำ หรือนำลงร่าง | `409 state_conflict` |
| บทความที่ลบแล้ว | `404` ทุกเส้น |

การเขียน แก้ เผยแพร่ นำลง และลบ บันทึก audit เป็น `article.created`, `article.updated`, `article.published`, `article.unpublished` และ `article.deleted` การแก้ที่ไม่เปลี่ยนอะไรไม่บันทึก และเนื้อหาบันทึกเป็นความยาว ไม่คัดลอกลง log

## ใส่บทความตัวอย่าง

```sh
dotnet run --project backend/src/HappyPaws.Api -- seed-articles
# หรือใน Docker
docker compose run --rm api seed-articles
```

คำสั่งนี้ใส่บทความสี่เรื่องจาก `SampleArticles.cs` วันที่เผยแพร่ย้อนหลังจากวันที่รัน 2, 9, 16 และ 23 วัน รายการจึงมีลำดับ

- รันซ้ำได้ เรื่องที่มี slug อยู่แล้วถูกข้าม ไม่ถูกเขียนทับ คำสั่งบอกว่าใส่เรื่องไหน และข้ามเรื่องไหน
- เรื่องตัวอย่างที่พนักงานลบไปแล้วก็ถูกข้าม เพราะแถวที่ลบยังจอง slug ไว้ จึงไม่ถูกใส่กลับ
- ถ้าคลินิกแก้บทความในฐานข้อมูลไปแล้ว การรัน seed อีกครั้งไม่ทำให้สิ่งที่แก้หายไป
- ต้องรัน `migrate` ก่อน เพราะตาราง `articles` มาจาก migration `Articles`

**แก้หรือเพิ่มบทความทำอย่างไร** ใช้แท็บ "บทความ" ในหน้าตั้งค่า (ดูด้านล่าง) บทความจาก seed ก็แก้ที่นั่นได้ แต่ slug ของบทความ seed ถูกตรึงแล้ว เพราะเผยแพร่แล้วตั้งแต่ตอนใส่

## หน้าเว็บ

| หน้า | ที่อยู่ | แสดงอะไร |
|---|---|---|
| หน้าแรก | `/` คอลัมน์ "บทความจากทีมสัตวแพทย์" | สามเรื่องล่าสุด จำนวนตั้งที่ `homeArticleCount` ใน `features/home/content/articles.ts` |
| รวมบทความ | `/articles` | ทุกเรื่อง สูงสุด 50 เรื่อง เมนู "บทความ" บน header และลิงก์ "บทความสุขภาพสัตว์" ใน footer พามาที่นี่ |
| อ่านบทความ | `/articles/{slug}` | ชื่อเรื่อง คำโปรย ผู้เขียน เวลาอ่าน วันที่เผยแพร่ รูปปก และเนื้อหา ชื่อแท็บของเบราว์เซอร์เป็นชื่อบทความ |

- หน้าเว็บเรียก API จากฝั่งเซิร์ฟเวอร์ทุกครั้งที่เปิดหน้า บทความใหม่จึงขึ้นทันทีโดยไม่ต้อง build ใหม่ และหน้าของพนักงานยังสั่ง `revalidatePath` ของ `/`, `/articles` และ `/articles/[slug]` ทุกครั้งที่เขียน แก้ เผยแพร่ นำลง ลบ หรือรูปปกมาถึง เผื่อวันที่หน้าเหล่านี้ถูก cache
- รูปปกที่พนักงานอัปโหลดแสดงจาก `cover_image_url` ด้วยแท็ก `<img>` ธรรมดา เพราะเป็นลิงก์อายุสั้นที่ `next/image` ปรับขนาดไม่ได้ ถ้ามีทั้งสองช่อง ใช้ `cover_image_url` ก่อน
- ถ้าเรียก API ไม่ได้ หน้าแรกยังเปิดได้ คอลัมน์บทความขึ้นข้อความว่ายังโหลดบทความไม่ได้ แทนที่ทั้งหน้าจะพัง ถ้าไม่มีบทความเลย ขึ้นว่ายังไม่มีบทความ
- เนื้อหาแสดงเป็นข้อความ แยกย่อหน้าที่บรรทัดว่าง ไม่แปลงเป็น HTML บทความจึงพา script หรือลิงก์เข้าหน้าเว็บไม่ได้
- รูปปกที่ยังไม่มี แสดงเป็นกรอบเส้นประ (`ImageSlot`)
- บทความที่ไม่มีอยู่แสดงหน้า 404 ของเว็บ

### หน้าของพนักงาน

| หน้า | ที่อยู่ | แสดงอะไร |
|---|---|---|
| รายการบทความ | `/settings/articles` | ทุกบทความที่ยังไม่ถูกลบ ป้ายสถานะ ร่าง ตั้งเวลาไว้ หรือเผยแพร่แล้ว ตัวกรองสถานะ ช่องค้น และปุ่ม "เขียนบทความใหม่" |
| เขียนบทความใหม่ | `/settings/articles/new` | ช่องชื่อเรื่อง slug คำโปรย ผู้เขียน เวลาอ่าน และเนื้อหา บันทึกเป็นร่างแล้วพาไปหน้าแก้ |
| แก้บทความ | `/settings/articles/{id}` | ช่องเดียวกัน (slug ปิดเมื่อเคยเผยแพร่แล้ว) ปุ่ม "ดูตัวอย่าง" ที่แสดงเนื้อหาแบบเดียวกับหน้าเว็บ กล่องการเผยแพร่ กล่องรูปปก และกล่องลบ |

- แท็บ "บทความ" ขึ้นเฉพาะบัญชีที่ถือ `content:manage` และเมนู "ตั้งค่า" ขึ้นให้บัญชีที่ถือ scope นี้อย่างเดียวด้วย
- การนำลง การเอารูปปกออก และการลบ ถามยืนยันอีกครั้งพร้อมบอกผล
- การเลือกรูปปกส่งไฟล์จากเบราว์เซอร์ตรงไปที่ URL ที่ลงชื่อแล้ว จากนั้นหน้าอ่านบทความใหม่ เพราะการที่ไฟล์มาถึงเปลี่ยน version ของบทความ ข้อความที่กำลังพิมพ์อยู่ไม่หาย
- คนที่บันทึกทับการแก้ของคนอื่นได้ข้อความให้โหลดหน้าใหม่ ไม่ใช่การบันทึกทับเงียบ ๆ

## ข้อจำกัดที่รู้อยู่

- ยังไม่มีหมวดหมู่ แท็ก การค้นหาบนหน้าสาธารณะ ประวัติฉบับแก้ หรือการตั้งเวลาเผยแพร่ผ่านหน้าจอ
- ลบแล้วกู้คืนไม่ได้ และไฟล์รูปปกเก่าไม่ถูกลบออกจากที่เก็บ (ไม่มีลิงก์ใดชี้ไปและไม่ถูกแสดง)
- ไม่ถอดเสียงชื่อเรื่องภาษาไทยเป็น slug ต้องตั้งเอง
- การเปิดอ่านบทความไม่ถูกนับสถิติ
- บทความตัวอย่างเป็นคำแนะนำทั่วไป ควรให้สัตวแพทย์ของคลินิกอ่านทวนก่อนเปิดใช้งานจริง
