# การจองและนัดหมาย

นัดหมาย (`appointments`) คือการกันเวลาของหมอหนึ่งคนที่สาขาหนึ่ง ให้สัตว์เลี้ยงหนึ่งตัว สำหรับบริการหนึ่งอย่าง ลูกค้าจองเองผ่าน portal ส่วนพนักงานจองแทนที่เคาน์เตอร์ เมื่อสัตว์มาถึงและเช็กอิน ระบบออกบัตรคิวให้ทันที ต่อจากนั้นเป็นเรื่องของ [คิว](queue.md) และ [การตรวจ](consultations-and-records.md)

ตอนนี้มีแค่ API ยังไม่มีหน้าจองหรือหน้าตารางนัดบนเว็บ ทุก path อยู่ใต้ `/v1`

## Endpoint

| Endpoint | ใครเรียก | สิทธิ์ | ทำอะไร |
|---|---|---|---|
| `GET /booking/availability?service=&date=&vet=&branch=` | ทุกคน ไม่ต้องเข้าสู่ระบบ | public | ช่วงว่างของบริการในวันหนึ่ง |
| `POST /booking/holds` | ลูกค้า | `portal` | กันช่วงเวลาไว้ 10 นาทีระหว่างกรอกฟอร์ม |
| `POST /portal/appointments` | ลูกค้า | `portal` | ยืนยันการจอง ต้องมี `Idempotency-Key` |
| `GET /portal/appointments?upcoming=` | ลูกค้า | `portal` | นัดที่จะถึง หรือประวัติย้อนหลัง |
| `POST /staff/appointments` | พนักงาน | `appointment:write` | จองแทนลูกค้า รับ walk-in ต้องมี `Idempotency-Key` |
| `GET /staff/appointments?date=&status=&vet_id=&branch=&q=` | พนักงาน | `appointment:read` | ตารางนัดของวัน แบ่งหน้าแบบ cursor |
| `PATCH /staff/appointments/{id}` | พนักงาน | `appointment:write` | เปลี่ยนหมอ บริการ หรืออาการที่แจ้ง ต้องมี `If-Match` |
| `GET /appointments/{id}` | ทั้งสองฝั่ง | ดูหัวข้อสิทธิ์ | อ่านนัดหนึ่งรายการ |
| `POST /appointments/{id}/reschedule` | ทั้งสองฝั่ง | ดูหัวข้อสิทธิ์ | เลื่อนนัด |
| `POST /appointments/{id}/cancel` | ทั้งสองฝั่ง | ดูหัวข้อสิทธิ์ | ยกเลิก บันทึกเหตุผลและผู้ยกเลิก |
| `POST /appointments/{id}/confirm` | ทั้งสองฝั่ง | ดูหัวข้อสิทธิ์ | ยืนยันว่าจะมา |
| `POST /appointments/{id}/check-in` | ทั้งสองฝั่ง | ดูหัวข้อสิทธิ์ | เช็กอินและออกบัตรคิว ต้องมี `Idempotency-Key` |

## สถานะ 8 แบบ

| ค่าที่เก็บ | ความหมาย | กันเวลาหมอ | จบแล้ว |
|---|---|---|---|
| `draft` | สงวนไว้ตาม contract ยังไม่มีทางไหนสร้างนัดในสถานะนี้ | ไม่ | ไม่ |
| `booked` | จองแล้ว ทุกการจองเริ่มที่นี่ | ใช่ | ไม่ |
| `confirmed` | ลูกค้าหรือเคาน์เตอร์ยืนยันแล้ว | ใช่ | ไม่ |
| `checked_in` | มาถึงแล้ว มีบัตรคิว | ใช่ | ไม่ |
| `in_consultation` | อยู่ในห้องตรวจ เปิดเคสแล้ว | ใช่ | ไม่ |
| `completed` | ปิดเคสแล้ว | ไม่ | ใช่ |
| `cancelled` | ยกเลิก | ไม่ | ใช่ |
| `no_show` | ไม่มาตามนัด ผ่าน `POST /staff/appointments/{id}/no-show` ดู [นัดขั้นสูง](advanced-booking.md) | ไม่ | ใช่ |

"กันเวลาหมอ" คือชุด `AppointmentTransitions.OccupyingStatuses` ชุดเดียวกันนี้ถูกใช้ทั้งในการคำนวณช่วงว่างและใน exclusion constraint ของฐานข้อมูล นัดที่ออกจากชุดนี้คืนเวลาให้ทันทีโดยไม่ต้องลบแถว

## ลำดับที่นัดเดิน

```text
  draft ──► booked ──────── ยืนยัน ────────► confirmed
              │  ▲                              │
              │  └──── เลื่อนนัด (กลับเป็น booked) ┘
              │                                 │
              └───── เช็กอิน (walk-in) ────┐     │ เช็กอิน
                                         ▼     ▼
                                        checked_in
                                            │  เปิดเคส  POST /staff/consultations
                                            ▼
                                      in_consultation
                                            │  ปิดเคส  POST /staff/consultations/{id}/close
                                            ▼
                                        completed

  ทางออก:  booked, confirmed ──► cancelled หรือ no_show
           checked_in ──► cancelled
```

ระบบบังคับลำดับนี้จริง ต่างจากระบบที่ปล่อยให้เปลี่ยนอะไรก็ได้ ทางทั้งหมดเขียนไว้ที่เดียวใน `AppointmentTransitions` การข้ามขั้นได้ `409 state_conflict` พร้อม `details.current_state` และ `details.attempted`

- `booked` ไป `checked_in` ตรง ๆ เป็นทางจริง เพราะ walk-in จองและเช็กอินที่เคาน์เตอร์ในคราวเดียว
- พอสัตว์มาถึงแล้ว (`checked_in`) จะเป็น `no_show` ไม่ได้อีก
- `completed` ไม่มีทางย้อน การแก้สิ่งที่บันทึกไปแล้วทำผ่าน amendment ของเวชระเบียน ไม่ใช่เปิดนัดใหม่
- การกดซ้ำบางอย่างไม่ถือเป็นข้อผิดพลาด ยืนยันซ้ำ ยกเลิกซ้ำ และเปิดเคสซ้ำ ได้คำตอบปกติโดยไม่มีอะไรเปลี่ยน เพราะปุ่มยืนยันอยู่ในข้อความเตือนและ LINE ซึ่งคนกดสองครั้งเป็นเรื่องธรรมดา

## ใครเปลี่ยนสถานะได้

5 เส้นที่ขึ้นต้นด้วย `/appointments/{id}` ใช้ path เดียวกันทั้งพนักงานและลูกค้า จึงไม่ติด `[RequireScope]` ที่ controller แต่ตัดสินใน `AppointmentAccess`

- พนักงานผ่านเมื่อถือ scope ของเส้นนั้น และนัดอยู่ในสาขาที่ตัวเองเข้าถึงได้
- ลูกค้าผ่านเมื่อดูแลสัตว์ตัวนั้น ตรวจจากสัตว์ ไม่ใช่จาก `customer_id` ของนัด ผู้ดูแลร่วมจึงเห็นนัดที่อีกคนจองไว้
- คนอื่นได้ `404` ไม่ใช่ `403` เพื่อไม่ให้ใช้ endpoint นี้ไล่หาว่ารหัสนัดไหนมีจริง

| การเปลี่ยน | ทางเข้า | พนักงาน | ลูกค้า |
|---|---|---|---|
| ยืนยัน | `POST /appointments/{id}/confirm` | `appointment:write` | เจ้าของสัตว์ |
| เช็กอิน | `POST /appointments/{id}/check-in` | `appointment:checkin` | เจ้าของสัตว์ (เช็กอินเอง) |
| ยกเลิก | `POST /appointments/{id}/cancel` | `appointment:write` | เจ้าของสัตว์ ไม่มี cutoff |
| เลื่อนนัด | `POST /appointments/{id}/reschedule` | `appointment:write` ข้าม cutoff และ lead time ได้ | เจ้าของสัตว์ ก่อนถึง cutoff เท่านั้น |
| เข้าห้องตรวจ | เปิดเคส `POST /staff/consultations` | `consult:write` | ไม่ได้ |
| เสร็จสิ้น | ปิดเคส `POST /staff/consultations/{id}/close` | `record:sign` | ไม่ได้ |
| ยกเลิกอัตโนมัติ | บันทึกสัตว์เสียชีวิต | ระบบยกเลิกนัดในอนาคตทั้งหมด เหตุผล `สัตว์เลี้ยงเสียชีวิต` ดู [ลูกค้าและสัตว์เลี้ยง](customers-and-pets.md) | |

role ตั้งต้นที่ได้ `appointment:*` คือ `receptionist` และเจ้าของกับผู้ดูแลคลินิก ดู [พนักงานและสิทธิ์](staff-and-roles.md)

## สิ่งที่เกิดตามมา

- **เช็กอิน** เปลี่ยนนัดเป็น `checked_in` และออกบัตรคิวใน transaction เดียว ถ้าอย่างหนึ่งล้มอีกอย่างก็ไม่เกิด บัตรได้หมอคนเดียวกับนัด เลขคิวมาจากการตั้งค่าคิว ดู [คิว](queue.md) เช็กอินซ้ำได้บัตรใบเดิมคืน ไม่ออกเลขใหม่ หลัง commit ระบบส่ง `ticket.updated` ไปที่กระดานคิว
- **ยกเลิก** บันทึก `cancelled_at`, ผู้ยกเลิก (`cancelled_by_user_id`) และเหตุผล เวลาหมอว่างทันทีเพราะสถานะไม่อยู่ในชุดที่กันเวลาแล้ว ไม่มีขั้น "คืน slot" แยกที่อาจล้มเหลว แถวไม่ถูกลบ
- **เลื่อนนัด** ตรวจช่วงเวลาใหม่ทั้งหมดอีกรอบ โดยไม่นับเวลาของนัดตัวเอง (เลื่อน 10 นาทีจึงไม่ชนกับตัวเอง) แล้วตั้งสถานะกลับเป็น `booked` และล้าง `confirmed_at` เพราะลูกค้ายืนยันเวลาเดิม ไม่ใช่เวลาใหม่
- **แก้นัด** (`PATCH`) ถ้าเปลี่ยนบริการ เวลาสิ้นสุดเลื่อนตามระยะเวลาของบริการใหม่ และตรวจว่าไม่ทับคิวถัดไป `reason` ที่ไม่ส่งมาคือไม่แตะ ส่งสตริงว่างคือล้าง
- **ไม่มีการแจ้งเตือน** จากการจอง ยืนยัน เลื่อน หรือยกเลิก ระบบเตือนนัดยังไม่ได้ทำ

## การหาช่วงว่าง

ช่วงว่างมาจาก **ตารางเวร** (`staff_shifts`) ไม่ใช่เวลาทำการ สาขาที่เปิดแต่ไม่มีหมอเข้าเวรจึงไม่มีช่วงว่าง เวลาทำการเป็นสิ่งที่คลินิกบอกลูกค้า ส่วนวันหยุดของสาขาปิดการจองทั้งวัน ดู [ตั้งค่าคลินิก](clinic-setup.md)

```text
 เวรของหมอที่ให้บริการนี้ได้
   แบ่งเป็นช่องตาม slot_minutes เริ่มนับจากต้นเวร
   ตัดช่องที่ทับนัดที่ยังกันเวลา
   ตัดช่องที่ทับ hold ที่ยังไม่หมดอายุ
   ตัดช่องก่อน lead time และเกินจำนวนวันที่จองล่วงหน้าได้
   ตัดช่องนอกช่วงเวลาจองออนไลน์ของบริการ
 = ช่วงว่าง
```

| ค่า | ค่าเริ่มต้น | ตั้งที่ |
|---|---|---|
| ขนาดช่อง `slot_minutes` | 30 นาที | การตั้งค่าการจอง |
| lead time | 120 นาที | การตั้งค่าการจอง |
| จองล่วงหน้าได้ไม่เกิน | 60 วัน | การตั้งค่าการจอง |
| cutoff การเปลี่ยนนัดของลูกค้า | 12 ชั่วโมงก่อนนัด | การตั้งค่าการจอง |
| ระยะเวลาของนัด | ตามบริการ | [บริการ](services.md) |

- ช่องเริ่มนับจากต้นเวร ไม่ใช่เที่ยงคืน หมอที่เข้าเวร 09:10 จึงได้ช่อง 09:10, 09:40, 10:10
- การทับกันนับแบบครึ่งเปิด นัดที่จบ 10:30 ไม่ชนกับนัดที่เริ่ม 10:30
- คำตอบจำกัดอยู่ในวันที่ถาม เวรที่ลากข้ามเที่ยงคืนไม่ทำให้วันจันทร์มีช่องของเช้าวันอังคาร `date` คือวันตามเวลาของคลินิก
- บริการที่ไม่มีอยู่ ปิดจองออนไลน์ หรือไม่เปิดที่สาขานั้น ได้ `404` เหมือนกันหมด feed สาธารณะจึงใช้ไล่หาบริการภายในไม่ได้
- คลินิกสาขาเดียวไม่ต้องส่ง `branch` หลายสาขาต้องส่ง

**ก่อนจองได้ต้องมีเวร** ระบบที่ติดตั้งใหม่ยังไม่มีเวรของใคร ทุกการจองจึงได้ `slot_unavailable` จนกว่าจะสร้างเวรด้วย `POST /staff/schedules/shifts` เวลาพักและวันลาเป็นช่องว่างในเวรอยู่แล้ว จึงไม่ต้องหักแยกในขั้นตอนข้างบน ดู [ตารางเวร](schedules.md)

**เมื่อไม่ได้ระบุหมอ** ระบบเลือกหมอที่เข้าเวร ให้บริการนี้ได้ และว่างตลอดช่วงนั้น ถ้าคลินิกตั้งกติกาจ่ายเคสไว้ (เช่น หมอแมวรับเคสแมวก่อน) คนที่กติกาแรกที่ตรงระบุไว้ได้ก่อน ถ้าไม่ว่างก็ไปคนถัดไปตามลำดับปกติ กติกาไม่เคยทำให้ช่วงที่ว่างอยู่จองไม่ได้ การจองจากเคาน์เตอร์และจากลูกค้ารู้ชนิดสัตว์จึงใช้กติกาตามชนิดสัตว์ได้ ส่วนการถือ slot ตอนกรอกฟอร์มยังไม่รู้ว่าเป็นสัตว์ตัวไหน จึงใช้ได้เฉพาะกติกาตามบริการ

## hold

`POST /booking/holds` กันช่วงเวลาไว้ 10 นาทีระหว่างที่ลูกค้ากรอกฟอร์ม ช่วงนั้นหายจาก availability ของคนอื่น

- ตรวจช่วงว่างและบันทึก hold ใน transaction เดียว
- หมดอายุด้วยเวลา `expires_at` ไม่มีงานเบื้องหลังมากวาด hold ที่เลยเวลาไม่กันอะไรอีก แม้แถวยังอยู่
- hold เป็นของลูกค้าที่สร้าง และใช้ได้ครั้งเดียว ใช้ของคนอื่นได้ `409 hold_not_yours` ใช้ของที่หมดอายุหรือใช้ไปแล้วได้ `409 hold_expired`
- ไม่มี endpoint ปล่อย hold คืนก่อนเวลา ฟอร์มที่ถูกทิ้งกันเวลาหมอไว้จนครบ 10 นาที
- จองโดยไม่มี hold ได้ เพราะช่องทางอื่น เช่นเคาน์เตอร์ ไม่ผ่านฟอร์มบนเว็บ
- hold ไม่มี constraint ระดับฐานข้อมูลแบบนัด ถ้า hold สองอันชนกันจริง ตัวกันชั้นสุดท้ายคือ exclusion constraint ตอนจอง

## การจอง

ลูกค้า (`POST /portal/appointments`) และพนักงาน (`POST /staff/appointments`) ใช้ตัวตรวจช่วงเวลาตัวเดียวกัน (`BookingSlotResolver`) ต่างกันแค่สามเรื่อง

| | ลูกค้า | พนักงาน |
|---|---|---|
| lead time | ต้องเคารพ | ข้ามได้ จองย้อนหลังได้ไม่เกิน 1 ชั่วโมง (ตามเก็บ walk-in ที่เริ่มไปแล้ว) |
| บริการที่ปิดจองออนไลน์ | จองไม่ได้ | จองได้ |
| ความเป็นเจ้าของ | ต้องดูแลสัตว์ตัวนั้น | ไม่ตรวจ ลูกค้าบนนัดคือเจ้าของหลักของสัตว์ และต้องอยู่ในสาขาที่ตัวเองเข้าถึงได้ |

กติกาที่ใช้กับทั้งสองฝั่ง

- สัตว์ที่บันทึกว่าเสียชีวิตแล้วจองไม่ได้
- บริการต้องเปิดอยู่ และเปิดที่สาขานั้น
- ช่วงเวลาต้องอยู่ในเวรของหมอทั้งช่วง และไม่ทับนัดหรือ hold อื่น
- ไม่ระบุหมอ ระบบเลือกหมอที่ให้บริการนี้ได้และว่างคนแรก เรียงตามรหัส การขอซ้ำจึงได้หมอคนเดิม
- เวลาที่ส่งมาไม่จำเป็นต้องตรงกับช่องในตาราง (เช่น walk-in ตอน 14:07) ดู [จุดที่ contract กำกวม](../assumptions.md)
- พนักงานติด `walk_in` ได้ และระบบบันทึก `booked_by_staff_id`

ช่วงเวลาที่ใช้ไม่ได้ได้ `422 slot_unavailable` พร้อม `details.suggested` เป็นเวลาว่างถัดไปไม่เกิน 3 ช่องของวันเดียวกัน รูปแบบ `HH:mm` ตามเวลาคลินิก สาเหตุที่เป็นไปได้คือ มีนัดอยู่แล้ว อยู่นอกเวร อยู่นอกช่วงที่จองได้ ตรงกับวันหยุด หรืออยู่นอกช่วงจองออนไลน์ของบริการ

### กันการจองซ้อน

ตัวจองตรวจช่วงเวลาซ้ำใน transaction ก่อนเขียน แต่ใต้ `READ COMMITTED` การจองสองรายการพร้อมกันยังเห็นปฏิทินว่างทั้งคู่ได้ ฐานข้อมูลจึงมี exclusion constraint `ex_appointments_staff_slot` บน `(branch_id, staff_id, tstzrange(starts_at, ends_at))` เฉพาะนัดที่กันเวลา คำขอที่แพ้ถูกแปลงกลับเป็น `slot_unavailable` โดย `PostgresErrorTranslator` และไม่มีเวลาแนะนำ เพราะปฏิทินเพิ่งเปลี่ยนไป ดู [ฐานข้อมูล](../database.md)

## เลื่อน ยกเลิก ยืนยัน

- **cutoff** ลูกค้าเลื่อนนัดไม่ได้เมื่อเหลือเวลาถึงนัดน้อยกว่า `cancellation_cutoff_hours` ได้ `409 cutoff_passed` พร้อม `details.cutoff_hours` และ `details.cutoff_at` ไม่ใช่ `403` เพราะสิทธิ์ไม่ได้ผิด แค่ต้องโทรหาคลินิก พนักงานไม่ติด cutoff
- **ยกเลิกไม่มี cutoff** contract พูดถึง cutoff เฉพาะการเลื่อน และการรู้ว่าลูกค้าไม่มาเร็วดีกว่าไม่รู้ ดู [จุดที่ contract กำกวม](../assumptions.md) แต่ลูกค้าที่ยกเลิกเองกระชั้นกว่า cutoff ของนโยบายยกเลิก ได้ `late_cancellation: true` และถูกนับเหมือนไม่มาตามนัด ดู [นัดขั้นสูง](advanced-booking.md#นโยบายยกเลิก)
- **ยกเลิกแล้วแจ้งคิวรอ** เวลาที่ว่างลงถูกแจ้งไปยังคนที่รอบริการนั้นอยู่ หลังการยกเลิก commit แล้ว
- **ประเภทนัด** ทุกการจองส่ง `type` ได้ ไม่ส่งคือ `regular` ประเภทกำหนดระยะเวลา ว่าลูกค้าจองออนไลน์ได้ไหม และความเร่งด่วนของคิวตอนเช็กอิน การเลื่อนนัดคงความยาวเดิมของนัดไว้
- **ลูกค้าเลื่อนนัด** ต้องเคารพ lead time และช่วงจองออนไลน์ด้วย พนักงานไม่ต้อง
- **เลื่อนและแก้ได้เฉพาะนัดที่ยังกันเวลาและยังไม่เข้าห้องตรวจ** คือ `booked`, `confirmed`, `checked_in` นอกนั้นได้ `409 state_conflict`
- **`If-Match`** `PATCH /staff/appointments/{id}` บังคับส่ง ไม่ส่งได้ `422 validation_failed` เพราะพนักงานสองคนเปิดนัดเดียวกันเป็นเรื่องปกติ ส่วนการเลื่อนนัดตรวจเมื่อส่งมาเท่านั้น version ไม่ตรงได้ `409 version_conflict` ทุกคำตอบมี `ETag` ดู [การป้องกันคำขอ](../security/request-protection.md)

## สิ่งที่ไม่ใช่สถานะ

| เรื่อง | คืออะไร |
|---|---|
| ยืนยันแล้วหรือยัง | `confirmed_at` เช็กอินโดยไม่เคยยืนยันจะได้ค่านี้ด้วย เลื่อนนัดแล้วถูกล้าง |
| walk-in | `walk_in` ติดตอนจอง ไม่เปลี่ยนกติกาใด ๆ หลังจากนั้น |
| ผู้จอง | `booked_by_staff_id` ว่างเมื่อลูกค้าจองเอง |
| hold ที่ใช้ | `source_hold_id` เก็บไว้ตามรอยถ้ามีข้อโต้แย้งเรื่องจองซ้อน |
| อาการที่แจ้ง | `reason` ส่งต่อเป็น `chief_complaint` ตอนเปิดเคส |

## ข้อสังเกตจากโค้ด

- ยกเลิกนัดที่เช็กอินแล้ว บัตรคิวไม่ถูกเอาออกจากกระดาน เคาน์เตอร์ต้องกดออกจากคิวเอง
- เลื่อนนัดที่ `checked_in` ทำได้ และสถานะกลับเป็น `booked` ขณะที่บัตรคิวยังอยู่บนกระดาน
- เช็กอินไม่ตรวจว่านัดเป็นของวันนี้ บัตรคิวที่ได้เป็นของวันที่เช็กอิน
- `GET /portal/appointments` กรองด้วย `customer_id` ของนัด ส่วน `GET /appointments/{id}` ตรวจจากการดูแลสัตว์ ผู้ดูแลร่วมจึงเปิดนัดที่อีกคนจองได้ แต่ไม่เห็นในรายการของตัวเอง

## ยังไม่ได้ทำ

การเตือนนัด และหน้าจองกับหน้าตารางนัดบนเว็บ ส่วนไม่มาตามนัด นัดต่อเนื่อง คิวรอ ตรวจนัดชน ประเภทนัด และนโยบายยกเลิก ทำแล้วใน [นัดขั้นสูง](advanced-booking.md) ตารางเวรอยู่ใน [ตารางเวร](schedules.md)
