# ชวนเพื่อน

ลูกค้าเดิมส่งลิงก์ของตัวเองให้เพื่อน เพื่อนที่เป็นลูกค้าใหม่จองนัดผ่านลิงก์นั้นได้เลยโดยไม่ต้องสมัครก่อน เมื่อเพื่อนมาใช้บริการและชำระบิลแรกครบ ทั้งสองคนได้แต้มสะสม ค่าตั้งต้นคือคนชวนได้ 100 แต้ม เพื่อนได้ 100 แต้ม และคนชวนได้แต้มจากเพื่อนไม่เกิน 5 คนต่อเดือน

ฟีเจอร์นี้ไม่อยู่ใน contract เจ้าของงานขอเพิ่มและอนุมัติแล้ว รายละเอียดของ API อยู่ใน [ส่วนขยาย contract § 39](../contract-extensions.md)

## ใครใช้ ใช้ทำอะไร

| ใคร | ทำอะไรได้ |
|---|---|
| ลูกค้าที่มีบัญชีออนไลน์ | เปิด "ชวนเพื่อน" (`/portal/referral`) คัดลอกลิงก์ แชร์ทาง LINE และดูจำนวนเพื่อนที่จองผ่านลิงก์ |
| เพื่อนที่ได้ลิงก์ | กดลิงก์ `/r/{รหัส}` แล้วจองที่ `/book` ตามปกติ เห็นบรรทัด "มีคนชวนมา" |
| พนักงานที่ถือ `crm:read` | ดูว่าใครชวนใคร สถานะ และแต้มที่ให้ไป ที่แท็บ "ชวนเพื่อน" (`/crm/referrals`) |
| พนักงานที่ถือ `settings:write` | เปิดปิดการชวนเพื่อน ตั้งแต้มของแต่ละฝั่ง และเพดานต่อเดือน ที่ `/settings/loyalty` |

## เริ่มใช้

การชวนเพื่อนปิดอยู่เป็นค่าตั้งต้น เพราะแต้มคือส่วนลดในบิลถัดไป คลินิกที่อัปเดตระบบไม่ควรเริ่มแจกแต้มโดยไม่ได้ตัดสินใจ

1. เปิด "ตั้งค่า" แล้วแท็บ "แต้มสะสม"
2. ในส่วน "ชวนเพื่อน" ติ๊ก "เปิดใช้การชวนเพื่อน" ดูแต้มของคนชวน แต้มของเพื่อน และเพดานต่อเดือน
3. กดบันทึกกติกาแต้ม

ระหว่างที่ปิด ลิงก์ของลูกค้ายังพาไปหน้าจองได้ แต่ไม่บันทึกการชวนและไม่มีใครได้แต้ม หน้า portal บอกลูกค้าว่ายังไม่เปิดให้ได้แต้ม

## รหัสและลิงก์

- ลูกค้าแต่ละคนมีรหัสเดียว ยาว 8 ตัว เช่น `7KX4PM2Q` ไม่มีตัวที่อ่านสลับกันง่าย คือ 0, O, 1, I และ L
- รหัสถูกสร้างครั้งแรกที่ลูกค้าเปิดหน้า "ชวนเพื่อน" และไม่เปลี่ยนอีก
- ลิงก์คือที่อยู่ของเว็บตามด้วย `/r/` และรหัส ตั้งส่วนต้นได้ที่ `Referrals:LinkTemplate` ต้องเป็นโดเมนจริงตอนติดตั้ง
- พิมพ์รหัสด้วยตัวเล็ก หรือมีช่องว่างและขีดก็ใช้ได้

## เพื่อนต้องเป็นลูกค้าใหม่

การชวนบันทึกตอนเพื่อนยืนยันเบอร์ในขั้นสุดท้ายของ `/book` (หรือตอนสมัครด้วย `POST /auth/register` ที่ส่งรหัสมา)

| กรณี | ผล |
|---|---|
| รหัสใช้ไม่ได้ หรือปิดการชวนอยู่ | ไม่บันทึกอะไร จองต่อได้ตามปกติ |
| ใช้รหัสของตัวเอง | บันทึกว่าไม่ได้แต้ม "ใช้ลิงก์ของตัวเอง" |
| เบอร์นี้มีบัญชีอยู่แล้ว หรือเคาน์เตอร์มีเรกคอร์ดของเบอร์นี้อยู่ก่อน | บันทึกว่าไม่ได้แต้ม "เป็นลูกค้าเดิมอยู่แล้ว" |
| เบอร์โทรหรืออีเมลเดียวกับคนชวน | บันทึกว่าไม่ได้แต้ม "ใช้เบอร์โทรหรืออีเมลเดียวกับคนชวน" |
| เคยถูกชวนมาแล้ว | ไม่บันทึกซ้ำ ลูกค้าหนึ่งคนถูกชวนได้ครั้งเดียว |
| ลูกค้าใหม่ | บันทึกเป็น "รอบิลแรก" |

ลูกค้าใหม่คือคนที่เรกคอร์ดลูกค้าถูกสร้างตอนจองหรือสมัครครั้งนี้ จึงยังไม่มีการตรวจ นัด หรือบิลมาก่อน การชวนที่ไม่ได้แต้มยังบันทึกไว้ให้คลินิกเห็นว่ามีคนลองใช้รหัส

## ได้แต้มเมื่อไร

- เมื่อบิลแรกของเพื่อนชำระครบและมีเงินที่จ่ายจริง บิลของการตรวจหรือบิลที่เคาน์เตอร์ก็ได้
- ทั้งสองคนได้แต้มในสมุดแต้มเดิม ชนิด "แต้มชวนเพื่อน" วันหมดอายุตามอายุแต้มของคลินิกตอนนั้น
- แต้มชวนเพื่อนเพิ่มแต้มคงเหลือ ไม่เพิ่มแต้มตลอดชีพ ระดับสมาชิกจึงยังมาจากเงินที่ลูกค้าจ่ายจริง เหมือนการปรับแต้มด้วยมือ
- ให้ครั้งเดียวต่อการชวน บิลถัดไปของเพื่อนไม่ได้แต้มชวนเพื่อนอีก บิลสองใบที่ชำระพร้อมกันก็ได้ครั้งเดียว
- แถวแต้มชวนเพื่อนไม่มีเลขบิล ประวัติแต้มของคนชวนจึงไม่เห็นบิลของเพื่อน
- บันทึกลง audit log เป็น `referral.rewarded`

## เพดานต่อเดือน

คนชวนได้แต้มจากเพื่อนไม่เกินเพดาน (ค่าตั้งต้น 5 คน) ต่อเดือนปฏิทินตามเวลาคลินิก เพื่อนคนที่ 6 ของเดือนยังได้แต้มของตัวเองเต็ม และการชวนยังนับว่าได้แต้มแล้ว แต่คนชวนได้ 0 แต้ม หน้า CRM แสดงว่า "คนชวนครบเพดานของเดือนแล้ว" เดือนใหม่เริ่มนับใหม่

## กรณีอื่น

- **ปิดการชวนระหว่างทาง** การชวนที่รอบิลแรกอยู่ แล้วบิลแรกชำระตอนที่ปิดอยู่ ถูกปิดว่าไม่ได้แต้ม "ปิดการชวนเพื่อนอยู่ตอนบิลแรกชำระ" เปิดทีหลังก็ไม่ได้แต้มย้อนหลัง
- **คืนเงิน** ไม่หักแต้มชวนเพื่อนคืน การหักแต้มคืนของระบบตามเงินบนบิล ซึ่งใช้กับแต้มที่ได้จากบิล แต้มชวนเพื่อนไม่ได้มาจากยอดเงิน ถ้าจำเป็นต้องหัก ใช้การปรับแต้มด้วยมือพร้อมเหตุผล บิลที่ชำระครบแล้วยกเลิกไม่ได้อยู่แล้ว
- **เปลี่ยนค่า** แต้มและเพดานใหม่ใช้กับบิลที่ชำระหลังบันทึก การชวนที่ได้แต้มไปแล้วเก็บแต้มของตัวเองไว้

## ความเป็นส่วนตัว

- เพื่อนรู้แค่ว่ามีคนชวนมา หน้าเว็บและ API ไม่บอกชื่อคนชวน
- การตรวจรหัสสาธารณะ (`GET /referrals/{code}`) ตอบแค่ว่าใช้ได้หรือไม่ ไม่บอกว่ารหัสเป็นของใคร จำกัด 30 ครั้งต่อนาทีต่อที่อยู่ IP
- คนชวนเห็นแค่จำนวนใน portal ไม่เห็นชื่อหรือข้อมูลของเพื่อน
- ชื่อทั้งสองฝั่งอยู่ในหน้า CRM ซึ่งต้องมี `crm:read`

## หน้าเว็บ

| หน้า | มีอะไร |
|---|---|
| `/r/{รหัส}` | ไม่มีหน้าของตัวเอง ตรวจรหัสแล้วพาไป `/book?ref=รหัส` ถ้าใช้ได้ หรือ `/book` ถ้าใช้ไม่ได้ ไม่มีหน้า error ไม่ถูกเก็บโดย search engine |
| `/book` | ตรวจ `ref` อีกครั้ง แสดงบรรทัด "มีคนชวนมา" เหนือฟอร์มเมื่อรหัสใช้ได้ และส่งรหัสไปตอนยืนยันเบอร์ รหัสที่ใช้ไม่ได้ถูกข้ามเงียบ ๆ |
| `/portal/referral` | ลิงก์ ปุ่มคัดลอก ปุ่มแชร์ทาง LINE กติกาพร้อมแต้มปัจจุบัน และจำนวนเพื่อนที่จองผ่านลิงก์ รอบิลแรก ได้แต้มแล้ว แต้มที่ได้ และเดือนนี้เทียบกับเพดาน อยู่ในเมนูบัญชีของ portal |
| `/crm/referrals` | รายการการชวน ใหม่สุดก่อน ทีละ 25 แถว แต่ละแถวมีสถานะ คนชวน เพื่อน วันที่ แต้มของแต่ละฝั่ง เหตุผลที่ไม่ได้แต้ม และลิงก์บิลแรก ค้นลูกค้าเพื่อดูเฉพาะคนเดียวได้ |
| `/settings/loyalty` | ส่วน "ชวนเพื่อน" ในฟอร์มกติกาแต้มสะสมเดิม |

ปุ่มแชร์ทาง LINE เปิด `https://line.me/R/share?text=` พร้อมข้อความสั้นและลิงก์ ทุกหน้าใช้ได้บนจอกว้าง 390px โดยไม่ต้องเลื่อนหน้าไปด้านข้าง

## Endpoint

| Method | Endpoint | Scope | ทำอะไร |
|---|---|---|---|
| GET | `/portal/referral` | `portal` | รหัส ลิงก์ และจำนวนของลูกค้าเอง |
| GET | `/referrals/{code}` | สาธารณะ | `{ "valid": true }` หรือ `false` |
| GET | `/staff/referrals?customer=&cursor=` | `crm:read` | ใครชวนใคร |
| POST | `/booking/guest/verify` ช่อง `referral_code` | สาธารณะ | รหัสจากลิงก์ ไม่บังคับ |
| POST | `/auth/register` ช่อง `referral_code` | สาธารณะ | รหัสจากลิงก์ ไม่บังคับ |
| GET, PUT | `/clinic/settings/loyalty` ช่อง `referral_*` | `settings:read`, `settings:write` | ค่าชวนเพื่อนสี่ค่า ไม่ส่งใน `PUT` คือคงค่าเดิม |

## ตาราง

`referral_codes` หนึ่งแถวต่อลูกค้า และ `referrals` หนึ่งแถวต่อเพื่อน แต้มอยู่ใน `loyalty_entries` เดิม ชนิด `Referral` ค่าตั้งอยู่ใน `loyalty_settings` เดิม migration `ReferAFriend` ดู [ฐานข้อมูล](../database.md#migration)

## ข้อจำกัด

- ไม่มีช่องกรอกรหัสที่เคาน์เตอร์ตอนพนักงานสร้างลูกค้า การชวนนับเฉพาะเพื่อนที่จองหรือสมัครเองผ่านลิงก์
- หน้าสมัคร `/register` ยังไม่ส่งรหัส ลิงก์ชวนเพื่อนพาไปหน้าจองแทน
- ไม่มีการเปลี่ยนรหัส และไม่มีการแก้หรือยกเลิกการชวนด้วยมือ
- ไม่แจ้งคนชวนเมื่อเพื่อนได้แต้ม
- จนกว่า API จะอ่านที่อยู่ IP จริงผ่าน proxy ได้ เพดานการตรวจรหัสเป็นถังเดียวของทุกคนที่มาผ่านหน้าเว็บ ถ้าเต็ม ลิงก์ยังพาไปหน้าจองได้ แต่ไม่มีบรรทัด "มีคนชวนมา" และไม่บันทึกการชวน
