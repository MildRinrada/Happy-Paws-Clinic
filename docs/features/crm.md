# แพ็กเกจ คูปอง และแต้มสะสม

โมดูลนี้ดูแลสี่เรื่องที่ทำให้ลูกค้ากลับมาที่คลินิก คือ แพ็กเกจที่ซื้อล่วงหน้า คูปองส่วนลด แต้มสะสมกับระดับสมาชิก และกลุ่มลูกค้าสำหรับส่งประกาศ ผู้ใช้หลักคือเจ้าของคลินิกหรือผู้ดูแลที่วางโปรโมชัน และแคชเชียร์ที่ใช้คูปองและแต้มตอนเก็บเงิน

ทุกเรื่องผูกกับบิล แพ็กเกจขายบนบิลและถูกตัดสิทธิ์ตอนออกบิล คูปองและแต้มเป็นส่วนลดบนบิล แต้มได้มาจากเงินที่จ่ายบนบิล การยกเลิกบิลและการคืนเงินจึงย้อนผลของเรื่องเหล่านี้ด้วย ดู [การเงิน](billing.md)

## endpoint

| Endpoint | scope | ใช้ทำอะไร |
|---|---|---|
| `POST /staff/packages` | `crm:manage` | ขายแพ็กเกจให้ลูกค้า ออกบิลในจังหวะเดียวกัน ต้องส่ง `Idempotency-Key` |
| `POST /staff/coupons` | `crm:manage` | สร้างโค้ดส่วนลด |
| `POST /staff/segments` | `crm:manage` | บันทึกกลุ่มลูกค้าจากเงื่อนไข และนับจำนวนคนในกลุ่ม |
| `GET /staff/loyalty/{customer_id}` | `crm:read` | แต้ม ระดับสมาชิก ประวัติแต้ม ประวัติคูปอง และแพ็กเกจของลูกค้า |
| `GET /portal/packages` | portal | ลูกค้าดูแพ็กเกจของตัวเอง ดู [portal ลูกค้า](portal.md) |

เส้นเดิมที่รับช่องใหม่

| Endpoint | ช่องใหม่ | ใช้ทำอะไร |
|---|---|---|
| `POST /staff/invoices/{id}/discounts` | `coupon_code` หรือ `points` | ใช้คูปองหรือแลกแต้มเป็นส่วนลดบนบิล |
| `POST /staff/integrations/line/broadcast` | `segment_id` | ส่งประกาศ LINE ถึงกลุ่มลูกค้าที่บันทึกไว้ |
| `POST /staff/invoices` | `source_id` ของรายการชนิด `service` | รหัสบริการในแคตตาล็อก ทำให้แพ็กเกจครอบรายการนั้นได้ (ช่องนี้มีอยู่เดิม) |

contract บรรยายแต่ละเส้นไว้บรรทัดเดียว การตีความทั้งหมดอยู่ใน [assumptions.md § 43](../assumptions.md)

## แพ็กเกจ

```json
{ "customer_id": "cus_...", "pet_id": "pet_...", "name": "ตรวจสุขภาพ 4 ครั้ง",
  "service_ids": ["svc_..."], "total_uses": 4, "price_satang": 180000,
  "expires_on": "2027-10-09", "branch_id": "brn_..." }
```

คำตอบ `201` มีทั้งแพ็กเกจ (`package`) และบิลที่ออก (`invoice`)

**ขายบนบิล ใช้ได้เมื่อจ่ายครบ**

- การขายสร้างแพ็กเกจและออกบิลหนึ่งรายการในจังหวะเดียวกัน รายการเป็นชนิด `other` ชื่อ "แพ็กเกจ ชื่อ (N ครั้ง)" และ `source_id` เป็นรหัสแพ็กเกจ
- แพ็กเกจเป็น `pending_payment` จนบิลนั้นชำระครบ แล้วจึงเป็น `active` แพ็กเกจที่ใช้ได้ก่อนจ่ายเงินคือเครดิตที่คลินิกไม่ได้ตั้งใจให้
- แพ็กเกจราคา 0 ได้บิล 0 บาท ซึ่งเป็น `paid` ทันที แพ็กเกจจึงใช้ได้ทันที
- ต้องส่ง `Idempotency-Key` เพราะเป็นการสร้างเงิน ส่งซ้ำด้วย key เดิมได้ผลเดิม ไม่ขายซ้ำ
- `pet_id` ไม่บังคับ ถ้าระบุต้องเป็นสัตว์ที่ลูกค้าดูแลอยู่ และแพ็กเกจครอบเฉพาะบิลของสัตว์ตัวนั้น ถ้าไม่ระบุครอบทุกตัว
- `expires_on` ไม่บังคับ เป็นวันสุดท้ายที่ใช้ได้ (นับวันของคลินิก) ต้องไม่ก่อนวันนี้ ไม่ระบุคือไม่หมดอายุ
- `service_ids` 1 ถึง 20 บริการ ต้องมีในแคตตาล็อก จำนวนครั้ง 1 ถึง 1,000

**ตัดสิทธิ์อัตโนมัติตอนออกบิล**

- เมื่อบิลมีบริการในแคตตาล็อกที่แพ็กเกจของลูกค้าครอบ ระบบตัดสิทธิ์เอง ไม่มีปุ่มให้กด ใช้ได้กับบิลสองแบบ คือบิลที่ออกตอนปิดเคส (หัตถการที่ผูกกับบริการ) และบิลที่สร้างเองที่รายการชนิด `service` มี `source_id` เป็นรหัสบริการ
- ส่วนที่แพ็กเกจครอบลงบิลเป็นรายการราคา 0 ชื่อ "ชื่อบริการ (ใช้สิทธิ์แพ็กเกจ ชื่อแพ็กเกจ)" ส่วนที่เกินสิทธิ์ที่เหลือลงเป็นอีกรายการราคาเต็ม เช่น ทำ 3 ครั้งแต่เหลือสิทธิ์ 1 ได้รายการ 1 ครั้งราคา 0 และ 2 ครั้งราคาเต็ม
- ถ้ามีหลายแพ็กเกจที่ครอบ ใช้แพ็กเกจที่หมดอายุก่อนก่อน แพ็กเกจที่ไม่มีวันหมดอายุใช้ทีหลัง
- บริการที่ราคา 0 อยู่แล้วไม่ตัดสิทธิ์
- บิลที่ทุกรายการถูกแพ็กเกจครอบมียอด 0 และเป็น `paid` ทันที เหมือนบิล 0 บาทอื่น ส่วน `charges_satang` ในคำตอบของการปิดเคสยังเป็นมูลค่าหัตถการก่อนหักแพ็กเกจ
- แต่ละครั้งที่ตัดสิทธิ์เป็นหนึ่งแถวใน `package_uses` ผูกกับบิลและรายการ และเขียน audit `package.used`

**ยกเลิกและคืนเงิน**

| เหตุการณ์ | ผลต่อแพ็กเกจ |
|---|---|
| ยกเลิกบิลที่ใช้สิทธิ์ไป | สิทธิ์กลับเข้าแพ็กเกจ แถวการใช้ถูกปิดด้วย `released_at` |
| ยกเลิกบิลขายแพ็กเกจ (ยังไม่รับเงิน) | แพ็กเกจเป็น `cancelled` |
| คืนเงินบิลขายแพ็กเกจ ไม่ว่าบางส่วนหรือทั้งใบ | แพ็กเกจเป็น `cancelled` สิทธิ์ที่ใช้ไปแล้วยังนับว่าใช้ สิทธิ์ที่เหลือใช้ไม่ได้อีก |
| คืนเงินบิลที่ใช้สิทธิ์ไป | ไม่คืนสิทธิ์ เพราะบริการเกิดขึ้นจริง |

ทั้งสองแบบเขียน audit `package.cancelled` พร้อมเหตุผล การคืนเงินบางส่วนของบิลแพ็กเกจปกติคือคืนค่าครั้งที่เหลือ แคชเชียร์คิดยอดเอง ระบบไม่คิดให้

**สถานะ**

| ค่า | หน้าจอแสดง | เมื่อไร |
|---|---|---|
| `pending_payment` | รอชำระเงิน | ขายแล้ว บิลยังไม่ครบ |
| `active` | ใช้ได้ | จ่ายครบ ยังมีสิทธิ์ ยังไม่หมดอายุ |
| `used_up` | ใช้ครบแล้ว | ใช้สิทธิ์หมด |
| `expired` | หมดอายุ | เลยวันหมดอายุ |
| `cancelled` | ยกเลิกแล้ว | บิลขายถูกยกเลิกหรือคืนเงิน |

สถานะคำนวณทุกครั้งที่อ่าน ตามลำดับ ยกเลิก หมดอายุ รอชำระ ใช้ครบ แล้วจึงใช้ได้ ไม่มีคอลัมน์สถานะให้ใครตั้งเอง

## คูปอง

```json
{ "code": "VACCINE10", "name": "ลดค่าวัคซีน 10%", "percent": 10,
  "service_ids": ["svc_..."], "max_redemptions": 100, "per_customer_limit": 1,
  "valid_from": "2026-10-01", "valid_until": "2026-12-31", "branch_id": "brn_..." }
```

| ช่อง | กติกา |
|---|---|
| `code` | ตัวอักษรอังกฤษ ตัวเลข และขีด 4 ถึง 20 ตัว เก็บเป็นตัวพิมพ์ใหญ่ ตอนใช้ไม่สนตัวพิมพ์ ไม่ส่งระบบสุ่มให้ 8 ตัวที่ไม่มีตัวที่อ่านสับสน (0 O 1 I L U) ซ้ำกับคูปองอื่นตอบ `409 coupon_code_taken` |
| `percent` หรือ `amount_satang` | อย่างใดอย่างหนึ่ง เปอร์เซ็นต์มากกว่า 0 ไม่เกิน 100 ทศนิยมไม่เกินสองตำแหน่ง |
| `service_ids` | ลดเฉพาะรายการของบริการเหล่านี้ ว่างคือลดจากยอดก่อนส่วนลดทั้งบิล |
| `max_redemptions` | ใช้ได้กี่ครั้งรวมทุกคน ไม่ส่งคือไม่จำกัด |
| `per_customer_limit` | ลูกค้าหนึ่งคนใช้ได้กี่ครั้ง ไม่ส่งคือไม่จำกัด |
| `valid_from`, `valid_until` | วันของคลินิก รวมทั้งสองวัน วันเริ่มไม่ส่งคือวันนี้ วันสิ้นสุดไม่ส่งคือไม่หมดอายุ |
| `branch_id` | ใช้ได้เฉพาะบิลของสาขานี้ ไม่ส่งคือทุกสาขา |

**สาขา** พนักงานที่ผูกสาขาสร้างคูปองได้เฉพาะสาขาของตัวเอง คูปองทุกสาขาสร้างได้เฉพาะบัญชีที่ไม่ผูกสาขา (เจ้าของหรือผู้ดูแล) เพราะเคาน์เตอร์สาขาหนึ่งไม่ควรแจกส่วนลดให้สาขาอื่น

### ใช้คูปองตอนเก็บเงิน

`POST /staff/invoices/{id}/discounts` scope `invoice:discount`

```json
{ "coupon_code": "vaccine10" }
```

- คูปองเป็นส่วนลดหนึ่งแถวบนบิล ไม่ต้องส่งเหตุผลและผู้อนุมัติ เหตุผลระบบเขียนว่า "คูปอง โค้ด (ชื่อ)" ผู้อนุมัติคือคนที่สร้างคูปอง เพราะการอนุมัติเกิดตอนออกคูปองแล้ว ผู้บันทึกคือคนที่กด
- เปอร์เซ็นต์คิดจากยอดของรายการที่คูปองใช้ได้ ปัดลงเป็นสตางค์ จำนวนเงินไม่เกินยอดของรายการที่ใช้ได้ และส่วนลดไม่เกินยอดค้างของบิล รายการที่แพ็กเกจครอบราคา 0 จึงไม่ช่วยให้ลดได้มากขึ้น
- ตรวจตามลำดับ วันเริ่ม วันสิ้นสุด จำนวนรวม จำนวนต่อลูกค้า สาขา แต่ละข้อมีรหัสของตัวเอง ทั้งหมดเป็น `409`

| รหัส | ความหมาย |
|---|---|
| `not_found` (404) | ไม่มีโค้ดนี้ |
| `coupon_not_started` | ยังไม่ถึงวันเริ่ม |
| `coupon_expired` | เลยวันสิ้นสุด |
| `coupon_used_up` | ใช้ครบจำนวนรวมแล้ว |
| `coupon_customer_limit` | ลูกค้าคนนี้ใช้ครบแล้ว |
| `coupon_not_applicable` | ใช้กับบิลนี้แล้ว คนละสาขา หรือบิลไม่มีรายการที่คูปองลดได้ |

- **ใช้พร้อมกันสองคน** แคชเชียร์สองคนใช้คูปองใช้ได้ครั้งเดียวในเวลาเดียวกัน ได้สำเร็จหนึ่งคน อีกคนได้ `coupon_used_up` เพราะการใช้คูปองถือ lock ของคูปองนั้นใน transaction และอ่านจำนวนใหม่หลังได้ lock ฐานข้อมูลกันอีกชั้นด้วย check constraint ว่าจำนวนที่ใช้ไม่เกินจำนวนรวม และ unique index ว่าคูปองหนึ่งใช้ได้ครั้งเดียวต่อบิล
- **ยกเลิกบิล** คืนการใช้คูปอง จำนวนลดลงหนึ่ง แถวการใช้ถูกปิดด้วย `released_at` และยังอยู่ในประวัติ **คืนเงิน** ไม่คืนการใช้คูปอง

## แต้มสะสมและระดับสมาชิก

| กติกา | ค่า |
|---|---|
| ได้แต้ม | 1 แต้มต่อ ฿100 ที่จ่ายจริงบนบิล ปัดลง (฿1,460 ได้ 14 แต้ม) |
| แต้มเข้าเมื่อไร | เมื่อบิลชำระครบ (`paid`) บิลที่จ่ายบางส่วนยังไม่ได้แต้ม บิลที่ยอด 0 ไม่ได้แต้ม |
| คืนเงิน | หักแต้มคืนให้เหลือเท่ากับแต้มของเงินที่คลินิกเก็บไว้ บิล ฿1,460 คืน ฿500 เหลือ 9 แต้ม |
| แลกแต้ม | 1 แต้ม = ส่วนลด ฿1 |
| หมดอายุ | ไม่หมด |
| ระดับ | `member` ตั้งแต่ 0 `silver` ตั้งแต่ 200 `gold` ตั้งแต่ 1,000 นับจากแต้มตลอดชีพ |

แต้มตลอดชีพคือแต้มที่ได้ลบแต้มที่ถูกหักคืน ไม่หักแต้มที่แลกไป ลูกค้าที่แลกแต้มจึงไม่ตกระดับ ตัวเลขทั้งหมดอยู่ที่ `Domain/Crm/LoyaltyRules.cs` ไม่มีหน้าตั้งค่า

**สมุดแต้ม** ทุกการเปลี่ยนแปลงเป็นหนึ่งแถวใน `loyalty_entries` ไม่มีการแก้แถว ยอดคือผลรวม

| ชนิด | หน้าจอแสดง | เครื่องหมาย |
|---|---|---|
| `earn` | ได้แต้มจากบิล | บวก |
| `reverse` | หักแต้มคืนเพราะคืนเงิน | ลบ |
| `redeem` | แลกแต้มเป็นส่วนลด | ลบ |
| `restore` | คืนแต้มที่แลกไว้ (บิลถูกยกเลิก) | บวก |

ไม่เก็บยอดคงเหลือเป็นคอลัมน์ เพราะยอดที่เก็บไว้ต้องถูก lock ทุกครั้งที่ลูกค้ารับชำระ และการรับเงินไม่ควรล้มเพราะตัวนับแต้มไม่ว่าง การได้แต้มและการหักคืนแค่เพิ่มแถว บิลหนึ่งใบได้แต้มครั้งเดียว ฐานข้อมูลกันด้วย unique index บางส่วน การแลกแต้มถือ lock ต่อลูกค้า สองบิลจึงแลกแต้มก้อนเดียวกันพร้อมกันไม่ได้ ยอดอาจติดลบได้ในกรณีเดียว คือลูกค้าแลกแต้มไปแล้วแล้วบิลที่ให้แต้มถูกคืนเงิน

### แลกแต้มตอนเก็บเงิน

`POST /staff/invoices/{id}/discounts` scope `invoice:discount`

```json
{ "points": 50 }
```

- เป็นส่วนลดหนึ่งแถว เหตุผล "แลกแต้มสะสม 50 แต้ม" ผู้อนุมัติและผู้บันทึกคือคนที่กด
- แต้มไม่พอตอบ `409 insufficient_points` พร้อมจำนวนที่มี ส่วนลดเกินยอดค้างของบิลตอบ `409 invalid_discount` พร้อมจำนวนแต้มสูงสุดที่แลกได้
- ยกเลิกบิลคืนแต้มที่แลก (`restore`) คืนเงินไม่คืนแต้มที่แลก

### ดูบัญชีแต้ม

`GET /staff/loyalty/{customer_id}` scope `crm:read` คืน `points_balance`, `lifetime_points`, `tier`, `next_tier` (ระดับถัดไปและแต้มที่ยังขาด ไม่มีเมื่ออยู่ระดับสูงสุด), `rules`, `history` (50 แถวล่าสุดพร้อมเลขบิล), `coupon_redemptions` (50 แถวล่าสุด) และ `packages`

ลูกค้าเป็นของคลินิก ไม่ใช่ของสาขา เหมือน `GET /staff/customers/{id}` และแต้มที่ได้สาขาหนึ่งใช้อีกสาขาได้ พนักงานทุกสาขาที่ถือ `crm:read` จึงเห็นทั้งบัญชี ไม่มีลูกค้าตอบ `404`

## กลุ่มลูกค้า

```json
{ "name": "สุนัขที่ไม่มา 6 เดือน",
  "criteria": { "species": ["สุนัข"], "inactive_days": 180, "branch_id": "brn_..." } }
```

| เงื่อนไข | ความหมาย |
|---|---|
| `species` | มีสัตว์ที่ยังมีชีวิตอยู่ในความดูแล เป็นชนิดใดชนิดหนึ่งในรายการ ไม่สนตัวพิมพ์ ไม่เกิน 10 ชนิด |
| `inactive_days` | "ไม่มา N วัน" เคยมาแล้ว และครั้งล่าสุดนานกว่า N วัน คนที่ไม่เคยมาเลยไม่นับ |
| `visited_within_days` | มาภายใน N วัน ถ้าใช้คู่กับ `inactive_days` ต้องมากกว่า เช่น ไม่มา 180 วันแต่มาภายใน 365 วัน |
| `min_spend_satang` | ยอดจ่ายลบยอดคืนใน 365 วันล่าสุด อย่างน้อยเท่านี้ |
| `tiers` | ระดับสมาชิกเป็นหนึ่งใน `member`, `silver`, `gold` |
| `has_active_package` | `true` มีแพ็กเกจที่ใช้ได้วันนี้ `false` ไม่มีเลย |
| `branch_id` | เฉพาะลูกค้าที่เคยมาสาขานี้ และนับการมากับยอดเฉพาะสาขานี้ |

- ทุกเงื่อนไขที่ส่งต้องจริงพร้อมกัน ต้องมีอย่างน้อยหนึ่งเงื่อนไข สาขาอย่างเดียวก็นับ
- **การมา** คือเคสที่เปิดหรือบิลที่ไม่ถูกยกเลิก เหมือนรายงานลูกค้าใหม่และกลับมา ลูกค้าที่ถูกรวมเข้ากับอีกคนนับเป็นคนที่รวมเข้าไป ลูกค้าที่ปิดบัญชีหรือถูกรวมไปแล้วไม่อยู่ในกลุ่ม
- **เก็บเป็นเงื่อนไข ไม่ใช่รายชื่อ** คนที่ "ไม่มา 6 เดือน" เปลี่ยนทุกวัน ระบบจึงคำนวณใหม่ทุกครั้งที่ใช้ ตัวเลขที่เก็บคือจำนวนตอนสร้าง
- คำตอบมี `customer_count` (จำนวนคนตอนนี้) และ `reachable_count` (ในนั้นมีกี่คนที่ยอมรับข่าวสารการตลาดและมี LINE ที่ยังติดตามอยู่ คือคนที่ประกาศ LINE ส่งถึงได้)
- **สาขา** พนักงานที่ผูกสาขาสร้างกลุ่มได้เฉพาะสาขาของตัวเอง กลุ่มทุกสาขาสร้างได้เฉพาะบัญชีที่ไม่ผูกสาขา เพราะจำนวนคนบอกข้อมูลลูกค้าของสาขาที่บัญชีนั้นมองไม่เห็น
- เงื่อนไขทั้งหมดเป็น SQL คำสั่งเดียว (`SegmentQuery`) ทั้งตัวนับตอนสร้างและรายชื่อตอนส่งประกาศใช้คำสั่งเดียวกัน สองตัวเลขนี้จึงไม่ขัดกัน

### ส่งประกาศถึงกลุ่ม

`POST /staff/integrations/line/broadcast` scope `notify:broadcast`

```json
{ "segment_id": "seg_...", "message": "เดือนนี้ฉีดวัคซีนลด 10%" }
```

ส่ง `customer_ids` หรือ `segment_id` อย่างใดอย่างหนึ่ง ผู้รับคือสมาชิกของกลุ่ม ณ ตอนส่ง ที่ยอมรับข่าวสารการตลาดและมี LINE ที่ยังติดตามอยู่ เกิน 200 คนหรือไม่มีเลยตอบ `422` บน `segment_id` ที่เหลือเหมือนการประกาศแบบรายชื่อ คือด่านความยินยอม โควตาต่อเดือน และ audit ซึ่งเก็บ `segment_id` ด้วย ดู [LINE](line.md)

## รายได้และรายงาน

- รายงานรายรับนับจากเงินที่รับจริง เงินขายแพ็กเกจจึงเป็นรายได้ตอนรับชำระ ไม่ใช่ตอนใช้สิทธิ์
- บริการที่ใช้แพ็กเกจเป็นรายการราคา 0 จึงไม่ถูกนับเป็นรายได้ซ้ำ ยอดที่ออกบิล (`invoiced`) ก็ไม่ซ้ำด้วย
- รายงานบริการทำเงินนับเงินแพ็กเกจเป็นชนิด `other` ไม่ได้แบ่งให้บริการที่ใช้สิทธิ์ บริการที่ใช้แพ็กเกจขึ้นในรายงานด้วยจำนวนครั้ง แต่รายได้ 0
- ส่วนลดจากคูปองและแต้มเป็นส่วนลดปกติ ลดยอดบิลเหมือนส่วนลดที่ให้เอง

## ใครทำอะไรได้

| role ตั้งต้น | scope | ทำได้ |
|---|---|---|
| `clinic_owner` | `*` | ทุกอย่าง |
| `clinic_admin` | ทุก scope ยกเว้นสองตัว รวม `crm:read`, `crm:manage` | ทุกอย่าง |
| `cashier` | `invoice:*` | ใช้คูปองและแลกแต้มบนบิล แต่ไม่เห็นยอดแต้มและสร้างโปรโมชันไม่ได้ |
| role อื่น | ไม่มี `crm:*` | ไม่มีสิทธิ์ในโมดูลนี้ |

scope สองตัวนี้อยู่ในรายการของ contract อยู่แล้ว ตาราง role ของ contract ไม่ได้ให้กับ `receptionist` หรือ `cashier` จึงไม่ได้เพิ่ม คลินิกเพิ่มเองได้ที่ `PUT /staff/roles/{id}/permissions` เช่นให้แคชเชียร์ถือ `crm:read` เพื่อเห็นแต้มของลูกค้าตอนเก็บเงิน

## ประวัติการทำงาน

audit ที่เพิ่ม `package.sold`, `package.used`, `package.cancelled`, `coupon.created`, `segment.created` การใช้คูปองและแลกแต้มเขียน `invoice.discounted` เดิม พร้อม `source` (`manual`, `coupon`, `points`), `coupon_code` และ `points` การได้และหักแต้มไม่เขียน audit เพราะสมุดแต้มคือบันทึกนั้นเอง และผูกกับบิลทุกแถว บิลขายแพ็กเกจเขียน `invoice.issued` ด้วย `source: package_sale`

## หน้าจอ

`/crm` เมนู **แพ็กเกจและโปรโมชัน** เห็นเมื่อถือ `crm:read` หรือ `crm:manage` มีแท็บตามสิทธิ์ และ `/crm` พาไปแท็บแรกที่ใช้ได้

| แท็บ | scope | ทำอะไร |
|---|---|---|
| ขายแพ็กเกจ `/crm/packages` | `crm:manage` | ค้นลูกค้า เลือกสัตว์ (ไม่บังคับ) เลือกบริการ จำนวนครั้ง ราคา และวันหมดอายุ ขายที่สาขาปัจจุบัน ขายแล้วมีลิงก์ไปบิลเพื่อรับเงิน และบอกว่าแพ็กเกจใช้ได้เมื่อจ่ายครบ |
| สร้างคูปอง `/crm/coupons` | `crm:manage` | โค้ด (ว่างให้ระบบสุ่ม) ลดเป็นเปอร์เซ็นต์หรือจำนวนเงิน บริการ จำนวนครั้ง ช่วงวันที่ และสาขา สร้างแล้วแสดงโค้ดตัวใหญ่ |
| กลุ่มลูกค้า `/crm/segments` | `crm:manage` | ชื่อกลุ่มและเงื่อนไข มีปุ่มลัด 90, 180, 365 วัน สร้างแล้วแสดงจำนวนคนและจำนวนที่ส่ง LINE ถึง ถ้าถือ `notify:broadcast` มีลิงก์ "ส่งประกาศ LINE ถึงกลุ่มนี้" |
| แต้มและสมาชิก `/crm/loyalty` | `crm:read` | ค้นลูกค้า (ไม่มี `customer:read` ต้องพิมพ์รหัสลูกค้า) แล้วแสดงแต้ม ระดับและแถบความคืบหน้า กติกา ประวัติแต้ม ประวัติคูปอง และแพ็กเกจ |

- **กลุ่มลูกค้าไม่มีหน้ารายการ** เพราะ contract ไม่มี endpoint อ่านกลุ่ม ลิงก์ไปหน้าประกาศจึงพารหัสกลุ่ม ชื่อ และจำนวนไปทางที่อยู่ของหน้า (`/notifications/broadcast?segment_id=&segment_name=&reachable=`) หน้าประกาศแสดง "ส่งถึงกลุ่ม ชื่อ (ประมาณ N คน)" แทนการเลือกลูกค้า และมีปุ่ม "เลือกลูกค้าเองแทน"
- **หน้าลูกค้า** มีการ์ด "แต้มและแพ็กเกจ" เมื่อถือ `crm:read` แสดงแต้ม ระดับ และแพ็กเกจที่ใช้ได้หรือรอชำระ พร้อมลิงก์ไปแท็บแต้ม โหลดไม่ได้แสดงข้อความบรรทัดเดียว ไม่ทำให้หน้าลูกค้าล้ม
- **หน้าบิล** การ์ดส่วนลดมีสี่แบบ คือ จำนวนเงิน เปอร์เซ็นต์ ใช้คูปอง และแลกแต้ม แบบแลกแต้มแสดงแต้มคงเหลือของลูกค้าเมื่อถือ `crm:read` ทั้งหมดส่ง `If-Match` เหมือนส่วนลดเดิม
- **สร้างบิลเอง** รายการที่เลือกจากบริการในแคตตาล็อกส่ง `source_id` เป็นรหัสบริการ แพ็กเกจจึงครอบบิลที่สร้างเองได้ และรายงานบริการทำเงินรู้ว่าเป็นบริการไหน
- **portal** หน้า `/portal/packages` แสดงแพ็กเกจรอชำระในกลุ่มที่ใช้ได้ และแพ็กเกจที่ยกเลิกในกลุ่มที่จบแล้ว

## ข้อจำกัดที่รู้อยู่

- ตัดสิทธิ์ตอนออกบิลเท่านั้น นัดที่ยังไม่มาไม่จองสิทธิ์ไว้ ถ้าลูกค้ามีนัดสองครั้งแต่เหลือสิทธิ์หนึ่ง ครั้งที่ออกบิลก่อนได้สิทธิ์
- ตัดสิทธิ์อัตโนมัติเสมอ ถ้าลูกค้าไม่อยากใช้แพ็กเกจกับครั้งนี้ ต้องสร้างบิลเองโดยไม่ส่ง `source_id`
- ค่ายาไม่ถูกแพ็กเกจครอบ แพ็กเกจครอบเฉพาะบริการในแคตตาล็อก
- บิลที่แพ็กเกจครอบทั้งใบเป็น `paid` ตั้งแต่ออก ค่ายาที่จ่ายหลังปิดเคสจึงออกเป็นบิลใบใหม่ ตามกติกาเดิมของบิลที่รับเงินแล้ว
- การคืนเงินบิลขายแพ็กเกจยกเลิกแพ็กเกจทั้งก้อน คืนบางครั้งแล้วใช้ต่อไม่ได้
- ไม่มีทางปรับแต้มด้วยมือ ยกเลิกการใช้คูปองโดยไม่ยกเลิกบิล ปิดคูปองก่อนวันสิ้นสุด หรือดูรายการคูปองและกลุ่มลูกค้า
- กลุ่มที่สร้างโดยพนักงานผูกสาขาต้องมีสาขา จึงไม่มีกลุ่มข้ามสาขาสำหรับบัญชีเหล่านั้น
- ประกาศถึงกลุ่มได้ครั้งละไม่เกิน 200 คนที่ส่งถึงได้ กลุ่มใหญ่กว่านั้นต้องแบ่งด้วยเงื่อนไขเพิ่ม
