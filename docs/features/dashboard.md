# ภาพรวมและรายงาน

ตัวเลขของคลินิกอยู่สองหน้า หน้า **ภาพรวม** (`/dashboard`) เป็นหน้าของวันนี้ บอกว่ามีงานอะไรรอทำ ใครจะมาในสองชั่วโมงข้างหน้า และตัวเลขหลักของวันนี้ หน้า **รายงาน** (`/reports`) เป็นรายงานตามช่วงวันที่ที่เลือก แบ่งเป็นสองแท็บ คือสถิติการทำงาน (นัด คิว ภาระงานของหมอ) และธุรกิจ (รายรับ บริการ ลูกค้า ผลงานรายบุคคล)

รายงานทุกตัวในหน้านี้เป็นการอ่านอย่างเดียว ตัวเลขทุกตัวคำนวณสดจากตารางที่โมดูลอื่นเขียนไว้แล้ว เช่น นัดจาก `appointments` เงินจาก `invoice_payments` และ `invoice_refunds` ส่วนเดียวที่เขียนข้อมูลคือการส่งออกรายงานเป็นไฟล์ ดูหัวข้อ [ส่งออกรายงาน](#ส่งออกรายงาน)

## ใครเห็นอะไร

| ส่วนของหน้า | Endpoint | scope |
|---|---|---|
| หน้าภาพรวมและการ์ดวันนี้ | `GET /staff/dashboard/today` | `dashboard:read` |
| แท็บสถิติการทำงาน | `GET /staff/stats/appointments`, `/staff/stats/queue`, `/staff/stats/workload` | `stats:read` |
| แท็บธุรกิจ: รายรับ บริการ ลูกค้า | `GET /staff/analytics/revenue`, `/staff/analytics/services`, `/staff/analytics/retention` | `analytics:read` |
| แท็บธุรกิจ: ผลงานรายบุคคล | `GET /staff/analytics/staff-performance` | `analytics:hr` |

- role ตั้งต้นที่เห็นได้ทุกส่วนคือ `clinic_owner` (ถือ `*`) และ `clinic_admin` (ได้ทุก scope ในแคตตาล็อกตอน seed) ส่วน `veterinarian` และ `receptionist` ได้ `dashboard:read` ตั้งแต่ติดตั้ง จึงเปิดหน้าภาพรวมได้ แต่ไม่เห็นรายรับและหน้ารายงาน ([contract-extensions.md § 46](../contract-extensions.md)) role อื่นไม่มี scope กลุ่มนี้ คลินิกต้องเพิ่มให้เอง
- `analytics:read` ไม่ได้เปิดผลงานรายบุคคล เพราะรายงานนั้นจัดอันดับคน ต้องใช้ `analytics:hr` แยกต่างหาก
- เมนู **ภาพรวม** ขึ้นเมื่อบัญชีถือ `dashboard:read` เมนู **รายงาน** ขึ้นเมื่อถือ `stats:read`, `analytics:read` หรือ `analytics:hr` อย่างใดอย่างหนึ่ง ส่วนไหนที่ไม่มีสิทธิ์จะไม่ถูกวาด และ API ก็ตรวจซ้ำทุกคำขอ
- บัญชีที่ไม่มี `dashboard:read` แต่ดูรายงานได้ ถ้าเปิด `/dashboard` จะถูกพาไป `/reports`
- กล่องอื่นในหน้าภาพรวมใช้ scope ของหน้าที่กล่องนั้นลิงก์ไป ดูตารางในหัวข้อ [หน้าภาพรวมบนเว็บ](#หน้าภาพรวมบนเว็บ)

### สาขา

ใช้กติกาเดียวกับการอ่านข้อมูลอื่นของพนักงาน (`BranchGuard`)

- ส่ง `?branch=` เพื่อดูสาขาเดียว ถ้าเป็นสาขาที่ตัวเองไม่ได้ประจำ ได้ `403 forbidden`
- ถ้าไม่ส่ง พนักงานที่ผูกสาขาเห็นผลรวมของสาขาตัวเองเท่านั้น ไม่ใช่ทั้งคลินิก ผู้ถือ `*` หรือบัญชีที่ไม่ผูกสาขาเห็นทุกสาขา
- หน้าเว็บส่งสาขาที่เลือกอยู่ในคอนโซลเสมอ

### ช่วงวันที่

- `from` และ `to` เป็นวันตามปฏิทินคลินิก (`YYYY-MM-DD`) นับรวมทั้งสองวัน
- วันเริ่มที่เที่ยงคืนเวลากรุงเทพ ไม่ใช่ UTC เงินที่รับตอนตีหนึ่งของวันที่ 5 จึงนับเป็นวันที่ 5 ไม่ใช่วันที่ 4 ตัวช่วยที่ใช้คือ `ClinicDays` ตัวเดียวกับตารางเวร
- ถ้าไม่ส่ง ได้ 30 วันล่าสุดจนถึงวันนี้ ยกเว้นรายงานลูกค้าที่ได้ 6 เดือนล่าสุด
- ยาวได้ไม่เกิน 366 วัน วันสุดท้ายอยู่ก่อนวันแรก หรือวันที่ผิดรูปแบบ ได้ `422 validation_failed` ที่ช่อง `to` หรือช่องที่ผิด
- `granularity` (เฉพาะนัดและรายรับ) เป็น `day`, `week` หรือ `month` ค่าเริ่มต้นคือ `day` สัปดาห์เริ่มวันจันทร์ ค่าอื่นได้ `422`
- กราฟมีทุกช่วงรวมช่วงที่เป็นศูนย์ วันที่เงียบจึงเห็นเป็นศูนย์ ไม่ได้หายไปจากกราฟ

## การ์ดวันนี้

`GET /staff/dashboard/today?branch=` คืนตัวเลขของวันนี้ตามเวลาคลินิก

| การ์ด | ตัวเลข | นับอย่างไร |
|---|---|---|
| นัดวันนี้ | ทั้งหมด ยังไม่มา มาแล้ว เสร็จแล้ว ยกเลิก ไม่มาตามนัด | นัดที่ **เริ่ม** วันนี้ ไม่นับ `draft` "ยังไม่มา" คือ `booked` และ `confirmed` "มาแล้ว" คือ `checked_in` และ `in_consultation` |
| คิววันนี้ | ออกบัตร รอเรียก ถูกเรียก อยู่ในห้อง ตรวจเสร็จ ข้าม ออกไปแล้ว | บัตรคิวของวันนี้ (`service_date`) ตามสถานะปัจจุบัน |
| | รอเฉลี่ย | เวลาจากออกบัตรถึงถูกเรียก เฉลี่ยเฉพาะบัตรที่ถูกเรียกแล้ว |
| | รอนานสุดตอนนี้ | นาทีตั้งแต่ออกบัตรของบัตรที่ยังรอเรียกอยู่และรอนานที่สุด |
| เคสตรวจ | เปิดค้าง ปิดวันนี้ | เคสที่ยังเปิดอยู่ตอนนี้ไม่ว่าเปิดวันไหน และเคสที่ปิดวันนี้ |
| รายรับวันนี้ | รับชำระ คืนเงิน สุทธิ จำนวนรายการ | นิยามเดียวกับรายงานรายรับด้านล่าง แต่เป็นวันนี้วันเดียว |
| งานของฉัน | นัดของฉัน คิวที่รอฉัน เคสที่ฉันเปิดค้าง | นัดวันนี้ที่จองกับผู้เรียก (ไม่นับที่ยกเลิก) บัตรคิววันนี้ที่มอบหมายให้ผู้เรียกและยังรอหรือถูกเรียก และเคสที่ผู้เรียกเปิดค้าง |

**การ์ดรายรับขึ้นเฉพาะบางคน** `dashboard:read` ไม่ใช่สิทธิ์เรื่องเงิน การ์ดนี้จึงถูกใส่เฉพาะเมื่อผู้เรียกถือ `analytics:read` หรือ `invoice:write` อยู่แล้ว คือคนที่เห็นเงินก้อนเดียวกันจากทางอื่นได้อยู่แล้ว ถ้าไม่ถือ คีย์ `revenue` ไม่อยู่ในคำตอบเลย

contract บอกว่าการ์ดนี้เป็น "การ์ดสรุปหน้าแรกของแต่ละบทบาท" ระบบไม่ได้ตรวจชื่อ role เพราะคลินิกสร้าง role เองได้ ความต่างระหว่างบทบาทมาจาก scope ที่ถือ (การ์ดรายรับ) และจากตัวผู้เรียกเอง (การ์ดงานของฉัน)

## สถิติการทำงาน

### นัดหมาย

`GET /staff/stats/appointments?from=&to=&branch=&granularity=`

- นับนัดตามวันที่ **เริ่ม** ไม่ใช่วันที่จอง คำถามคือวันนั้นยุ่งแค่ไหนและมีคนไม่มากี่คน ไม่นับ `draft`
- `cancelled` คือยกเลิกโดยใครก็ได้ `late_cancelled` คือยกเลิกหลังเวลาตัดตามนโยบายยกเลิก
- `booked_online` คือนัดที่ไม่มีพนักงานเป็นผู้จองและไม่ใช่ walk-in คือลูกค้าจองเอง
- `cancellation_rate` = ยกเลิก หาร นัดทั้งหมด
- `no_show_rate` = ไม่มาตามนัด หาร นัดที่ **ไม่ได้ถูกยกเลิก** เพราะนัดที่ยกเลิกแล้วไม่มีใครคาดว่าจะมา ถ้าเอามาเป็นตัวหาร คลินิกที่ยกเลิกเยอะจะดูเหมือนลูกค้ามาตรงนัดดีขึ้น
- อัตราเป็นทศนิยม 0 ถึง 1 สี่ตำแหน่ง ถ้าตัวหารเป็นศูนย์ คีย์นั้นไม่ถูกส่งมา ไม่ได้ส่งเป็น 0 เพราะ "อัตราไม่มา 0%" ของวันที่ไม่มีนัดเลยอ่านเหมือนคลินิกทำได้ดี

### คิว

`GET /staff/stats/queue?from=&to=&branch=`

- วันคือ `service_date` ของบัตร คือวันที่ระบบคิวออกเลขให้ ตัวเลขจึงตรงกับกระดานคิวของวันเดียวกัน
- **รอเฉลี่ย** คือออกบัตรถึงถูกเรียก เฉลี่ยเฉพาะบัตรที่เคยถูกเรียก บัตรที่ลูกค้ากลับไปก่อนถูกเรียกไม่มีเวลารอให้วัด ถ้านับเป็นศูนย์จะทำให้การเดินออกดูเหมือนบริการเร็ว
- **อยู่ในห้องเฉลี่ย** คือเข้าห้องถึงตรวจเสร็จ
- **ชั่วโมงพีค** คือชั่วโมงตามเวลาคลินิกที่ออกบัตรมากที่สุด ถ้าเท่ากันเลือกชั่วโมงแรก `peak_hours` มีครบ 24 ชั่วโมงพร้อมจำนวนบัตรและเวลารอเฉลี่ยของชั่วโมงนั้น
- **คิวค้าง** (`outstanding`) คือบัตรที่ยังไม่จบ ได้แก่ รอเรียก ถูกเรียก และอยู่ในห้อง ถ้าช่วงวันที่มีวันนี้ คือคิวที่ยังรออยู่จริง ถ้าเป็นวันที่ผ่านไปแล้ว คือบัตรที่ลืมปิด

### ภาระงานของสัตวแพทย์

`GET /staff/stats/workload?from=&to=&branch=`

| ตัวเลข | นับอย่างไร |
|---|---|
| `cases` | เคสที่ **ปิด** ในช่วงนี้ นับให้หมอที่เปิดเคส |
| `average_case_minutes` | เวลาจากเปิดถึงปิดเคส เฉลี่ยของเคสเหล่านั้น |
| `appointments` | นัดในช่วงนี้ที่จองกับหมอคนนั้น ไม่นับที่ยกเลิก |
| `open_cases` | เคสที่หมอคนนั้นเปิดค้าง **ตอนนี้** |
| `waiting_queue` | บัตรคิว **วันนี้** ที่มอบหมายให้หมอคนนั้นและยังรอหรือถูกเรียก |
| `totals.unassigned_queue` | บัตรคิววันนี้ที่ยังรอและยังไม่มีหมอ |

งานค้างเป็นตัวเลขของปัจจุบันเสมอ ไม่ขึ้นกับช่วงวันที่ เพราะตารางไม่ได้เก็บประวัติว่าเมื่อเดือนมีนาคมมีงานค้างเท่าไร รายชื่อมีเฉพาะหมอที่มีตัวเลขอย่างน้อยหนึ่งอย่าง เรียงจากเคสมากไปน้อย

## รายงานธุรกิจ

### รายรับ

`GET /staff/analytics/revenue?from=&to=&branch=&granularity=`

**รายรับนับแบบเงินเข้าออกจริง (cash basis)** คือ

```text
รายรับสุทธิ = เงินที่รับชำระในวันนั้น - เงินที่คืนในวันนั้น
```

- **รับชำระ** คือแถวใน `invoice_payments` นับในวันที่รับเงิน (`collected_at`) ตามเวลาคลินิก
- **คืนเงิน** คือแถวใน `invoice_refunds` นับในวันที่คืน (`refunded_at`) และตามช่องทางที่คืนจริง ไม่ใช่วันหรือช่องทางของการจ่ายครั้งแรก รับด้วยบัตรแล้วสัปดาห์ต่อมาคืนเป็นเงินสด วันแรกบัตรได้เงิน วันหลังลิ้นชักเงินสดขาด ซึ่งตรงกับที่เกิดขึ้นจริง
- **สาขา** คือสาขาของบิลที่เงินก้อนนั้นผูกอยู่
- **ช่องทาง** มีครบสามช่องทาง `cash`, `card`, `promptpay` เสมอ แม้ช่องทางนั้นเป็นศูนย์

ทำไมเป็นแบบนี้ เพราะเป็นตัวเลขเดียวที่ตรงกับลิ้นชักเงินและเครื่องรูดบัตรตอนปิดวัน และสอดคล้องกับกติกาของ [การเงิน](billing.md) ทุกข้อ

| กรณี | ผลต่อรายรับ |
|---|---|
| บิลยกเลิก (`void`) | ไม่มีผล เพราะยกเลิกได้เฉพาะบิลที่ยังไม่รับเงินเลย |
| ส่วนลด | ไม่มีผลโดยตรง ส่วนลดทำให้ลูกค้าจ่ายน้อยลง รายรับคือเงินที่จ่ายจริง |
| คืนเงินบางส่วน | หักเฉพาะยอดที่คืน แม้บิลจะเปลี่ยนเป็นสถานะ `refunded` ทั้งใบ ([assumptions.md](../assumptions.md) ข้อ 22) |
| บิลที่ยังไม่จ่ายหรือจ่ายไม่ครบ | นับเฉพาะเงินที่รับแล้ว |
| บิลยอด 0 บาท | ไม่มีเงินเข้า จึงเป็นศูนย์ |
| จ่ายหลายช่องทางในบิลเดียว | แต่ละก้อนเข้าช่องทางของตัวเอง |

**ยอดที่ออกบิล** (`invoiced_satang`) เป็นอีกมุมหนึ่งที่ให้มาเทียบ คือยอดรวมของบิลที่ **ออก** ในช่วงนี้ที่ไม่ได้ยกเลิก คำนวณแบบเดียวกับ `Invoice` คือ ผลรวมรายการ ลบ ส่วนลด ยอดนี้ต่างจากรายรับด้วยบิลที่ยังไม่จ่าย และเงินที่รับในช่วงนี้สำหรับบิลของช่วงอื่น

เงินทุกจำนวนเป็นสตางค์ (`*_satang`) แบบเดียวกับ Billing หน้าเว็บแปลงเป็นบาทตอนแสดงด้วย `formatBaht`

### บริการทำเงิน

`GET /staff/analytics/services?from=&to=&branch=`

contract ให้รายงานนี้ตอบว่าบริการไหนทำเงิน และกำไรต่อบริการหลังหักยา

1. **บิลไหน** บิลที่ **ออก** ในช่วงนี้ ไม่นับบิลที่ยกเลิก บริการได้เงินจากการมาครั้งที่ทำบริการนั้น จึงใช้วันที่ของบิล ต่างจากรายรับที่ใช้วันที่รับเงิน
2. **เงินเท่าไร** เงินที่บิลเก็บได้จริง คือ รับชำระ ลบ คืนเงิน ของบิลนั้น แล้วแบ่งให้แต่ละรายการตามสัดส่วนราคาเต็ม
3. **ยาในบิลเดียวกัน** ส่วนของรายการยา (`kind = medicine`) แบ่งต่อให้รายการบริการในบิลเดียวกันตามสัดส่วนราคา แสดงเป็น `medicine_satang` ข้างบริการ

ตัวอย่าง บิลมีบริการตรวจ ฿600 ยา ฿200 และของอื่น ฿200 รวม ฿1,000 ได้ส่วนลด ฿100 รับเงิน ฿900 แล้วคืน ฿90 บิลนี้เก็บได้ ฿810 คือ 81% ของราคาเต็ม

| รายการ | ราคาเต็ม | ส่วนที่ได้ (81%) |
|---|---|---|
| ตรวจ | ฿600 | ฿486 |
| ยา | ฿200 | ฿162 แสดงเป็นค่ายาข้างบริการตรวจ |
| ของอื่น | ฿200 | ฿162 |

บริการตรวจจึงมี `revenue_satang` 48,600 `medicine_satang` 16,200 และ `revenue_excluding_medicine_satang` 32,400

- ทำไมแบ่งตามสัดส่วน เพราะส่วนลดและการคืนเงินบันทึกต่อบิล ไม่ได้บันทึกต่อรายการ การแบ่งตามสัดส่วนเป็นวิธีเดียวที่ข้อมูลรองรับ และทำให้ผลรวมของทุกรายการในบิลเท่ากับเงินที่บิลเก็บได้พอดี
- บิลที่ยังไม่จ่ายยังเก็บเงินไม่ได้ ส่วนที่ได้จึงเป็นศูนย์ แต่ `billed_satang` (ราคาเต็ม) ยังนับ
- รายการบริการผูกกับบริการในแคตตาล็อกได้สองทาง คือหัตถการในเคสที่เลือกบริการไว้ (บิลจากการปิดเคส) หรือ `source_id` ของรายการที่เป็นรหัสบริการ (บิลที่สร้างเอง) รายการบริการที่พิมพ์เองโดยไม่ผูกบริการ จัดกลุ่มตามข้อความของรายการ
- `by_kind` คือเงินก้อนเดียวกันแยกตามประเภทรายการ ผลรวมสี่ประเภทเท่ากับเงินที่ทุกบิลเก็บได้ ปัดเศษเป็นสตางค์ที่ผลรวมของแต่ละกลุ่ม จึงอาจต่างจากผลรวมจริงได้ไม่เกินไม่กี่สตางค์
- **ค่ายามาจากการจ่ายยา** ตั้งแต่มีโมดูลคลังยา การจ่ายยาเพิ่มรายการ `medicine` ลงบิลของเคสเอง ([สต๊อกยาและเวชภัณฑ์](inventory.md#ค่ายาขึ้นบิลเดียวกับการรักษา)) วิธีคำนวณไม่เปลี่ยน ค่ายาที่ไปอยู่บิลใบใหม่ เพราะบิลของเคสรับเงินไปแล้ว ไม่มีบริการในบิลเดียวกัน จึงนับใน `by_kind` ของ `medicine` แต่ไม่ขึ้นข้างบริการใด
- **นี่ยังไม่ใช่กำไร** `revenue_excluding_medicine_satang` คือรายได้ของบริการหักค่ายาที่ขายไปพร้อมกัน ไม่ใช่หักต้นทุนยา ต้นทุนมีในระบบแล้ว (ต้นทุนต่อหน่วยในการรับเข้าและใบสั่งซื้อ) แต่รายงานยังไม่ใช้ เพราะต้องเพิ่มตัวเลขใหม่ในคำตอบ ซึ่งยังไม่ได้ขออนุมัติ

### ลูกค้าใหม่และลูกค้าที่กลับมา

`GET /staff/analytics/retention?from=&to=&branch=`

- **การมาหนึ่งครั้ง** คือการเปิดเคสตรวจให้ลูกค้า หรือการออกบิลให้ลูกค้าที่ไม่ได้ยกเลิก นับทั้งสองอย่างเพราะลูกค้าที่มาอาบน้ำตัดขนโดยไม่ได้พบหมอก็คือลูกค้าที่กลับมา
- **ลูกค้าใหม่** ในเดือนใดคือลูกค้าที่มาครั้งแรกในชีวิตในเดือนนั้น ระบบมองย้อนไปก่อนช่วงรายงานด้วย ลูกค้าที่มาครั้งแรกปีที่แล้วจึงไม่ใช่ลูกค้าใหม่ของเดือนนี้
- **ลูกค้าที่กลับมา** คือลูกค้าที่มาในเดือนนั้นและเคยมาก่อนเดือนนั้น
- ลูกค้าที่ถูกรวมเข้ากับเรกคอร์ดอื่น นับเป็นเรกคอร์ดที่ถูกรวมเข้าไป รายชื่อซ้ำที่แก้ที่เคาน์เตอร์จึงไม่กลายเป็นลูกค้าใหม่
- ถ้าระบุสาขา "ครั้งแรก" หมายถึงครั้งแรกที่ **สาขานั้น**
- รายงานนับเป็นเดือนเต็ม วันแรกถูกเลื่อนไปวันที่ 1 ของเดือน

**cohort รายเดือน** แต่ละแถวคือลูกค้าใหม่ของเดือนหนึ่ง `retained[k]` คือจำนวนคนในกลุ่มนั้นที่มาอีกในเดือนที่ k หลังเดือนแรก (`retained[0]` คือทั้งกลุ่ม) `retention_rates` คือค่าเดียวกันเป็นสัดส่วนของกลุ่ม แสดงเฉพาะกลุ่มที่เริ่มในช่วงรายงาน เพราะกลุ่มที่เริ่มก่อนนั้นไม่มีเดือนแรกให้เทียบ

### ผลงานรายบุคคล

`GET /staff/analytics/staff-performance?from=&to=&branch=` ต้องใช้ `analytics:hr`

| ตัวเลข | นับอย่างไร |
|---|---|
| `cases`, `average_case_minutes` | เคสที่คนนั้นปิดในช่วงนี้ และเวลาเฉลี่ยจากเปิดถึงปิด |
| `treatments` | หัตถการที่คนนั้นเป็นผู้ทำ |
| `attributed_revenue_satang` | รายรับแบบเงินเข้าออกจริงในช่วงนี้ (รับ ลบ คืน) ของบิลที่มาจากเคสของคนนั้น |
| `collected_satang` | เงินที่คนนั้นรับที่เคาน์เตอร์ แยกไว้เพราะคนที่รับเงินไม่ใช่คนที่ทำให้ได้เงิน |

- รายชื่อมีพนักงานที่ active ทุกคนในสาขาที่ดูอยู่ (รวมคนที่ไม่ผูกสาขา) แม้เป็นศูนย์ทั้งแถว และมีคนอื่นที่มีตัวเลขในสาขานั้นด้วย การจัดอันดับที่ตัดคนที่ไม่มีเคสออกเงียบ ๆ จะซ่อนแถวที่ผู้จัดการกำลังมองหาพอดี
- **คะแนนรีวิว** ที่ contract พูดถึงยังไม่มี เพราะระบบยังไม่มีที่เก็บรีวิวเลย ถ้าส่ง 0 จะอ่านเหมือนคะแนนแย่

## หน้าภาพรวมบนเว็บ

หน้า `/dashboard` เป็นหน้าแรกของวันสำหรับคนที่เปิดระบบตอนเช้า เรียงจากบนลงล่างดังนี้

1. **หัวหน้า** ชื่อหน้า สาขา และปุ่มลัดสี่ปุ่ม ออกบัตรคิว สร้างนัด ลงทะเบียนลูกค้าใหม่ และรับชำระ
2. **ต้องจัดการตอนนี้** คู่กับ **นัดถัดไป 2 ชม.** สองกล่องเคียงกันบนจอกว้าง และซ้อนกันบนมือถือ
3. **วันนี้** ตัวเลขหลักสี่ช่อง และแถบ **งานของฉัน** อยู่บนสุดเมื่อมี
4. **สรุปเช้านี้** ของผู้ช่วย AI เมื่อเปิด AI ไว้ ([ผู้ช่วย AI สำหรับพนักงาน](staff-ai.md#สรุปเช้า))
5. **รายละเอียดวันนี้** ตัวเลขทุกตัวของการ์ดวันนี้แยกตามสถานะ พับไว้ตั้งแต่แรก กดเพื่อเปิด
6. **ลูกค้าที่ถึงเวลากลับมา**

ทุกกล่องอ่านด้วย endpoint ที่มีอยู่แล้ว ไม่มี endpoint ใหม่ กล่องที่บัญชีไม่มีสิทธิ์อ่านจะไม่ถูกวาด และกล่องที่อ่านไม่สำเร็จ (ถูกปฏิเสธ หาไม่เจอ หรือ API ตอบผิดพลาด) หายไปเฉพาะกล่องนั้น ส่วนอื่นของหน้ายังแสดงตามปกติ เซสชันที่หมดอายุยังถูกพาไปหน้าเข้าสู่ระบบเหมือนเดิม

### ต้องจัดการตอนนี้

แต่ละบรรทัดคืองานหนึ่งประเภท มีจำนวน และทั้งบรรทัดเป็นลิงก์ไปหน้าที่ทำงานนั้น บรรทัดขึ้นเฉพาะเมื่อจำนวนมากกว่าศูนย์ และบัญชีถือ scope ของหน้านั้น

| บรรทัด | อ่านจาก | scope | ลิงก์ไป | นับอย่างไร |
|---|---|---|---|---|
| คิวที่รอเรียกเกิน 30 นาที | `GET /staff/queue` | `queue:read` | `/queue` | บัตรที่ยังรอเรียก (`waiting` และ `skipped`) ที่ออกบัตรมาแล้วอย่างน้อย 30 นาที บรรทัดเล็กบอกเวลารอนานสุด |
| ข้อความลูกค้าที่รอตอบ | `GET /staff/threads?status=awaiting_reply&messages=0&limit=100` | `message:read` | `/messages?status=awaiting_reply` | จำนวนกล่องข้อความที่รอตอบ ถ้าเกินหนึ่งหน้าแสดงเป็น "100+" |
| รีวิวที่รอตรวจ | `GET /staff/reviews?status=pending` | `content:manage` | `/settings/reviews` | จำนวนรีวิวที่รอตรวจในหน้าแรก (25 รายการ) ถ้ามีหน้าถัดไปแสดงเป็น "25+" |
| ยาที่หมด หมดอายุ หรือใกล้หมดอายุ | `GET /staff/inventory/alerts?branch=` | `inventory:read` | `/inventory/alerts` | แจ้งเตือนชนิด `out_of_stock`, `expired` และ `near_expiry` ช่วงใกล้หมดอายุใช้ค่าตั้งต้นของ API (90 วัน) เท่ากับหน้าแจ้งเตือน ยาที่แค่ใกล้หมด (`low_stock`) ไม่นับ เพราะยังไม่ใช่งานของวันนี้ |
| นัดวันนี้ที่เสี่ยงไม่มา | `GET /staff/appointments/attendance-risk?date=วันนี้` | `appointment:read` | `/appointments?date=วันนี้` | นัดระดับ `medium` และ `high` ที่ยังไม่ถึงเวลา ให้โทรยืนยันก่อน เป็นชุดเดียวกับแถบนัดเสี่ยงในปฏิทิน |

- ไม่มีบรรทัดไหนมีงาน กล่องเขียนว่า "เรียบร้อยดี ไม่มีงานค้าง"
- ถ้าบางบรรทัดอ่านไม่สำเร็จ กล่องบอกว่า "บางรายการตรวจไม่ได้ในตอนนี้" คำว่าเรียบร้อยดีจึงไม่ปิดบังการอ่านที่ล้มเหลว
- บัญชีที่ไม่มี scope ของบรรทัดไหนเลย ไม่เห็นกล่องนี้
- **เกณฑ์ 30 นาที** คลินิกยังตั้งเองไม่ได้ ค่าตั้งของคิวมีแค่รูปแบบเลขคิว จึงเป็นค่าคงที่ `LONG_WAIT_MINUTES` ใน `features/analytics/lib/today-settings.ts` ไฟล์เดียวกับค่าคงที่อื่นของหน้านี้
- **ยังไม่มีบรรทัดเคสตรวจที่เปิดค้างมาตั้งแต่ก่อนวันนี้** ไม่มี endpoint ที่บอกวันเปิดของเคสที่ค้าง `consultations.open` ของการ์ดวันนี้นับเคสที่เปิดอยู่ทุกเคส รวมเคสที่กำลังตรวจตามปกติ และไม่มีหน้ารายการเคสให้ลิงก์ไป ถ้าต้องการต้องเพิ่ม endpoint ก่อน

### นัดถัดไป 2 ชม.

ต้องมี `appointment:read` อ่าน `GET /staff/appointments?date=วันนี้` แล้วเลือกนัดที่เริ่มภายในสองชั่วโมงข้างหน้าและสถานะเป็น `booked`, `confirmed` หรือ `checked_in` แสดงไม่เกิน 8 นัด ที่เหลือบอกเป็น "และอีก N นัด"

- แต่ละแถวมีเวลา ชื่อสัตว์ ชื่อเจ้าของ และสถานะ
- ชื่อมาจากผลของเสี่ยงไม่มาที่หน้าอ่านไว้แล้ว ซึ่งมีชื่อของนัดที่ยังเปิดทุกนัด นัดที่เช็กอินแล้วไม่อยู่ในนั้น จึงอ่านจากเรกคอร์ดลูกค้าเมื่อมี `customer:read` หรืออ่านชื่อสัตว์จากเรกคอร์ดสัตว์เมื่อมี `patient:read` ถ้าอ่านไม่ได้แสดงว่า "ไม่ทราบชื่อสัตว์"
- ระบบไม่มีหน้าของนัดเดี่ยว ทุกแถวจึงลิงก์ไปปฏิทินนัดของวันนี้ ซึ่งเป็นที่ที่จัดการนัด
- ไม่มีนัดในช่วงนั้น กล่องเขียนว่า "ไม่มีนัดใน 2 ชั่วโมงข้างหน้า"

### ปุ่มลัด

| ปุ่ม | ไปหน้า | ขึ้นเมื่อถือ |
|---|---|---|
| ออกบัตรคิว | `/queue` (ปุ่มออกบัตรคิวอยู่บนหน้าคิว) | `queue:read` และ `queue:write` |
| สร้างนัด | `/appointments/new` | `appointment:write` |
| ลงทะเบียนลูกค้าใหม่ | `/customers/new` | `customer:write` |
| รับชำระ | `/billing` (เปิดที่แท็บค้างชำระ) | `invoice:write` และ `payment:collect` |

ปุ่มขึ้นเฉพาะเมื่อบัญชีถือทุก scope ที่หน้านั้นต้องใช้ กดแล้วจึงไม่เจอหน้าที่บอกว่าไม่มีสิทธิ์

### ตัวเลขหลักของวันนี้

มาจาก `GET /staff/dashboard/today` ช่องละหนึ่งตัวเลข และทุกช่องเป็นลิงก์เมื่อบัญชีเปิดหน้าปลายทางได้

| ช่อง | ตัวเลข | บรรทัดเล็ก | ลิงก์ไป |
|---|---|---|---|
| นัดวันนี้ | นัดทั้งหมด | เทียบกับวันเดียวกันของสัปดาห์ก่อน และจำนวนที่ยังไม่มา | ปฏิทินนัดวันนี้ (`appointment:read`) |
| รอเรียก | คิวที่รอเรียก | รอนานสุด | `/queue` (`queue:read`) |
| อยู่ในห้องตรวจ | คิวที่อยู่ในห้อง | ตรวจเสร็จแล้วกี่คิว | `/queue` (`queue:read`) |
| รายรับวันนี้ (สุทธิ) | รับสุทธิ | ยอดทั้งวันของสัปดาห์ก่อน | แท็บธุรกิจของรายงาน (`analytics:read`) หรือบิลที่ชำระแล้ว (`invoice:write`) |

- **ช่องรายรับขึ้นเมื่อ API ส่ง `revenue` มา** คือบัญชีที่ถือ `analytics:read` หรือ `invoice:write` หน้าเว็บไม่ตัดสินเอง
- **งานของฉัน** API ส่ง `mine` ให้พนักงานทุกคน หน้าเว็บจึงวาดแถบนี้เฉพาะเมื่อมีอย่างน้อยหนึ่งตัวเลขที่มากกว่าศูนย์ (นัดของฉัน คิวที่รอฉัน เคสที่ฉันเปิดค้าง) และวางไว้ก่อนตัวเลขหลัก หมอที่มีงานของตัวเองจึงเห็นงานของตัวเองก่อน โดยหน้าเว็บไม่ต้องดูชื่อ role เลย ช่องเคสที่ฉันเปิดค้างไม่เป็นลิงก์ เพราะไม่มีหน้ารายการเคส
- บรรทัดบนขวาบอกเวลาที่นับตัวเลข (`generated_at`) และบอกว่าหน้านี้อัปเดตเองทุก 1 นาที

**เทียบกับสัปดาห์ก่อน** หน้าเว็บอ่านรายงานตามช่วงวันที่ตัวเดิม โดยให้วันเริ่มและวันจบเป็นวันเดียวกัน คือวันเดียวกันของสัปดาห์ก่อน (เจ็ดวันก่อน) ไม่มี endpoint ใหม่

- นัดอ่านจาก `GET /staff/stats/appointments` (`stats:read`) นัดทั้งวันเทียบกับนัดทั้งวันได้ตรง ๆ แสดงเป็น "+3 จากสัปดาห์ก่อน" "-2 จากสัปดาห์ก่อน" หรือ "เท่ากับสัปดาห์ก่อน"
- รายรับอ่านจาก `GET /staff/analytics/revenue` (`analytics:read`) รายรับของวันนี้ยังไม่จบวัน ถ้าเทียบเป็นเปอร์เซ็นต์กับทั้งวันของสัปดาห์ก่อนจะดูเหมือนลดลงทุกเช้า จึงแสดงเป็นบรรทัดอ้างอิง "สัปดาห์ก่อนทั้งวัน ฿15,200.00" แทน
- ถ้าบัญชีไม่มี scope หรืออ่านไม่สำเร็จ บรรทัดเทียบไม่ขึ้นเลย ไม่มีข้อความผิดพลาด

### สรุปเช้านี้

แสดงแค่ประโยคที่ AI เขียน ไม่ซ้ำตัวเลข เพราะตัวเลขของวันนี้อยู่ด้านบนแล้วและใหม่กว่า ข้อความยาวถูกตัดเหลือสามบรรทัดพร้อมปุ่ม "ดูเพิ่ม" ปุ่มขึ้นเฉพาะเมื่อข้อความยาวเกินสามบรรทัดจริง

### ลูกค้าที่ถึงเวลากลับมา

ต้องมี `crm:read` อ่าน `GET /staff/customers/due-back?reason=vaccine_overdue` ห้ารายแรก แต่ละแถวมีชื่อลูกค้า ชื่อสัตว์ และเลยกำหนดมากี่วัน รายการนี้ไม่มีเบอร์โทร จึงอ่าน `GET /staff/customers/{id}` ทีละราย (ห้าครั้ง) เมื่อบัญชีมี `customer:read` แล้วแสดงเบอร์เป็นลิงก์โทรออก ถ้าไม่มีสิทธิ์แถวมีแค่ชื่อ ท้ายกล่องมีลิงก์ไปรายชื่อทั้งหมด (`/crm/due-back`) และไปรายชื่อลูกค้าที่หายไปนานกว่าปกติ

### อัปเดตเองทุก 1 นาที

คอมโพเนนต์เล็ก ๆ ฝั่งเบราว์เซอร์เรียก `router.refresh()` ทุก 60 วินาที หน้าเว็บอ่านข้อมูลบนเซิร์ฟเวอร์ใหม่ทั้งหน้า ส่วนที่เปิดอยู่ เช่น รายละเอียดวันนี้ และตำแหน่งที่เลื่อนไว้ ยังอยู่เหมือนเดิม

- หยุดนับเมื่อแท็บถูกซ่อน (`document.visibilityState` ไม่ใช่ `visible`) และอ่านใหม่หนึ่งครั้งทันทีเมื่อกลับมาที่แท็บ แล้วเริ่มนับใหม่
- **สรุปเช้าอ่านซ้ำได้โดยไม่เสียโควตา** `GET /staff/ai/daily-brief` คืนสรุปที่เก็บไว้ ไม่เรียกโมเดลและไม่นับการใช้ (`GetDailyBriefHandler`) จึงอ่านใหม่ทุกนาทีได้

### ลิงก์เก่าของรายงาน

รายงานตามช่วงวันที่เคยอยู่ใต้การ์ดวันนี้ในหน้านี้ ลิงก์เก่าแบบ `/dashboard?tab=&from=&to=&granularity=` ยังใช้ได้ หน้าเว็บส่งต่อไป `/reports` พร้อมค่าเดิมทุกค่า

## หน้ารายงานบนเว็บ

- หน้า `/reports` มีแท็บ **สถิติการทำงาน** และ **ธุรกิจ** แท็บที่ไม่มีสิทธิ์ไม่ถูกวาด แท็บหน้าตาเป็นแท็บบนเส้นใต้ ไม่ใช่ปุ่ม
- ช่วงวันที่อยู่ในที่อยู่ของหน้า (`/reports?tab=&from=&to=&granularity=`) ส่งลิงก์ต่อให้คนอื่นได้ และปุ่มย้อนกลับย้อนไปช่วงก่อนหน้า มีปุ่มลัด 7 วัน 30 วัน 90 วัน และเดือนนี้
- ข้อความ "ดูได้ครั้งละไม่เกิน 366 วัน" เป็นตัวเล็กใต้ช่องวันที่ และผูกกับช่องวันที่ทั้งสองด้วย `aria-describedby` โปรแกรมอ่านหน้าจอจึงอ่านพร้อมช่อง
- ค่าในที่อยู่ที่ผิดรูปแบบหรือยาวเกิน 366 วัน หน้าเว็บปรับให้ถูกก่อนเรียก API แทนที่จะแสดงข้อผิดพลาด
- กราฟเป็นแท่ง SVG ธรรมดาแบบเดียวกับกราฟน้ำหนักในหน้าสัตว์ ไม่ใช้ไลบรารีกราฟ ชี้ที่แท่งเพื่อดูตัวเลข ทุกกราฟมีตารางหรือการ์ดตัวเลขอยู่ข้างกัน แกนตั้งมีป้ายค่าสูงสุดหนึ่งป้ายเหนือกราฟ คู่กับเส้นประที่ความสูงของแท่งที่สูงที่สุด
- รายงานที่ API ปฏิเสธ แสดงเป็นข้อความในตำแหน่งของรายงานนั้น ส่วนอื่นของหน้ายังแสดงได้
- ตารางเงินแยกช่องทางและแยกสาขาเลื่อนด้านข้างได้ในกล่องของตัวเองบนมือถือ ไม่ดันหน้ากว้างเกินจอ

## ส่งออกรายงาน

| Method | Endpoint | scope | หน้าที่ |
|---|---|---|---|
| POST | `/staff/reports/exports` | `report:export` และ scope ของรายงานนั้น | สั่งสร้างไฟล์ ตอบ `202` พร้อม job id ทันที |
| GET | `/staff/reports/exports/{id}` | `report:export` | สถานะ และลิงก์ดาวน์โหลดอายุ 1 ชั่วโมงเมื่อไฟล์พร้อม |

```json
POST /v1/staff/reports/exports
{ "report": "revenue", "format": "csv", "from": "2026-09-01", "to": "2026-09-30", "branch_id": "brn_..." }
```

| `report` | ข้อมูลจาก | ต้องมี scope เพิ่ม |
|---|---|---|
| `revenue` | รายรับรายวัน แยกสาขาและช่องทางชำระ | `analytics:read` |
| `services` | รายได้ต่อบริการและต่อชนิดรายการ | `analytics:read` |
| `retention` | ลูกค้าแต่ละเดือนแยกตามเดือนที่มาครั้งแรก | `analytics:read` |
| `staff_performance` | ผลงานรายบุคคล | `analytics:hr` |
| `appointments` | นัดแยกวันและผล | `stats:read` |
| `queue` | บัตรคิวแยกวัน ชั่วโมง และสถานะ | `stats:read` |
| `workload` | ภาระงานของหมอ | `stats:read` |

- **ต้องมีสิทธิ์ดูรายงานนั้นบนหน้าจอด้วย** contract ใส่แค่ `report:export` แต่ไฟล์รายรับคือข้อมูลชุดเดียวกับ `GET /staff/analytics/revenue` คนที่ดูหน้านั้นไม่ได้จึงต้องไม่ได้ไฟล์นั้นแทน ขาดได้ `403 insufficient_scope` บอก scope ที่ขาด
- `from`, `to`, `branch_id` ใช้กติกาเดียวกับหน้ารายงาน ค่าเริ่มต้นเท่ากับของหน้านั้น (30 วัน ลูกค้าใหม่และกลับมาได้ 6 เดือน) ยาวไม่เกิน 366 วัน สาขาที่ไม่ได้ประจำได้ `403`
- **ขอบเขตถูกตรึงตอนสั่ง** วันและสาขาที่คิดจาก token ของผู้สั่งถูกเก็บในงาน (`branch_ids`) worker ที่สร้างไฟล์ไม่มีผู้ใช้ จึงไม่มีทางขยายไฟล์ของผู้จัดการสาขาให้กลายเป็นทั้งคลินิก
- `format` เป็น `csv` (ค่าเริ่มต้น) `xlsx` หรือ `pdf` ค่าอื่นได้ `422` ที่ช่อง `format` contract ไม่ได้บอกรูปแบบไฟล์ `xlsx` และ `pdf` จึงเป็นส่วนขยายที่เจ้าของงานขอ ดู [contract-extensions.md § 21](../contract-extensions.md) ทุกรูปแบบมีแถวและหัวคอลัมน์ภาษาไทยชุดเดียวกัน เงินเป็นบาทสองตำแหน่ง

| `format` | ไฟล์ | หน้าตา |
|---|---|---|
| `csv` | `.csv` (`text/csv`) | UTF-8 มี BOM เปิดด้วย Excel ได้ภาษาไทยถูกต้อง ข้อความที่ขึ้นต้นด้วย `=` `+` `-` `@` ถูกเติม `'` ข้างหน้า กันสูตรที่แฝงมาในชื่อคน |
| `xlsx` | `.xlsx` (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`) | Excel หนึ่งชีตตั้งชื่อตามรายงาน แถวแรกเป็นหัวคอลัมน์ตัวหนาที่ตรึงไว้ ความกว้างคอลัมน์ตามข้อมูล ช่องมีชนิด คือ จำนวนเป็นตัวเลข เงินเป็นตัวเลขแบบ `#,##0.00` วันที่เป็นวันที่จริงแบบ `yyyy-mm-dd` เดือนแบบ `yyyy-mm` ค่าใช่หรือไม่เป็น TRUE FALSE ทุกช่องเขียนเป็นค่า ไม่มีสูตรเลย ข้อความที่ขึ้นต้นด้วย `=` จึงอยู่ตามที่พิมพ์โดยไม่ต้องเติม `'` ชื่อคลินิก สาขา และช่วงวันอยู่ใน properties ของไฟล์ |
| `pdf` | `.pdf` (`application/pdf`) | ตาราง A4 แนวนอนพร้อมพิมพ์ หัวทุกหน้ามีชื่อคลินิก ชื่อรายงาน สาขา และช่วงวัน ท้ายทุกหน้ามีเวลาที่สร้างและ "หน้า 1 / 3" ตารางยาวขึ้นหน้าใหม่โดยหัวคอลัมน์ซ้ำทุกหน้า วันที่เป็นภาษาไทยแบบปีพุทธศักราช ตัวเลขชิดขวา ช่องว่างแสดงเป็น `-` ใช้ QuestPDF และฟอนต์ Sarabun ชุดเดียวกับเอกสารของสัตว์ (สัญญาอนุญาต Community ดู [งานรักษาต่อเนื่อง](clinical-records.md)) |

- แถวในไฟล์เป็นแถวละเอียดสุดที่ query ของรายงานคืน เช่น รายรับหนึ่งแถวต่อวัน สาขา และช่องทาง ไม่ใช่ยอดรวมบนหน้าจอ ให้ spreadsheet รวมเอง ตัวเลขจึงมาจาก query ชุดเดียวกับหน้ารายงาน
- **อ่านได้เฉพาะคนที่สั่ง** คนอื่นได้ `404` เพราะไฟล์ถูกตัดตามสาขาและสิทธิ์ของผู้สั่ง
- ลิงก์ดาวน์โหลดเป็น URL ที่ลงชื่อของที่เก็บไฟล์ (`/storage/files/{token}`) ไม่ต้องมีเซสชัน หมดอายุใน 1 ชั่วโมง เรียก `GET` อีกครั้งได้ลิงก์ใหม่ ไฟล์ดาวน์โหลดตามชื่อเช่น `revenue_2026-09-01_2026-09-30.csv` นามสกุลตามรูปแบบที่สั่ง ไฟล์เก็บผ่าน `LocalFileStorage` ตัวเดียวกับเอกสารของสัตว์ ดู [contract-extensions.md § 12](../contract-extensions.md)
- การสั่งเขียน `report.exported` ลง audit log พร้อมรายงาน ช่วงวัน และสาขา

**สถานะ** `queued` แล้ว `running` แล้ว `succeeded` หรือ `failed` งานสร้างโดยตัวตั้งเวลาเบื้องหลัง (งาน `report-exports` ทุก 15 วินาที และถูกปลุกทันทีเมื่อมีคำขอใหม่ใน instance เดียวกัน) worker จองงานด้วย `FOR UPDATE SKIP LOCKED` API หลาย instance จึงไม่สร้างไฟล์เดียวกันซ้ำ งานที่ค้าง `running` เกิน 10 นาทีถูกคืนเข้าคิว ลองได้สามครั้งแล้วเป็น `failed` (`export_timed_out`) ถ้าปิดตัวตั้งเวลาไว้ (`Jobs:Enabled = false`) งานจะค้าง `queued` จนกว่าจะมี instance ที่เปิดอยู่

**บนหน้าเว็บ** บัญชีที่ถือ `report:export` เห็นกล่อง **ส่งออกรายงาน** ใต้ช่วงวันที่ในหน้า `/reports` เลือกได้เฉพาะรายงานที่ตัวเองมีสิทธิ์ดู เลือกไฟล์เป็น Excel (ค่าเริ่มต้น) CSV หรือ PDF ใต้ปุ่มมีคำอธิบายสั้น ๆ ของไฟล์ที่เลือก ใช้ช่วงวันที่และสาขาที่แสดงอยู่ กดแล้วหน้าเว็บถามสถานะทุก 2 วินาทีจนไฟล์พร้อม แล้วแสดงลิงก์ดาวน์โหลด ถ้านานเกินหนึ่งนาทีจะหยุดถามและให้ปุ่มดูสถานะอีกครั้งแทน

## ข้อจำกัดที่รู้อยู่

- **ยังไม่มีกำไรจริง** ต้องรอต้นทุนยาจากโมดูลคลังยา
- **ยังไม่มีคะแนนรีวิว** ไม่มีที่เก็บรีวิว
- **ไฟล์ที่สร้างแล้วยังไม่มีงานลบทิ้ง** ไฟล์อยู่ในที่เก็บไฟล์จนกว่าจะลบเอง
- **PDF ของช่วงยาวอาจหลายสิบหน้า** เพราะเป็นแถวละเอียดสุดชุดเดียวกับ CSV ไม่ใช่ยอดรวม เช่นคิวรายชั่วโมงทั้งปี ไม่มีกราฟในไฟล์ทุกรูปแบบ
- **คำนวณสดทุกครั้ง** ไม่มีตารางสรุปล่วงหน้า ข้อมูลของคลินิกขนาดหนึ่งถึงสองสาขาเร็วพอ ถ้าข้อมูลโตมาก ดู index ที่แนะนำด้านล่าง
- **นัดที่จองออนไลน์** แยกจากการที่ไม่มีพนักงานเป็นผู้จอง นัดที่สร้างด้วยวิธีอื่นในอนาคตที่ไม่ใส่ผู้จองจะถูกนับเป็นออนไลน์ด้วย

### index ที่ควรเพิ่มเมื่อข้อมูลโต

| ตาราง | index | ช่วยรายงาน |
|---|---|---|

| `consultations` | `(customer_id, opened_at)` | ลูกค้าใหม่และกลับมา (หาการมาครั้งแรกของแต่ละคน) |
