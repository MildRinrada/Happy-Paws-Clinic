# portal ลูกค้า

สิ่งที่เจ้าของสัตว์เห็นและทำได้หลังเข้าสู่ระบบ คือหน้าแรก สัตว์เลี้ยงของตัวเอง ประวัติการรักษาส่วนที่คลินิกเปิดให้ กล่องแจ้งเตือน ส่งไฟล์ให้คลินิก และแพ็กเกจ นัดหมาย ใบแจ้งหนี้ และความยินยอมของ portal อยู่ในหน้าของเรื่องนั้น ๆ

ทุก endpoint ใต้ `/portal/*` ต้องมี scope `portal` และจำกัดอยู่ที่สัตว์ที่ผู้เรียกดูแล สัตว์ของคนอื่นตอบ `404` ไม่ใช่ `403` เพื่อไม่บอกว่า id นั้นมีอยู่จริง การเข้าสู่ระบบของลูกค้าอยู่ใน [การเข้าสู่ระบบของลูกค้า](customer-sign-in.md) ส่วนที่ตีความเองอยู่ใน [ข้อสมมติ § 40](../assumptions.md)

## Endpoint

| Method | Endpoint | ทำอะไร |
|---|---|---|
| GET | `/portal/home` | สัตว์ นัดถัดไป คิววันนี้ แจ้งเตือน และวัคซีนที่ครบกำหนด ในคำขอเดียว |
| GET | `/portal/pets` | สัตว์ทั้งหมดที่บัญชีนี้ดูแล |
| PATCH | `/portal/pets/{id}` | แก้รูป ชื่อเล่น อาหาร และพฤติกรรม |
| GET | `/portal/pets/{id}/records` | ประวัติการรักษา เฉพาะส่วนที่คลินิกเปิดให้เห็น |
| GET | `/portal/notifications` | กล่องแจ้งเตือน |
| POST | `/portal/notifications/read` | ทำเครื่องหมายว่าอ่านแล้ว (ส่วนขยาย) |
| POST | `/portal/documents` | ส่งรูปอาการหรือผลจากคลินิกอื่น |
| GET | `/portal/packages` | แพ็กเกจและสิทธิ์ที่เหลือ |

## หน้าแรก

`GET /portal/home` รวมสิ่งที่หน้าแรกบนมือถือต้องใช้ในคำขอเดียว

| ช่อง | มาจาก |
|---|---|
| `pets` | เหมือน `GET /portal/pets` |
| `next_appointment` | นัดที่จะถึงซึ่งยังไม่ถูกยกเลิก |
| `queue` | บัตรคิววันนี้ที่ยังรออยู่ พร้อมจำนวนคิวที่อยู่ก่อน `pet_id` และ `appointment_id` (ไม่มีสำหรับ walk-in) |
| `unread_notifications`, `latest_notifications` | กล่องแจ้งเตือน สามข้อความล่าสุด |
| `vaccinations_due` | วัคซีนที่เลยกำหนดหรือครบกำหนดใน 30 วัน ของสัตว์ที่ยังมีชีวิต |

## สัตว์เลี้ยงและการแก้ข้อมูลของเจ้าของ

`GET /portal/pets` คืนสัตว์ทุกตัวที่บัญชีดูแล ทั้งเป็นเจ้าของหลักและผู้ดูแลร่วม สัตว์ที่เสียชีวิตยังอยู่ในรายการพร้อม `is_deceased` แต่ละตัวมีข้อมูลของคลินิก (ชื่อ ชนิด HN ไมโครชิป น้ำหนักล่าสุด การแพ้) ข้อมูลของเจ้าของ (ชื่อเล่น รูป อาหาร พฤติกรรม) และ `may_view_history` ว่าหน้าประวัติจะเปิดได้ไหม

```http
PATCH /v1/portal/pets/pet_...
{ "nickname": "ลูลู่", "diet": "อาหารเม็ดสูตรผิวแพ้ง่าย", "behaviour": "กลัวเสียงไดร์", "photo_document_id": "doc_..." }
```

- ส่งเฉพาะที่เปลี่ยน ส่งค่าว่างเพื่อลบ ใช้ `If-Match` ได้
- **แก้ได้แค่สี่ช่องนี้** request ไม่มีช่องอื่นเลย ส่งชื่อหรือชนิดมาก็ไม่มีที่ให้ลง เวชระเบียนจึงแตะไม่ได้โดยโครงสร้าง ไม่ใช่โดยการตรวจที่อาจลืม
- รูปต้องเป็นไฟล์รูปภาพของสัตว์ตัวนั้นที่ส่งผ่าน `POST /portal/documents` และอัปโหลดเสร็จแล้ว ไม่อย่างนั้นได้ `422` ที่ `photo_document_id`
- พนักงานเห็นสี่ช่องนี้ใน `GET /staff/pets/{id}` ด้วย พฤติกรรมคือสิ่งที่ผู้ช่วยอยากรู้ก่อนเปิดกรง

## ประวัติการรักษา

`GET /portal/pets/{id}/records` ต้องเป็นผู้ดูแลที่ลิงก์อนุญาตให้ดูประวัติ ไม่อย่างนั้น `404`

คลินิกเลือกส่วนที่เปิดให้เจ้าของเห็นด้วย `PATCH /clinic/settings/medical-record` ช่อง `owner_visible_sections` ค่าตั้งต้นคือไม่เปิดเลย เจ้าของจึงเห็นแค่วันที่มาตรวจ

| ส่วน | สิ่งที่เจ้าของเห็น |
|---|---|
| `vitals` | น้ำหนัก อุณหภูมิ ชีพจร การหายใจ |
| `examination` | ระบบที่ตรวจ ปกติหรือไม่ และหมายเหตุ |
| `diagnosis` | คำวินิจฉัย |
| `treatment` | ชื่อหัตถการและจำนวน ไม่มีราคา |
| `prescription` | ยา ขนาด วิธีใช้ จำนวนวัน คำแนะนำ |
| `lab_result` | ผลแล็บ **เฉพาะที่หมออ่านแล้ว** |
| `attachments` | ไฟล์ที่คลินิกเลือกให้เห็น และไฟล์ที่เจ้าของส่งเอง พร้อมลิงก์ดาวน์โหลดอายุ 10 นาที |

- ส่วนที่ไม่เปิด **ไม่อยู่ในคำตอบเลย** ไม่ใช่รายการว่าง "ไม่มียา" กับ "คลินิกไม่แสดงยาที่นี่" ต่างกัน
- คำตอบสร้างเป็นรูปของเจ้าของตั้งแต่ต้น ไม่มีช่องสำหรับราคา หมายเหตุภายใน หรือ id ของคนที่ทำ
- ผลแล็บแสดงหลังหมออ่าน เพราะเจ้าของไม่ควรรู้ค่าผิดปกติจากหน้าเว็บก่อนคนในคลินิก
- เวชระเบียนที่มี amendment แสดงฉบับล่าสุด

## กล่องแจ้งเตือน

**ทุกข้อความที่คลินิกส่งถึงลูกค้าเข้ากล่องนี้** หลังผ่านด่านความยินยอม และก่อนส่งเข้าช่องทางใด ข้อความที่ LINE ส่งไม่ถึงจึงยังอยู่ในกล่อง ข้อความที่ถูกระงับเพราะไม่ได้ยินยอม ไม่เข้ากล่องด้วย

```json
{ "data": [ { "id": "ntf_...", "template": "queue.called", "title": "ถึงคิว A014 แล้ว", "body": "เชิญที่ห้องตรวจ room_2", "sent_at": "...", "read_at": null } ],
  "page": { "next_cursor": null }, "unread_count": 1 }
```

- `?unread=true` เอาเฉพาะที่ยังไม่อ่าน
- การเปิดรายการไม่ทำเครื่องหมายอะไร
- `POST /portal/notifications/read` ส่ง `{ "ids": [...] }` หรือ `{}` เพื่อทำทั้งหมด ได้ `marked` และ `unread_count` คืน id ที่ไม่ใช่ของตัวเองไม่มีผล ดู [contract-extensions.md § 13](../contract-extensions.md)

## ส่งไฟล์ให้คลินิก

```http
POST /v1/portal/documents
{ "pet_id": "pet_...", "file_name": "rash.jpg", "content_type": "image/jpeg", "size_bytes": 204800, "kind": "photo" }
```

ได้ URL สำหรับ `PUT` ไฟล์ แบบเดียวกับฝั่งพนักงาน ดู [งานรักษาต่อเนื่อง](clinical-records.md#ไฟล์แนบในแฟ้มสัตว์) ไฟล์ถูกระบุว่ามาจากเจ้าของ (`source: owner`) คลินิกจึงแยกได้ว่าอะไรคลินิกเขียน อะไรเจ้าของส่งมา และเจ้าของเห็นไฟล์ของตัวเองเสมอ

## แพ็กเกจ

`GET /portal/packages` คืนแพ็กเกจที่ซื้อไว้ จำนวนครั้งทั้งหมด ใช้ไปแล้ว ที่เหลือ วันหมดอายุ และ `status` (`active`, `used_up`, `expired`) แพ็กเกจที่ใช้ได้ขึ้นก่อน

**ตอนนี้ว่างเสมอ** การขายแพ็กเกจคือ `POST /staff/packages` ของ Tier 3 ซึ่งยังไม่ได้ทำ ตารางและการอ่านพร้อมแล้ว

## หน้าเว็บของลูกค้า

ลูกค้าที่เข้าสู่ระบบที่ `/login` มาถึง `/portal` ส่วนพนักงานไปหน้าคิวของคลินิกที่ `/queue` หน้าของลูกค้าทุกหน้ามี `/portal` นำหน้า เพราะ `/queue` ถูกใช้ไปแล้ว

| หน้า | ที่อยู่ | แสดงอะไร |
|---|---|---|
| หน้าแรก | `/portal` | การ์ดคิวและนัด วัคซีนที่ใกล้ครบกำหนด สัตว์เลี้ยง และแจ้งเตือนล่าสุด |
| สัตว์เลี้ยงของฉัน | `/portal/pets` | การ์ดของสัตว์แต่ละตัว: ข้อมูลที่คลินิกบันทึก อาหาร พฤติกรรม และการแพ้ |
| นัดหมาย | `/portal/appointments` | นัดที่กำลังจะถึง และนัดที่ผ่านมา อย่างละ 20 รายการ |
| ประวัติการรักษา | `/portal/records?pet=` | ประวัติทีละตัว เลือกสัตว์ได้ด้านบน |
| จองนัด | `/portal/book?pet=` | จองนัดสามขั้น: รายละเอียด วันและเวลา ยืนยัน |
| แก้ข้อมูลสัตว์เลี้ยง | `/portal/pets/{id}/edit` | รูป ชื่อเล่น อาหาร และพฤติกรรม |
| แจ้งเตือน | `/portal/notifications` | กล่องแจ้งเตือนเต็ม แยกแท็บทั้งหมดและยังไม่อ่าน |
| บัญชีของฉัน | `/portal/account` | ข้อมูลติดต่อ ช่องทางรับข้อความ รหัสผ่าน ความยินยอม อุปกรณ์ และคำขอ PDPA |

`/portal/queue` ที่อยู่เดิมของการ์ดยังเปิดได้ และจะพาไป `/portal`

ปุ่ม "จองนัดหมาย" บนหน้าแรกสาธารณะและท้ายเว็บลิงก์ไป `/portal/book` ถ้ายังไม่ได้ล็อกอิน middleware จะพาไป `/login?next=/portal/book` และหลังล็อกอินจะกลับมาหน้าจอง ค่า `next` ถูกตรวจบนเซิร์ฟเวอร์ (`destinationFor` ใน `features/authentication/lib/home-path.ts`) รับเฉพาะ path ในเว็บนี้ และเฉพาะหน้าที่บัญชีนั้นใช้ได้ หน้าใน `/portal` ต้องเป็นลูกค้า หน้าอื่นต้องเป็นพนักงาน

### จองนัด

1. **รายละเอียด** เลือกสัตว์ (เฉพาะตัวที่ยังมีชีวิต) สาขา (แสดงเมื่อมีมากกว่าหนึ่ง) บริการที่เปิดจองออนไลน์ของสาขานั้น ประเภทนัด (นัดปกติหรือติดตามผล ซึ่งเป็นสองประเภทที่ลูกค้าจองได้ตามค่าตั้งต้น) และอาการถ้ามี
2. **วันและเวลา** เลือกวันจากปุ่ม 14 วันข้างหน้า หรือช่องวันที่ แล้วเลือกเวลาที่ว่างจาก `GET /booking/availability` ถ้าวันนั้นมีหมอว่างมากกว่าหนึ่งคน จะเลือกหมอได้ ถ้าไม่เลือก backend เลือกหมอที่ว่างให้
3. **ยืนยัน** การกดเลือกเวลาจะกันเวลาไว้ทันทีด้วย `POST /booking/holds` นาน 10 นาที หน้ายืนยันนับถอยหลังให้เห็น กดยืนยันแล้วเรียก `POST /portal/appointments` พร้อม `hold_id`

- idempotency key ผูกกับการกันเวลาแต่ละครั้ง กดยืนยันซ้ำได้นัดเดียว เลือกเวลาใหม่ได้ key ใหม่
- เวลาที่ถูกจองไปก่อน (`slot_unavailable`) กลับไปขั้นที่ 2 พร้อมปุ่มเวลาใกล้เคียงที่ backend เสนอใน `details.suggested`
- กันเวลาหมดอายุ (`hold_expired`) ปุ่มยืนยันกดไม่ได้ และบอกให้เลือกเวลาใหม่
- ไม่มี endpoint ยกเลิกการกันเวลา ถ้าลูกค้าเปลี่ยนเวลา เวลาเดิมจะถูกกันไว้จนครบ 10 นาที
- ลูกค้าอ่านค่าตั้งการจองไม่ได้ (ต้องมี `settings:read`) หน้าเว็บจึงไม่รู้ว่าจองล่วงหน้าได้กี่วัน วันที่เกินจะได้รายการเวลาว่างเปล่า

### แก้ข้อมูลสัตว์เลี้ยง

- ส่งทั้งสามช่องข้อความทุกครั้ง ช่องที่ลบจนว่างคือการล้างข้อมูลช่องนั้น และส่ง `If-Match` เป็น `version` ถ้ามีการแก้จากที่อื่นก่อน จะได้ข้อความให้โหลดหน้าใหม่ ไม่เขียนทับกัน
- **รูปส่งตรงจากเบราว์เซอร์ไปที่เก็บไฟล์** หน้าเว็บขอ `POST /portal/documents` (kind `photo`) ได้ URL ที่เซ็นแล้ว เบราว์เซอร์ `PUT` ไฟล์ไปที่ URL นั้นเอง แล้วจึงบันทึก `photo_document_id` ไฟล์ไม่ผ่านเซิร์ฟเวอร์หน้าเว็บ
- ไฟล์ที่รับได้คือ JPG, PNG, WEBP และ HEIC ไม่เกิน 10 MB ตรวจในหน้าเว็บก่อน และ backend ตรวจซ้ำ
- **ก่อนติดตั้งจริง** เบราว์เซอร์ของลูกค้าต้องเข้าถึง `Storage:PublicBaseUrl` ได้ และต้องใส่ origin ของหน้าเว็บใน `Cors:AllowedOrigins` ของ API ตอนนี้ตั้งไว้เฉพาะ `http://localhost:3000` ใน development

### แจ้งเตือน

- หน้าละ 20 ข้อความ ดูข้อความเก่ากว่าด้วยลิงก์ที่มี `cursor` API เดินหน้าได้อย่างเดียว จึงมีแค่ลิงก์กลับไปข้อความล่าสุด ไม่มีปุ่มย้อนทีละหน้า
- ปุ่ม "อ่านแล้ว" ทีละข้อความ และ "อ่านแล้วทั้งหมด" เรียก `POST /portal/notifications/read` แล้วรีเฟรชตัวเลขบนกระดิ่ง

### บัญชีของฉัน

- **ข้อมูลส่วนตัวและช่องทางรับข้อความ** เขียนผ่าน `PATCH /me` ทั้งคู่ และใช้ `version` ร่วมกัน บันทึกฟอร์มหนึ่งแล้วอีกฟอร์มยังบันทึกต่อได้ การเปลี่ยนอีเมลหรือเบอร์โทรต้องใส่รหัสผ่านปัจจุบัน ช่องนี้จะขึ้นเมื่อแก้สองช่องนั้นเท่านั้น
- **เปลี่ยนรหัสผ่าน** backend ตอบรหัสเดิมผิดด้วย `401` ซึ่งเป็นรหัสเดียวกับ session หมดอายุ action นี้จึงไม่ใช้ตัวจัดการกลางที่จะพาไปหน้าเข้าสู่ระบบ แต่แสดงว่ารหัสผ่านปัจจุบันไม่ถูกต้องที่ช่องนั้น เปลี่ยนสำเร็จแล้ว อุปกรณ์อื่นทุกเครื่องถูกออกจากระบบ
- **ความยินยอม** ส่งเฉพาะสวิตช์ที่ลูกค้าขยับ ค่าตั้งต้นที่ไม่ได้แตะจึงยังเป็นค่าตั้งต้น ไม่กลายเป็นการตัดสินใจที่บันทึกไว้
- **อุปกรณ์** แสดงชื่อเบราว์เซอร์และระบบจาก user agent แบบคร่าว ๆ ออกจากระบบเครื่องอื่นได้ทีละเครื่อง เครื่องที่ใช้อยู่ออกจากระบบได้จากเมนูชื่อ
- **คำขอ PDPA** ส่ง `POST /portal/data-requests` แบบ ขอดูข้อมูล แก้ไข ขอรับเป็นไฟล์ หรือขอลบ เจ้าหน้าที่ดำเนินการต่อ

### หัวเว็บสองแบบ

- **ในหน้าของลูกค้า** หัวเว็บมีเมนู หน้าแรก สัตว์เลี้ยงของฉัน นัดหมาย และประวัติการรักษา ทางขวามีกระดิ่งพร้อมจำนวนที่ยังไม่อ่าน ปุ่มจองนัด และเมนูชื่อลูกค้า (บัญชีของฉัน แจ้งเตือน หน้าเว็บคลินิก และออกจากระบบ) บนมือถือ เมนูย้ายไปเป็นแถบล่างจอ 4 ปุ่ม
- **ในหน้าสาธารณะตอนล็อกอินอยู่** เมนูยังเป็นของหน้าสาธารณะ แต่ปุ่ม "เข้าสู่ระบบ" และ "สมัครใช้งานฟรี" กลายเป็นปุ่ม "บัญชีของฉัน" ปุ่มนี้ลิงก์ไป `/login` ซึ่งพาลูกค้าไป portal และพาพนักงานไปหน้าคิว
- หน้าสาธารณะยังเป็นหน้า static จึงไม่ได้อ่าน session จริง หน้าเว็บรู้ว่าล็อกอินอยู่จากคุกกี้ `hp_signed_in` ซึ่งมีค่าเป็น `1` เท่านั้น ไม่ใช่รหัสผ่านหรือ token ถ้าค่าในคุกกี้ไม่ตรงกับความจริง ปุ่มก็แค่พาไปหน้า `/login` ซึ่งตรวจ session จริงอีกครั้ง
- กระดิ่งลิงก์ไปหน้าแจ้งเตือน (`/portal/notifications`)

### การ์ดคิวและนัด

หน้าแรกแสดง**การ์ดหนึ่งใบต่อหนึ่งการมาคลินิก** วันนี้มีนัดหรือคิวกี่รายการก็ได้การ์ดเท่านั้น เช่น หมามีนัดและแมวมาแบบ walk-in จะได้สองการ์ด เรียงจากที่ถูกเรียกอยู่ อยู่ในห้องตรวจ รอเรียก แล้วจึงที่ยังไม่มาถึง ถ้าวันนี้ไม่มีอะไรเลย จะแสดงนัดถัดไปหนึ่งใบ

บัตรคิวใน `GET /portal/home` มี `pet_id` และ `appointment_id` (ไม่มีสำหรับ walk-in) หน้าเว็บจับคู่บัตรกับนัดด้วย `appointment_id` เท่านั้น เลขคิวของสัตว์ตัวหนึ่งจึงไม่ไปขึ้นบนการ์ดของอีกตัว สองช่องนี้เพิ่มหลังทดลองกับข้อมูลจริง ก่อนหน้านั้นการ์ดนัดของหมาเคยหยิบเลขคิว walk-in ของแมวมาแสดง และซ่อนปุ่มเช็กอินของหมา

การ์ดแต่ละใบแสดง
- บริการ ชื่อสัตว์ ชื่อหมอ และเวลานัด
- เลขคิวและจำนวนคิวที่อยู่ก่อน
- แถบความคืบหน้า เช็กอิน รอเรียก ตรวจ ชำระเงิน
- กล่องสีเหลืองบอกสิ่งที่ควรทำตอนนี้
- ปุ่มเช็กอินล่วงหน้า เลื่อนนัด และแชทกับคลินิก

- **นัดของวันนี้มาก่อน** แม้เลยเวลาเริ่มแล้ว เพราะ `next_appointment` ของ `GET /portal/home` นับจากตอนนี้ไปข้างหน้า นัด 10:30 จะหายจากการ์ดตอน 10:31 ทั้งที่น้องยังรอตรวจอยู่ หน้าเว็บจึงอ่าน `GET /portal/appointments?upcoming=false` ประกอบด้วย
- **ชื่อบริการและชื่อหมอ** มาจาก `GET /services` และ `GET /team` บริการที่ไม่ได้เปิดจองออนไลน์จึงไม่มีชื่อ และหมอที่ไม่ได้แสดงบนหน้าทีมขึ้นเป็น "สัตวแพทย์ที่ว่างในวันนั้น"
- **กล่องสีเหลืองก่อนเช็กอิน** บอกเวลาที่ควรมาถึง คือเวลานัดลบ 15 นาที ไม่ได้บอกว่าควรออกจากบ้านเมื่อไร เพราะระบบไม่มีตำแหน่งของลูกค้าและข้อมูลจราจร
- **เช็กอินล่วงหน้า** เรียก `POST /appointments/{id}/check-in` พร้อม idempotency key การกดซ้ำไม่ทำให้ได้สองคิว ถ้า backend ปฏิเสธ เช่นยังไม่ถึงเวลา ข้อความจะขึ้นใต้ปุ่ม
- **อัปเดตเองทุก 15 วินาที** ระหว่างที่เปิดหน้าอยู่ และหยุดเมื่อสลับแท็บหรือปิดจอ
- ปุ่มเลื่อนนัดและแชทกับคลินิกยังชี้ไป `#` เพราะยังไม่มีหน้านั้น แก้ลิงก์ได้ที่ `frontend/src/features/portal/content/visit-card.ts`

### ประวัติการรักษา

- มีให้เลือกเฉพาะสัตว์ที่ `may_view_history` เป็นจริง ผู้ดูแลร่วมที่ลิงก์ไม่อนุญาตจึงไม่เห็นตัวเลือกนั้น
- ถ้าคลินิกยังไม่เปิดส่วนใดเลย (`visible_sections` ว่าง ซึ่งเป็นค่าตั้งต้น) หน้าเว็บบอกตรง ๆ ว่าตอนนี้เห็นแค่วันที่มาตรวจ ไม่ปล่อยให้ดูเหมือนข้อมูลหาย
- ส่วนที่ API ไม่ส่งมาไม่ถูกวาดเลย ส่วนที่ส่งมาแต่ว่างขึ้นว่า "ไม่มี"

## ข้อจำกัดที่รู้อยู่

- หน้าแพ็กเกจ เลื่อนนัด ยกเลิกนัด และแชทกับคลินิกยังไม่มีหน้าเว็บ ปุ่มเลื่อนนัดและแชทบนการ์ดยังชี้ไป `#`
- ลูกค้าส่งไฟล์อื่นที่ไม่ใช่รูปสัตว์ (เช่นผลจากคลินิกอื่น) จากหน้าเว็บยังไม่ได้ แม้ `POST /portal/documents` จะรับแล้ว
- กล่องแจ้งเตือนไม่ถูกลบ
- ยังขายและตัดสิทธิ์แพ็กเกจไม่ได้
- ดาวน์โหลดไฟล์ด้วยลิงก์ที่ใครได้ไปก็เปิดได้จนหมดอายุ 10 นาที
