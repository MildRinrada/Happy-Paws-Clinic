# portal ลูกค้า

สิ่งที่เจ้าของสัตว์เห็นและทำได้หลังเข้าสู่ระบบ คือหน้าแรก สัตว์เลี้ยงของตัวเอง ประวัติการรักษาส่วนที่คลินิกเปิดให้ กล่องแจ้งเตือน ส่งไฟล์ให้คลินิก และแพ็กเกจ นัดหมาย ใบแจ้งหนี้ และความยินยอมของ portal อยู่ในหน้าของเรื่องนั้น ๆ

ทุก endpoint ใต้ `/portal/*` ต้องมี scope `portal` และจำกัดอยู่ที่สัตว์ที่ผู้เรียกดูแล สัตว์ของคนอื่นตอบ `404` ไม่ใช่ `403` เพื่อไม่บอกว่า id นั้นมีอยู่จริง การเข้าสู่ระบบของลูกค้าอยู่ใน [การเข้าสู่ระบบของลูกค้า](customer-sign-in.md) ส่วนที่ตีความเองอยู่ใน [ข้อสมมติ § 40](../assumptions.md)

## Endpoint

| Method | Endpoint | ทำอะไร |
|---|---|---|
| GET | `/portal/home` | สัตว์ นัดถัดไป คิววันนี้ แจ้งเตือน และวัคซีนที่ครบกำหนด ในคำขอเดียว |
| GET | `/portal/pets` | สัตว์ทั้งหมดที่บัญชีนี้ดูแล |
| PATCH | `/portal/pets/{id}` | แก้รูป ชื่อเล่น อาหาร และพฤติกรรม |
| GET | `/portal/pets/{id}/records` | ประวัติการรักษา เฉพาะส่วนที่คลินิกเปิดให้เห็น |
| GET | `/portal/notifications` | กล่องแจ้งเตือน |
| POST | `/portal/notifications/read` | ทำเครื่องหมายว่าอ่านแล้ว (ส่วนขยาย) |
| POST | `/portal/documents` | ส่งรูปอาการหรือผลจากคลินิกอื่น |
| GET | `/portal/packages` | แพ็กเกจและสิทธิ์ที่เหลือ |

## หน้าแรก

`GET /portal/home` รวมสิ่งที่หน้าแรกบนมือถือต้องใช้ในคำขอเดียว

| ช่อง | มาจาก |
|---|---|
| `pets` | เหมือน `GET /portal/pets` |
| `next_appointment` | นัดที่จะถึงซึ่งยังไม่ถูกยกเลิก |
| `queue` | บัตรคิววันนี้ที่ยังรออยู่ พร้อมจำนวนคิวที่อยู่ก่อน |
| `unread_notifications`, `latest_notifications` | กล่องแจ้งเตือน สามข้อความล่าสุด |
| `vaccinations_due` | วัคซีนที่เลยกำหนดหรือครบกำหนดใน 30 วัน ของสัตว์ที่ยังมีชีวิต |

## สัตว์เลี้ยงและการแก้ข้อมูลของเจ้าของ

`GET /portal/pets` คืนสัตว์ทุกตัวที่บัญชีดูแล ทั้งเป็นเจ้าของหลักและผู้ดูแลร่วม สัตว์ที่เสียชีวิตยังอยู่ในรายการพร้อม `is_deceased` แต่ละตัวมีข้อมูลของคลินิก (ชื่อ ชนิด HN ไมโครชิป น้ำหนักล่าสุด การแพ้) ข้อมูลของเจ้าของ (ชื่อเล่น รูป อาหาร พฤติกรรม) และ `may_view_history` ว่าหน้าประวัติจะเปิดได้ไหม

```http
PATCH /v1/portal/pets/pet_...
{ "nickname": "ลูลู่", "diet": "อาหารเม็ดสูตรผิวแพ้ง่าย", "behaviour": "กลัวเสียงไดร์", "photo_document_id": "doc_..." }
```

- ส่งเฉพาะที่เปลี่ยน ส่งค่าว่างเพื่อลบ ใช้ `If-Match` ได้
- **แก้ได้แค่สี่ช่องนี้** request ไม่มีช่องอื่นเลย ส่งชื่อหรือชนิดมาก็ไม่มีที่ให้ลง เวชระเบียนจึงแตะไม่ได้โดยโครงสร้าง ไม่ใช่โดยการตรวจที่อาจลืม
- รูปต้องเป็นไฟล์รูปภาพของสัตว์ตัวนั้นที่ส่งผ่าน `POST /portal/documents` และอัปโหลดเสร็จแล้ว ไม่อย่างนั้นได้ `422` ที่ `photo_document_id`
- พนักงานเห็นสี่ช่องนี้ใน `GET /staff/pets/{id}` ด้วย พฤติกรรมคือสิ่งที่ผู้ช่วยอยากรู้ก่อนเปิดกรง

## ประวัติการรักษา

`GET /portal/pets/{id}/records` ต้องเป็นผู้ดูแลที่ลิงก์อนุญาตให้ดูประวัติ ไม่อย่างนั้น `404`

คลินิกเลือกส่วนที่เปิดให้เจ้าของเห็นด้วย `PATCH /clinic/settings/medical-record` ช่อง `owner_visible_sections` ค่าตั้งต้นคือไม่เปิดเลย เจ้าของจึงเห็นแค่วันที่มาตรวจ

| ส่วน | สิ่งที่เจ้าของเห็น |
|---|---|
| `vitals` | น้ำหนัก อุณหภูมิ ชีพจร การหายใจ |
| `examination` | ระบบที่ตรวจ ปกติหรือไม่ และหมายเหตุ |
| `diagnosis` | คำวินิจฉัย |
| `treatment` | ชื่อหัตถการและจำนวน ไม่มีราคา |
| `prescription` | ยา ขนาด วิธีใช้ จำนวนวัน คำแนะนำ |
| `lab_result` | ผลแล็บ **เฉพาะที่หมออ่านแล้ว** |
| `attachments` | ไฟล์ที่คลินิกเลือกให้เห็น และไฟล์ที่เจ้าของส่งเอง พร้อมลิงก์ดาวน์โหลดอายุ 10 นาที |

- ส่วนที่ไม่เปิด **ไม่อยู่ในคำตอบเลย** ไม่ใช่รายการว่าง "ไม่มียา" กับ "คลินิกไม่แสดงยาที่นี่" ต่างกัน
- คำตอบสร้างเป็นรูปของเจ้าของตั้งแต่ต้น ไม่มีช่องสำหรับราคา หมายเหตุภายใน หรือ id ของคนที่ทำ
- ผลแล็บแสดงหลังหมออ่าน เพราะเจ้าของไม่ควรรู้ค่าผิดปกติจากหน้าเว็บก่อนคนในคลินิก
- เวชระเบียนที่มี amendment แสดงฉบับล่าสุด

## กล่องแจ้งเตือน

**ทุกข้อความที่คลินิกส่งถึงลูกค้าเข้ากล่องนี้** หลังผ่านด่านความยินยอม และก่อนส่งเข้าช่องทางใด ข้อความที่ LINE ส่งไม่ถึงจึงยังอยู่ในกล่อง ข้อความที่ถูกระงับเพราะไม่ได้ยินยอม ไม่เข้ากล่องด้วย

```json
{ "data": [ { "id": "ntf_...", "template": "queue.called", "title": "ถึงคิว A014 แล้ว", "body": "เชิญที่ห้องตรวจ room_2", "sent_at": "...", "read_at": null } ],
  "page": { "next_cursor": null }, "unread_count": 1 }
```

- `?unread=true` เอาเฉพาะที่ยังไม่อ่าน
- การเปิดรายการไม่ทำเครื่องหมายอะไร
- `POST /portal/notifications/read` ส่ง `{ "ids": [...] }` หรือ `{}` เพื่อทำทั้งหมด ได้ `marked` และ `unread_count` คืน id ที่ไม่ใช่ของตัวเองไม่มีผล ดู [contract-extensions.md § 13](../contract-extensions.md)

## ส่งไฟล์ให้คลินิก

```http
POST /v1/portal/documents
{ "pet_id": "pet_...", "file_name": "rash.jpg", "content_type": "image/jpeg", "size_bytes": 204800, "kind": "photo" }
```

ได้ URL สำหรับ `PUT` ไฟล์ แบบเดียวกับฝั่งพนักงาน ดู [งานรักษาต่อเนื่อง](clinical-records.md#ไฟล์แนบในแฟ้มสัตว์) ไฟล์ถูกระบุว่ามาจากเจ้าของ (`source: owner`) คลินิกจึงแยกได้ว่าอะไรคลินิกเขียน อะไรเจ้าของส่งมา และเจ้าของเห็นไฟล์ของตัวเองเสมอ

## แพ็กเกจ

`GET /portal/packages` คืนแพ็กเกจที่ซื้อไว้ จำนวนครั้งทั้งหมด ใช้ไปแล้ว ที่เหลือ วันหมดอายุ และ `status` (`active`, `used_up`, `expired`) แพ็กเกจที่ใช้ได้ขึ้นก่อน

**ตอนนี้ว่างเสมอ** การขายแพ็กเกจคือ `POST /staff/packages` ของ Tier 3 ซึ่งยังไม่ได้ทำ ตารางและการอ่านพร้อมแล้ว

## ข้อจำกัดที่รู้อยู่

- ยังไม่มีหน้าเว็บฝั่งลูกค้า
- กล่องแจ้งเตือนไม่ถูกลบ
- ยังขายและตัดสิทธิ์แพ็กเกจไม่ได้
- ดาวน์โหลดไฟล์ด้วยลิงก์ที่ใครได้ไปก็เปิดได้จนหมดอายุ 10 นาที
