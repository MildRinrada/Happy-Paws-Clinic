# portal ลูกค้า

สิ่งที่เจ้าของสัตว์เห็นและทำได้หลังเข้าสู่ระบบ คือหน้าแรก สัตว์เลี้ยงของตัวเอง ประวัติการรักษาส่วนที่คลินิกเปิดให้ กล่องแจ้งเตือน ส่งไฟล์ให้คลินิก และแพ็กเกจ นัดหมาย ใบแจ้งหนี้ และความยินยอมของ portal อยู่ในหน้าของเรื่องนั้น ๆ

ทุก endpoint ใต้ `/portal/*` ต้องมี scope `portal` และจำกัดอยู่ที่สัตว์ที่ผู้เรียกดูแล สัตว์ของคนอื่นตอบ `404` ไม่ใช่ `403` เพื่อไม่บอกว่า id นั้นมีอยู่จริง การเข้าสู่ระบบของลูกค้าอยู่ใน [การเข้าสู่ระบบของลูกค้า](customer-sign-in.md) ส่วนที่ตีความเองอยู่ใน [ข้อสมมติ § 40](../assumptions.md)

## Endpoint

| Method | Endpoint | ทำอะไร |
|---|---|---|
| GET | `/portal/home` | สัตว์ นัดถัดไป คิววันนี้ แจ้งเตือน และวัคซีนที่ครบกำหนด ในคำขอเดียว |
| GET | `/portal/pets` | สัตว์ทั้งหมดที่บัญชีนี้ดูแล |
| PATCH | `/portal/pets/{id}` | แก้รูป ชื่อเล่น อาหาร และพฤติกรรม |
| GET | `/portal/pets/{id}/records` | ประวัติการรักษา เฉพาะส่วนที่คลินิกเปิดให้เห็น |
| GET | `/portal/notifications` | กล่องแจ้งเตือน |
| POST | `/portal/notifications/read` | ทำเครื่องหมายว่าอ่านแล้ว (ส่วนขยาย) |
| POST | `/portal/documents` | ส่งรูปอาการหรือผลจากคลินิกอื่น |
| GET | `/portal/packages` | แพ็กเกจและสิทธิ์ที่เหลือ |
| GET | `/portal/invoices` | บิลของตัวเอง `?unpaid=true` คือบิลที่ยังค้าง รายละเอียดอยู่ใน [บิลและการชำระเงิน](billing.md) |
| GET | `/portal/thread` | บทสนทนากับคลินิกของตัวเอง ใหม่ไปเก่า (ส่วนขยาย § 24) |
| POST | `/portal/thread/messages` | เขียนถึงคลินิก (ส่วนขยาย § 24) |

หน้าเลื่อนนัดและยกเลิกนัดใช้ endpoint ที่พนักงานกับลูกค้าใช้ร่วมกัน คือ `GET /appointments/{id}`, `POST /appointments/{id}/reschedule` และ `POST /appointments/{id}/cancel` กติกาอยู่ใน [การจองและนัดหมาย](booking-and-appointments.md) และ [นัดขั้นสูง](advanced-booking.md)

## หน้าแรก

`GET /portal/home` รวมสิ่งที่หน้าแรกบนมือถือต้องใช้ในคำขอเดียว

| ช่อง | มาจาก |
|---|---|
| `pets` | เหมือน `GET /portal/pets` |
| `next_appointment` | นัดที่จะถึงซึ่งยังไม่ถูกยกเลิก |
| `queue` | บัตรคิววันนี้ที่ยังรออยู่ พร้อมจำนวนคิวที่อยู่ก่อน `pet_id` และ `appointment_id` (ไม่มีสำหรับ walk-in) |
| `unread_notifications`, `latest_notifications` | กล่องแจ้งเตือน สามข้อความล่าสุด |
| `vaccinations_due` | วัคซีนที่เลยกำหนดหรือครบกำหนดใน 30 วัน ของสัตว์ที่ยังมีชีวิต |

## สัตว์เลี้ยงและการแก้ข้อมูลของเจ้าของ

`GET /portal/pets` คืนสัตว์ทุกตัวที่บัญชีดูแล ทั้งเป็นเจ้าของหลักและผู้ดูแลร่วม สัตว์ที่เสียชีวิตยังอยู่ในรายการพร้อม `is_deceased` แต่ละตัวมีข้อมูลของคลินิก (ชื่อ ชนิด HN ไมโครชิป น้ำหนักล่าสุด การแพ้) ข้อมูลของเจ้าของ (ชื่อเล่น รูป อาหาร พฤติกรรม) และ `may_view_history` ว่าหน้าประวัติจะเปิดได้ไหม

```http
PATCH /v1/portal/pets/pet_...
{ "nickname": "ลูลู่", "diet": "อาหารเม็ดสูตรผิวแพ้ง่าย", "behaviour": "กลัวเสียงไดร์", "photo_document_id": "doc_..." }
```

- ส่งเฉพาะที่เปลี่ยน ส่งค่าว่างเพื่อลบ ใช้ `If-Match` ได้
- **แก้ได้แค่สี่ช่องนี้** request ไม่มีช่องอื่นเลย ส่งชื่อหรือชนิดมาก็ไม่มีที่ให้ลง เวชระเบียนจึงแตะไม่ได้โดยโครงสร้าง ไม่ใช่โดยการตรวจที่อาจลืม
- รูปต้องเป็นไฟล์รูปภาพของสัตว์ตัวนั้นที่ส่งผ่าน `POST /portal/documents` และอัปโหลดเสร็จแล้ว ไม่อย่างนั้นได้ `422` ที่ `photo_document_id`
- พนักงานเห็นสี่ช่องนี้ใน `GET /staff/pets/{id}` ด้วย พฤติกรรมคือสิ่งที่ผู้ช่วยอยากรู้ก่อนเปิดกรง

## ประวัติการรักษา

`GET /portal/pets/{id}/records` ต้องเป็นผู้ดูแลที่ลิงก์อนุญาตให้ดูประวัติ ไม่อย่างนั้น `404`

คลินิกเลือกส่วนที่เปิดให้เจ้าของเห็นด้วย `PATCH /clinic/settings/medical-record` ช่อง `owner_visible_sections` ค่าตั้งต้นคือไม่เปิดเลย เจ้าของจึงเห็นแค่วันที่มาตรวจ

| ส่วน | สิ่งที่เจ้าของเห็น |
|---|---|
| `vitals` | น้ำหนัก อุณหภูมิ ชีพจร การหายใจ |
| `examination` | ระบบที่ตรวจ ปกติหรือไม่ และหมายเหตุ |
| `diagnosis` | คำวินิจฉัย |
| `treatment` | ชื่อหัตถการและจำนวน ไม่มีราคา |
| `prescription` | ยา ขนาด วิธีใช้ จำนวนวัน คำแนะนำ |
| `lab_result` | ผลแล็บ **เฉพาะที่หมออ่านแล้ว** |
| `attachments` | ไฟล์ที่คลินิกเลือกให้เห็น และไฟล์ที่เจ้าของส่งเอง พร้อมลิงก์ดาวน์โหลดอายุ 10 นาที |

- ส่วนที่ไม่เปิด **ไม่อยู่ในคำตอบเลย** ไม่ใช่รายการว่าง "ไม่มียา" กับ "คลินิกไม่แสดงยาที่นี่" ต่างกัน
- คำตอบสร้างเป็นรูปของเจ้าของตั้งแต่ต้น ไม่มีช่องสำหรับราคา หมายเหตุภายใน หรือ id ของคนที่ทำ
- ผลแล็บแสดงหลังหมออ่าน เพราะเจ้าของไม่ควรรู้ค่าผิดปกติจากหน้าเว็บก่อนคนในคลินิก
- เวชระเบียนที่มี amendment แสดงฉบับล่าสุด

## กล่องแจ้งเตือน

**ทุกข้อความที่คลินิกส่งถึงลูกค้าเข้ากล่องนี้** หลังผ่านด่านความยินยอม และก่อนส่งเข้าช่องทางใด ข้อความที่ LINE ส่งไม่ถึงจึงยังอยู่ในกล่อง ข้อความที่ถูกระงับเพราะไม่ได้ยินยอม ไม่เข้ากล่องด้วย

```json
{ "data": [ { "id": "ntf_...", "template": "queue.called", "title": "ถึงคิว A014 แล้ว", "body": "เชิญที่ห้องตรวจ room_2", "sent_at": "...", "read_at": null } ],
  "page": { "next_cursor": null }, "unread_count": 1 }
```

- `?unread=true` เอาเฉพาะที่ยังไม่อ่าน
- การเปิดรายการไม่ทำเครื่องหมายอะไร
- `POST /portal/notifications/read` ส่ง `{ "ids": [...] }` หรือ `{}` เพื่อทำทั้งหมด ได้ `marked` และ `unread_count` คืน id ที่ไม่ใช่ของตัวเองไม่มีผล ดู [contract-extensions.md § 13](../contract-extensions.md)

## ส่งไฟล์ให้คลินิก

```http
POST /v1/portal/documents
{ "pet_id": "pet_...", "file_name": "rash.jpg", "content_type": "image/jpeg", "size_bytes": 204800, "kind": "photo" }
```

ได้ URL สำหรับ `PUT` ไฟล์ แบบเดียวกับฝั่งพนักงาน ดู [งานรักษาต่อเนื่อง](clinical-records.md#ไฟล์แนบในแฟ้มสัตว์) ไฟล์ถูกระบุว่ามาจากเจ้าของ (`source: owner`) คลินิกจึงแยกได้ว่าอะไรคลินิกเขียน อะไรเจ้าของส่งมา และเจ้าของเห็นไฟล์ของตัวเองเสมอ

## แพ็กเกจ

`GET /portal/packages` คืนแพ็กเกจที่ซื้อไว้ จำนวนครั้งทั้งหมด ใช้ไปแล้ว ที่เหลือ ราคา วันหมดอายุ และ `status` (`pending_payment`, `active`, `used_up`, `expired`, `cancelled`) แพ็กเกจที่ใช้ได้ขึ้นก่อน ตามด้วยที่รอชำระ แล้วจึงเป็นที่จบแล้ว

แพ็กเกจมาจากการขายที่เคาน์เตอร์ (`POST /staff/packages`) ใช้ได้เมื่อบิลขายชำระครบ และถูกตัดสิทธิ์เองเมื่อออกบิลบริการที่แพ็กเกจครอบ คำตอบเป็นรูปเดียวกับที่พนักงานเห็นใน `GET /staff/loyalty/{customer_id}` ลูกค้ากับเคาน์เตอร์จึงเห็นสิทธิ์ที่เหลือตรงกันเสมอ ดู [แพ็กเกจ คูปอง และแต้มสะสม](crm.md)

## หน้าเว็บของลูกค้า

ลูกค้าที่เข้าสู่ระบบที่ `/login` มาถึง `/portal` ส่วนพนักงานไปหน้าคิวของคลินิกที่ `/queue` หน้าของลูกค้าทุกหน้ามี `/portal` นำหน้า เพราะ `/queue` ถูกใช้ไปแล้ว

| หน้า | ที่อยู่ | แสดงอะไร |
|---|---|---|
| หน้าแรก | `/portal` | การ์ดคิวและนัด วัคซีนที่ใกล้ครบกำหนด สัตว์เลี้ยง และแจ้งเตือนล่าสุด |
| สัตว์เลี้ยงของฉัน | `/portal/pets` | การ์ดของสัตว์แต่ละตัว: ข้อมูลที่คลินิกบันทึก อาหาร พฤติกรรม และการแพ้ |
| นัดหมาย | `/portal/appointments` | นัดที่กำลังจะถึง และนัดที่ผ่านมา อย่างละ 20 รายการ นัดที่ยังเปลี่ยนได้มีปุ่มเลื่อนนัดและยกเลิกนัด |
| เลื่อนนัด | `/portal/appointments/{id}/reschedule` | เลือกวันและเวลาใหม่ด้วยตัวเลือกเวลาตัวเดียวกับหน้าจอง แล้วยืนยัน |
| ประวัติการรักษา | `/portal/records?pet=` | ประวัติทีละตัว เลือกสัตว์ได้ด้านบน |
| จองนัด | `/portal/book?pet=&service=&branch=` | จองนัดสามขั้น: รายละเอียด วันและเวลา ยืนยัน |
| แก้ข้อมูลสัตว์เลี้ยง | `/portal/pets/{id}/edit` | รูป ชื่อเล่น อาหาร และพฤติกรรม |
| ส่งไฟล์ให้คลินิก | `/portal/pets/{id}/documents` | ส่งรูปหรือเอกสารของสัตว์ตัวนั้น ลิงก์จากการ์ดสัตว์ "ส่งรูปหรือเอกสารให้คลินิก" |
| แพ็กเกจ | `/portal/packages` | แพ็กเกจที่ใช้ได้อยู่ และที่ใช้ครบหรือหมดอายุแล้ว ลิงก์อยู่ในเมนูชื่อลูกค้า |
| บิลและใบเสร็จ | `/portal/invoices?unpaid=` | ยอดค้างชำระรวม บิลทั้งหมดหรือเฉพาะที่ค้าง กดที่บิลเพื่อดูรายการ การชำระ และใบเสร็จ ลิงก์อยู่ในเมนูชื่อลูกค้า |
| แจ้งเตือน | `/portal/notifications` | กล่องแจ้งเตือนเต็ม แยกแท็บทั้งหมดและยังไม่อ่าน |
| แชทกับคลินิก | `/portal/messages?cursor=` | บทสนทนากับคลินิกและช่องพิมพ์ ลิงก์อยู่ในเมนูชื่อลูกค้าและปุ่มบนการ์ดนัด |
| บัญชีของฉัน | `/portal/account` | ข้อมูลติดต่อ ช่องทางรับข้อความ รหัสผ่าน ความยินยอม อุปกรณ์ และคำขอ PDPA |

`/portal/queue` ที่อยู่เดิมของการ์ดยังเปิดได้ และจะพาไป `/portal`

ปุ่ม "จองนัดหมาย" บนหน้าแรกสาธารณะ ท้ายเว็บ หน้าเกี่ยวกับคลินิก และหน้าติดต่อ ลิงก์ไป `/book` ซึ่งจองได้โดยไม่ต้องสมัครก่อน (ดู [จองโดยไม่ต้องสมัครก่อน](#จองโดยไม่ต้องสมัครก่อน)) ลูกค้าที่ล็อกอินอยู่แล้วถูกพาจาก `/book` มาที่ `/portal/book` ส่วนคนที่เปิด `/portal/book` ตรง ๆ โดยยังไม่ได้ล็อกอิน middleware จะพาไป `/login?next=/portal/book` และหลังล็อกอินจะกลับมาหน้าจอง ค่า `next` ถูกตรวจบนเซิร์ฟเวอร์ (`destinationFor` ใน `features/authentication/lib/home-path.ts`) รับเฉพาะ path ในเว็บนี้ และเฉพาะหน้าที่บัญชีนั้นใช้ได้ หน้าใน `/portal` และ `/book` ต้องเป็นลูกค้า หน้าอื่นต้องเป็นพนักงาน

### จองนัด

1. **รายละเอียด** เลือกสัตว์ (เฉพาะตัวที่ยังมีชีวิต) สาขา (แสดงเมื่อมีมากกว่าหนึ่ง) บริการที่เปิดจองออนไลน์ของสาขานั้น ประเภทนัด (นัดปกติหรือติดตามผล ซึ่งเป็นสองประเภทที่ลูกค้าจองได้ตามค่าตั้งต้น) และอาการถ้ามี
2. **วันและเวลา** เลือกวันจากปุ่ม 14 วันข้างหน้า หรือช่องวันที่ แล้วเลือกเวลาที่ว่างจาก `GET /booking/availability` ถ้าวันนั้นมีหมอว่างมากกว่าหนึ่งคน จะเลือกหมอได้ ถ้าไม่เลือก backend เลือกหมอที่ว่างให้
3. **ยืนยัน** การกดเลือกเวลาจะกันเวลาไว้ทันทีด้วย `POST /booking/holds` นาน 10 นาที หน้ายืนยันนับถอยหลังให้เห็น กดยืนยันแล้วเรียก `POST /portal/appointments` พร้อม `hold_id`

- idempotency key ผูกกับการกันเวลาแต่ละครั้ง กดยืนยันซ้ำได้นัดเดียว เลือกเวลาใหม่ได้ key ใหม่
- เวลาที่ถูกจองไปก่อน (`slot_unavailable`) กลับไปขั้นที่ 2 พร้อมปุ่มเวลาใกล้เคียงที่ backend เสนอใน `details.suggested`
- กันเวลาหมดอายุ (`hold_expired`) ปุ่มยืนยันกดไม่ได้ และบอกให้เลือกเวลาใหม่
- ไม่มี endpoint ยกเลิกการกันเวลา ถ้าลูกค้าเปลี่ยนเวลา เวลาเดิมจะถูกกันไว้จนครบ 10 นาที
- ลูกค้าอ่านค่าตั้งการจองไม่ได้ (ต้องมี `settings:read`) หน้าเว็บจึงไม่รู้ว่าจองล่วงหน้าได้กี่วัน วันที่เกินจะได้รายการเวลาว่างเปล่า

### จองโดยไม่ต้องสมัครก่อน

หน้าสาธารณะ `/book` (ส่วนขยาย § 27) ให้คนที่ยังไม่มีบัญชีเลือกบริการและเวลาได้ก่อน แล้วยืนยันด้วยเบอร์โทรในขั้นสุดท้าย ไม่มีปุ่มสมัครคั่นกลาง กติกาของ backend อยู่ใน [contract-extensions.md § 27](../contract-extensions.md)

1. **รายละเอียด** สาขา (เมื่อมีมากกว่าหนึ่ง) บริการที่เปิดจองออนไลน์ และอาการถ้ามี ใช้ `DetailsStep` ตัวเดียวกับหน้าจองใน portal แต่ไม่ถามสัตว์และประเภทนัด เพราะยังไม่รู้ว่าเป็นใคร และรายการประเภทนัดอ่านได้เฉพาะลูกค้าที่ล็อกอิน ทุกนัดจากหน้านี้เป็นประเภท `regular`
2. **วันและเวลา** `TimeStep` ตัวเดียวกัน เวลาว่างจาก `GET /booking/availability` การเลือกเวลายังไม่กันเวลา
3. **เบอร์โทร** สรุปสิ่งที่เลือก และช่องเบอร์ กดส่งรหัสแล้วเรียก `POST /booking/guest/start` ซึ่งกันเวลาไว้ 10 นาทีและส่งรหัสทาง SMS ถ้าเวลาถูกจองไปก่อน (`slot_unavailable`) กลับไปขั้นที่ 2 พร้อมเวลาใกล้เคียงที่ backend เสนอ
4. **ยืนยันรหัส** รหัส 6 หลัก ชื่อที่ให้คลินิกเรียก ช่องติ๊กยอมรับนโยบายความเป็นส่วนตัว (บังคับ ลิงก์ไป `/privacy`) และช่องติ๊กรับข่าวสาร (ไม่บังคับ) นับถอยหลังเวลาที่กันไว้ให้เห็น ส่งรหัสอีกครั้งได้หลัง 60 วินาที และเปลี่ยนเบอร์ได้ กดยืนยันแล้ว server action เรียก `POST /booking/guest/verify` เขียน token ลงคุกกี้ httpOnly แบบเดียวกับการสมัคร จากตรงนี้คนนั้นคือลูกค้าที่ล็อกอินแล้ว
5. **น้องที่จะมา** ลูกค้าเดิมเห็นสัตว์ที่ยังมีชีวิตของตัวเองให้เลือก และตัวเลือก "น้องตัวใหม่" คนใหม่กรอกชื่อน้องและเลือกชนิด (สุนัข แมว กระต่าย หรือพิมพ์เอง) กดยืนยันแล้วเรียก `POST /portal/appointments` พร้อม `hold_id` และ `pet_id` หรือ `new_pet` สำเร็จแล้วพาไป `/portal/appointments` ซึ่งมีนัดใหม่อยู่ในรายการ

- **ไม่บอกว่าเบอร์มีบัญชีไหมก่อนรหัสถูก** ขั้นที่ 3 และ 4 เหมือนกันทุกเบอร์ ข้อความว่า "ถ้าเคยมีบัญชีแล้ว ระบบใช้ชื่อเดิม" เขียนไว้ใต้ช่องชื่อสำหรับทุกคน
- **idempotency key** หนึ่งตัวต่อการยืนยันรหัสหนึ่งครั้ง กดยืนยันซ้ำได้นัดเดียว ถ้า backend ปฏิเสธ ครั้งถัดไปใช้ key ใหม่ เพราะคำตอบที่ถูกปฏิเสธถูกเก็บไว้กับ key เดิม
- **เวลาที่กันไว้หมดอายุ** ในขั้นที่ 4 ปุ่มยืนยันหายไป มีปุ่มกลับไปเลือกเวลาใหม่ ในขั้นที่ 5 (ล็อกอินแล้ว) ข้อความผิดพลาดมีลิงก์ไป `/portal/book` พร้อมบริการและสาขาเดิม
- **เบอร์พนักงาน** ขั้นที่ 4 แสดงข้อความของ backend (`409 contact_taken`) ว่าเบอร์นี้จองผ่านหน้านี้ไม่ได้ ไม่มีใครถูกล็อกอิน
- **ล็อกอินอยู่แล้ว** เปิด `/book` แล้วลูกค้าถูกพาไป `/portal/book` พร้อม `?service=` และ `?branch=` เดิม พนักงานถูกพาไปหน้าของพนักงาน แบบเดียวกับ `/login` ส่วนบนของหน้ามีลิงก์ "เข้าสู่ระบบก่อนจอง" สำหรับคนที่มีบัญชี ซึ่งพากลับมาที่ `/portal/book` หลังล็อกอิน
- **middleware** `/book` อยู่ใน matcher เพื่อต่ออายุ session ที่มีอยู่ (หน้าจึงรู้ว่าใครล็อกอิน) แต่ไม่บังคับให้ล็อกอิน เหมือน `/login` หน้านี้ไม่พาคนออกในระหว่างที่ server action ของหน้าเองกำลังทำงาน เพราะการยืนยันรหัสเขียนคุกกี้และทำให้หน้าถูก render ใหม่ ถ้าพาออกตรงนั้นฟอร์มจะหายก่อนถึงขั้นสุดท้าย
- **วัดผลได้ทีหลัง** แต่ละขั้นเป็นสถานะของตัวเอง กรอบฟอร์มมี `data-booking-flow="guest"` และ `data-booking-step` เป็น `details`, `time`, `phone`, `code` หรือ `pet` ไม่มีตัวติดตามของบริษัทอื่นบนหน้า
- `?service=` และ `?branch=` เลือกบริการและสาขาให้ล่วงหน้าเมื่อตรงกับที่เปิดอยู่ บริการที่ไม่ระบุสาขาเลือกสาขาแรกที่มีบริการนั้น ค่าที่ไม่ตรงถูกข้ามไป (`preselect-booking.ts` ใช้ร่วมกับ `/portal/book`)

### เลื่อนนัดและยกเลิกนัด

ปุ่มทั้งสองขึ้นเฉพาะนัดที่ยัง `booked` หรือ `confirmed` และยังไม่ถึงเวลานัด นัดที่เช็กอินแล้วต้องคุยกับเคาน์เตอร์ ปุ่มเลื่อนนัดบนการ์ดคิวและนัดของหน้าแรกพาไปหน้าเดียวกัน

**เลื่อนนัด**
1. หน้าเลื่อนนัดแสดงนัดเดิม แล้วใช้ตัวเลือกวันและเวลาของหน้าจอง (`TimeStep` ใน `features/booking`) เปิดที่วันของนัดเดิม เวลาว่างมาจาก `GET /booking/availability` ของบริการและสาขาเดิม
2. หน้ายืนยันแสดงเวลาเดิม เวลาใหม่ และหมอ แล้วเรียก `POST /appointments/{id}/reschedule` พร้อม `If-Match` เป็น `version` ที่อ่านมา

- **ไม่มีการกันเวลา** endpoint เลื่อนนัดไม่รับ `hold_id` และตรวจเวลาซ้ำเอง หน้ายืนยันจึงบอกว่าเวลายังไม่ได้กันไว้ ถ้ามีคนจองไปก่อน (`slot_unavailable`) กลับไปหน้าเลือกเวลาพร้อมเวลาใกล้เคียงที่ backend เสนอ
- **หมอ** ถ้าลูกค้าเลือกหมอ ส่งหมอคนนั้น ถ้าไม่เลือก และหมอเดิมว่างในเวลานั้น ส่งหมอเดิม ไม่อย่างนั้นส่งหมอคนแรกที่ว่าง ต้องส่งเสมอ เพราะถ้าไม่ส่ง backend ใช้หมอเดิม ซึ่งอาจไม่ว่างในเวลาที่เลือก
- **นัดกลับเป็นรอยืนยัน** การเลื่อนล้างการยืนยันเดิม หน้ายืนยันบอกเรื่องนี้ก่อนกด
- **เลยเวลาที่คลินิกกำหนด** backend ตอบ `409 cutoff_passed` หน้าเว็บแสดงข้อความของ backend (บอกจำนวนชั่วโมง) เวลาที่ปิดรับจาก `details.cutoff_at` และลิงก์ติดต่อคลินิก ลูกค้าอ่านค่า cutoff ล่วงหน้าไม่ได้ (ต้องมี `settings:read`) ก่อนเลือกเวลาจึงมีแค่ข้อความทั่วไปว่าเลื่อนออนไลน์ได้ถึงเวลาที่คลินิกกำหนด
- มีการแก้นัดจากที่อื่นระหว่างเปิดหน้า (`409 version_conflict`) บอกให้โหลดหน้าใหม่

**ยกเลิกนัด**
- กดยกเลิกนัดแล้วจะเปิดกล่องยืนยันใต้นัดนั้น บอกนโยบายก่อน คือยกเลิกได้ทุกเมื่อ แต่ถ้ากระชั้นกว่าที่คลินิกกำหนด จะนับเป็นการยกเลิกกระชั้นชิด รวมกับการไม่มาตามนัด และถ้าเกินจำนวนที่ยอมให้ คลินิกอาจเก็บค่าปรับ มีลิงก์เลื่อนนัดแทน และช่องเหตุผลที่ไม่บังคับ (ไม่เกิน 500 ตัวอักษร)
- ข้อความนโยบายไม่มีตัวเลข เพราะ `GET` ของนโยบายยกเลิกไม่มี และนโยบายอ่านได้เฉพาะจากคำตอบของ `PUT` ฝั่งพนักงาน หน้าเว็บจึงบอกล่วงหน้าไม่ได้ว่าการยกเลิกครั้งนี้จะนับว่ากระชั้นไหม หรือมีค่าปรับเท่าไร
- หลังยกเลิก นัดในรายการเปลี่ยนเป็น "ยกเลิก" และถ้า backend ตอบ `late_cancellation: true` จะมีบรรทัดสีแดงว่ายกเลิกกระชั้นชิด
- ค่าปรับไม่ถูกออกบิลเอง ถ้าคลินิกเก็บ จะเป็นบิลที่เคาน์เตอร์ ซึ่งขึ้นในหน้าบิลและใบเสร็จ

### แก้ข้อมูลสัตว์เลี้ยง

- ส่งทั้งสามช่องข้อความทุกครั้ง ช่องที่ลบจนว่างคือการล้างข้อมูลช่องนั้น และส่ง `If-Match` เป็น `version` ถ้ามีการแก้จากที่อื่นก่อน จะได้ข้อความให้โหลดหน้าใหม่ ไม่เขียนทับกัน
- **รูปส่งตรงจากเบราว์เซอร์ไปที่เก็บไฟล์** หน้าเว็บขอ `POST /portal/documents` (kind `photo`) ได้ URL ที่เซ็นแล้ว เบราว์เซอร์ `PUT` ไฟล์ไปที่ URL นั้นเอง แล้วจึงบันทึก `photo_document_id` ไฟล์ไม่ผ่านเซิร์ฟเวอร์หน้าเว็บ
- ไฟล์ที่รับได้คือ JPG, PNG, WEBP และ HEIC ไม่เกิน 10 MB ตรวจในหน้าเว็บก่อน และ backend ตรวจซ้ำ
- **ก่อนติดตั้งจริง** เบราว์เซอร์ของลูกค้าต้องเข้าถึง `Storage:PublicBaseUrl` ได้ และต้องใส่ origin ของหน้าเว็บใน `Cors:AllowedOrigins` ของ API ตอนนี้ตั้งไว้เฉพาะ `http://localhost:3000` ใน development

### ส่งไฟล์ให้คลินิก

- เลือกประเภทเอกสาร เลือกไฟล์ และใส่ชื่อเรื่องได้ถ้าต้องการ ไฟล์ที่รับคือ JPG, PNG, WEBP, HEIC และ PDF ไม่เกิน 10 MB ตรวจในหน้าเว็บก่อนส่ง
- ไฟล์ส่งตรงจากเบราว์เซอร์ไปที่เก็บไฟล์ แบบเดียวกับรูปสัตว์ จึงมีเงื่อนไขเรื่อง `Cors:AllowedOrigins` เหมือนกัน
- ส่งเสร็จแล้วมีปุ่มส่งไฟล์อื่นต่อ และลิงก์ไปประวัติการรักษาถ้าลูกค้าดูประวัติของสัตว์ตัวนั้นได้

### แพ็กเกจ

- แยกสองกลุ่ม ใช้ได้อยู่ (รวมแพ็กเกจที่รอชำระเงิน มีป้าย "รอชำระเงิน") กับ ใช้ครบ หมดอายุ หรือยกเลิกแล้ว แต่ละใบบอกครั้งที่เหลือ สัตว์ที่ใช้ได้ วันหมดอายุ (เตือน "ใกล้หมดอายุ" เมื่อเหลือไม่ถึง 30 วัน) และวันที่ซื้อ
- ชื่อบริการมาจากเมนูบริการสาธารณะ บริการที่ไม่ได้เปิดจองออนไลน์จึงไม่มีชื่อ
- บัญชีที่ยังไม่มีแพ็กเกจเห็นหน้าว่าง ซึ่งอธิบายว่าแพ็กเกจจะขึ้นที่นี่เมื่อซื้อที่คลินิก พร้อมลิงก์ไปหน้าติดต่อและหน้าจองนัด
- ลิงก์อยู่ในเมนูชื่อลูกค้า ไม่ได้อยู่ในแถบล่างจอ เพราะแถบนั้นมีที่สำหรับ 4 ปุ่มพอดี

### บิลและใบเสร็จ

- ด้านบนคือ**ยอดค้างชำระรวม** บวกจาก `balance_satang` ของบิลใน `GET /portal/invoices?unpaid=true` (สูงสุด 100 ใบ ถ้าเกินจะมี `+` ต่อท้ายจำนวน) พร้อมบอกว่าชำระได้ที่เคาน์เตอร์ ถ้าไม่มีบิลค้าง จะขึ้นบรรทัดสั้น ๆ ว่าไม่มียอดค้างชำระ
- แท็บ "ทั้งหมด" และ "ค้างชำระ" หน้าละ 20 ใบ ใหม่สุดก่อน ดูบิลเก่ากว่าด้วยลิงก์ที่มี `cursor` เหมือนหน้าแจ้งเตือน
- บิลที่ยังค้าง (`open` หรือ `partially_paid` และยอดค้างมากกว่าศูนย์) มีกรอบสีเหลืองและบอกยอดค้างใต้ยอดรวม บิลที่ยกเลิกแล้วขีดฆ่ายอดรวม
- กดที่บิลเพื่อดูรายละเอียดในที่เดิม ได้แก่ รายการพร้อมจำนวนและราคาต่อหน่วย ส่วนลดพร้อมเหตุผล ยอดรวม ยอดที่ชำระ ยอดคืนเงิน ยอดค้าง การชำระแต่ละครั้ง (เงินสด บัตร หรือพร้อมเพย์) การคืนเงิน และเลขที่ใบเสร็จ (บอกถ้าเป็นใบกำกับภาษี) ทุกยอดมาจาก backend หน้าเว็บไม่บวกเอง เงินแสดงด้วย `formatBaht`
- รายละเอียดอยู่ในหน้ารายการ ไม่มีหน้าแยกต่อบิล เพราะ `GET /portal/invoices` ส่งบิลมาครบทุกส่วนแล้ว และไม่มี endpoint อ่านบิลใบเดียวของลูกค้า

### แจ้งเตือน

- หน้าละ 20 ข้อความ ดูข้อความเก่ากว่าด้วยลิงก์ที่มี `cursor` API เดินหน้าได้อย่างเดียว จึงมีแค่ลิงก์กลับไปข้อความล่าสุด ไม่มีปุ่มย้อนทีละหน้า
- ปุ่ม "อ่านแล้ว" ทีละข้อความ และ "อ่านแล้วทั้งหมด" เรียก `POST /portal/notifications/read` แล้วรีเฟรชตัวเลขบนกระดิ่ง

### แชทกับคลินิก

บทสนทนาเดียวกับที่พนักงานตอบในหน้า "ข้อความลูกค้า" ทั้งข้อความที่ลูกค้าพิมพ์ในหน้านี้และที่พิมพ์ถึงบัญชี LINE ของคลินิกจาก LINE ที่ผูกไว้ เป็นส่วนขยาย ดู [ข้อความลูกค้า](messaging.md#แชทใน-portal-ส่วนขยาย--24) และ [contract-extensions.md § 24](../contract-extensions.md)

- ข้อความของลูกค้าอยู่ขวา ของคลินิกอยู่ซ้ายพร้อมชื่อผู้ตอบ หรือคำว่า "คลินิก" เมื่อไม่มีชื่อ ข้อความที่ลูกค้าส่งมาทาง LINE บอกว่า "ส่งทาง LINE"
- หน้าแสดง 50 ข้อความล่าสุด ข้อความเก่ากว่าดูด้วยลิงก์ "ดูข้อความก่อนหน้า" (`cursor`) หน้าเก่าไม่มีช่องพิมพ์ และมีลิงก์กลับไปข้อความล่าสุด
- ช่องพิมพ์รับ 1 ถึง 1,000 ตัวอักษร ส่งแล้วช่องว่างลงและข้อความขึ้นในบทสนทนา ข้อความที่ backend ปฏิเสธ เช่นส่งถี่เกิน 60 ครั้งต่อนาที ขึ้นเหนือช่องพิมพ์
- หน้าอ่านใหม่ทุก 15 วินาทีขณะเปิดอยู่ (`LiveRefresh` ตัวเดียวกับการ์ดนัด) และหยุดเมื่อแท็บถูกซ่อน
- เมื่อมีคำตอบใหม่ขึ้นบนจอ หน้ากดว่าอ่านแล้วให้สำเนา `thread.reply` ในกล่องแจ้งเตือน ตัวเลขบนกระดิ่งจึงลดลงเอง
- มีคำเตือนว่าถ้าน้องป่วยฉุกเฉินให้โทรหาคลินิก อย่ารอคำตอบในแชท

### บัญชีของฉัน

- **ข้อมูลส่วนตัวและช่องทางรับข้อความ** เขียนผ่าน `PATCH /me` ทั้งคู่ และใช้ `version` ร่วมกัน บันทึกฟอร์มหนึ่งแล้วอีกฟอร์มยังบันทึกต่อได้ การเปลี่ยนอีเมลหรือเบอร์โทรต้องใส่รหัสผ่านปัจจุบัน ช่องนี้จะขึ้นเมื่อแก้สองช่องนั้นเท่านั้น
- **เปลี่ยนรหัสผ่าน** backend ตอบรหัสเดิมผิดด้วย `401` ซึ่งเป็นรหัสเดียวกับ session หมดอายุ action นี้จึงไม่ใช้ตัวจัดการกลางที่จะพาไปหน้าเข้าสู่ระบบ แต่แสดงว่ารหัสผ่านปัจจุบันไม่ถูกต้องที่ช่องนั้น เปลี่ยนสำเร็จแล้ว อุปกรณ์อื่นทุกเครื่องถูกออกจากระบบ
- **ความยินยอม** ส่งเฉพาะสวิตช์ที่ลูกค้าขยับ ค่าตั้งต้นที่ไม่ได้แตะจึงยังเป็นค่าตั้งต้น ไม่กลายเป็นการตัดสินใจที่บันทึกไว้
- **อุปกรณ์** แสดงชื่อเบราว์เซอร์และระบบจาก user agent แบบคร่าว ๆ ออกจากระบบเครื่องอื่นได้ทีละเครื่อง เครื่องที่ใช้อยู่ออกจากระบบได้จากเมนูชื่อ
- **คำขอ PDPA** ส่ง `POST /portal/data-requests` แบบ ขอดูข้อมูล แก้ไข ขอรับเป็นไฟล์ หรือขอลบ เจ้าหน้าที่ดำเนินการต่อ

### หัวเว็บสองแบบ

- **ในหน้าของลูกค้า** หัวเว็บมีเมนู หน้าแรก สัตว์เลี้ยงของฉัน นัดหมาย และประวัติการรักษา ทางขวามีกระดิ่งพร้อมจำนวนที่ยังไม่อ่าน ปุ่มจองนัด และเมนูชื่อลูกค้า (บัญชีของฉัน แพ็กเกจของฉัน บิลและใบเสร็จ แจ้งเตือน หน้าเว็บคลินิก และออกจากระบบ) บนมือถือ เมนูย้ายไปเป็นแถบล่างจอ 4 ปุ่ม
- **ในหน้าสาธารณะตอนล็อกอินอยู่** เมนูยังเป็นของหน้าสาธารณะ แต่ปุ่ม "เข้าสู่ระบบ" และ "สมัครใช้งานฟรี" กลายเป็นปุ่ม "บัญชีของฉัน" ปุ่มนี้ลิงก์ไป `/login` ซึ่งพาลูกค้าไป portal และพาพนักงานไปหน้าคิว
- หน้าสาธารณะยังเป็นหน้า static จึงไม่ได้อ่าน session จริง หน้าเว็บรู้ว่าล็อกอินอยู่จากคุกกี้ `hp_signed_in` ซึ่งมีค่าเป็น `1` เท่านั้น ไม่ใช่รหัสผ่านหรือ token ถ้าค่าในคุกกี้ไม่ตรงกับความจริง ปุ่มก็แค่พาไปหน้า `/login` ซึ่งตรวจ session จริงอีกครั้ง
- กระดิ่งลิงก์ไปหน้าแจ้งเตือน (`/portal/notifications`)

### การ์ดคิวและนัด

หน้าแรกแสดง**การ์ดหนึ่งใบต่อหนึ่งการมาคลินิก** วันนี้มีนัดหรือคิวกี่รายการก็ได้การ์ดเท่านั้น เช่น หมามีนัดและแมวมาแบบ walk-in จะได้สองการ์ด เรียงจากที่ถูกเรียกอยู่ อยู่ในห้องตรวจ รอเรียก แล้วจึงที่ยังไม่มาถึง ถ้าวันนี้ไม่มีอะไรเลย จะแสดงนัดถัดไปหนึ่งใบ

บัตรคิวใน `GET /portal/home` มี `pet_id` และ `appointment_id` (ไม่มีสำหรับ walk-in) หน้าเว็บจับคู่บัตรกับนัดด้วย `appointment_id` เท่านั้น เลขคิวของสัตว์ตัวหนึ่งจึงไม่ไปขึ้นบนการ์ดของอีกตัว สองช่องนี้เพิ่มหลังทดลองกับข้อมูลจริง ก่อนหน้านั้นการ์ดนัดของหมาเคยหยิบเลขคิว walk-in ของแมวมาแสดง และซ่อนปุ่มเช็กอินของหมา

การ์ดแต่ละใบแสดง
- บริการ ชื่อสัตว์ ชื่อหมอ และเวลานัด
- เลขคิวและจำนวนคิวที่อยู่ก่อน
- แถบความคืบหน้า เช็กอิน รอเรียก ตรวจ ชำระเงิน
- กล่องสีเหลืองบอกสิ่งที่ควรทำตอนนี้
- ปุ่มเช็กอินล่วงหน้า เลื่อนนัด และแชทกับคลินิก

- **นัดของวันนี้มาก่อน** แม้เลยเวลาเริ่มแล้ว เพราะ `next_appointment` ของ `GET /portal/home` นับจากตอนนี้ไปข้างหน้า นัด 10:30 จะหายจากการ์ดตอน 10:31 ทั้งที่น้องยังรอตรวจอยู่ หน้าเว็บจึงอ่าน `GET /portal/appointments?upcoming=false` ประกอบด้วย
- **ชื่อบริการและชื่อหมอ** มาจาก `GET /services` และ `GET /team` บริการที่ไม่ได้เปิดจองออนไลน์จึงไม่มีชื่อ และหมอที่ไม่ได้แสดงบนหน้าทีมขึ้นเป็น "สัตวแพทย์ที่ว่างในวันนั้น"
- **กล่องสีเหลืองก่อนเช็กอิน** บอกเวลาที่ควรมาถึง คือเวลานัดลบ 15 นาที ไม่ได้บอกว่าควรออกจากบ้านเมื่อไร เพราะระบบไม่มีตำแหน่งของลูกค้าและข้อมูลจราจร
- **เช็กอินล่วงหน้า** เรียก `POST /appointments/{id}/check-in` พร้อม idempotency key การกดซ้ำไม่ทำให้ได้สองคิว ถ้า backend ปฏิเสธ เช่นยังไม่ถึงเวลา ข้อความจะขึ้นใต้ปุ่ม
- **อัปเดตเองทุก 15 วินาที** ระหว่างที่เปิดหน้าอยู่ และหยุดเมื่อสลับแท็บหรือปิดจอ
- ปุ่มเลื่อนนัดพาไปหน้าเลื่อนนัดของนัดนั้น ขึ้นเฉพาะนัดที่ยัง `booked` หรือ `confirmed` และยังไม่ถึงเวลานัด
- ปุ่มแชทกับคลินิกพาไปหน้าแชทใน portal (`/portal/messages`) ดู [แชทกับคลินิก](#แชทกับคลินิก) แก้ลิงก์ได้ที่ `frontend/src/features/portal/content/visit-card.ts`

### ประวัติการรักษา

- มีให้เลือกเฉพาะสัตว์ที่ `may_view_history` เป็นจริง ผู้ดูแลร่วมที่ลิงก์ไม่อนุญาตจึงไม่เห็นตัวเลือกนั้น
- ถ้าคลินิกยังไม่เปิดส่วนใดเลย (`visible_sections` ว่าง ซึ่งเป็นค่าตั้งต้น) หน้าเว็บบอกตรง ๆ ว่าตอนนี้เห็นแค่วันที่มาตรวจ ไม่ปล่อยให้ดูเหมือนข้อมูลหาย
- ส่วนที่ API ไม่ส่งมาไม่ถูกวาดเลย ส่วนที่ส่งมาแต่ว่างขึ้นว่า "ไม่มี"

## ข้อจำกัดที่รู้อยู่

- หน้าแชทยังส่งรูปหรือไฟล์ไม่ได้ และยังไม่บอกว่าเจ้าหน้าที่อ่านแล้ว ดู [ข้อความลูกค้า](messaging.md#ยังไม่ได้ทำ)
- ลูกค้าไม่เห็นตัวเลขของนโยบายก่อนเลื่อนหรือยกเลิก (cutoff ของการเลื่อน cutoff ของการยกเลิก ค่าปรับ และจำนวนครั้งที่ยอมให้) เพราะไม่มี endpoint ที่ลูกค้าอ่านได้ การเลื่อนที่เลยเวลาจะรู้ตอนกดยืนยัน
- การเลื่อนนัดไม่กันเวลาไว้ระหว่างที่ลูกค้าอ่านหน้ายืนยัน
- ชำระบิลผ่านเว็บไม่ได้ เพราะ contract ไม่มี endpoint ชำระของลูกค้า และยังไม่มี payment gateway ไม่มีไฟล์ PDF ของใบเสร็จให้ดาวน์โหลด และไม่มี endpoint อ่านบิลใบเดียว
- หน้าเลื่อนนัด กล่องยกเลิกนัด และหน้าบิลยังไม่ได้ทดสอบในเบราว์เซอร์ด้วยบัญชีลูกค้า ผ่านแค่ typecheck และ lint
- ไม่มีรายการไฟล์ที่ลูกค้าส่งไปแล้ว ไฟล์จะเห็นในประวัติการรักษาเฉพาะเมื่อคลินิกเปิดส่วนไฟล์แนบให้เจ้าของเห็น
- หน้าส่งไฟล์และหน้าแพ็กเกจยังไม่ได้ทดสอบในเบราว์เซอร์ด้วยบัญชีลูกค้า ผ่านแค่ typecheck และ lint
- กล่องแจ้งเตือนไม่ถูกลบ
- ดาวน์โหลดไฟล์ด้วยลิงก์ที่ใครได้ไปก็เปิดได้จนหมดอายุ 10 นาที
