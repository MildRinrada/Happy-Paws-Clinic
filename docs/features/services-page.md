# หน้าบริการและราคา

หน้า `/services` บอกผู้เยี่ยมชมว่าคลินิกมีบริการอะไร ราคาเท่าไร และใช้เวลานานแค่ไหน แล้วให้กดจองบริการที่ต้องการได้ทันที ไม่ต้องเข้าสู่ระบบ ปุ่ม **ดูบริการและราคา** ใน Hero ของหน้าแรก เมนู **บริการ** บน header ลิงก์ **บริการและราคา** ใน footer และลิงก์ใต้การ์ดบริการบนหน้าแรกพามาที่นี่

## ข้อมูลมาจากไหน

ทุกอย่างบนหน้าอ่านจาก API ทุกครั้งที่เปิดหน้า ราคาที่พนักงานแก้จึงขึ้นบนเว็บทันที

| ส่วน | มาจาก | หมายเหตุ |
|---|---|---|
| บริการ ระยะเวลา ราคา ราคาแยก และสาขาที่มีบริการ | `GET /services` | เฉพาะบริการที่เปิดใช้งานและเปิดจองออนไลน์ |
| ชื่อหมวดและลำดับหมวด | `GET /services/categories` | แสดง **ทุกหมวด** ตามลำดับนี้ รวมหมวดที่ยังไม่มีบริการจองออนไลน์ ถ้าอ่านไม่ได้ แสดงเฉพาะหมวดที่บริการอ้างถึง โดยใช้รหัสหมวดเป็นหัวข้อ |
| ชื่อสาขา | `GET /clinic/branches` | ใช้เมื่อคลินิกมีมากกว่าหนึ่งสาขา |
| เบอร์โทรคลินิกและ LINE | `GET /clinic/contacts` | อ่านผ่าน `loadSiteInfo` ครั้งเดียวต่อคำขอ ชุดเดียวกับที่ header และ footer ใช้ |
| ข้อความและรูปของแถบหัว | `loadPageBanner('services')` | ตัวอ่านแถบหัวกลางที่หน้าทีมของเราใช้ด้วย ตอนนี้คืนค่าตั้งต้นจากไฟล์เนื้อหา ดู [ส่วนที่รอการอนุมัติ](#ส่วนที่รอการอนุมัติ) |

แก้บริการและราคาที่หน้าจอพนักงาน **ตั้งค่า > บริการและราคา** ดู [บริการ](services.md) บริการที่จองได้ที่เคาน์เตอร์อย่างเดียวจะไม่ขึ้นบนหน้านี้ ถ้าอยากให้ขึ้นต้องเปิดจองออนไลน์ให้บริการนั้น แก้เบอร์โทรและ LINE ที่ **ตั้งค่า > ข้อมูลติดต่อ**

เบอร์โทรที่ใช้คือเบอร์ประเภท `phone` ของทั้งคลินิกอันแรก ถ้าไม่มีจึงใช้ของสาขา LINE ใช้รายการประเภท `line` แบบเดียวกัน และต้องมีลิงก์ที่ขึ้นต้นด้วย `http` หรือ `https` จึงจะขึ้นปุ่ม

## หน้าตา

หน้าทำตามดีไซน์ของเจ้าของ ย่อขนาดให้คอลัมน์เนื้อหากว้าง 992 px เท่าหน้าอื่นของเว็บ เรียงจากบนลงล่าง

1. **แถบหัวสีเขียวเข้ม** คำนำสีเหลือง หัวข้อสองบรรทัด คำอธิบาย ปุ่ม **จองนัดหมาย** (ส้ม ตัวอักษรเข้ม) และ **ดูช่องทางติดต่อ** (ขอบขาวโปร่ง) ทางขวามีรูปขอบมน มีวงกลมตกแต่งสี่วง (เหลือง ส้ม เขียวอมฟ้า เหลือง) ที่มุมล่างขวาของรูป บนมือถือรูปย้ายไปอยู่ใต้ข้อความ ถ้าไม่มีรูป หน้าวาดกรอบเส้นประแทน
2. **แถบไปที่หมวด** ใต้แถบหัว ปุ่มหมวดละหนึ่งปุ่ม มีจุดสีประจำหมวด กดแล้วเลื่อนลงไปที่หมวดนั้น บนมือถือเลื่อนแถบไปทางข้างได้ ตัวหน้าไม่เลื่อนตาม
3. **หมวดละหนึ่งส่วน** เรียงตามลำดับของ contract (ตรวจ วัคซีน ทันตกรรม ผ่าตัด แล็บ กรูมมิ่ง) หัวข้อหมวด คำอธิบายหนึ่งบรรทัด ทางขวาบอกจำนวนบริการ เช่น `3 บริการ` แล้วมีเส้นเข้มคั่น ใต้เส้นเป็นการ์ดบริการ 3 คอลัมน์บนจอกว้าง 2 คอลัมน์บนแท็บเล็ต และ 1 คอลัมน์บนมือถือ บริการในหมวดเรียงตามที่ API ส่งมา
4. **หมวดที่ยังไม่มีบริการจองออนไลน์** แสดงหัวข้อ คำอธิบาย และเส้นคั่นเหมือนกัน แต่ทางขวาเป็นลิงก์ **โทรสอบถาม** ที่โทรหาเบอร์คลินิก ถ้าคลินิกยังไม่ตั้งเบอร์ ลิงก์ไปหน้าติดต่อ ไม่มีการ์ด
5. **การ์ดบริการ** พื้นเทาอ่อนขอบมน ชื่อบริการ ป้ายระยะเวลาทางขวา คำอธิบายบริการ (เมื่อ API มีให้) ตารางราคาแยก (ถ้ามี) ข้อความ `มีที่ <ชื่อสาขา>` (เฉพาะคลินิกหลายสาขา และบริการไม่ได้มีทุกสาขา) เส้นคั่น แล้วแถวล่าง `เริ่มต้น ฿450` กับปุ่มเขียวเข้ม **จองบริการนี้ →**
6. **บรรทัดเรื่องราคา** ตัวอักษรสีเทาหนึ่งบรรทัดใต้หมวดสุดท้าย บอกว่าราคาเป็นราคาตั้งต้น และหน้านี้มีเฉพาะบริการที่จองออนไลน์ได้
7. **กล่องสีส้มปิดหน้า** หัวข้อ **ไม่แน่ใจว่าน้องต้องใช้บริการไหน** ปุ่ม **ทักแชท LINE** (ม่วง ไปที่ลิงก์ LINE ของคลินิก) และ **โทร <เบอร์คลินิก>** (ดำ โทรออกได้เลย) ปุ่มไหนไม่มีข้อมูลติดต่อจะไม่แสดง ถ้าไม่มีทั้งสองอย่าง แสดงปุ่ม **ดูช่องทางติดต่อ** ไปหน้า `/contact` แทน

ถ้า API ของบริการไม่ตอบ หน้ายังเปิดได้ แถบหัวและกล่องสีส้มยังอยู่ ตรงกลางบอกว่ายังโหลดรายการไม่ได้พร้อมลิงก์ไปหน้าติดต่อ ถ้ายังไม่มีบริการที่เปิดจองออนไลน์เลย หน้าบอกให้โทรหรือนัดผ่านคลินิก แล้วยังแสดงทุกหมวดพร้อมลิงก์ **โทรสอบถาม**

## ราคาแสดงอย่างไร

| กรณี | แสดง |
|---|---|
| ราคาเดียว | `เริ่มต้น ฿500` เพราะค่าใช้จ่ายจริงขึ้นกับการตรวจและการรักษา |
| มีราคาแยกตามชนิดสัตว์หรือน้ำหนัก | `เริ่มต้น ฿400` คือราคาต่ำสุดในบรรดาราคาพื้นฐานและราคาแยกทุกแถว ในการ์ดมีรายการราคาแยกทีละแถว แล้วต่อด้วย **นอกเหนือจากนี้** ซึ่งคือราคาพื้นฐาน |
| ราคาเป็น 0 | `สอบถามราคา` |

ราคาเต็มบาทไม่มีทศนิยม ราคาที่มีสตางค์แสดงสองตำแหน่ง น้ำหนักสูงสุดของแต่ละแถวไม่นับรวม เหมือนที่หน้าจอพนักงานบอก เช่น `สุนัข 10 ถึงไม่ถึง 20 กก.`

ระยะเวลาเขียนเป็น `30 นาที` `1 ชม.` หรือ `1 ชม. 30 นาที`

## ปุ่มจองบริการนี้

ปุ่มไปที่ `/book?service=<id ของบริการ>` เช่น `/book?service=svc_checkup` หน้าจองจะเลือกบริการนั้นไว้ให้ ปุ่ม **จองนัดหมาย** บนแถบหัวไปที่ `/book` โดยไม่เลือกบริการ ที่อยู่ของปุ่มตั้งที่ `serviceCard.bookHref` ในไฟล์เนื้อหาของหน้า และ `pageBannerDefaults.services` ใน `features/site-banners/content/page-banners.ts`

## ส่วนที่รอการอนุมัติ

สองเรื่องนี้ต้องเพิ่มใน backend ก่อน ยังไม่ได้อนุมัติ หน้าเตรียมที่ไว้แล้ว เมื่อ API พร้อมจะแก้เฉพาะจุดเดียว

**แก้แถบหัวจากหน้าจอพนักงาน** เจ้าของอยากแก้ข้อความ ปุ่ม และรูปของแถบหัวเองได้ ซึ่งเป็นส่วนขยายที่ยังรอการอนุมัติ ตอนนี้ข้อมูลทั้งหมดของแถบหัวผ่านฟังก์ชันเดียว คือ `loadPageBanner(page)` ใน `frontend/src/features/site-banners/lib/load-page-banner.ts` ซึ่งใช้ร่วมกันทุกหน้าที่มีแถบหัวแบบนี้ ตอนนี้มี `services` และ `team` (หน้า [ทีมของเรา](team.md)) ฟังก์ชันคืนค่าตั้งต้นของหน้านั้นจาก `pageBannerDefaults` ใน `features/site-banners/content/page-banners.ts` component ของแต่ละหน้ารับข้อมูลชุดนี้ทาง props อย่างเดียว เมื่อมี API ให้เปลี่ยนเนื้อฟังก์ชันนี้เป็นการอ่าน API ตามชื่อหน้า ที่ถอยกลับไปใช้ค่าตั้งต้นเมื่ออ่านไม่ได้ หน้าอื่นไม่ต้องแก้ รูปร่างของข้อมูล (`PageBannerData` ใน `features/site-banners/types/page-banner.types.ts`)

| ช่อง | ความหมาย |
|---|---|
| `eyebrow` | คำนำเหนือหัวข้อ บนหน้านี้เป็นสีเหลือง |
| `heading` | หัวข้อ ขึ้นบรรทัดใหม่ตรงที่มี `\n` |
| `lead` | คำอธิบายใต้หัวข้อ |
| `primaryAction` | `{ label, href }` ปุ่มส้ม |
| `secondaryAction` | `{ label, href }` ปุ่มรอง ไม่บังคับ ไม่มีแล้วแถบหัวมีปุ่มเดียว บนหน้านี้เป็นปุ่มขอบขาว |
| `image` | `{ src, alt }` ไม่บังคับ ไม่มีแล้วหน้าวาดกรอบว่าง |

**คำอธิบายบริการ** API ยังไม่มีช่องคำอธิบายบริการ หน้าเพิ่ม `description?: string` ใน `PublicService` ไว้แล้ว ถ้า `GET /services` ส่งมา การ์ดแสดงเป็นย่อหน้าใต้ชื่อ และใส่ใน `description` ของข้อมูลโครงสร้างด้วย ถ้าไม่ส่งมา การ์ดไม่มีย่อหน้านั้น ไม่มีข้อความตัวอย่างหรือช่องว่างให้ผู้เยี่ยมชมเห็น

## ชิ้นส่วนที่ใช้ร่วมกับหน้าอื่น

หน้านี้ประกอบจากชิ้นส่วนกลางของเว็บสาธารณะใน `frontend/src/components/site/` ทั้งหมด หน้าอื่นของเว็บสาธารณะใช้ชุดเดียวกันแล้ว ดู [หน้าไหนใช้ชิ้นไหน](../ui-ux.md#หน้าไหนใช้ชิ้นไหน)

| ชิ้นส่วน | ใช้ทำอะไรในหน้านี้ |
|---|---|
| `PageBanner` (`size="feature"`) พร้อม `BannerImage` และ `BannerDots` | แถบหัว รูป และวงกลมตกแต่ง |
| `ChipNav` และ `DotChip` | แถบไปที่หมวด |
| `SectionHeader` | หัวหมวด คำอธิบาย จำนวนบริการ และเส้นคั่น |
| `SiteCard` (`tone="muted"`), `MetaPill`, `CardDivider` | การ์ดบริการ ป้ายระยะเวลา และเส้นคั่นในการ์ด |
| `CtaBand` (`variant="inset"`) | กล่องสีส้มปิดหน้า |
| `CtaLink` แบบ `solidInk`, `outline`, `forest`, `violet`, `dark` | ปุ่มทั้งหมด |

## ข้อจำกัด

- ไม่มีรูปของแต่ละบริการ เพราะ API ไม่มีที่เก็บรูปบริการ
- รูปบนแถบหัวตอนนี้ใช้รูปเดียวกับหน้าเกี่ยวกับคลินิก (`/images/about/vet-exam-dog.jpg`) จนกว่าจะแก้แถบหัวจากหน้าจอพนักงานได้
- คำอธิบายใต้ชื่อหมวดเป็นข้อความในไฟล์เนื้อหา ไม่ได้มาจาก API หมวดใหม่ที่ไม่มีในไฟล์จะไม่มีคำอธิบาย
- หน้า render ใหม่ทุกครั้งที่เปิด (`force-dynamic`) ไม่ทำ static เพราะตอน build อาจไม่มี API ให้เรียก
