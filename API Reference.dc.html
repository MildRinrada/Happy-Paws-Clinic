ภาพรวมและ Base URL

แต่ละคลินิกติดตั้งเป็น instance ของตัวเอง ข้อมูลไม่เชื่อมกันข้ามคลินิก API จึงไม่มี path ระดับ platform ไม่มี clinic directory และไม่มี tenant switcher — clinic context มาจาก host ของ instance ไม่ใช่จาก parameter ที่ client ส่ง

Production https://api.happypaws.co.th/v1
Staging https://api.staging.happypaws.co.th/v1
Auth Authorization: Bearer <access_token>
Idempotency Idempotency-Key: <uuid> (ทุก POST ที่สร้างเงิน/นัด/คิว)
Isolation by deployment
ทุก resource ผูกกับ instance เดียว ไม่มี clinic_id ใน path ให้สลับได้
Two audiences
พนักงานใช้ /staff/* ลูกค้าใช้ /portal/* โดยแชร์ domain object เดียวกัน
One account, many capabilities
บัญชีเดียวเป็นทั้งลูกค้าและพนักงานได้ แยกกันด้วย membership ใน instance นี้

Conventions และ Errors

Pagination · cursor-based: ?limit=25&cursor= คืน data[] และ page.next_cursor
Filtering · ?status=checked_in&date=2026-08-22&vet_id=stf_204&q=มิโล
Time · ISO 8601 พร้อม offset 2026-08-22T10:30:00+07:00 · เงินเป็นสตางค์ 146000
Concurrency · ทุก mutable resource มี version ส่งกลับใน If-Match ไม่ตรงตอบ 409
Rate limit · 600 req/นาที ต่อ token · endpoint ส่งข้อความ 60/นาที

State machines

draft→ booked→ confirmed→ checked_in→ in_consultation→ completed | cancelled no_show

waiting→ called→ in_room→ served | skipped left

draft→ signed→ amended ลบไม่ได้ · ทุกฉบับเก็บถาวรพร้อมผู้ลงนาม
Invoice
